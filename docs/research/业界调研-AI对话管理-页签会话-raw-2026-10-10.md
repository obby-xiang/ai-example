# 业界调研（原始稿）：页签级/无历史列表 AI 会话的「清空/重开对话」设计

- 检索日期：2026-10-10（全部条目的检索日均为此日）
- 配套结论稿：`chat-panel-research/业界调研-页签会话-结论.md`
- 调研背景：本项目为「会话=浏览器页签」模型——`sessionId` 存 `sessionStorage`，关页签即永久丢失，无会话列表、无历史、无跨页签恢复，服务端记忆 6 小时 TTL。本稿回答同类产品的「重开对话」按钮叫什么、放哪、要不要确认、删不删服务端记忆。

### A1. kapa.ai（Chat SDK 内嵌对话）— 本项目的最近邻

kapa.ai 的官方 Chat SDK 教程明确示范了内嵌对话界面的「重开对话」按钮。

- 按钮**名称**：`New Chat`（图标用 `LuRefreshCw` 循环箭头，与文字并排）
- 按钮**位置**：面板**顶部 header**，与标题 `AI Assistant` 左右分栏（`justify-content: space-between`），标题在左、按钮在右
- 按钮**状态**：`disabled={conversation.length === 0}`——**没有对话时按钮禁用置灰**，不弹空确认
- 点击后行为：`resetConversation()`；官方 checkpoint 原文 *"The 'New Chat' button should clear all messages when clicked."*
- **是否有二次确认：无。** 官方教程里 `onClick={resetConversation}` 直接绑定，没有任何 confirm 层
- 服务端记忆处置：**官方教程未提**。SDK 只有 `resetConversation` 这一层，文档没说它是否清服务端 retrieval 会话

  > `function ChatHeader({ conversation, resetConversation }) { ... <button className={styles.newChatButton} onClick={resetConversation} disabled={conversation.length === 0}><LuRefreshCw /> New Chat</button> ... }`
  >
  > `**Testing:** Submit multiple questions to verify the chat automatically scrolls to display the latest responses. The "New Chat" button should clear all messages when clicked.`

## B. 客服 / 支持类聊天挂件

### B1. HubSpot Conversations SDK — 「会话已结束 + 新开会话」的标准双文案

官方 SDK 文档里能看到完整的「结束后重开」链路文案，含**确切英文串**：

- 结束后的系统文案：`Your chat has ended`
- 其下方链接：`To start a new chat, click here`
- 开关：`hideNewThreadLink` — *"When set to true, prevent the **To start a new chat, click here** link from appearing below the **Your chat has ended** text when a chat has ended."*
- 编程式重开：`widget.refresh` 的 `openToNewThread` 参数 — *"Whether to force a new thread to be created."*
- **清 cookie / 真正重置**：
  - `clear()` — *"deletes cookies related to the chat widget and **returns it to its default state on subsequent load**"*；被清的 cookie 含 `messagesUtk`（用于 *"Referencing historical conversations"*）
  - `clear({resetWidget:true})` — *"clear all chat related cookies, remove the widget from the page, and create a new instance of the chat widget"*
- **★ 这回答 (c) 的关键分化**：`clear()` 的效果是「**下次加载时**才回到默认态」（保留到下次加载），而 `resetWidget:true` 是**立即**移除并新建实例
- **二次确认：无**（全部是 API 语义，无 confirm）
- 服务端记忆：cookie `messagesUtk` 被删 → 服务端**认不出老访客**，即间接清了服务端会话关联
- 事件侧：`conversationClosed` 只在 inbox 侧关闭时触发，*"Site visitors minimizing or closing the chat widget will not trigger this event"*（关闭挂件 ≠ 结束会话）
- 来源：<https://developers.hubspot.com/docs/api-reference/latest/conversations/chat-configuration/chat-widget-sdk>　检索日期 2026-10-10　【官方文档实证】

### B2. Talkdesk Chat Widget V2 — 命名与确认文案最完整的一手来源

Talkdesk 的可配置文案字段（含**默认值**）几乎把这类产品的词汇表全盘托出：

| 字段 | 默认值 | 官方说明 |
|---|---|---|
| `startChatButtonLabel` | **`Start new chat`** | "Display copy in Start New Conversation button" |
| `endedChatMessage` | **`End chat`** | "System message text displayed at the end of conversation." |
| `chatConfirmButtonEndChat` | **`Yes, end chat`** | 结束对话确认框的确认按钮 |
| `chatCancelButtonEndChat` | **`Cancel`** | 结束对话确认框的取消按钮 |
| `chatConfirmButtonRetryEndChat` / `chatCancelButtonRetryEndChat` | `Try again` / `Dismiss` | 取消失败时的重试/关闭 |

- **★ 明确存在「标准的确认提示」**：`end` 方法说明原文 *"The `end` method programmatically terminates the active conversation, **replicating the behavior of a user manually closing the chat but bypassing the standard confirmation prompt**."* → 即用户手动关闭时**有**确认，API 可绕过
- **★ 事件命名直接印证按钮名**：`onConversationClear` — *"triggered when the contact person clicks the **Start New Chat** button to clear the current conversation."*
- **★ (c)/(d) 的关键分化**：`reset` 方法原文：

  > "The `reset` method reverts the chat widget to its default initial state without removing it from the DOM. When invoked, it minimizes the widget window, clears the notification badge, and reloads the internal iframes to prepare for a fresh session. **While the server-side conversation state remains intact, all local client-side cache is purged, preventing the current user from restoring the previous session.**"

  → 即 **本地全清 + 服务端保持**，这正是「页签级会话」的典型实现口径
- `destroy` 方法原文：*"While this action terminates the active connection, **the underlying conversation state is preserved on the server**. Consequently, if the widget is re-initialized via the `init` method **within 24 hours**, the previous conversation can be restored for the user."* → 服务端会话有 24h 可恢复窗口
- 另有 `popupCloseConversation()` 触发关闭弹窗
- 来源：<https://docs.talkdesk.com/docs/chat-widget-v2>　检索日期 2026-10-10　【官方文档实证】

| 档位 | 官方定义 |
|---|---|

## D. 设计规范 / 文章

### D1. MongoDB 设计系统（LeafyGreen Chat Library）— **最直接的规范级证据**

**这是唯一检索到的、把「没有历史时的对话面板」明确写成设计规范的官方设计系统。**

- Chat History 一节原文：

  > "Once the user is logged in to MongoDB account, their chat conversations would be able to be saved in Chat History. Drawer: **If the chat history is not available because users are not logged in, we recommend using the default Chat window without the new chat and chat history icon in the top banner.**"

  → 官方建议：**没有历史时，就把「新建对话」和「历史」两个图标一起从顶栏拿掉**（而不是只拿掉历史、留一个 New chat）
- Full Screen Layout 的历史存在侧边导航里；Drawer 里存在对话面板里
- 抽屉宽度规范：默认 432px，min 320px、max 520px；小屏切成 overlay 并至少占 50% viewport
- 空状态规范：欢迎语 + 建议提示词（Suggested Prompts），**用户一输入提示词，欢迎语就淡出**
- Assistant 命名规范：产品内统一叫 `MongoDB Assistant`，不按位置改名；CTA 不要加 "for me"
- 来源：<https://www.mongodb.design/pattern/chat>　检索日期 2026-10-10　【官方文档实证】
