## 根因

`frontend-tools.ts` 有三处把 `conditions` 当可选参数兜底成空对象：

| # | 位置 | 代码 |
|---|---|---|
| 1 | `WORKSPACE_ACTIONS.set_condition.toUiEvent` | `{ type:'set_conditions', defCode, conditions: args.conditions ?? {} }` |
| 2 | `normalizeActionArgs`（页面 handler 载荷归一） | `{ defCode: args.defCode ?? '', conditions: args.conditions ?? {} }` |
| 3 | ui_event 同名动作 `toUiEvent('set_conditions')` | `{ type:'set_conditions', defCode, conditions: args.conditions ?? {} }` |

后果：模型/调用方漏传 `conditions`（例如只给 `defCode` 想"先打开条件面板"）时，

- **页面已挂载**：第 2 处把漏参补成 `{}` → 页面 handler 走"显式清空"分支 → PUT `{}`、回成功；
- **页面未挂载**：第 1/3 处补成 `{}` → 契约层同样 PUT `{}`、写工作区并回成功。

即"漏参"被静默解释成"清空全部筛选条件"（= 无条件 = 导出全部）。

## 修改

### `frontend/src/utils/frontend-tools.ts`

新增判据：

```ts
function hasExplicitConditionPayload(args: Record<string, unknown>): boolean {
  return Object.prototype.hasOwnProperty.call(args, 'conditions')
    && args.conditions !== undefined
    && args.conditions !== null
}
```

- `set_condition.toUiEvent`：`defCode` 为空**或** `!hasExplicitConditionPayload(args)` ⇒ `null`
  （落到"参数不完整"失败，零写）；
- `normalizeActionArgs('set_condition')`：`conditions: args.conditions`（**原样透传**，不再 `?? {}`）；
- ui_event 同名动作 `toUiEvent('set_conditions')`：同样要求 `defCode` 非空且 `conditions` 显式提供；
- `WORKSPACE_ACTION_REQUIRED_ARGS.set_condition` ⇒
  `缺少 defCode 或 conditions（查询条件对象；清空条件请显式传空对象）`；
- `UI_EVENT_REQUIRED_ARGS.set_conditions` ⇒
  `缺少 defCode / conditions（查询条件对象；清空条件请显式传空对象），或 defCode 是空串`。

### `frontend/src/views/ExportWizardView.vue`

页面 handler（`export.setConditions`）在 `defCode` 校验之后、任何状态/网络写入之前新增：

```ts
if (!Object.prototype.hasOwnProperty.call(payload, 'conditions')
  || payload.conditions === undefined
  || payload.conditions === null) {
  return { ok: false, reason: '缺少 conditions（查询条件对象；清空条件请显式传空对象）：本次未设置查询条件（未落库、未改动页面条件）' }
}
```

（`normalizeActionArgs` 现在恒带 `conditions` 键、值为 `undefined`，因此 `payload.conditions === undefined`
这一支才是执行器路径的命中点；直接调用 handler 且完全缺键时由 hasOwnProperty 分支兜住。）

### 文案与 RC-3 的一致性

RC-3 规则要求"参数错误文案不内嵌 JSON"（`r166b-fixes` 断言结果不含 `{` / `"`）。因此提示语用
「请显式传空对象」而不是 `{}` 字面量；该既有用例的**期望串**随之更新（仍是精确整串 + 无 JSON 字形，
未放宽断言）。

## 边界与不声称

- `conditions` 现在是 `set_condition` / `set_conditions` 的**必填**参数：模型只给 `defCode`
   会被判"参数不完整"（可行动文案要求补 `conditions` 或显式传空对象清空）。这是协议收紧，
  与后端 `WizardActionGuard` 要求"至少 scopeKeys 或 fields"同向。
- `conditions: null` 视为漏参（失败），不当作清空；只有 `{}`（空对象）才清空。
- 参数提示文案为通过 RC-3（禁内嵌 JSON），用「空对象」措辞，不出现 `{}` 字面量。
- 其它工作区动作（`select_definitions` 等）的可选/必填口径未改。
- 真机 E2E、真实模型对"必填参数"的服从率未验。
