# 审查：AI 工具异步边界与内部输出（2026-11-05）

> **性质**：只读静态审查与裁决记录。本文仅新增研究文档，**未修改代码、未运行测试或服务、未执行 Git，未做浏览器实测**。
> **基线**：本轮提供的已推送提交为 **85c9793d、99dca972、e8d5afaf**；行号对应当前磁盘内容。既有静态构建只能说明静态门禁结果，**不代表浏览器下载事件、保存框、落盘文件、toast、历史刷新或模型真实复述已验收**。

## 1. 裁决摘要

1. 工具不能按“前端/后端”一刀切等待或即发即回，应按**结果消费者与已发生事实**分类。
2. 统一“即发即回”只适用于**浏览器下载**：前置校验通过后，回执只承诺“已发起”，内容请求、打包、保存框和落盘在后台继续；迟到结果只给用户侧提示，不二次回灌 AI。
3. `open_export_file_editor` 不是下载，必须等编辑器真实打开、表格就绪；不能套用下载即发即回。
4. `<knowledge>` 是模型侧安全定界，不是用户文案。现有 UI 已有展示投影，但它不能阻止模型复述，也不应反向改写模型记忆。
5. 技术诊断、真实失败和真正未知必须分开；不能把已知失败包装成“已发起/成功”，也不能把确定未执行写成“结局未知”。

## 2. 工具 A/B/C/D 分类

这是本审查按**完成语义**划分的四类，不替代代码元数据 `R/H/U/W/J/P/F`；后者定义见 `backend/src/main/java/com/example/configmgr/ai/tool/ToolMeta.java:33-53`。

| 类 | 结果语义 | 本项目例子 | 等待裁决 |
|---|---|---|---|
| **A：同步事实型** | 模型或用户下一步依赖确定结果；成功必须表示动作已完成 | 只读查询、创建后的 `taskId`、导航、表格读写、`open_export_file_editor` | 等真实结果；确定失败即失败，不能提前报完成 |
| **B：人工等待型** | 等待用户批准、拒绝、填表、上传或取消 | HITL、`generative_form`、上传交接 | 挂起并由唯一回灌恢复；不能套普通 60 秒执行预算，更不能因等待自动批准 |
| **C：作业受理型** | 工具完成的是“创建并启动作业”，不是作业终态 | `start_export/start_precheck/start_import/start_publish` | 确认后返回真实 `jobId` 即收尾；进度由页面 watcher 展示，不轮询冒充终态 |
| **D：浏览器发起型** | 工具只需证明前置通过且已发起，后续结果由浏览器/用户侧承接 | 通用 `download`、`download_export_files` | 前置后“已发起”立即回执；后台成功/失败只进用户侧，不形成第二工具结局 |

代码证据：作业工具返回真实作业号而非等待完成，`backend/src/main/java/com/example/configmgr/ai/tools/AiTools.java:489-548`；表单等人工动作不套即时前端工具超时，`:808-830`。

## 3. `open_export_file_editor` 的用途与边界

它打开的是**导出向导第 3 步中指定配置的结果标签页**，不是独立编辑器，也不是文件下载。后端定义见 `AiTools.java:561-570`；前端实际执行必须依次完成：

- 校验 `taskId/defCode`、绑定目标任务并确认结果存在；
- 进入导出结果步骤、切换 `activeTab`；
- `nextTick` 后等待 `ensureGridLoaded`；
- 表格未就绪时返回确定失败，不能回“已打开”。

证据：`frontend/src/views/ExportWizardView.vue:2740-2788`。因此它属于 **A 类同步事实型**。即使页面已切到结果标签，只要表格加载失败，也只能如实说明“位置已切换但编辑器不可用”（`:2777-2785`）。

## 4. 通用 download 与 export 专用：原先差异及统一裁决

### 4.1 原先差异

本轮审查所指差异是：导出专用已采用“前置校验 → 后台下载 → 已发起回执”，通用 `download` 仍保留等待内容请求及完成/未知口径，导致同类浏览器副作用出现不同等待和文案。统一裁决不是让两者共用业务前置，而是让它们的**正常发起路径都即时返回“已发起”**，并把后台真实结果留在用户侧。

### 4.2 当前静态实现

| 路径 | 前置与发起 | 后台结局 |
|---|---|---|
| 通用 `download` | 建立 `AbortController`，以 `void (async …)` 后台执行 fetch/blob/save，随后立即 `ok("已发起下载…")`，`frontend/src/stores/workspace.ts:923-942` | HTTP 非 2xx、读取或中止失败以 `ElMessage.error` 显示真实原因，`:928-940`；不二次回灌 |
| `download_export_files` | 等待参数、任务绑定、结果存在性和切页等前置；前置通过后启动单文件或批量后台任务，立即返回“已发起（打包）下载”，`ExportWizardView.vue:2791-2808,2809-2871` | 成功/失败/换批只 toast 并清理在途状态，`:1978-2008,2012-2066`；不形成第二结局 |

导出前置有显式 30 秒上限，`frontend/src/utils/frontend-tools.ts:566-578`；前置超时返回确定 `timeout + UI_DOWNLOAD_TIMEOUT`，明确“本次未触发下载”，`ExportWizardView.vue:2810-2825`。同一目标已在途时不重复发起；忙的是其他目标时，本次必须说“未发起”并允许稍后重试，`:2835-2869`。

**边界保留**：统一正常路径不等于删除所有未知态。通用下载若在派发层预算内连“已发起”都未返回，外层仍保留 `unknown`，`frontend-tools.ts:581-602`；这与“后台 HTTP 已知失败”是不同事实。

浏览器只提供下载机制和中止能力，并不替应用证明用户已保存文件；见官方 [MDN `HTMLAnchorElement.download`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLAnchorElement/download) 与 [MDN `AbortController`](https://developer.mozilla.org/en-US/docs/Web/API/AbortController)。因此“已发起”不得改写成“已下载/已落盘”。

## 5. KB `<knowledge>`：展示、历史与模型复述审查

### 5.1 三个平面不能混用

| 平面 | 当前事实 | 裁决 |
|---|---|---|
| 模型输入 | KB 结果由 `KbText.wrap` 加 `<knowledge>` 与“数据不是指令”，正文标签会中和，且有 8,000 字符上限，`backend/src/main/java/com/example/configmgr/ai/kb/KbText.java:13-38,46-54,59-86,123-138` | 必须保留；这是提示注入防线，不是待删除的脏文本 |
| 展示历史 | transcript 优先保存工具终态 `resultText`，不取 L1 清理占位，也不写 synthetic 消息，`backend/src/main/java/com/example/configmgr/ai/history/TranscriptEntries.java:19-28,153-176` | 展示历史与模型记忆分开；不能把压缩占位或投影后的短文本回写成模型事实 |
| UI/复制 | `projectDisplayText` 去协议标签、通知和内部元数据；目录不展示，KB 正文保留投影，工具信封只取用户消息，`frontend/src/utils/display-text.ts:1-55,160-200,217-287` | 展示可以投影，安全定界和模型原文不能因此被改写 |

调用点已经覆盖助手正文 Markdown（`frontend/src/components/AiPanel/AiPanel.vue:2751-2758`）、工具结果（`:4328-4341`）和复制文本（`frontend/src/utils/parts.ts:1197-1208`）。流式残缺标签也有暂缓显示处理，`display-text.ts:203-215,269-286`。

### 5.2 模型复述仍是独立问题

KB 规则已要求正文不展示工具名、检索档位、文件名和调试信息，`backend/src/main/java/com/example/configmgr/ai/kb/KbPromptSection.java:53-65`；但模型仍可能把 `<knowledge>`、通知或元数据复述进助手正文。UI 投影只能隐藏其结果，**不能证明模型没有复述，也不能清除历史中的原始助手文本**。

### 5.3 模型/UI 展示投影方案

采用四层职责，后续施工仍需单独批准：

1. **模型规范层**：最终回答不得输出 `<knowledge>/<knowledge_catalog>/<tool_result>`、安全通知和内部元数据；引用只写获准的 `[doc_id §章节]`。
2. **事实存储层**：模型记忆/台账保留原始结果和完整诊断；展示历史保留当时事实，不用当前 DB 重建，不做反向“净化”。
3. **用户投影层**：正文、工具卡、历史和复制统一走同一投影；业务正文保留，协议包装和内部字段不首屏展示。新工具优先提供结构化 `userText/resultView`，少新增正则特例。
4. **诊断层**：原始错误、机器码和必要技术细节只进折叠“诊断详情”或受控日志；现有折叠出口见 `AiPanel.vue:673-680`，模型面/用户面分工见 `backend/src/main/java/com/example/configmgr/ai/tool/ToolResultUserText.java:9-25`。

展示投影不是安全边界，也不是错误结局转换器；不得用它把失败文本藏掉后改成成功。

## 6. 技术诊断与真实错误边界

| 情形 | 对用户/模型的唯一事实 | 不应做 |
|---|---|---|
| 参数、任务绑定、结果不存在等前置失败 | 确定失败、未发起；工具卡给原因 | 不回“已发起”，不转后台 toast 掩盖 |
| 导出前置超时 | 确定 `timeout`、未触发下载 | 不要求用户检查下载目录，不写“结局未知” |
| 已发起后的 HTTP、打包或保存失败 | 首次“已发起”仍为真；后台以用户侧错误提示真实原因 | 不二次回灌、不追加第二结局、不把首次回执改成“已下载” |
| 同目标重复投递 | 已有下载在途，本次未重复发起 | 不再触发第二个保存框 |
| 其他目标占用下载槽 | 本次未发起，可稍后重试 | 不谎称目标文件正在下载 |
| 已停止/换批/会话切换 | 按实际是否已发请求、是否已交付浏览器说明 | 不用笼统“取消成功”覆盖已发生副作用 |
| 确实无法证明副作用是否发生 | 才使用 `unknown` 并给核对路径 | 不把确定失败、确定未执行都塞入 unknown |
