# 设计 · B1 挂起即断 SSE（流派 B 连接语义）+ 多实例适配路线

- 日期：2026-10-20（二十九棒首务 · 用户直裁「先把前端挂起（hitl、表单等）需要中断sse、服务多实例适配做了」）
- 裁决依据：`docs/决策看板.md` 2026-10-20「架构方向裁决」；调研件 `docs/research/调研-多实例SSE扇出与HITL业界架构-2026-10-20.md` §6/§7
- 语义口径：**运行态 = 流派 A**（`new SseEmitter(-1L)` + 挂起期 2s 心跳保活）→ **目标态 = 流派 B**（挂起即断连，恢复走重连补帧）；**切换点 = 本批 B1 落地**。多实例完整适配 = B2（pub-sub 扇出）→ B3（fencing 租约），本稿含路线，施工仅 B1。
- 现状勘察依据：二十九棒勘察报告（agent-1274 后端 / agent-1275 前端，2026-10-20），关键锚点在文中以 `文件:行号` 标注。

## 1. B1 范围

**做**：人机挂起（HITL 确认卡 + 生成式表单 GF + 其余前端工具）发生时，后端在确认卡/表单卡请求帧送达后**主动完成（complete）本 run 全部 SSE 订阅**，连接不再挂住等人；前端把挂起收流视为**正常收尾**（非断流）；用户决策（批准/拒绝/提交/取消表单）后前端**带 `?lastSeq` 重连收流**；为让断连窗口内产生的帧可补回，`delta` 帧**改为入档**。

**不做（本批明确排除）**：B2 事件日志 Stream 化 / pub-sub 唤醒 / FrameStore 抽象；B3 epoch 租约；挂起期线程驻留改造（`aiRunExecutor` 池 20 挂起占线程维持现状，见裁决 6）；`Last-Event-ID` 请求头引入（见裁决 2）；任何卡面样式 / 按钮位置边距改动。

## 2. 关键裁决（十条）

1. **断连触发点 = `ConfirmGate.await` 发出本批全部 `confirm_request` / `frontend_tool_request` 帧之后、进入阻塞等待之前**，由 ConfirmGate 调 `SseChatEmitter.completeSubscriptions(runId)`（幂等、零订阅者 no-op）。**不得挂在 `suspended` 帧上**：实测帧序为 `suspended`（`SpToolCallingManager.java:263`）**早于** `confirm_request`（`ConfirmGate.java:315`），挂 suspended 会把确认卡请求帧截断在门外，用户收不到卡。
2. **续传锚 = 既有 `?lastSeq` 查询参数**（`AiController.java:308,315` + 前端 `api/sse.ts:51-54` 已是该契约），语义等价于业界 `Last-Event-ID`；不引入 SSE `id:` 字段与请求头双轨（EventSource 不支持自定义头，自研解析器现丢 `id:`，`sse.ts:130-141`）。
3. **`delta` 入档**：`RunStore.appendEvent`（`RunStore.java:568-589`）从跳过名单移除 `delta`（`heartbeat` 仍不入档）；`EVENT_WINDOW=3000` + session-ttl（24h 滑动）维持。附带收益：断流期正文尾部丢失（T3b 根因）随本批根治——断流重连后 delta 可经 lastSeq 差量补回。
4. **回放不再跳过 `delta`**：`stageReplay`（`SseChatEmitter.java:455-476`）取消 delta 跳过；回放仍按 `seq > lastSeq` 差量 + 孤儿过滤。刷新恢复主路不受影响（`restoreSuspendedSnapshot` 以 `archiveMaxSeq` 为 lastSeq，回放集为空）。
5. **ConfirmGate 等待循环主体不动**：`renewSessionCurrent` / `renewSuspensionTtl` / `beacon.pulse` 每 2s 切片照常（挂起态 24h 滑动续期不能停）；挂起期 `heartbeat` 帧在零订阅者下自然无落地（不入档、不扇出），不为断连改等待循环代码；但须核验 `emit()` 零订阅者路径无副作用（发号/截断/落档顺序不炸）。
6. **线程驻留保留**：挂起期 `aiRunExecutor` 平台线程仍驻留（池 20，`AiExecutorConfig.java:50-62`），本批只放连接不放线程；事件驱动化与 B3 租约一并再评估。已知上限：单实例并发挂起 ≤20。
7. **恢复双路径保留**：同实例决策 = 本地 latch 唤醒快路径（`ConfirmGate.submitDecision` → `WOKE_IN_PROCESS_GATE`）；跨实例/崩溃 = 既有 `maybeTriggerResume` → `ResumeService.resume` 路径；本批不加 epoch 围栏（B3）。
8. **前端挂起收流 = 正常收尾**：`stores/ai.ts` 的 `send()`/`onClose` 增「suspended 分支」——挂起导致的流关闭不置 `streamInterrupted`、不报「结果可能不完整」；`finally` 不再无条件清 `suspended`（现行 `:1513` 直写为 B1 必改点）；`loading` 在挂起收流时复位（挂起期不再占用「工作中」态），`suspended` 保持为真。
9. **决策后重连收流**：`confirm()`（批准/拒绝）与 `submitGenerativeForm()`/`cancelGenerativeForm()`（经 `submitFrontendToolResult`）POST 成功后，以 `lastSeq = runSeq[runId]` 调既有 `reattachActive`/`resumeSnapshotStream` 重连收流，重连期间 `loading` 复置；重连失败走既有 notice + 一键重挂入口（不新增 UI）。决策与重连间的帧由裁决 3/4 的入档+差量回放兜底，零丢失。
10. **停止入口回归防护**：挂起断流后 `loading=false`，`AiPanel.vue:743-753` 停止按钮判据须扩为 `loading || suspended`（仅可见性条件，样式像素级不动）；`stop()` 在挂起态无连接可 abort，仍须发 `POST /api/ai/cancel/{runId}` 并清 `suspended`/`activeForm`。

## 3. 契约变更清单

- **帧**：类型集不变；`delta` 从「不入档」变「入档」（回放可见性变化）；挂起期 `heartbeat` 不再到达客户端（连接已断），前端 `case 'heartbeat'` 空实现不受影响。
- **端点**：无新增/无签名变更；`GET /api/ai/events/{runId}?lastSeq=N` 语义不变（行为变化：挂起中重连 = 回放空集后挂起等待，决策后重连 = 差量补帧+直播）。
- **客户端行为**：挂起收流正常化（裁决 8）；决策后自动重连（裁决 9）；停止按钮可见性（裁决 10）。
- **响应字段**：`resumeTrigger` 取值口径（`WOKE_IN_PROCESS_GATE`/`SCHEDULED` 等）本批不变。

## 4. 迁移与回滚

- 单部署批次：前后端同批发布，不混部（旧前端连新后端会把挂起收流误判断流；新前端连旧后端则决策后重连空挂——均可接受，因为同批同版本发布）。
- 回滚 = revert 本批 commit；无数据迁移（Redis 键族不变，`ai:events:` 内容形态不变、仅 delta 开始入档）。
- 120s 前端工具超时（`frontendToolTimeoutSeconds`）在挂起断流后仍在服务端计时：超时结局帧入档，客户端在用户提交时经 409/`syncGateFromAuthority` 既有路径收敛。本批不改该超时语义。

## 5. 验收口径

1. 后端单测全绿（现役 563/563 · 90 类为基数）+ 新增/改口径用例：挂起即 complete、delta 入档、delta 差量回放、零订阅者 emit 无副作用、`ReattachLastSeqConformanceTest` 口径同步。
2. 前端单测全绿（现役 490/490 · 24 文件为基数）+ 新增：挂起收流不判断流、决策后重连带 lastSeq、停止按钮挂起可见。
3. `yarn typecheck` 0、`yarn build` 通过、check-docs 6/6、脱敏终扫 0 命中。
4. E2E（`scripts/verify-e2e.ps1`，桩上游）29 用例绿；必要时同步脚本对「挂起后连接关闭」的读取口径。
5. 实机核验（桩模式）：发起会触发确认卡的轮次 → 挂起后 netstat/curl 证实 SSE 连接已断、确认卡正常渲染 → 点批准 → 前端自动重连且续跑正文完整（无重复、无缺口）→ 刷新页面恢复挂起态 → 再决策仍闭环。
6. CI 五 job 绿。

## 6. 风险与边界

- **EVENT_WINDOW=3000 与 delta 入档**：超长 run（决策后增量 >3000 帧）可能把早段 delta 裁出窗口，极端长生成下重连补帧出现尾部缺口。概率低（单帧截断 + 典型轮次帧量远低于窗口），留痕不堵；B2 换 Redis Stream `MAXLEN ~` 时一并重估。
- **线程驻留**：连接已放、线程未放；>20 并发挂起会触发既有 `EXECUTOR_SATURATED` 口径。本批接受。
- **多实例仍裸**：B1 落地后「B2 完成前生产只能单实例」口径不变；跨实例双驱动风险仍由 `ai:resume:lock` + `claimExecution` 兜底，B3 围栏根治。
- **多窗口**：实时同步降级为操作/刷新时同步（裁决既定口径）；两页签同连同一 run 的幂等仍靠帧 seq（现状维持）。
- **Redis 信任边界 / at-most-once 语义**：B2/B3 议题，本稿仅登记。

## 7. B2 / B3 路线（本批不施工）

- **B2 pub-sub 扇出**：`ai:events:` 从 LIST+LTRIM 换 Redis Stream（`XADD MAXLEN ~` + `XRANGE`），抽象 `FrameStore` 接口（单实例内存环 / 多实例 Stream）；`SseChatEmitter.emit` 降级为「落 Stream + `PUBLISH ai:wake:<runId>` 唤醒（不传帧体）」；新增 `RedisMessageListenerContainer` 订阅侧按连接唤醒后 `XRANGE > lastSentSeq` 补发；`seq` 取号改 Redis `INCR` 收敛单写者；`RunRegistry` 收窄为本实例连接注册表。口径锁定：**B2 完成前生产只能单实例**。
- **B3 fencing 租约**：续跑权 = `SET ai:lease:<runId> <epoch> NX PX ttl` + 续租 + 写回带 epoch 校验（Lua/WATCH）；`RunSnapshot` 增 `runEpoch`；`maybeTriggerResume` 从「查本地 latch」升级为「先抢租约」；承接挂账「多实例确认误路由 / 跨实例租约未覆盖」（`docs/任务看板.md:368`）；`gateWaitMs` 挂起等待累计随 epoch 落 Redis 或重起算并留痕。
