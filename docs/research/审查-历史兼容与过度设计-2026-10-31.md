## 一、租户 / 存储面（S-01…S-17）

### S-01 前置边界：身份自报、无登录鉴权，隔离 = 命名空间隔离（不是安全边界）

- **原文**：身份来自客户端请求头 `X-Tenant-Id`/`X-User-Id`，只与硬编码目录 `TenantUserDirectory` 校验（`ai/tenant/TenantUserDirectory.java:36`），**没有登录、没有鉴权**（设计文档原文如此）。
- **结论**：本次核查成立的「隔离」是**命名空间隔离**；任何调用方都能自报目录内任一身份去读该身份的对话数据。若会话号又可被猜出（见 S-02），则「切身份头 + 猜号」即可读到他人会话。**这一点是全链路最大的残余风险，属设计取舍，需在验收口径里显式写清。**
- **报告不把它列为缺陷**，只要求写进验收口径。

### S-02 会话发号退化为裸毫秒时间戳（与设计说明不符）

- **证据**：`common/id/TimestampIdGenerator.java:18-19` 直接 `return System.currentTimeMillis();`；`git 7fe21114`「统一通过接口按时间戳发号」**删除**了 `SessionIdGenerator`（含 `app.instance-slot` 实例位 + 原子序列 + 时钟回拨处理）以及 CI 里的实例位校验，`application.yml` 的 `app.instance-slot` 一并移除。
- **设计说明原文要求**：「使用时间戳 + 实例内原子序列 + 实例标识，避免同毫秒和多实例重复」（`docs/superpowers/specs/2026-10-30-ai-tenant-user-design.md:17`）。
- **影响（报告列三条）**：
  1. **可用性**：同一身份同毫秒（多实例同毫秒、Windows 上时钟粒度可能 >1ms）必然撞号；重取窗口仅 3 次 × ≤4ms ≈ 12ms，并发开多页签会出现成批 `503 SESSION_ID_UNAVAILABLE`。
  2. **可猜**：会话号 = 13 位墙钟时间戳，配合「身份头自报无鉴权」构成实际的跨租户读取路径。
  3. **无跨实例唯一性**：不同租户同号是设计允许的，但运维/日志/反馈表里「同号不同身份」无法区分，排障与取证成本上升。
- **隔离本身未破**：所有数据键都含身份段，同号不同身份互不可见（`RunStoreTenantIsolationTest`、`AiSessionPurgeServiceTest#purgeInOneIdentityDoesNotTouchAnotherIdentityWithTheSameSessionId`）。
- **报告最小修复**：恢复「实例位 + 进程内原子序列」（或雪花号），集群 profile 未配置实例位即启动失败；把 `TimestampIdGeneratorTest`（现断言「等于 `currentTimeMillis()`」，等于把偏差钉死）改为断言「同毫秒内单调递增且含实例位」。
- **复核（静态）**：当前 `TimestampIdGenerator` 类注已自述「这是当前阶段的通用实现……需要更强唯一性时替换 `IdGenerator` 实现」，即**临时方案已被写进代码注释**。本件不据此改判断，只记录事实。

### S-03 `/chat` 不校验会话归属，「会话号必须后端发号」未在服务端强制

- **证据**：`ai/run/ResilientChatService.java:619` `sessionService.ensure(sessionId)`——不存在就 `SET NX` 登记到**调用者身份**下；`/chat` 从未校验 `AiSessionService.exists()`，也没有格式/长度校验（`ai/web/AiChatRequest.java:37` 仅 `String`）。
- **影响**：客户端可自造任意 sessionId（含超长/含冒号），在**自己身份**下凭空开出会话记录、记忆键、run 键、附件索引。跨身份读写不发生（键含身份段），但：(a) 契约失效，`POST /api/ai/session` 的唯一性/撞号保护可被绕过；(b) 每次新 id 都留一组带 TTL 的键，配合 IP 限流（60/分）只能限额不杜绝；(c) 反馈端点同样接受客户端 `sessionId`（`ai/web/AiController.java:2728`），不做归属校验。
- **报告最小修复**：`/chat` 进入前要求 `sessionService.exists(sessionId)` 为真（否则 410/400 引导取号），并加 `^[1-9]\d{0,18}$` 与长度上限；反馈端点可选校验该 session 属于当前身份。

### S-04 首次销毁的「全局回退枚举」是 O(全部租户轮次) 的 Redis 往返

- **证据**：`ai/session/AiSessionPurgeService.java:564-575`——会话索引没有 `__session_runs_complete__` 哨兵时，遍历 `ai:runs` 全体成员，对每个成员调 `snapshotOwner(runId)`（`:600` 附近），而 `snapshotOwner` 用**当前身份**拼键（`ai/run/RunStore.java:1875`）。
- **结论**：**不越权**（别人的成员在当前身份键下恒为 `MISSING`，不读对方数据），但成本是「全索引大小 × 每次一次 GET」，是本仓唯一的会话面全量遍历。
- **报告最小修复**：上线前用 `scripts/redis-run-migration.mjs` 或一次性任务回填哨兵；或给回退分支加 `MAX_CANDIDATES` 上限 + WARN。

### S-05 进程内日志节流集合按裸 runId

- **证据**：`ai/run/RunStore.java:300` 附近三个 `Set<String>`（`add(runId)`）。跨身份同名 runId 会让一方的 WARN 被一方「已告警」抑制。
- **影响**：仅日志，无数据。报告修复建议：改用 `LocalRunKey.of(runId)`。

### S-06 `ai_feedback` 是唯一「对话内容进业务库」的例外，且内容由客户端提供

### S-13 页签行为（原文 §六，4 点）

1. **业务页面切换 ≠ 新会话**：`stores/workspace.ts:172 enterPage` 只改 `page/pageId/taskType/step/taskId`，不动 `ai.sessionId`；下一次请求把 `workspace.page` 作为 `context.page` 发出（`components/AiPanel/AiPanel.vue:2345`）。这是「页签级会话」，与 `docs/03-技术方案文档-v2.1.md:437`「新页签＝新会话」一致。
2. **新页签 = 新会话**：空 `sessionStorage` → 无指针 → `ensureSession()` 向后端取号（`stores/ai.ts:8304`）。
3. **复制页签 = 新会话且不串**：Web Locks 探活判为 `duplicate` → 清本页签继承现场（保留身份回写）→ `adoptFreshSession()`（清屏、清镜像、清草稿、纪元+1、旧锁释放）→ 重新取号；`writeMirrorNow` 在 `identity !== sessionIdentity` 时拒写（`stores/ai.ts:1009`、`:1181`、`:8450`、`:3156`）。测试：`ai-tenant-duplicate-tab-identity.spec.ts`、`duplicated-tab-clear.spec.ts`、`tab-ownership-lifecycle.spec.ts`。
4. **降级边界**：`navigator.locks` 不可用（非安全上下文/旧浏览器）时判 `unsupported`，按「恢复」处理——此时复制页签会**共用**同一 sessionId（同身份），并发发送得 409 并重挂到同一 run；不是跨身份问题，但「复制页签必须新会话」在该环境不成立。

### S-14 「遍历租户 / 扫描面」专项（原文 §七，通过）

- **遍历租户列表**：`TenantUserDirectory.tenants()` 仅被目录接口使用（`web/TenantDirectoryController.java:24`），`exists()` 仅被身份过滤器使用（`TenantIdentityFilter.java:144`）。**没有任何** `for (tenant …)` 驱动任务/恢复的代码。
- **`KEYS` / `FLUSHDB` / `SELECT`**：后端源码 0 处。
- **`SCAN`**：仅 4 处，全部有界且 pattern 逐字含身份：`AiSessionPurgeService.java:784`（`ai:ctx:archive:<t>:<u>:<sid>:*`）、`AiSessionPurgeService.java:817`（`chat:mem:staging:…`）、`SessionPurgePendingStore.java:336`（跨身份但身份取自 JSON、上限 200）、`scripts/redis-run-migration.mjs:381`（离线运维脚本）。
- **从全量 key / 全量会话反推租户**：只存在「从复合成员/记录里读身份」（`RunKeyScope.parseIndexMember`、`parseScopedKey`、`RedisChatMemoryRepository.memberIdentity`、`Pending.tenantId/userId`），没有「先扫 key 再解析身份段去操作」的路径。`sessionId` 允许含冒号不会造成身份段歧义（前两个冒号唯一确定 t/u）。
- **定时任务只处理已知 run/tenant**：启动/运行期扫描走 `ai:runs` 复合成员；销毁重试走队列表 + 有界 SCAN；续租/看门狗/保活/交棒全部 `RunIdentityScope.open`。

### S-15 哪些存储是「合理的 Redis 候选」而非业务库（原文 §八，通过）

**合理且应当留在 Redis**（全部运行时/短生命周期/跨实例协调面，均带 TTL 或随会话销毁）：会话记录、`session:current/runs/active`、记忆窗口与 staging、run 快照、待决、幂等台账、事件 Stream/兼容 LIST、seq/xtrim/xack、续跑租约+fence+取号、req/decided、ctx/ledger/archive/safety、附件登记与两个索引、销毁 pending/guard/queue、限流窗口、唤醒频道、取消标志、结算观测位、心跳/活动锚点、任务/作业资源锁、全局索引 `ai:runs` / `chat:mem:__ids__`。

### S-16 租户存储测试缺口（原文 §九，6 条）
