## 根因

`registerPageHandler(PAGE_HANDLER_OPEN_EXPORT_EDITOR)` 的第一个分支返回字符串：

```ts
if (!defCode) {
  return '缺少 defCode，无法打开在线编辑器'   // ← 字符串
}
```

`runPageHandler` 的 `interpretHandlerOutcome` 把字符串解读为"成功 + 该文本"⇒ 缺参调用落成
`outcome: 'ok'`、`availability: 'available'`：工具卡显示成功，模型以为编辑器已打开，实际零执行
（没读文件、没切页）。与 R6 的 `export.setConditions` 同族。

## 修改

### `frontend/src/views/ExportWizardView.vue`

```ts
if (!defCode) {
  // R7：参数错误必须结构化失败；其它刻意信息型回执（只读态「任务已结束，仅供查看…」）保持字符串不动
  return { ok: false, reason: '缺少 defCode，无法打开在线编辑器（未执行）' }
}
```

- 该分支在任何读文件 / 切页 / 落库之前 ⇒ **零执行不变**（单测断言 `downloadFile` / `goToStep` 均未被调用）。
- 只读态回执 `'任务已结束，仅供查看，…'` 等**刻意信息型**字符串一律未动（它们是"已发生事实"的陈述，
  字符串兼容解读仍适用）。

## 可达性说明（如实）

`open_export_file_editor` 在 `frontend-tools` 侧有必填参数校验（`defCode`），所以**经工具路由**时
缺参先被工具层拦成 `failed`（文案「缺少必填参数 defCode（配置定义编码）」）—— 该路径本来就是
fail-closed。本次缺陷的**字符串分支**只在"直接调用页面 handler"（页面内代码 / 未来执行器改动）
时可达；因此单测以**直调 handler** 锁缺陷，路由用例作为相邻对照锁"路由侧不会变成功"。
