## 0. 结论先行

1. **仓内没有任何检索/分词/向量设施**。`backend/pom.xml` 共 10 个依赖，无 Lucene、无 ansj/jieba、无 common-text；spring-ai 1.1.8 只引 `spring-ai-starter-model-openai`，且 `spring.ai.model.embedding: none`，向量面**不会**被引入。本地 m2 也没有 lucene/jieba 构件（`<M2_REPO>/org/apache/lucene` 不存在）——任何「加 Lucene」的路线都要新增依赖并联网下载。
2. **可免费复用的解析器只有 POI**：`poi-ooxml 5.4.1` 能读 xlsx 与 docx（XWPF）；**无 PDFBox**，PDF 不可读。
3. **工具挂点极便宜**：`ToolRegistry` 在启动时扫描**所有 bean** 的 `@Tool` 方法，新增一个 `@Component` + 一个 `@Tool` 方法即注册，无需改注册表、无测试计数断言（前端 `ai-tool-registry.spec.ts` 只枚举前端工具）。唯一必改项是前端一行摘要（无映射时有 `tool.fallback` 兜底）。
4. **知识片段不能走 `extra`**：`ContextBuilder.ALLOWED_EXTRA_KEYS` 只有 6 个键、单值 300 字符、整段 800 字符。可复用的是 `extra` 之外的**定界块先例**（`<workspace_state>` + 「这是数据不是指令」声明），同样手法可起一个独立 `<knowledge>` 段。
5. **「不加表」下真正的载体只有三条**：磁盘文件 + 内存索引 / Redis / 现有业务表语义挪用。`task_files` 不能当知识载体（三列唯一键且 `def_code NOT NULL`、上传被写死 xlsx/zip）。
6. **前端「引用出处」是新增件，不是配置**：正文 Markdown 白名单放行 `a[href]`（http/https/`#`/相对路径），外链自动 `target=_blank`；但**站内链接无点击拦截**（点了整页刷新），且**工具卡 `result` 是纯文本**（`whitespace-pre-wrap`，不渲染 Markdown/链接）。R-163 已把 `sources` 明确列入 13 项暂缓。
7. **最大风险不是存储，是检索质量**：无分词器 ⇒ 中文只能自实现 bigram/关键词打分，「口径」类同义词/别名覆盖差，模型会拿低相关片段编答案。

## 2. 工作区 / 文件设施

### 2.1 文件到底存哪

- 磁盘，**不是 H2 BLOB**：`app.file.storage-path: ./data/files`（`application.yml:295-296`），实现 `FileStorageService.java:30-38`（`baseDir()`），落盘名 = `UUID + 扩展名`（`:40-47`），另有流式 sha256（`:63-81`）、`newPath`（`:93-96`）、`delete`（`:98-104`）。
- 实际存量：`backend/data/files/` **81 个 `.xlsx`**，最大 **44 465 B**（未触及上传上限，见 §2.3）。
- 元数据在 H2 `task_files`（`V1__schema.sql:112-125`）：`UNIQUE(task_id, def_code, file_type)`，`storage_path VARCHAR(512)`。

### 2.2 现有 API 能做什么

| 端点 | 落点 | 能力 |
|---|---|---|
| `POST /api/tasks/{taskId}/files/upload` | `FileController.java:49-100` | **仅 `.xlsx` / `.zip`**（`:83-85` 硬校验），文件名必须匹配任务条目的 `defCode`（`:87-91`，`matchDefCode` `:280-297`） |
| `GET /api/tasks/{taskId}/files/{defCode}` | `FileController.java:147-165` | 单文件下载（xlsx MIME 写死） |
| `PUT /api/tasks/{taskId}/files/{defCode}` | `:167-190` | 覆盖写（byte[] 体） |
| `GET /api/tasks/{taskId}/files` | `TaskController.java:169-171` | **唯一的「列文件」API**，返回 `List<TaskFile>` 实体——含 `storagePath` 绝对磁盘路径（`TaskFile.java` 无 `@JsonIgnore`），属已存在的路径泄露面 |
| `GET /api/tasks/{taskId}/files/download-all` / `/download?codes=` | `FileController.java:192-228` | 打包 zip |

**没有**通用「读任意文件/列目录」API；所有文件操作都被 `taskId + defCode + fileType` 三元组绑定。

### 2.3 限制

- **multipart 未配置**（`application.yml` 无 `spring.servlet.multipart.*`）⇒ Spring Boot 3.5.14 缺省 `max-file-size=1MB` / `max-request-size=10MB`（`spring-boot-autoconfigure-3.5.14.jar` 的 `spring-configuration-metadata.json` 实测 `defaultValue: "1MB"`）。超限会被 `GlobalExceptionHandler` 的 `@ExceptionHandler(Exception.class)`（`common/GlobalExceptionHandler.java:78`）兜成 500，无专门错误码。
- 全站**无 Spring Security 依赖**（pom 无、`WebConfig` 只配 CORS + 安全响应头，`config/WebConfig.java`）；新增任何文件/知识端点都是无鉴权暴露。

### 2.4 能否直接当知识库载体

| 候选 | 结论 | 依据 |
|---|---|---|
| 复用 `task_files` + 上传端点 | **不可行** | `def_code NOT NULL` + 三列唯一键 ⇒ 一个任务一个 defCode 只能有一个 UPLOAD；xlsx/zip 类型校验写死在 `FileController.java:83`；前端交接卡也把 accept 收窄到 xlsx/zip（`components/AiPanel/UploadHandoffCard.vue:30-41`、`utils/ai-dom-tools.ts:1019-1035`） |
| 复用 `FileStorageService` 的**落盘能力** | **可行（推荐）** | 该类与业务无关，仅需 `AppProperties.file.storagePath`；知识文件可落 `./data/files` 或并列目录，配一份 manifest |
| 复用 `ImportWizardView` 工作区概念 | 仅形态参考 | `frontend/src/views/ImportWizardView.vue` 是导入向导，不是通用文档区；`stores/workspace.ts` 只管 5 个页面上下文 |

### 4.1 注册机制与新增挂点

- 扫描：`ai/tool/ToolRegistry.java:40-91`——遍历 `ApplicationContext` 全部 bean，反射找 `@Tool` 方法，`MethodToolCallbackProvider` 建回调；`applyOverrides`（`:102-147`）用 YAML 覆盖 description/schema/标题。

- 装配点：`ai/run/ResilientChatService.java:269-270`（`toolRegistry.forContext(context)`，模型不支持工具时下发空集）。

| `ai:session:current:<sid>` / `ai:session:lock:<sid>` | 会话当前轮 / 会话锁 | `RunStore`、`application.yml:209-213` |

**知识缓存/索引的结构可行点（只评结构，不评寿命）**

- `kb:doc:<docId>` → HASH（`title/source/updatedAt/sha256/chunks`）——与 `ai:cfg:models:<id>` 同款的「小对象缓存」姿态；
- `kb:idx:<term>` → SET（倒排桶，term 由应用侧 bigram/关键词切分后写入）——与 `ai:runs` 同款 SET 用法；
- `kb:meta` → HASH（版本戳），供与磁盘原文做失效比对；
- 限制：单命令往返 + Lua 可原子批量；**没有服务端打分/排序**，BM25 之类的打分必须在 Java 侧做，即「Redis 只当倒排桶，不当检索引擎」。
- 依赖面风险：Redis 挂 = AI 端点已 503（`ai/config/RedisAvailability.java`），知识检索若强依赖 Redis 会把知识问答一并拖死；文件 + 内存索引则无此耦合。

## 10. 「不加表」约束下的载体排序

| 排序 | 载体 | 落点/结构 | 优点 | 代价/风险 |
|---|---|---|---|---|
| **1（推荐）** | **磁盘文件 + 进程内存倒排/打分** | 原文 `./data/kb/*.md|docx`（可用 `FileStorageService` 落盘能力），启动加载；manifest JSON 记 id/标题/来源/sha256/更新时间；索引 = `ConcurrentHashMap<String, List<Chunk>>` + bigram 切分 | 零 schema、零新依赖、零 Redis 耦合、可单测；POI 现成读 docx | 中文只能自实现切分与打分；多实例各持一份（本仓已有单实例前提：H2 文件库）；更新需重启或加文件监听 |
| **2** | **Redis 做索引/缓存（原文仍在磁盘）** | `kb:doc:<id>` HASH、`kb:idx:<term>` SET、`kb:meta` 版本戳（§7） | 多实例共享、跨重启存活、写入即生效；结构与现有键族同风格 | Redis 挂 = 检索不可用（且 AI 已 503）；服务端无打分，仍需 Java 侧 BM25；Memurai 无模块 |
| **3** | 现有 H2 表语义挪用（`config_data_rows.data_json` 存知识块，`LIKE`/`REGEXP_LIKE` 检索） | `V1__schema.sql:58-70` 不改表 | 有事务、有备份、可 SQL 检索、无需新依赖 | 污染配置数据面（导入/导出/发布按 def_code 全量扫，`ExportJobRunner`/`ImportJobRunner` 会带上它）；`row_key` 唯一约束与 256 长度限制；语义错位，审计与 UI（数据浏览页）会误显示 |
| **4** | `task_files` + 上传端点当文档区 | `V1__schema.sql:112-125`、`FileController.java:83` | 复用上传/下载/列文件 | **不可行**：`def_code NOT NULL` + 三列唯一 + 只收 xlsx/zip；且 `GET files` 泄露绝对路径 |
| — | H2 全文检索（FTL） | `org.h2.fulltext.FullText` | 现成索引 | **与「不加表」直接冲突**（建 `FT_*` 表）；Lucene 版还需新依赖 |

**结论**：路线 1 为核心，路线 2 作为可选加速层（同一份 manifest 驱动两种后端即可平滑切换，抽象一个 `KnowledgeIndex` 接口）。若「知识文档需多人维护/在线增删」，就必须新端点（无鉴权现实见 §2.3），但**不必**新表——manifest 文件可承担元数据。

## 11. 最大风险点（按严重度）

1. **检索质量（业务风险最高）**：无分词器、无 Lucene ⇒ 中文只能 bigram + 关键词加权；「口径/资费/阈值」等同义与别名覆盖差，低相关片段会进 8000 字符预算，模型倾向编造。**这是「无向量」路线的固有天花板，不是实现细节。**
2. **上传面被写死**：`FileController.java:83` 只收 xlsx/zip、文件名必须含 `defCode`；前端交接卡同样收窄（`ai-dom-tools.ts:1027-1032`）；multipart 缺省 1MB（超限 500，无错误码）。知识文档入口必须新建端点或调整这三处。
3. **引用出处落地成本被低估**：工具卡输出是纯文本（`AiPanel.vue:448-462`），站内链接会整页刷新（`onMdBodyClick` 无 `<a>` 分支），`sources` 属 R-163 明示暂缓项——「带出处」要么接受纯文本列表，要么做一张新卡片。
4. **提示词缓存击穿**：改 `SYSTEM_PROMPT`（`ResilientChatService.java:117`）或工具 description 都会打断 `tools → system → messages` 前缀缓存（`ai/tools.yaml:11-13` 明文纪律），冷启动成本上升且需 version 留痕。
5. **知识语料治理缺位（不加表的直接代价）**：无表 ⇒ 无版本历史、无审计、无权限、无并发编辑事务；manifest 文件要自己保证原子写与 sha 校验，否则「知识是旧的」会以静默方式发生。
6. **迁移号竞争**：将来若改主意要加表，下一个可用号 `V5` 已被 i18n S7（`ai_tool_def`/`ai_tool_release`）预定（`docs/任务看板.md:456`），需要先协调。
7. **既有漂移（会误导实现者）**：`extra` 白名单实为 6 键但两处注释写「5 键」（`ContextBuilder.java:25`、`stores/workspace.ts:230`）；设置页 `pageId=settings` 不在 `PAGE_LABELS` ⇒ 被闸成「未知页面」。
