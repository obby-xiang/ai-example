## 1. 执行原则与并行规则

1. 先冻结 D02–D16 的公共语义，再并行改文件；不得让不同负责人各自发明语言、状态或按钮词。
2. 同一文件只能有一个语义负责人。跨文件但共享同一契约的任务必须同批对账。
3. 后端提示词、工具语义、前端卡片、其他 ToC 页面可分组并行；locale 两个文件必须同键同步。
4. `tools.yaml`、`AiTools.java`、`frontend/src/types/tools.ts` 不宜分头独立决策；先冻结工具语义矩阵，再机械同步，`version` 只升一次。
5. 只改方案确认的文案、描述和必要呈现参数；发现需要改协议、Schema、状态机或业务逻辑时，停止扩张并登记偏差，不在本批暗中实现。
6. 后续测试就近复用项目既有测试体系；不新增依赖。实际负责人、实际测试文件和命令在施工后补录。
