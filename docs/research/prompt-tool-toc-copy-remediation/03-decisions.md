## 2. 固定 emoji 短指令

以下文字为最终固定值，后续施工必须逐字采用：

```text
跟随用户语言，简洁专业，保留必要术语和原始标识；未明确要求时不新增emoji，原文既有符号不清理。
```

配套解释只用于明确边界，不替换上述短指令：

- “跟随用户语言”按 D02 的助手生成内容优先级执行。
- “原始标识”按 D03 保留，但不因此允许内部标识进入 ToC 主文案。
- “不新增emoji”不等于禁止 Markdown，也不要求英文、ASCII 或纯文本。
- “原文既有符号不清理”覆盖逐字引用、代码、日志和原始数据；不做全仓符号清洗。

## 3. 官方建议与项目决定的分离

| 内容 | 官方/规范能支持的层级 | 本项目最终决定的额外部分 |

| 工具描述 | OpenAI/Anthropic/Google/MCP 支持清晰能力、触发、边界、参数和运行时校验 | 稳定中文单语、按需描述长度、三处同步和版本只升一次是项目决定 |

| 未知枚举 | ICU 提供 `other`；WCAG/W3C 提供语言与可访问性边界 | “通用标签＋安全公开代码”及敏感值不回显是项目决定 |
| HITL | AG-UI 支持应用决定执行、未批准不得冒充已批准；NN/g/Apple 支持结果型按钮 | “批准具体动作/不执行”和不可逆结果型按钮的固定项目词汇是呈现规格变化 |

| 表单与卡片 | GitLab/Carbon/NN/g/WCAG 提供设计建议或适用准则 | 本批纳入常显标签、上传前置、状态词表及不改预览档位是项目范围决定 |

## 4. 规格变化登记

后续施工审查的 `specChanges` 至少应如实覆盖以下实际触及项；未触及的不得预写为已变化：

1. 系统提示词中的语言、术语、emoji、确认和工具选择规则。
2. 有效工具描述、注解缺省、前端镜像及 `tools.yaml` 版本。
3. ToC 用户文案、状态词、错误兜底、动态枚举和 i18n 消息。
4. AI 工具确认按钮由泛化“批准/拒绝”改为“批准具体动作/不执行”。
5. 不可逆页面确认由通用“确定/取消”改为结果型按钮。
6. AI 设置页相关字段由 placeholder 主标签改为常显标签。

这些变化均为提示词或呈现规格变化；不得被描述成 API、SSE、Redis、状态机、确认门或业务执行语义变化。

## 5. 后续 supersede：一轮闭环与简洁按钮（2026-11-08）

用户最新裁决优先于本文件 D11/D12/D13 的按钮呈现口径，但不改变确认门、风险级别和业务执行安全边界：

1. 任何能一轮完成的操作必须在同一轮对话走到真实终点，包括“创建导出任务”；HITL/表单操作是同轮续跑，不得要求用户再次发送“开始导出”等重复指令。未经相应批准不得真实执行，用户拒绝/取消后不得自动重试。
2. HITL 确认卡恢复“拒绝/批准”；HITL 询问卡和生成式表单使用“取消/提交”；真实多步骤询问卡允许“上一步/下一步”，最后一步提交；预览使用“取消/应用”；一般弹窗使用“取消/确认”；只有特别危险或不可逆操作显示确认复选框。
3. 不再采用“批准具体动作/不执行”、结果型长按钮和“保留xxx”系列近义出口。业务对象、数量和危险后果放正文，按钮只表达简单动作；取消作业与删除任务等业务差异仍须明确。
4. 内部自动恢复、参数归一、重试和跳过不向用户展示；真实失败、未知结局和用户真实拒绝/取消不得隐藏。此规则不是用隐藏卡片掩盖状态机问题，而是先从源头消除无效内部过程。

详细现状与目标对照见 `docs/research/分析-AI交互卡操作文案现状-2026-11-08.md`；验收见 `docs/verification/AI对话独立复测清单-2026-11-05.md` 第 7 节。
