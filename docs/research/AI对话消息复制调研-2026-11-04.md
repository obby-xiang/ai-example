# AI 对话消息复制：主流行为与当前实现调研

- 日期：2026-11-04
- 范围：C 端聊天产品的消息级复制、选中复制、代码块复制及剪贴板格式。
- 本次只沉淀调研，不修改复制功能。

## 一、主流产品的基本分工

### 1. 消息按钮复制

消息按钮通常复制 AI 回答正文，不包含思考过程、工具执行状态、时间戳、操作按钮等界面辅助信息。很多产品复制的是**原始 Markdown 文本**，而不是渲染后的富文本。

证据：

- OpenAI Community 的讨论明确区分了“消息复制按钮得到原始 AI 输出”和“选中内容复制为 HTML”：<https://community.openai.com/t/chatgpt-output-as-markdown/501444>。
- Claude Code 的功能需求以 claude.ai 的“复制原始 Markdown”行为为目标：<https://github.com/anthropics/claude-code/issues/63363>。

因此，复制后出现 `#`、`**`、反引号、表格竖线等 Markdown 符号，不能单独认定为实现错误；需要先明确产品要提供的是 Markdown 原文还是富文本。

### 2. 鼠标选中后复制

选中页面内容再复制更接近所见即所得。粘贴到 Word、Google Docs 等支持 HTML 的目标应用时，可以保留部分排版；粘贴到纯文本编辑器时，只保留文本及基本换行。

### 3. 代码块复制

代码块通常有独立复制按钮，只复制代码内容，不带“代码块”标题、语言标签或复制按钮。

### 4. 整段会话导出/分享

完整会话、多个消息、思考/工具记录或特定文件格式属于导出/分享能力，不应让单个“复制消息”按钮承担全部语义。

## 二、剪贴板格式：纯文本与多格式

`navigator.clipboard.writeText()` 只写入 `text/plain`，不会向 Word/Google Docs 提供富文本表示。

MDN 的 `Clipboard.write()` 支持在一个 `ClipboardItem` 中同时提供多种 MIME 表示，例如：

- `text/html`：供支持富文本的粘贴目标使用；
- `text/plain`：供纯文本目标使用。

参考：<https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/write>；`writeText` 参考：<https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText>。

是否采用多格式复制应由产品复制契约决定，不应把“Markdown 原文”和“富文本复制”混为一谈。

## 三、当前项目实现

代码位置：

- `frontend/src/utils/parts.ts:1224-1229`：`deriveCopyText` 只取消息 `parts` 中的 `text` 段，并以 `\n\n` 拼接。
- `frontend/src/components/AiPanel/AiPanel.vue:4826-4841`：优先 `navigator.clipboard.writeText`，失败时回退临时 textarea + `execCommand('copy')`。

当前剪贴板内容为：

> 原始文本/Markdown + 每个 text 段之间额外一个空行，MIME 为纯文本。

不包含：

- 思考过程；
- 工具卡、确认卡、表单；
- 时间戳和消息操作按钮。

不包含 `text/html`，所以粘贴到富文本应用时不会保留加粗、列表、表格等渲染样式。

## 四、判断与待明确事项

1. **内容范围基本合理**：仅复制用户可见的回答正文，不复制工具、思考和时间等辅助信息，符合主流消息复制口径。
2. **Markdown 原文本身不是缺陷**：它属于主流实现之一，但与“所见即所得”不是同一目标。
3. **若产品预期是富文本粘贴，当前实现不满足**：需要另行设计 `text/html + text/plain` 的多格式复制，而不是继续只改文本拼接。
4. **段间空行需要独立确认**：当前对每个 text 段强制插入空行，不一定与模型原始输出完全一致；工具卡前后的正文可能出现比预期更多的段落间隔。
5. **不应继续用“业界惯例”笼统解释段间空行**：它是本项目独立选择，需要按预期复制效果单独验收。

本次用户决定暂不调整复制功能，本文仅作为后续需要时的设计与验收依据。
