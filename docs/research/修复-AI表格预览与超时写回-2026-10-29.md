## Task 1：`sheetVer` 不得用全局 `workspace.dataVersion` 判"表被改"

### 根因

1. 两个向导的 `sheet.current` 页面能力把 `version: workspace.dataVersion` 交出去，`resolveSheetContext`
   原样落成 `SheetContext.version` —— 而 `dataVersion` 是**工作区全局**计数：记一条动作、换步骤之外的
   契约同步都会自增。
2. `replanSheet`（切档重算 / 计数档物化）以 `plan.sheetVer !== ctx.version` 作为硬闸 —— 于是
   **任何无关 touch** 都会把预览判成"预览已失效（表格在此期间被修改）"，用户明明没动过表。
3. 反向也不严：真正需要拦的"目标行主键被改"在 `sheetVer` 相同（比如手动改了主键但没触发全局版本）
   时反而拦不住。

### 修改

- `frontend/src/utils/sheet-tools.ts`
  - 新增 `sheetContentVersionOf(adapter)`：**表内**内容版本。适配器给了 `contentVersion()` 就用它；
    否则按**该适配器**的 `loadGeneration` 派生（同表重载 +1，其余不动）。**不读 `workspace.dataVersion`**。
  - `SheetAdapter` 新增可选 `contentVersion?(): number`；`SheetContext.version` 文档改为"表内内容版本"。
  - `replanSheet`：删掉 `sheetVer` 比对，硬闸改为 **① `previewIdentityMismatch`（toolCallId +
    instanceId + loadGeneration + scope）② `sameTargetFingerprint`（目标行主键指纹）**，
    与 `applySheetPlan` 同口径。
- `frontend/src/utils/frontend-tools.ts`：`resolveSheetContext` 的 `ctx.version` 改为
  `sheetContentVersionOf(adaptor)`，**忽略页面回报的 version**（旧 handler 的全局 `dataVersion` 因此进不来）。
- `frontend/src/views/ExportWizardView.vue` / `ImportWizardView.vue`：`sheet.current` 不再回报
  `version: workspace.dataVersion`（注释说明原因）。
- `frontend/src/components/SpreadGrid.vue`：适配器实现 `contentVersion()` —— 程序化载入、AI `writeCells`、
  用户手改（CellChanged/RangeChanged/RowChanged）各 +1。

## Task 2：`UiEventLifetime.abandoned` 传到页面 handler / 登记执行器，超时或停止后零写

### 根因

`abandoned` 原先只在契约层 `dispatchUiEvent` 内被读到。路由 1（登记执行器）与路由 2/4（页面能力
handler：selectDefs / setConditions / nextStep / openEditor）**收不到**这个标记：

- 预算到点：`executeFrontendTool` 已回灌"超时"，被抛弃的 handler 仍在下一次 await 之后写工作区
  （`setSelectedDefs` / `setStep` / `setQueryConditions`）、页面选中集与步骤；
- 用户点「停止」：`stop()` 只做了 `abortUiOperations()`（后续界面动词）与轮次收口，**在途**前端工具
  的续体没有任何作废途径。

### 修改

- `frontend/src/types/workspace.ts`：`UiEventLifetime` 移到这里（store 再导出保持既有 import 面）；
  `PageHandler` 增加第二参数 `lifetime?: UiEventLifetime`。
- `frontend/src/utils/frontend-tools.ts`
  - `FrontendToolExecutor` 第二参数 `lifetime?`；`runRegisteredTool(…, lifetime)` 透传给执行器，
    `defaultExecutor` 的 `open_export_file_editor` 也把 lifetime 交给页面 handler。
  - `runPageHandler(…, lifetime?)` 调 `handler(args, lifetime)`；路由 4 与路由 2（`runWorkspaceAction`
    的 handler 分支）都传。
  - 新增 `liveLifetimes` 登记表与 `abandonInFlightFrontendTools()`：作废**所有在途**执行（预算到点外的
    第二触发面）。
- `frontend/src/stores/ai.ts`：`stop()` 在 `abortUiOperations()` 之后调用 `abandonInFlightFrontendTools()`。
- 新增 `frontend/src/utils/ui-lifetime.ts`：`uiAbandoned` / `uiAbandonedReply` / `uiAbandonGuard`
  （页面侧判据与文案单一源；缺省不传 lifetime ⇒ 行为不变）。
- `ExportWizardView.vue` / `ImportWizardView.vue`：
  - `export.nextStep` / `export.selectDefs` / `export.setConditions` / `export.start` /
    `PAGE_HANDLER_OPEN_EXPORT_EDITOR` 与 `import.nextStep` / `import.selectDefs`：入口即作废 ⇒ 结构化失败，
    零页面/工作区写；

  - `setConditions` 在 `PUT` 返回后、写工作区之前判一次（已落库但未写工作区如实说明）；
  - `import.selectDefs` 在 `nextTick/selectionSettle` 之后、切编辑区与 `loadEditors()` 之前判一次。
  - **授权不变**：只读态守卫、HITL 预览/确认门、起作业前置闸一律未动。

## Task 3：AI 应用的表格写入标 `source=AI`，`start_export` 不再误判"用户未保存"

### 根因

`SpreadGrid` 的 `data-changed` 事件**不带来源**：AI 在预览卡上应用（适配器 `writeCells`）与用户手改
发的是同一个事件。页面因此：

- 把工作区动作记成默认来源（`界面`）—— 上下文里变成"用户改了导出结果表格（尚未保存）"；
- 判脏闸回执沿用 `exportBlockedByDirty`（"**你**有尚未保存的编辑"）—— 模型据此把 `start_export`
  当成用户未决事项。

### 修改

- `frontend/src/components/SpreadGrid.vue`：`data-changed` 载荷改为 `origin: 'user' | 'ai'`
  （用户改事件 = `user`；适配器 `writeCells` = `ai`）。
- `frontend/src/views/ExportWizardView.vue`：
  - `gridDirtyBy: 'user' | 'ai'`（任一用户改动即归 `user`；只被 AI 写过则 `ai`）；
  - `onGridChanged(origin)`：AI 来源 ⇒ `workspace.touch(…, 'AI')`（文案点名"AI 已把改动写入…"）；
    用户来源仍记 `界面`；AI 脏后用户再改会补一条 `界面` 动作（不把用户改动挂在 AI 名下）；

## Task 4：`applySheetPlan` 中途异常必须如实 failed，登记可撤销与实际写入数

### 根因

`applySheetPlan` 按 500 行分块 `writeCells`，任一块抛错直接冒泡：

- 卡面/回灌**没有任何回执**（`confirmWritePreview` 的 finally 只收口决策位）；
- 前面几块**已经写进表格**，却没有登记反向补丁 —— 用户既不知道改了多少，也撤不回来；
- 计划仍是 `pending`，重试会把已写部分再写一遍。

### 修改（复审返修后的最终形态）

- `frontend/src/utils/sheet-tools.ts`
  - **`SheetAdapter.writeCells` 契约改为如实回报**（复审 I-1）：
    `writeCells(updates): { applied: SheetCellUpdate[]; error?: unknown }`，**不再 throw**；
    `applied` = 真的进了表格的更新（越界/不可写的不在其中），中途失败时 = 失败前已落部分。
    `SpreadGrid` 逐 run 累积 `applied`，遇错即停并回报 `error`（不再猜"整块全成/全失"）。
  - `applySheetPlan` 用 `applied` 反查 `changes`（`row:col` 映射，`selectAppliedChanges`），
    **成功/失败两条路径都按真实落笔**算 `cells` / 撤销补丁 / 上色 / 回执：
    - 失败：`已写入 N 格 / 共 M 格 …`（N 精确到块内已落部分）；N=0 时才说"没有任何一格写入"；
    - 成功：`cells` 与回执"改动 N 格"都用实际落笔数（被适配器忽略的更新不冒充已改，
      并补一行"未落笔：K 格被适配器忽略"）。
  - `ApplySheetPlanOutcome` 失败变体保留 `appliedCells?` / `undoable?`；`plan.status` **先**落定
    （`applied` / `failed`），再做撤销登记与上色（复审 I-2）。
  - 撤销登记 `registerUndoEntry` 返回**真实登记结果**，`undoable` 与之一致；
    `registerUndoEntrySafe` / `markAppliedCellsSafe` best-effort —— 上色失败（典型：表已重建/关闭）
    不得吞掉回执或让计划停在 `pending`。成功路径同款（状态先 `applied` 再 best-effort 上色）。
  - `chunkUpdates` 改为按**行**切块（常量名 `SHEET_WRITE_CHUNK_ROWS` 即行数），
    多列更新不再把一行切到两个 chunk 里（半批失败不留"半行已改"）。
  - `applyUndoEntry` 同契约：写入中途失败 ⇒ 如实回"S 撤销中途失败：已回写 X / 共 Y 格"，
    撤销层保留（不弹栈），不谎称已撤销；`clearMarks` best-effort。
- `frontend/src/components/SpreadGrid.vue`：`writeCells` 逐 run 记录 `applied`；
  `restoring = false` 前置、`resumePaint` 单独 try（复审 Minor-7：绘制抛错不得让"程序化写入中"
  永久为真，否则之后用户手改不置脏）；`live()` 失败也按新契约回报 `{ applied: [], error }`。
- `frontend/src/types/ai.ts`：`SheetWritePlan.status` 增加 `'failed'`（半批已落笔，重放被状态闸拒绝）。

## 7. 边界与未做 / 不声称

- **未跑整文件 / 前端全量 / E2E / 主 CI**；上述"通过"只指所列单点用例。本返修同样未 push。
- **真机 E2E 未执行**：本机无 VL 域真机环境（无真实 SpreadJS / 后端 / 浏览器会话），
  "AI 应用后判脏闸文案""停止后在途工具零写""writeCells 块内部分落笔"均只在 jsdom 单测层验证；
  真实 SpreadJS 的 `setArray` 失活形态、`resumePaint` 抛错形态未经真机复现。
- `preflightDownload`（`download_export_files` 执行器内的切步路径）**未接** abandoned 守卫：
  它由执行器内部调用、且执行器本身已有前置超时（`DOWNLOAD_PREFLIGHT_TIMEOUT_MS`）；
  该路径的"停止后不切步"未纳入本批（登记为后续候选）。
- `import.startPrecheck` / `import.startImport` / `import.startPublish` 与 `run_job` 等**建作业**入口
  未加 abandoned 入口判据：本批范围是"工作区/步骤/选中集"，建作业属后端副作用，授权矩阵不变（登记）。
- 导入向导的视图级来源归因没有独立单测（实现与导出侧同形，grid 层契约已锁）。
- `sheetContentVersionOf` 的派生回退（适配器无 `contentVersion`）只按 `loadGeneration` 计数：
  纯数据面适配器下的**用户手改**不会推进表内版本（真表格走 SpreadGrid 的 `contentVersion`，
  不受影响）；预览硬闸已不依赖版本，故不影响正确性，只影响"摘要过期提示"的灵敏度。
- 判脏闸仍**拦下**仅有 AI 改动的 `start_export`（避免静默丢弃 AI 改动）；本批只修"来源与措辞"，
  不放开"AI 改动可被重导出覆盖"这一授权判断。
