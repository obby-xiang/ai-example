## 0. 结论先行

### 0.1 一句话

差距表里的 11 条**不是 11 件平行工程**，而是三层：**先把失败面与发现面收敛（今天就能用）→ 再把覆盖与感知抬起来（天花板）→ 最后才动架构（披露解冻 / 批量）**。本件据此切成 **5 批**，批 A 只碰存量文件、零新工具、零新帧、零新用户可见文案，是「一条指令就能开工」的那一批。

### 0.2 批次序列（与差距编号、P 层的对应）

| 批 | 名称 | 对应差距 | P 层 | 新工具 | 新帧 | 是否需先裁 |
|---|---|---|---|---|---|---|
| **A** | 收敛（失败面 + 发现面） | D4、D5-①③、D8 | P0 | 0 | 0 | 否（可直接开工） |
| **B** | 覆盖（注册面扩面 + 标注治理） | D1、D7 | P1 | 0 | 0 | 是（O-2） |
| **C** | 感知（只读文本快照 + 遍历健壮性） | D2-①、D10-①、D11-② | P1.5 | 0 | 0 | 否（文本快照口径见 O-5） |
| **D** | 治理（动作台账 + 确认档位） | D6、D4-④、D3、D7-③ | P2 | 0 | 0 | 是（O-1） |
| **E** | 架构（披露解冻 / 批量原语） | D5-②、D11-① | P3 | 待裁 | 0 | 是（O-4，且 O-3 已定方向） |

全序列硬约束：**16 帧冻结不破**（帧类型集仍 16，`frontend_tool_result` / `tool_result` 键集不变）、**不做截图与坐标**、**不让模型产出或猜测 selector**、**不做全域无围栏扫描**。

### 0.3 与调研 54「建议序」的一处改序（须明示）

调研 54 §9 的收口句是「扩面（P1）→ 收敛失败与发现（P0）→ 治理 → 架构」，而其 §7 表的 P0 行又写明「直接消 R2 的重试风暴与 token 浪费」。本件取 **P0 先做**，理由是三条**结构性依赖**：

1. 注册面扩面（批 B）会让 `ui_snapshot` 的行数与调用频次同时上升；**先做披露收窄与快照闸**，扩面时才不会把 token 与重试成本同比放大；
2. 同页导航直返与同参去重是**跨批次的地基**：批 B 的「导航到目标页 → 操作该页控件」正踩在这条裂缝上（R2 现场就是这条链）；
3. 失败回执从「结局未知」改成可判定态后，批 B/C 才有可信的回归判据（否则「扩面后失败变多」无法与「扩面后回执更诚实」区分）。

扩面仍是**天花板最高**的一件事，只是排在收敛之后，不是被降级。

## 3. 开放点（需用户裁决）

### O-1 · 确认三档是否引入（自动 / 批准后执行 / 拒绝）

**现状**：二值。`consequential` 零点击拒执（`frontend/src/utils/ai-dom-tools.ts:673`），`mutate-local` 免确认直接执行；`ui_*` 因通道优先（`backend/.../ai/gate/SpToolCallingManager.java:1456`）**永进不了后端确认门**。

| 选项 | 做法 | 利 | 弊 |
|---|---|---|---|
| **A（建议，先做窄）** | 保留二值为默认；新增**按元素 opt-in** 的第三档：元素显式声明可批准 ⇒ `ui_click` 悬挂并就地出确认卡，批准后执行、拒绝则 `rejected` | 能力损失最小地补上「帮我点一下这个」；确认面可控（只有声明过的元素会问）；复用既有确认卡的交互语汇，不新造帧、不新造卡类型 | 多一个「等人工具」⇒ `HUMAN_WAIT_FRONTEND_TOOLS` 扩容，`ui_click` 帧不再带超时；确认疲劳风险（42 件 §8.5 的理由仍在） |
| B（全局开关） | 加 `app.ai.ui.consequential: deny / approve`，全局切换 | 一次配置全体生效，运维简单 | 一刀切：要么到处弹确认、要么能力全失；且**元素级风险后端不可见**，全局档只能全问或全不问 |
| C（维持二值，不引入） | 现状不变 | 零成本、零新风险面；「不可逆动作在架构上被排除」这条安全性质最干净 | 用户说「帮我下载模板/点这个筛选」时 AI 只能说「请你自己点」，与业界主流（CUA「外部副作用前求确认」、AI SDK `toolApproval`）明确偏离；调研 54 的 D3 差距保持 |

**建议**：选 **A**，且第一版只开放给「可逆或可重做」的后果性动作（打开结果编辑器、下载模板、切到某步骤）。理由：三档的价值不在「多一档」，而在**把「拒绝」从唯一答案变成「可协商」**；按元素 opt-in 可把确认面压在开发者显式声明的少数元素上，避免全局开关的两难。这也符合用户「对齐业界主流」的目标，同时不放开不可逆动作。

| P2 | 任务中心 · `tasks.list` / `tasks.empty` | 行内「打开 / 取消」、空态「新建」 | 「AI 说已打开任务」的可视化落点；行操作要严守 `consequential` 边界（取消作业 = 后果性，拒执或走 O-1 的 approve 档） |
| P3（建议**不扩**） | 配置定义 · `definitions.*` | 搜索、行操作 | 已有 `get_config_def` / `list_config_defs` 等业务工具覆盖；扩面只增加标注维护成本与误标风险，收益低 |
| P3（建议**不扩**） | 数据浏览 · `data.table` | 表格视口 | 表格域已有 9 个专用工具（含 `find_rows`/`aggregate_sheet`）；用原语点格子正是调研 54 §5-D2 明确劝阻的路线 |

**选项**：A = 按上表 P1→P2 分两笔施工（建议）；B = 只做 P1 的导入向导（最小步）；C = 五页全扩（对齐「全页覆盖」的字面，但把标注维护面扩大到全站）。

**利弊**：A 覆盖率与成本最平衡，且给 P3 留了「用业务工具而非原语」的明确理由；B 最保守但导出向导（最高频）仍空；C 表面最像主流（无障碍树全页覆盖），但我们没有自动抽取，全页人工标注的维护成本是**长期的**，且误标面同比放大——**不推荐**。

**建议**：A。

### O-3 · `ui_*` 的 scope 从 `*` 收窄的兼容风险

**收窄方案（本件采用）**：`@ToolScope({"ui:on"})`，标签由 `extra.uiRegionCount` 计算；**缺失即披露**（fail-open），显式 `0` 才不披露。

| 风险 | 评估 | 处置 |
|---|---|---|
| 旧客户端 / curl / E2E 桩不带 `extra` | 工具仍披露（fail-open）⇒ 零回归 | A-12 用例锁死 |
| 与「续跑快照冻结」冲突 | 无：`forContext` 与 `matchesContext` 用同一份 `ctx`（`ToolRegistry.java:210`/`:264`），披露面与执行面结构上不分叉 | 沿用既有结构 |
| 把 `extra` 当提权面 | 不可能：标签只用于**收窄**，缺失才放行，永远不能凭伪造值获得未披露工具 | 设计约束，写进注释 |
| 模型把「工具消失」误读为能力故障 | 有风险：模型可能反复尝试或向用户道歉 | 提示词第 21 条显式说明（批 A 落地） |
| `uiRegionCount` 是客户端自报，可与真实区域不一致 | 中风险：报 0 而实际有区域 ⇒ 工具被误关 | 判据只用于**显式 0**；且 `ui_snapshot` 头行恒报真实区域数（地面真相在浏览器） |
| 既有断言「scope 一律 `*`」失效 | 必失效（`frontend/tests/ai-tool-registry.spec.ts:67`） | 改写为三分支断言（有区域/无区域/缺失），断言数不降 |
| token 收益不确定 | 7 工具 Schema ≈ 320~470 tokens/轮（42 件估算，推断 C）；收窄后仅在无区域页面省下 | 批 A 报告实测三页，不达标则复核判据 |

**选项**：A = 本件方案（区域存在性，fail-open）；B = 按页面白名单（`page:import` 等）——在 4/5 页注册后即失效，且换页首动作会被误拦（42 件 §4.4 已论证反对）；C = 不收窄（保持 `*`）。

**利弊**：A 收益真实且可回滚（一个标签 + 一处 scope）；B 与 42 件既有裁决冲突；C 保持现状但每轮为「看不见目标」的页面付 schema 成本。**建议 A**。

### O-4 · 批量原语（第 8 个工具）是否立项

| 选项 | 利 | 弊 |
|---|---|---|
| A（建议）**不立项**，只补短等待与前置条件 | 守住 7 工具与「每个动作一个回执」的可审计性；批 C 的短等待已消掉大部分「多字段要 N 轮」的痛点 | 多字段表单仍是 N 次调用 |
| B 立项（一次带动作数组，首错即停、其余 `skipped`） | 对齐 computer use / browser-use 的批量语义，省往返 | 破 42 件「不做第 8/9 个工具」裁决；配额/节流/停止/撤销的判定全部要重写；`skipped` 会让「半批执行」成为常态 |
| C 折中：给 `ui_fill` 加 `fields[]`（单工具多字段） | 不新增工具名，只扩一个参数 | 语义上已经是批量；`value` 白名单与回执粒度都要改 |

**建议**：A。理由：本仓的差距不在「动作粒度」，而在覆盖率与失败面（批 A/B）；批量原语是**架构级**改动，应等批 A/B 的真实痛感数据再裁。若用户坚持对齐主流批量语义，选 C 而非 B（工具数不变，回滚面更小）。

### O-5 · 只读文本快照的取数边界与字数闸

| 选项 | 范围 | 利 | 弊 |
|---|---|---|---|
| A（建议） | 仅区域内可见文本 + 表头 + 校验错误，600 字符 / 12 行 | 成本可控；不越「不做全域扫描」红线；正好覆盖「这页在说什么 / 为什么失败」两类问题 | 页面级提示（区域外的全局 banner）读不到 |

**建议**：A 起步；若实测「读不到全局提示」成为高频缺口，再按 B 补一条白名单（`[role=alert]` 且 `aria-live` 区域内/区域外均可），单列小批。

## 6. 我自决的非开放点（透明登记，供复核挑战）

| # | 自决 | 理由 |
|---|---|---|
| 1 | `uiRegionCount` **不进提示词**（不加进 `ALLOWED_EXTRA_KEYS`） | 它是披露信号而非模型输入；进提示词等于每轮多付 token 换零信息量 |
| 2 | 动态披露采用 **fail-open**（缺失即披露） | 缺失 ≠ 0；把旧客户端/测试面当 0 会造成「工具静默消失」这类最难查的故障 |
| 3 | 「导航已提交但页面未就绪」记为 `failed` + `UI_PAGE_NOT_READY`，而非新增 `partial` 线缆值 | 新增线缆值要动 conformance 与前后端映射；用**码**表达部分成功，帧契约零变更 |
| 4 | 机器码只在**前端→后端→台账/诊断**流动，不写进 `messages_zh/en` | 码是给机器与复盘用的；模型侧只读人话三段式，避免码泄漏进用户可见文本 |
| 5 | 快照闸只覆盖 5 个动词（click/fill/select/scroll/highlight），`ui_request_upload` 的 `ref?` 也需在快照集内 | 上传是唯一「等人」入口，ref 若可猜，等于给了「指向任意按钮」的能力 |
| 6 | 文本快照不做「回写/纠错」闭环（不做 `ui_click` 的文本定位） | 那是「让模型产出定位」的变体，触碰非目标② |
| 7 | 批 B 不做「区域内自动补全 ref」（41 件 §7.3 的 C 方案） | 自动生成的临时 ref 会削弱「标注即授权」的信任根；覆盖率用**人工标注**换，换取的是可审计 |

## 8. 一句话收口

**先让失败面可判定、让发现面按需收窄（批 A），再把覆盖与感知抬到能用（批 B/C），最后才谈台账与确认档位（批 D）与架构（批 E）**；三条非目标（不做截图、不让模型写选择器、不做全域扫描）在五批里逐条落成**结构约束而不是提示词劝告**——这是本序列与「照搬业界能力清单」的分界。
