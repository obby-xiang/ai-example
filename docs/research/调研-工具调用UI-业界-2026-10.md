## ③ 共识三条 + 分歧

**共识**
1. **一条有序流 + parts/事件数组即唯一真相**：AG-UI 明示到达序即协议序；AI SDK 用 `parts[]`；assistant-ui 同构。历史重载=重放同一数组，不另开通道。
2. **默认折叠 + 进行中显状态 + 完成后收成一行摘要**是事实标准（assistant-ui `defaultOpen=false`+spinner；Claude Code 单行汇总；OpenWebUI folded+Show more；ToolFallback 一行摘要）。
3. **截断属于运行时/harness，不属于 UI**，且必须 in-band 标记或落盘换引用（Claude Code/Gemini CLI/OpenHands/Codex 四家）；UI 层只做「Show more」。

**分歧**
- **交错 vs 归并**：AG-UI/AI SDK 严格按事件序交错（step-start 仅分隔）；assistant-ui/Claude Code 把连续工具调用**归并成组/单行**——同一数据两种呈现，无标准。
- **状态粒度**：细（AI SDK 7 态、区分 args 流式 vs 执行）vs 粗（CopilotKit 3 态 `inProgress/executing/complete`）。
- **截断单位不统一**：token（Claude Code）vs 字符（Gemini 40k/OpenHands 30k/smolagents 20k），同一 payload 差 5 倍，跨栈不可移植。
- **HITL 建模层次**：协议级终态+resume（AG-UI）｜part 状态级（AI SDK `approval-requested`）｜工具级 require-approval（Claude、Cline）。
- **ChatGPT 走第三条路**：不做「截断+展开」，而是让模型写**引用 ID**、服务端回填真值，从根上规避转述失真。
