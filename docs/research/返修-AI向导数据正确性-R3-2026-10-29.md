## R3-1：契约层 `set_conditions` 先校验后写

### 根因

`stores/workspace.ts#runUiEvent` 的 `set_conditions` 分支（页面未挂载时的兜底）把
`event.conditions`（模型给的**原始载荷**，对象或 JSON 字符串）直接 `tasksApi.setCondition` 并
`workspace.setQueryConditions`：

- `IN []` / 值算子空串 ⇒ 服务端落库成"0 行 / 空值"条件，工作区也记成已设置；
- 坏 JSON 字符串 ⇒ 以字符串落库（后端可能 400，也可能被当空条件）；
- 结构坏（`{"fields":"oops"}`、条目缺 `fieldCode`）⇒ `parseConditionJson` 静默丢条目后等于
  "无条件 = 导出全部"，且回执说成功。

### 修改

新增 `frontend/src/utils/condition-payload.ts#validateConditionPayload(payload)`：

1. 字符串载荷：空串 ⇒ 拒绝；`JSON.parse` 抛错 ⇒ 拒绝（**不可解析 ≠ 清空**）；
2. 对象载荷：`JSON.parse(JSON.stringify(...))` 深拷贝（序列化失败 ⇒ 拒绝）；
3. **结构完整性**（在解析之前，防止"静默丢条目变全量"）：必须是普通对象；
   `scopeKeys` 若存在必须是字符串数组；`fields` 若存在必须是数组，且每条必须是含
   `fieldCode` / `operator` 字符串的对象；
4. 与页面同判据：`parseConditionJson` → `draftModelFromCondition` → `buildConditionOutcome`；
   `invalid` ⇒ 拒绝（点名 `field:CODE` + 可行动指引：值必须填 / IN 至少一个值 / 空值判断用
   `EMPTY`·`NOT_EMPTY`）；
5. `cleared`（显式空条件，如 `{}`）⇒ 返回 `{condition: null, serialized: '{}'}`（清空，页面同口径）；
6. `ok` ⇒ `stringifyCondition(condition)`（同字段多条件、含逗号 IN 逐字保留）。

`stores/workspace.ts` 在**任何写之前**调用它：失败 `return fail(reason)`（零 `setCondition`、
零 `workspace.setQueryConditions`）；成功才 PUT 规范化 JSON 并按页面同形写工作区
（清空写 `null`）。**R4 修订**：清空改为**删键**（`clearQueryConditions`），页面与契约层同形；
  详见 `docs/research/返修-AI向导数据正确性-R4-2026-10-29.md`。

## R3-2：导入定义补请求的冷却

### 根因

R2 的 `ensureDefinitionsForEditors` 在 `!defsLoaded` 时**每次**编辑区载入都 `await loadDefinitions()`：
AI 连续调用 `sheet.current` / `select_definitions` / `confirm_step` 等都会各发一次
`GET /api/definitions`；若该请求挂起，每次调用还要等满 10s 上界 ⇒ 短时间内可把单次工具调用的
60s 预算吃满，并给定义服务打出一串重复请求。

### 修改（`frontend/src/views/ImportWizardView.vue`）

- 新增 `DEFINITIONS_RETRY_COOLDOWN_MS = 5_000` 与 `definitionsRetryBlockedUntil`：
  `loadDefinitions` **失败时**置 `now + 5s`；`ensureDefinitionsForEditors` 在
  `Date.now() < blockedUntil` 时**直接返回**（快速失败，不发请求）；
- 等待预算改为**按本次请求**计：`defsAttemptStartedAt` 记录请求起点，
  `awaitDefinitionsReady` 只等 `timeout - elapsed`（剩余额度为 0 立即返回）——同一挂起请求
  不会被每次调用各等满一轮；
- 重置入口（= 新的重试意图）：`bindTask`（显式换任务）与 `loadEditors(force=true)`
  （用户显式重载）调用 `resetDefinitionsRetryCooldown()`；
- 成功读到空列表（`defsLoaded=true`）仍然不重复请求；失败仍 fail-closed（不按 0 字段载入、
  零 `saveFile`）。

## 边界与不声称

- 冷却只覆盖"定义补请求"这一条链；`select_definitions` 的契约层校验仍按需拉一次
  `GET /api/definitions`（与 R1 相同，无缓存/无冷却；它由工具动作触发，不在本项范围）。
- 冷却期 5s 为常量（非配置项）；冷却期内编辑区载入返回失败，页面仍无"重试定义"可见按钮
  （服务恢复后由用户重载/换任务触发）。
- 结构校验只覆盖 `scopeKeys` / `fields` 的基本形状与条目必填键；操作符白名单、字段是否存在
  仍由后端判（400 走原有"落库失败"如实回执）。
- 显式 `{}` 视为清空（与页面 `buildConditionOutcome === 'cleared'` 同口径）；`{"fields":[]}`
  这类"结构合法但无条目"的载荷同样按清空处理 —— 已在代码注释与本文档中明示，属于与页面对齐
  的既定口径，不是"坏载荷静默变全量"（坏 JSON / 结构坏在上一步已拒绝）。
  **R4 修订**：只有显式 `{}` 才清空；`{"fields":[]}` 这类"有结构没内容"的载荷自 R4 起按坏载荷
  拒绝（见 R4 报告 §R4-1 配套收紧）。
- 真机 E2E、真实后端定义服务（慢响应/失败率分布）未验。
