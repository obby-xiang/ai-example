## 2. 最终裁决总表

| 议题 | 决定 | 边界 |
| --- | --- | --- |
| 多选批量操作 | 较长多选提供三态“全选”；部分选择时点击为全选，全部选择时点击为清空。多选组内部可显示“已选 X/Y”。 | 建议当前可解析选项超过 6 项才显示；少量选项不增加工具条。尊重 `maxItems`、加载、只读、禁用和动态选项状态，不按 `defCodes` 或业务标题特判。 |
| 多选语义与错误 | 多选使用真实组语义，组标题、提示和错误关联到组；首错能聚焦实际控件。 | 保留原生复选框、现有单滚动区和整表“取消/提交”，不引入双栏穿梭框、虚拟列表或复杂快捷键。 |
| 卡头标题 | 卡头只保留简短动作或用途、一个真实状态和展开控件。 | 任务号、作业号、配置编码、长任务名、文件名、写表范围和提交值放卡体；不用正则粗暴删除括号或业务名称。 |
| 卡头副标题 | 默认取消副标题，不再用“已选 N 项”、文件名、提交值、任务号等填充。 | 详细信息必须在卡体完整展示一次，不能靠原生 tooltip 或隐藏副标题补偿。 |
| 等待用户状态 | 所有交互卡统一显示 **待操作**。 | 不称“待提交”，因为用户还可以拒绝、取消或选择文件；不与全局“工作中/等待中”混用。英文建议使用 `Action required`。 |
| 交互卡终态 | HITL：已批准/已拒绝；表单：已提交/已取消；预览：已应用/已取消；上传：已上传/已取消。 | 真实用户停止和卡片失效可保留已取消/已失效；不能为了凑两种状态伪造用户决定。 |
| 请求在途 | 只让按钮显示忙碌并禁用，卡头保持待操作；受理后直接进入对应终态。 | 不新增“提交中/批准中”等卡头业务状态；未受理不得伪造已提交或已批准，失败保留草稿和重试出口。 |
| 后续执行 | 交互卡终态后保持静态，后续执行中、完成、失败、未执行不得改写用户决定。 | 执行事实由既有执行卡、任务中心或最终回复表达，不注入原交互卡，不共享状态机。 |
| 动态卡体 | 卡体展示确认当时的业务快照、填写内容和真实影响，恢复后仍可核对。 | 不把后续执行结果塞回交互卡；任务号等业务标识可保留，但只在适当内容位置出现一次。 |
| 长标题补偿 | 取消“超过 32 字就在卡体重复完整标题”的治理方式。 | 从源头保持卡头短，完整业务对象在卡体结构化展示，不重复整句。 |

## 3. 多选问题与结论

### 3.1 当前确实没有全选入口

- 多选只平铺逐项复选框：`frontend/src/components/AiPanel/FormRenderer.vue:134-158`。
- 状态更新只有单项追加/移除：`frontend/src/components/AiPanel/FormRenderer.vue:693-705`。
- 配置项字段为必填 `multi_select`，当前未设置 `maxItems`，选择全部配置在现有契约上合法：`backend/src/main/java/com/example/configmgr/ai/form/DefinitionSelectionForm.java:629-632`、`:670-681`。
- 配置目录为空或超过 50 项时不会下发当前平铺表；通用 Schema 也限制最多 50 个选项：`backend/src/main/java/com/example/configmgr/ai/form/DefinitionSelectionForm.java:645-653`、`frontend/src/types/form-schema.ts:99-102`。

结论：配置项场景需要全选，尤其“全部导出”和“先全选再取消少数项”。但不能给所有多选机械加入口；通用字段可能存在 `maxItems`，全选不能制造非法状态，也不能静默只选前 N 项。

### 3.2 多选还有明确的组语义和首错聚焦缺陷

- 组标题的 `for` 指向基础控件 ID，但实际多选输入 ID 都带选项后缀：`frontend/src/components/AiPanel/FormRenderer.vue:21-28`、`:147-155`。
- 多选缺少其他控件已有的 `aria-required`、`aria-invalid`、`aria-describedby` 关联。
- 首错聚焦也查找这个不存在的组 ID：`frontend/src/components/AiPanel/FormRenderer.vue:1003-1010`。

决定：使用 `fieldset/legend` 或等价真实组语义；首错聚焦到第一个可操作复选框或组容器。全选必须可 Tab 到，不能用自制全局 `Ctrl+A` 替代。

### 3.3 长列表和动态选项

- 字段区已有 `320px/45vh` 限高，提交按钮在滚动区外，保留该结构：`frontend/src/components/AiPanel/FormRenderer.vue:7`、`:217-240`。
- 已选值留在原位置，没有实时计数；长列表中难以核对漏选：`frontend/src/components/AiPanel/AiPanel.vue:4044-4063`。
- 动态数据源失败会把选项置空，没有加载失败说明或重试入口：`frontend/src/components/AiPanel/FormRenderer.vue:731-745`。

决定：在多选组内部提供轻量计数和批量操作；动态选项显示真实加载/失败状态及重试，不把空白组伪装成“没有可选项”。取消整表与清空选择必须保持不同语义。

## 4. 表头信息问题与结论

### 4.1 当前卡头同时承载过多信息

HITL 标题当前由“动作 + 任务类型 + 任务号 + 任务名”拼接：

- `frontend/src/components/AiPanel/AiPanel.vue:4015-4019`
- `frontend/src/locales/zh-CN.json:492-494`

标题、副标题和状态均在单行截断，副标题在容器不超过 360px 时直接隐藏：`frontend/src/components/AiPanel/BusinessCardHeader.vue:34-69`。原生 `title` 不是可靠的触屏或键盘补偿，隐藏副标题甚至没有可悬停元素。

结论：卡头只回答“需要用户做什么”，卡体回答“具体对象和完整内容是什么”。副标题默认退出，不再寻找另一段低价值文案填充。

### 4.2 32 字规则既重复又不能完整补偿

- 只有标题超过 32 个 Unicode 字符才在卡体重复完整标题：`frontend/src/components/AiPanel/AiPanel.vue:4025-4026`。
- 不超过 32 字但实际已被截断的标题，展开后没有补全。
- 超过 32 字又形成卡头、卡体重复；普通工具参数区还可能第三次出现任务号。

决定：删除“重复整句”的呈现思路，而不是调整字号或继续扩宽面板。任务名、任务号、配置编码等只在卡体出现一次。

### 4.3 同类重复不止 HITL

- 创建任务名称进入标题后，`gateRows` 未过滤 `title`，可能重复：`frontend/src/components/AiPanel/AiPanel.vue:4449-4458`。
- 表单提交值同时进入副标题和只读表单：`frontend/src/components/AiPanel/AiPanel.vue:4057-4063`。
- 写表范围同时进入副标题和范围行：`frontend/src/components/AiPanel/SheetPreviewCard.vue:219-220`。
- 上传文件名同时进入副标题和卡体：“上传中”还可能同时出现在卡头、文件名后和进度说明：`frontend/src/components/AiPanel/UploadHandoffCard.vue:122-147`。
- “确认步骤/确认当前步骤”等近义标题和摘要没有新增信息：`frontend/src/components/AiPanel/AiPanel.vue:2798-2812`。

决定：完整内容只保留卡体一处；没有新增信息的副标题全部省略。

## 5. 状态问题与最终模型

### 5.1 当前决策状态和执行状态被二次映射混合

- `approved` 映射为“已完成”：`frontend/src/components/AiPanel/cardPresentation.ts:84-85`。
- `rejected` 映射为“未执行”：`frontend/src/components/AiPanel/cardPresentation.ts:90-92`。
- 批准后执行中又覆盖为“执行中”：`frontend/src/components/AiPanel/AiPanel.vue:4099-4102`。
- `notApproved/notExecuted` 也统一为“未执行”：`frontend/src/components/AiPanel/cardPresentation.ts:93-95`。
- `cardStatusOf` 已返回 label，但 AiPanel 丢弃 label 后再次按 key 映射，形成结构性分叉：`frontend/src/components/AiPanel/AiPanel.vue:4072-4082`、`:4104-4114`。

此外，`start_export/start_import/start_publish` 的工具成功只表示作业已启动，不表示业务作业已完成：`backend/src/main/java/com/example/configmgr/ai/tools/AiTools.java:571`、`:609`、`:623`。当前“已完成”不仅混淆层次，还可能不是事实。

### 5.2 交互卡只保存用户意图和决定

| 卡片 | 等待用户 | 正常终态 | 卡体保留 |
| --- | --- | --- | --- |
| HITL 确认卡 | 待操作 | 已批准 / 已拒绝 | 操作对象、任务信息、条件、发布模式、危险影响和用户决定 |
| 生成式表单 | 待操作 | 已提交 / 已取消 | 表单字段、用户填写值和提交决定 |
| 写表预览 | 待操作 | 已应用 / 已取消 | 写表范围、预览内容和用户决定 |
| 上传卡 | 待操作 | 已上传 / 已取消 | 文件名、限制、上传结果和用户决定 |

真实取消、失效和未知结局按实际边界表达，不伪造批准或拒绝。后续执行结果不回写这些卡片。

### 5.3 技术请求在途不是新业务状态

点击按钮不等于后端已经受理：

1. 在途只禁用按钮并显示按钮忙碌，防止重复提交。
2. 卡头保持待操作，受理后直接落终态。
3. 未受理或校验失败时保留草稿、待操作和可行动错误，不伪造成功。
4. 受理后的执行失败由执行结果表达，不回写用户决定。

## 6. 动态内容缺失与恢复问题

### 6.1 数据未全部删除，但展示路径有缺口

- 创建任务参数行和后果说明仍存在：`frontend/src/components/AiPanel/AiPanel.vue:4437-4459`。
- `preflight.conditionSummary` 和 `preflight.publishMode` 持续传输，但 AiPanel 没有读取点。
- 创建任务的 `conditions` 被 `gateRows` 过滤，缺少等价内容展示。
- 已决只读 HITL 卡体只渲染 `gateRows/gateConsequenceText/readOnlyReasonText`，没有普通工具结果输出路径：`frontend/src/components/AiPanel/AiPanel.vue:481-512`。

裁决不是把执行结果重新塞回 HITL，而是确保**确认当时的业务快照**完整：任务名称、类型、条件、发布模式和危险影响在卡体可见；真实任务号、作业号和执行进度由执行结果或最终回复表达。

### 6.2 折叠和恢复会让用户以为内容消失

- 已决成功卡默认折叠，当前轮批准后可能立即收起：`frontend/src/components/AiPanel/cardPresentation.ts:121-136`、`frontend/src/components/AiPanel/AiPanel.vue:3591-3607`。
- `materializeRestoredDecidedCard` 收到 `arguments/preflight` 却未回填，恢复后可能只剩通用标题：`frontend/src/stores/ai.ts:8367`。
- 历史映射可能把 `APPROVED` 折成 `pending`，形成“已批准却显示待操作且无按钮”：`frontend/src/utils/parts.ts:680`、`frontend/src/utils/blocks.ts:569`。

决定：当前轮用户刚操作完保持原展开状态；历史已决卡可默认折叠。恢复必须保留业务快照和真实用户决定，不得出现无按钮的待操作假状态。

## 7. 其他有代码证据的问题

- 通用结果表最多一次渲染 200 行且没有组件内分页，在窄卡片小滚动区中核对成本高：`frontend/src/components/AiPanel/resultview/ResultViewTable.vue:63-103`。后续宜分页或分段加载，保留现有 200 行安全上限；写表预览已有每页 50 条，不要误伤。
- 多选提交摘要把多个值拼成单行，不利于核对；详细值应留在只读卡体，卡头不再重复：`frontend/src/utils/blocks.ts:540-549`。

## 8. 施工边界

1. 不改变 HITL 安全门、风险等级、批准前副作用禁令、业务状态机、API/SSE/Redis 契约。
2. 不删除真实任务号、作业号或业务标识，只调整其展示位置和去重。
3. 不把“待操作”扩展成全局对话状态；全局仍按既有“工作中/等待中”规格。
4. 不把执行失败、未知结局或用户真实拒绝/取消隐藏；只是放到正确的信息层。
5. 不用业务编码、标题、任务号或用例文本做展示特判，不通过正则剥离括号制造“短标题”。
6. 不引入复杂选择器、新组件或依赖；优先复用原生表单语义、现有 Vue/Tailwind 和既有卡片结构。
