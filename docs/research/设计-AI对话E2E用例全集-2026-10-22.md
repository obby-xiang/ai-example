## 1 问题溯源表

### 1.1 读法

「当时根因」一栏只写**可核的机制与落点**（文件:行以实证报告的快照为锚，行号会漂、以函数名为准）；「需要的 E2E 断言」一栏写**防回归判据**（必须能被脚本判红判绿，不写「体验更好」这类不可断言的话）；「承接」一栏对到 §2 的用例编号。

**为什么必须进 E2E 而不是单测**：这 40 条里有 33 条的病灶在**进程边界上**——「刷新」= 页面重载 + 历史整替 + 镜像续命；「停止」= 前端 abort 与后端收尾的时序；「重连」= 两个进程对同一 `seq` 的不同步。jsdom 里没有重载、没有真实 SSE 生命周期，这些面在单测里**结构上不可达**（这正是今天 78 个 spec 仍漏掉它们的根本原因）。

## 4 实施分期建议

### 4.1 承载层选择原则（一条判定树）

```
这条断言需要「浏览器重载 / 真实鼠标 / 真实网络断流」吗？
├─ 是 → 批③ Playwright UI 层（41 条：R-01~R-18 的 DOM 面、P-01~P-13 的卡面面、G-07/G-18、Q-01/Q-03/Q-07、C-01/C-02、K-09、T-06/T-12）
└─ 否 → 能在桩下确定性复现吗（帧序、端点、快照、幂等、降级）？
        ├─ 是 → 批① 进 verify-e2e.ps1（88 条）
        ├─ 只与「模型是否听话」有关（触发率、质量）→ 批② nightly 真模型（18 条）
        └─ 只在多实例/多页签下成立 → 批④ harness / 真机（7 条）
```

## 5 验收判据：什么样的覆盖算「补齐」

**六条硬判据**（缺一条即**不算**补齐；这份清单是给复核方打回用的）：

1. **12 域全覆盖，且每域至少 1 条 P0（QC 例外并说明理由）**：154 条里 P0 共 **32** 条，分布在 11 个域；`QC 快捷操作` 无历史缺陷（该能力为 2026-10 新增，未产生过线上/实测缺陷），故以 P1 守主路径，**不硬凑 P0**（如实登记，评审若要求可把 Q-01/Q-05 提为 P0）。任一有历史缺陷的域 P0 为 0 ⇒ 该域判未补齐。
2. **溯源表逐行有承接**：§1 的 40 行**每一行**至少 1 条用例承接，且承接用例的断言点能**原样否证**当时的现象（例：Q1 的断言点是"不得出现只剩用户气泡且无横幅"这一组合，而不是"刷新后应有提示"这种模糊话）。
3. **桩下零 SKIP**：批① 的 88 条在 `E2E_STUB_MODE=1` 下 PASS 或 FAIL，**不允许 SKIP**（SKIP 只在真模型"模型未触发"时合法，且只在批②）。
4. **不与单测重复**：表中标 `✅` 的 **114** 条，其 E2E 断言**必须包含一条单测结构上做不到的判据**（跨进程 / 跨刷新 / 真鼠标 / 真断流）；若某条 E2E 断言与既有 spec 逐字同义 ⇒ 判重复，打回删或改写。
5. **缺陷注入抽检 ≥10%**：对 154 条里抽 ≥16 条，**人为把对应缺陷改回去**（变异红），该条用例必须变红；抽检每域至少 1 条，且**刷新 9 条与停止 7 条 P0 全部必抽**（这两域是用户点名的场景，也是最容易"修好了又坏"的两处）。**不许用"跑通了就是对的"结论**。
6. **三层载体齐备**：接口级 + UI 级 + 真模型三层各有入口且能在 CI/夜间/手动三种节奏下跑；只做接口级不叫补齐（DOM 类缺陷 Q3/Q6/Q9 在接口级**不可能**被发现）。
