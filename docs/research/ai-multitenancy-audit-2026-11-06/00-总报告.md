# AI 对话多租户、用户隔离与多实例独立审查总报告

- 审查基线：`17080859f7b6905aafbbea90f6d2281913bcab9e`
- 审查日期：2026-11-06
- 审查方式：12 个全新 K3.1 Pro 子对话分领域静态审查，主控复核关键 P0/P1 源码证据并汇总
- 约束：未修改生产代码，未运行测试、批量验证脚本或动态攻击验证
- 部署口径：最多数十个租户、最多上百应用实例；同一用户请求可落到任意实例；数据库和 Redis 等基础设施共用
- 身份口径：用户隔离必须同时包含租户隔离；AI 对话数据必须按租户+用户隔离；跨租户业务 ID/编码只保证租户内唯一
- 目录口径：生产不存在“获取全部租户/循环租户列表”的能力，不得依赖；只允许根据真实请求已确认的身份按需缓存

## 1. 总结论

**当前实现不能直接按目标口径投入多租户、多实例生产。**

问题不是少量 Redis 键漏加 `tenantId`，而是四层边界同时存在缺口：

1. **可信身份边界未建立**：客户端可直接声明任意已登记租户/用户，配置管理面甚至整棵子树绕过身份过滤。
2. **多类核心数据仍是全局单份**：AI provider/model/默认参数、KB 文档与索引、任务/作业/配置定义、附件与部分业务事件均缺少租户或用户归属。
3. **多实例一致性依赖单实例假设**：锁故障放行、无租写回、取消丢失、fence 推进缺口、本地磁盘附件和裸 ID Pub/Sub/心跳均会在共享基础设施下产生错误结果。
4. **上下文与浏览器现场未完全封闭**：异步语言、业务作业身份、MDC 身份、前端身份切换代次和登出清理存在断点。

当前代码也有一批可复用基础：多数 run/frame/session 键已经身份化，恢复链经常显式重建 `RunIdentityScope`，反馈表已有 `(tenant_id,user_id,message_id)` 唯一约束，若只修复局部键名而不重构身份与归属模型，会浪费这些基础并扩大返工。

### 当前碰撞与目标设计缺陷必须区分

`tasks.id`、`jobs.id` 当前使用数据库 `IDENTITY`，在现有单库中数值通常全局递增。因此：

- 当前已经确定成立的是：**无属主查询、无授权写入、全局配置读取和 IDOR**。
- 裸 `taskId/jobId` 的 Redis 锁、Pub/Sub、心跳等还存在目标口径下的确定设计缺陷：一旦接受“ID 只在租户内唯一”，不同身份的同号对象必然冲突。
- 不得以“当前自增 ID 尚未重复”为理由保留裸 ID 查询、键、缓存或频道；所有接口和存储契约都必须显式包含归属。

## 3. 最高优先级问题

### 3.1 P0：请求身份可以伪造，所有“带身份的键”仍能被整体绕过

证据：

- `backend/src/main/java/com/example/configmgr/ai/tenant/TenantIdentityFilter.java:118-149` 直接信任 `X-Tenant-Id/X-User-Id`，只验证数值和静态目录成员关系。
- `backend/src/main/java/com/example/configmgr/ai/tenant/TenantUserDirectory.java:32-34` 静态列出有效组合。
- `backend/src/main/java/com/example/configmgr/ai/web/TenantDirectoryController.java:22-24` 无身份返回全部租户和用户。
- 前端 `frontend/src/utils/ai-identity.ts:78-105,130-138` 可从页签存储恢复并发送这些值。

攻击者自称受害者身份后，`RunStore.get`、会话归属复核、历史读取、HITL 确认、取消、回灌等检查都会把攻击者当成合法属主。命名空间隔离只能防止误串桶，不能替代认证。

**处置**：这是所有后续改造的前置阻断项。身份必须来自已认证主体及服务器端租户成员关系，或来自经过签名验证且无法绕过的可信网关注入。普通客户端头、请求体和浏览器存储不得直接成为身份事实。

### 3.2 P0：AI 配置管理面可未授权修改全局默认上游

证据：

- `TenantIdentityFilter.java:68-76,103-110` 将 `/api/ai/providers`、`/api/ai/models`、`/api/ai/settings` 整棵子树排除在身份边界之外。
- `backend/src/main/java/com/example/configmgr/ai/web/AiConfigController.java:104-131,136-168,173-209` 可创建/修改/删除 provider、探测、拉取模型和修改默认目标，无管理员或属主校验。
- `backend/src/main/java/com/example/configmgr/ai/config/db/AiProvider.java:51-57`、`AiSetting.java:52-57` 及数据库约束均为全局单份。

攻击者可把自己控制的上游设为默认，使其他用户后续提示词、上下文和工具信息发往攻击者端点；还可停用配置、消耗他人额度或发起出站探测。

**处置**：先封闭配置写、探测和模型拉取权限，再重构配置归属。只把路径重新纳入现有两个请求头的过滤并不足够，必须有管理员/配置所有者授权。

### 3.3 P0：AI provider/model/默认参数/运行时缓存全局共享

证据：

- `AiConfigService.java:118-128,310-317` 单例快照读取全部 provider 和 setting。
- `AiConfigWriter.java:497-519` 写全局默认值。
- `AiProviderRegistry.java:82-93` 的运行时键没有 tenant/user。
- `AiModelCatalog.java:34,90-119` 的 `ai:cfg:models:<providerId>` 不含身份、配置版本、端点或密钥代次。
- `AiConfigSeeder.java:89-117` 与 `AiConfigService.java:890-900,1028-1035` 的 ENV 密钥读取是实例本地状态，可能因实例配置漂移而使用不同上游账户。

**处置**：租户共享 provider 与用户级默认/授权必须分模，不能继续以一份全局配置同时承担两种语义。详见第 7 节。

### 3.4 P0：KB 是完整的全局知识域，不是单个缓存键遗漏

证据：

- `backend/src/main/java/com/example/configmgr/ai/kb/KbService.java:117-156` 只有一份 Snapshot、ETag 和刷新状态。
- `KbService.java:77-96,488-499` Lucene 文档无 tenant/user 字段；`569-588,643-651` 查询无身份过滤。
- `KbService.java:741-755,861-882` 按裸 docId/术语读取。
- Redis 文档/chunk/manifest/锁、HTTP 源、本地语料和样例播种均无身份维度。

影响包括跨租户检索与近似标题泄露、同名 docId 覆盖、刷新差集误删、跨实例索引分叉及共享索引目录互删。

**处置**：租户公共知识与用户私有知识分层；检索必须在索引查询层过滤，不能检索后仅凭前端遮盖。

### 3.5 P0：任务、作业、定义、文件与 AI 工具存在完整 IDOR 和越权写

证据：

- `backend/src/main/java/com/example/configmgr/task/entity/Task.java:14-23` 与 `job/entity/Job.java:12-20` 无 tenant/user。
- `TaskRepository.findAllOrdered`、`findByIdForUpdate`、`JobRepository` 的读取/取消/终态写均只按裸 ID。
- `backend/src/main/java/com/example/configmgr/ai/tools/AiTools.java:289-349` 可列全部任务、读任意 task/job。
- `AiTools.java:537-590` 的启动导出/预检/导入/发布没有属主检查。
- `ToolTargetResolver.java:114-161` 只核对工作区和类型，不核对租户/用户。
- `/api/tasks`、`/api/jobs` 不在 `/api/ai/**` 身份过滤器范围内。

知道或猜到 ID 即可读取、删除、取消、修改条件，甚至对他人的导入任务执行发布。HITL 只能证明“当前身份批准了该 ID”，不能证明“当前身份拥有该 ID”。

### 3.6 P0：`create_task` 幂等可跨身份复用或改写任务

证据：

- `backend/src/main/java/com/example/configmgr/task/service/TaskService.java:199-203,340-349,360-376` 只按 `aiCreateRun/aiCreateKey` 查重并直接返回已有任务。
- `Task.java:14-17` 与两份数据库 schema 的 `UNIQUE(ai_create_run)`、`UNIQUE(ai_create_key)` 均不含身份。
- 本地 `synchronized` 锁同样按裸 run/key。

相同 runId 在不同身份下合法存在时，后一身份可能得到前一身份任务，或被全局唯一约束阻断；continuation 也没有属主校验。

### 3.7 P0：配置定义全局共享，`defCode` 全局唯一

定义读取、选择、条件预检、表单选项和实际 Runner 均可能使用其他租户的同码定义。修改建议不能只删除全局唯一约束，必须同时重写所有查询、AI 槽位、导入导出映射、缓存与业务数据行的归属。

## 4. 多实例与分布式一致性问题

### 4.1 故障时放行会把单实例降级放大成集群并发

- `SessionGate.java:328-344`：Redis 锁结果不可知仍返回成功，只剩进程内门；同一会话可在不同实例双驱。
- `ResilientChatService.java:908,947-955`：首轮取租失败仍可继续；`DriveOwnership.none()` 被视为 owned。
- `LeaseService.java:845-860` 与 `RunStore.java:1506,1549,1882,1903`：本进程无租记录得到 `NEVER_HELD` 后可普通写，已有 fence 也只告警。
- `CancellationRegistry.java:194-200` 与 `AiController.java:1593-1603`：取消写共享 Redis 失败仍返回 `cancelled=true`，取消只存在接收请求的实例本地。
- `ResilientChatService.java:2563-2575` 与 `RunStore.java:1917-1921`：取消状态 UNKNOWN 仍允许 DONE，终态 CAS 不原子检查取消键。

**修复原则**：生产多实例模式下，锁/租约/权威取消不可确认时必须 fail-closed。单实例降级若确有需求，只能是显式独立部署配置，不能作为共享 Redis 生产集群的通用兜底。

### 4.2 fence 必须在取得租约时推进，而不是等首次写入

`LeaseService` 取得新租约时没有同步推进 fence，旧主在新主首写前仍可继续写快照、帧和工具认领。需要在同一原子操作中完成“租约所有权变化 + fence 递增”，之后每个副作用都校验 epoch。`NEVER_HELD` 不得绕过已有 run 的 lease/fence。

### 4.3 裸 ID 锁、事件与作业协调会串扰

- `LeaseKeys.java:38-59`：`ai:lock:task:<taskId>`、`ai:lock:job:<taskId>:<JOBTYPE>` 无身份。
- `task:events:<taskId>` Pub/Sub 和本地订阅表无身份，可能串发作业及配置项名称。
- job 心跳、runner active、取消、判死和部分 CHM 以裸 jobId 为域，可覆盖、误取消或误判死。
- 前端 `frontendToolsInFlight` 仅按 toolCallId，本地单飞可误抑制其他身份/轮次。

这些键、频道、owner、fencing 记录和对账证据必须一起改，不得只改写入侧而漏掉读取/恢复侧。

### 4.4 本地文件与共享 Redis 不构成多实例存储

文件守卫只验证绝对路径。实例 A 可登记文件元数据，实例 B/C 看不到 A 的本地磁盘，导致下载失败、清理遗漏或永久残留。KB 共享索引目录还可能互删构建目录。

**修复**：附件/导出文件使用共享对象存储或真正的共享文件系统；键包含 tenant/user/job/file 和内容摘要。每个实例的 Lucene 构建目录必须实例本地且唯一，快照发布走版本化原子切换，不共享可写构建目录。

### 4.5 后台任务缺少归属与可靠终态

- 业务 job 执行上下文没有完整 tenant/user/run/session/locale 固化。
- 看门狗终态写失败后存在不重试窗口。
- 百实例全量 DB 扫描和判死缺少统一 fencing/租约。
- 清理发现成员与台账身份需要交叉校验，不能因成员字符串可解析就直接操作。

后台必须从每条持久化工作项恢复身份，不能从调度线程 ThreadLocal 获取，也不能通过全租户目录寻找工作。

## 5. 上下文传播审查

| 上下文 | 已证有效机制 | 确定缺口 | 修改方向 |
|---|---|---|---|
| tenant/user | 多数 run 恢复、Reactor onNext、看门狗和 SSE 会按快照/执行信封重建 `RunIdentityScope` | 请求身份可伪造；业务 job 无完整身份模型；部分锁/缓存不消费身份 | 可信 principal + 不可变 `AiExecutionContext(tenant,user,run,session,locale,trace)`，显式穿过所有入口 |
| locale | 首轮 HTTP 到工作线程有显式传递 | 工具超时池漏 locale；RunSnapshot 未冻结；延迟重试和离线 emitter 可回落中文 | 快照增加 replyLocale；工具池保存/恢复外层 LocaleContext；所有合成错误走统一本地化 |
| run/session | `LocalRunKey` 覆盖多个本地注册表，恢复按快照重建 | 若干前端内存台账、草稿和恢复缓存只按裸 ID | 所有键、响应守卫和回调捕获完整身份代次 |
| trace/MDC | `AiMdcTaskDecorator`、`AiTrace.wrap*` 覆盖部分路径 | MDC 缺 tenant/user；裸异步入口漏传播；`eventOn` 可行首与事件体错绑 | 扩展 MDC 身份字段，统一装饰所有入口，显式 run 不同时重绑并 finally 恢复 |
| 浏览器身份代次 | 多个存储键已有身份指纹 | SSE/发号未固定操作身份；身份切换不作废 watcher/handler；无登出清理 | 每次操作捕获 identityEpoch，响应必须同时匹配 tenant/user/session/run/epoch |

补充：后端 `long` 经 JavaScript `number` 传递存在超过 `2^53` 的精度风险，身份 ID 应使用十进制字符串或限制在安全整数范围并显式校验。

## 6. 全租户目录与扫描专项

### 6.1 明确违反生产口径

1. `GET /api/ai/tenants` 公开返回全部租户和用户。
2. `TenantUserDirectory` 是静态全量注册表，身份验证通过循环该目录完成。
3. 前端启动、身份校验和默认选择依赖完整目录；目录不存在时会禁用对话，若自动选第一项还会让不同真实用户共用身份。

**必须删除这条依赖链**，改为只返回当前认证主体身份的 `/identity` 或由现有登录响应提供身份。不得用另一个“全部用户”接口替代。

### 6.2 不是租户目录接口，但同样必须重划的全局读取

- AI 配置全表 provider/setting 加载。
- 任务全表 `findAllOrdered` 与结果视图第二次全表读取。
- 作业/看门狗全量扫描。
- KB 全局 manifest、索引和本地目录。

这些属于全局数据扫描或全局单例，不会因“没有调用租户目录”而安全。改成真实请求/工作项身份驱动的窄查询。

### 6.3 全局恢复 ZSET 的边界

`ai:recovery:due` 的成员包含 `tenantId/userId/runId`，来源是原始 run 记录，不是租户目录。它不等同于获取租户列表，但属于跨身份工作项发现面。

可保留的前提是：

- 只把它当身份化工作队列，不返回租户目录或用户清单；
- 每条工作项重新做归属和授权校验；
- 报告严格按当前身份切片；
- 不使用 `TenantUserDirectory` 补全身份；
- 有界分页、租约和 fencing 适配百实例。

如果部署安全规范连跨身份工作队列也禁止，则只保留真实请求驱动的身份化恢复，不得改成循环租户列表。

## 7. 推荐的目标归属模型

不能机械地给所有数据同时加 tenant+user。应按业务共享语义分层，同时保证用户私有数据一定包含两者。

| 资源 | 推荐归属 | 说明 |
|---|---|---|
| 会话、run、frame、记忆、草稿、工具待决、取消、回灌 | `tenantId + userId + session/run/...` | 用户私有，禁止只按 tenant 或裸 ID |
| 任务、作业、附件、导出文件、反馈 | `tenantId + ownerUserId`；共享访问另做授权 | 查询、条件写、删除、下载和事件都必须校验 |
| 配置定义 | 默认 `tenantId + defCode`；私有定义再带 ownerUserId | 跨租户允许同码；用户权限不等同于复制定义 |
| AI provider 与密钥 | 租户共享时仅 `tenantId` + 管理权限；用户自有 provider 才加 userId | 租户共享密钥与用户偏好分开，不复制给每个用户 |
| 默认模型、显示偏好、用户授权 | `tenantId + userId` | 不得覆盖其他用户的默认值 |
| KB 公共文档 | `tenantId + docId` + 用户 ACL | 检索时同时过滤 tenant 与用户可见范围 |
| KB 用户私有文档/上传/历史 | `tenantId + userId + docId` | 不得进入租户公共索引后被他人检索 |
| Redis 可用性、实例本地线程池指标 | 全局/实例级 | 无用户数据，不必强行加身份；诊断输出仍需权限与脱敏 |

### 数据库约束示例

```text
tasks:       UNIQUE(tenant_id, owner_user_id, ai_create_run)
             UNIQUE(tenant_id, owner_user_id, ai_create_key)
definitions: UNIQUE(tenant_id, code)
ai_setting:  PRIMARY KEY(tenant_id, user_id, setting_key)
feedback:    UNIQUE(tenant_id, user_id, message_id) -- 当前已有，可保留
```

若 provider 采用租户共享模型：

```text
ai_provider: UNIQUE(tenant_id, code)
ai_model:    UNIQUE(tenant_id, provider_id, model_id)
```

所有读取、条件更新、悲观锁、删除和冲突回查都必须带相同归属谓词。子表通过复合外键或“先验证父级归属”的方式防止跨归属引用。

### 密钥迁移

当前密文 AAD 为 `provider.code + '|' + keyRef`，不能直接支持跨租户同 code。应先确定行归属，再使用包含 tenant（及用户自有时的 user）、providerId/code/keyRef 的 v2 AAD 重加密；未明确归属的旧行禁用等待管理员认领，不得默认归给第一租户或复制给全部用户。交换不同归属的密文必须解密失败。

### 键与缓存迁移

- 新版本使用身份化命名空间，例如 `ai:v2:...:<tenant>:<user>:...`。
- 旧键不读、不 SCAN、不按租户循环删除；短期锁让 TTL 自然结束，持久数据按明确映射离线迁移。
- 缓存只按真实请求/工作项身份按需建立，有容量上限和 TTL。
- 配置版本、密钥指纹、端点和模型目录代次要一起进入失效链。
- 不保留无身份 fallback，不通过双读猜测旧数据归属。

## 8. 分阶段修改建议

### 阶段 0：先阻断直接越权面

1. 建立可信认证与租户成员授权；禁用伪造头和默认第一身份。
2. 删除 `/api/ai/tenants` 及前端全目录依赖，改为当前身份引导。
3. 封闭 provider/model/settings 写、探测和拉取权限。
4. 将任务、作业、文件、定义等 REST 与 AI 工具统一纳入对象级授权。
5. 健康与诊断接口只保留最小公开信息，详细配置/Redis 错误移到受控运维面。

这一阶段不能只做前端隐藏，必须由后端拒绝。

### 阶段 1：建立归属与唯一性模型

1. 给任务/作业/定义/配置/KB/附件增加归属，回填只使用可证明映射。
2. 重写所有 Repository、AI 工具、预检、HITL 目标校验、Runner 和结果视图。
3. 重划复合唯一约束、密文 AAD、缓存和文件键。
4. 拆分租户共享 provider 与用户默认/授权，拆分租户公共 KB 与用户私有知识。
5. 对无归属旧数据执行隔离或下线，不设默认租户。

### 阶段 2：修复多实例一致性

1. 锁、租约、取消和终态不可确认时 fail-closed。
2. 抢租与 fence 递增原子化，所有副作用校验 epoch。
3. 取消命令可靠持久化，DONE/FAILED 与取消键在同一原子判定中处理。
4. 重划任务锁、作业心跳、Pub/Sub、取消、对账与本地 CHM。
5. 文件改共享存储，KB 索引改实例本地构建与版本化发布。
6. 后台按工作项恢复身份并补齐终态重试、租约和扫描预算。

### 阶段 3：封闭异步与浏览器现场

1. 引入统一不可变执行上下文，固化 tenant/user/run/session/locale/trace。
2. 修复工具超时池 locale、续跑语言、MDC 和 `eventOn`。
3. 前端操作捕获 identityEpoch，切换时先停连接、作废 handler/watcher，再清缓存并重新加载。
4. 登出停止全部请求/SSE/轮询并清理内存与本人存储；无身份旧键不得恢复。
5. 身份 ID 改字符串或限制安全整数范围。

### 阶段 4：处理加固项

- 动态选项回灌增加服务端成员校验。
- 工具超时后取消真实执行，避免“已结算但仍在跑”。
- 探测超时取消 future、响应流式限长、连接期防 DNS 重绑定。
- 短 ENV 密钥 fail-closed，禁止完整落入 `keyLast4`。
- 含密钥 record 脱敏 `toString()` 与 JSON 防线。
- `LeaseService.ended` 等无界本机墓碑增加 TTL/容量与清理。
- 日志节流键加入身份，避免跨身份互相抑制。

## 10. 可保留并复用的安全机制

- `RunKeyScope` 和多数 run/frame/session 键已有 tenant/user，且记录读取还有归属复核。
- `LocalRunKey` 已用于多个本地注册表，避免裸 runId。
- 多数异步恢复路径按快照或执行信封显式重建身份，而非单纯依赖 ThreadLocal。
- `RedisFrameWakeBus` 频道包含完整身份，监听器使用注册时固定身份退订。
- 反馈 DB 查询和唯一约束已有 tenant/user。
- provider 内 model 归属、DB 密钥 AES-GCM、解密失败不回落 ENV、ProviderView 不直接返回明文/密文是有效基础。
- `RedisAvailability` 的 PING 和实例级线程池指标属于合理全局状态，不应为了形式统一强行加租户键。

这些“已证安全”只覆盖相应局部机制，不能抵消本报告的 P0/P1 结论。
