## 0. 结论速览（十条硬口径）

1. **「业务行数据不出浏览器」是失实的，且是本次治理的第一块基石**：`read_sheet_summary` 的采样段是 `第 N 行 | 列=值 | 列=值`，值是 `cellDisplay()` 的单元格**原文**（`readSheetSummary` → `sampleRows.map`，`frontend/src/utils/sheet-tools.ts:598-603`），经 `frontend_tool_result` 回灌后**进入模型上下文**。准确表述 = 「业务行数据**只在采样上限内**离开浏览器，整表永不出域」。
2. **写侧同样漏了**：`planAppliedText` 回灌含「样例（前 3 处，Excel 行号）」的 `旧值 → 新值` 原文（`planAppliedText`，`sheet-tools.ts:896-909`；`SHEET_PREVIEW_SAMPLE_PAIRS = 3` 于 `:28`）。即写路径也是 D2 通道，授权范围必须一并覆盖，不能只覆盖读。
3. **治理缺位的实质是「没有一份授权记录」（挂账 L-22），不是「没有技术闸」**。技术闸已齐：20 行 / 2000 字符单点硬闸（`capSheetResult`，`:103-145`）、投影列上限（`SHEET_TOOL_MAX_COLUMNS = 5`，`:25`）、版本号、行指纹、预览三档。缺的是「谁批、批到哪、什么条件收回、多久复核」。**注**：读侧/写侧的生产文案在 2026-10-22 已被在途批部分订正（§3.0 逐条核对），但**授权记录本身仍缺**，且该在途改写未覆盖选区投影越界（§8 K-11）。
4. **本稿 §1 就是 L-22 的销记件**：一张 9 字段表 + 一份可直接填的成稿，填完即可归档，不依赖任何代码改动。
5. **开关 `app.ai.sheet.*` 四键，读默认开、写默认关**。写关的语义 = 工具**不进披露面**（`ToolRegistry#forContext` 与 `#matchesContext` 用**同一个谓词**，不新增第四道判定），不是「调用了再拒」。
6. **开关的生效口径 = 进程内一次绑定、改值需重启**（与 `app.ai.config.seed-force` 同口径），且按 7 键显化纪律**只在 yml 写注释、不写值**（值唯一事实源在 `AiProperties`，避免第二份）。
7. **关键落地约束：有效采样上限必须能到前端**。若键只作后端后验判定，「降采样」只能在数据已经进模型之后拒，等于没降。故 `/health` 增 additive `sheet` 块（先例 = 既有 `frontendToolTimeoutSeconds`），前端按 `min(键值, 硬编码常量)` 收紧。
8. **审计面不新增事件名、不新增键族、不新增持久层**：采样事实挂 `tool_call_end` 的 additive 字段；台账复用 `ai:safety:<sessionId>` 的 `kind=sheet_sample` 条目；计数挂 `/health.sheet`（进程内）。对照立法性裁决（决策看板图例「立法性纪律」类）：**任何字段不得含单元格值、不得含条件取值**。
9. **撤销深度 1 → 3**（`SHEET_UNDO_DEPTH`），补丁按 `planId` 绑定，撤销**整批全或无**（任一格被人工改过即整批拒撤，不做逐格跳过 —— 逐格跳过会产出「半撤销」，与「半批执行毒化历史」同族）；「AI 改动 vs 人工改动」区分视图落卡面 + 高亮开关，**不新增工具**。
10. **count 预览现状是「先物化全量变更再判硬上限」**（三个写工具的 `changes.length > SHEET_WRITE_HARD_MAX_CELLS` 判点，`sheet-tools.ts:1044` / `:1209` / `:1425`）：300 万格命中会先建 300 万对象再拒绝。改**单趟计数 + `HARD_MAX + 1` 提前中止**，复用聚合器算分布；同时卡面 `count` 档文案已承诺「只回计数与分布」却**零分布渲染**（`SheetPreviewCard.vue:41`）—— 文案在说谎，本批补齐。

## 1. D2 授权记录模板（read_sheet_summary 作为首个「业务行进模型」通道）

### 1.1 为什么必须有它（不是流程洁癖）

R8 的原文是：「**禁止**走上下文；只能 ① 服务端聚合 ② 服务端执行 ③ 产出文件 …… 断言点 = 工具清单 + 代码评审门（**禁新增 `get_*_rows` 类工具，除非附 D2 授权记录**）」（索引第 39 件 §4.2）。R9 另加一条前置：「任何 D2/D3 出域前，必须能回答『provider 是否零留存 / 不训练』」。这两条在表格批都已**落地为技术事实**，唯一缺的是**记录**（挂账 L-22 原文：属治理前置件而非技术缺陷）。

授权记录的作用不是免责，而是**把可调旋钮写死成可审的数字**：采样上限、投影规则、页面范围、保留期。没有记录，这些数字只能从代码里读，且任何一次「顺手调到 50 行」都不会触发任何流程。

### 1.2 字段设计（9 字段，逐字段给判定口径与可断言点）

### 1.5 撤销的执行动作（不是声明，是动作清单）

撤销必须能在 **1 小时内**执行完，否则记录就是装饰。四步，按序：

1. **关闸**：`app.ai.sheet.read-enabled=false`（§2）⇒ 8 工具全部退出披露面，模型无法再发起；重启生效。
2. **清在飞**：对处于挂起态的写预览卡 `POST /api/ai/cancel`（等的是人，取消是唯一出口）；已应用的改动只在浏览器内存，用户不保存即消失。
3. **留痕**：在 `docs/evidence/` 的授权件末尾追加「撤销记录」（时间、触发条件编号 R-N、执行人、影响面 = 已发生的 N 次采样）。
4. **回收**：确认无残留 —— `grep` 三处（日志、台账、错误文案）无业务值；确认无新增持久化文件。

> 反向要求（比撤销更重要）：**开关不是权限**。关闸只能止住"下一次"，止不住"已经发出去的"。所以 §4 的可见性必须先于 §2 的开关落地 —— 顺序倒了，撤销就成了盲撤。

| 触发 | 判据 | 动作 |

### 2.1 键清单（4 键；值唯一事实源 = `AiProperties`，yml 只写注释）

### 2.2 默认值取向与理由

- **读默认开**：R3 的物理闸已在（20 行 / 2000 字符 / 5 列 / 版本号），关掉读侧 = 把「这表有多少行」这类零风险问题也禁掉，用户会立刻要求打开，届时闸门会被当作麻烦而整体放宽。默认开 + 授权记录 + 可见性（§4）是比默认关更强的治理。
- **写默认关**：三条理由。① 写的可见后果在用户眼前的表格上（改错了用户当场看见，但"当场看见"不等于"能还原"）；② 与既有「模型配置写端点默认禁私网」「AI 可用性动态判空」同姿态 —— **改变状态的通道默认关，只读通道默认开**；③ 关掉的成本极低（打开是一次重启 + 一条 yaml 注释取消）。
- **两个上界键默认等于硬顶**：缺省即上限，避免"默认值悄悄小于硬顶"造成两套口径。

> **2026-10-22 裁决通过（主会话按业界主流代裁，用户授权）**：四键默认值定稿 = `app.ai.sheet.read-enabled = true` / `write-enabled = false` / `sample-max-rows = 20` / `projection-max-columns = 5`。依据：只读通道默认开、**改状态通道默认关**（与"模型配置写端点默认禁私网""AI 可用性动态判空"同姿态）；两个上界键缺省即硬顶，消掉"默认值悄悄小于硬顶"的第二套口径。

### 2.3 生效点单点化（防「两套口径」）

现状已有三道披露防线（`ToolRegistry` 注释原文）：① `forContext` 按 scope 标签裁剪工具子集；② 系统提示声明"只能使用当前披露的工具"；③ 执行前 `matchesContext` 复查。

开关**并入 ①③ 的同一个判定**，不新增第四道：

```text
判定 = scopeMatches(meta, tags) AND sheetSwitchAllows(name)
                              └─ 同一份 SheetSwitches 实例，①③ 都调它
```

- `SheetSwitches` 是**唯一**决定"表格工具此刻是否披露"的组件；`AiProperties.Sheet` 是它唯一的数据源。
- **禁止**在 `AiTools.java` 的哨兵桩方法体里做开关判断 —— 那样模型会看到一个"永远失败的工具"，白烧一轮 token，且用户看到的是"工具坏了"而不是"功能被关了"。
- 撤销工具随写闸：`undo_last_sheet_edit` 在写闸关时也不披露（否则模型会去撤销一个它做不了的改动的历史）。
- **双闸工具只有 `normalize_column` 一个**，规则写死为 `readEnabled AND writeEnabled`（理由见 §2.1 写闸行）。这条必须显式实现并在 S-02 的 32 例里单独覆盖（否则"建议档随读闸开、commit 档随写闸关"这种半开状态会让写闸形同虚设）。

> **2026-10-22 已裁（代裁，用户授权）**：`normalize_column` 的双档开关联动**钉 `readEnabled AND writeEnabled`**（不取"建议档随读闸、commit 档随写闸"的半开口径）。依据：该工具 `commit=false` 与 `commit=true` **同名同形参**，若按读闸开放则模型可直接传 `commit=true` 绕过写闸 —— 只有"两闸同时开才披露"才能让写闸不是装饰；代价是关写闸时连只读建议一起消失，这比"半开"安全得多的取舍。

### 2.4 关闭后的对外行为（逐面给码与文案）

| 面 | 写闸关时的行为 | 说明 |
|---|---|---|
| 工具披露 | 写 4 个（含撤销）不在 `forContext` 结果里 | 模型根本看不见，正常路径不会触发 |
| 旧缓存调用 | 执行前拦下，回执 `outcome=failed` + `code=SHEET_DISABLED` | **必须是新码**，不得复用 `BLOCKED` / `SCOPE_VIOLATION`：那两种码在卡面分别渲染为「被拦截」「越权」，会让用户以为是自己点错了 |
| 卡面文案 | 「表格写入功能已被管理员关闭，本次未做任何修改。」 | 与既有写侧失败文案同句式（「…，本次未做任何修改。」） |
| 模型侧文案 | 回执正文追加一句可行动提示：「不要重试；请让用户联系管理员开启表格写入，或改用导出后自行编辑。」 | 防模型换参数连撞（与 F1 首错即停同姿态） |
| 读闸关时 | 4 个纯读工具 + `normalize_column`（双闸工具）不披露；旧缓存调用回 `SHEET_DISABLED`，文案「表格读取功能已被管理员关闭，本次未读任何数据。」；写 3 个（`replace_values` / `update_rows` / 撤销）不受读闸影响 | 读闸关 = 连"有多少行"都不答，故文案必须显式说"未读任何数据"，防模型编造行数 |
| `/health` | `sheet.readEnabled` / `writeEnabled` 如实回显 | 与「配置面不能对运行面说谎」同纪律（`AiRetiredKeysWarner` 类注） |
| 前端 | 不特判；`resolveSheetContext` 只在被调用时才知道（而关闸后不会被调用） | 唯一前端改动 = 按 `/health.sheet` 收紧采样上界（§2.5） |

### 2.5 前端如何拿到有效上界（关键：不能在数据回来后判）

新增 additive 健康块（先例 = 既有 `frontendToolTimeoutSeconds` 折算值，`frontend/src/types/ai.ts:99`）：

```json
{

    "readEnabled": true,
    "writeEnabled": false,
    "sampleMaxRows": 20,
    "projectionMaxColumns": 5,
    "effectiveFrom": "config"
  }
```

- 前端在 `resolveSheetContext` 前 `clampSheetPolicy()`：`limit = min(args.limit ?? 5, policy.sampleMaxRows)`；投影列 `slice(0, policy.projectionMaxColumns)`（超出的列**具名拒绝**，不静默截断 —— 静默截断会让「列 A 没改」被误读成「列 A 本来就对」）。

## 5. 撤销与变更集（撤销深度 3 + planId + AI 改动 vs 人工改动）

### 5.1 现状（读码实证）

| 面 | 现值 | 落点 |
|---|---|---|
| 深度 | `SHEET_UNDO_DEPTH = 1` | `sheet-tools.ts:33` |
| 存储 | `WeakMap<SheetAdapter, {planId, defCode, changes}>` —— **一格槽**，撤销即 `delete` | `undoPatches`（`:1456`）、`undoLastSheetEdit`（`:1495`） |
| 绑定 | 补丁带 `planId`，但**只用于识别来源**，不参与判定 | `undoLastSheetEdit` 内仅回执引用 `patch.planId` |
| 生命周期 | 刷新即失效（WeakMap 随 adapter 消失） | 与挂账 L-41 同口径 |
| 人工改动感知 | **零**：不区分"这格是 AI 改的"还是"人手改回来的" | 全仓无该概念 |

三个后果：① 连续两次 AI 修改后，用户只能撤最后一次且撤完就没了；② 撤销会**覆盖**人工在同格上的修正（把用户的手改回滚掉）；③ 卡面无法回答"现在表里哪些格是 AI 改的"。

### 5.2 深度 3 的数据结构

```ts
// sheet-tools.ts
export const SHEET_UNDO_DEPTH = 3

interface SheetUndoEntry {
  planId: string          // 与 SheetWritePlan.planId 同值（同一份，不另生成）
  toolCallId: string
  tool: string            // replace_values / update_rows / normalize_column
  defCode: string
  atMs: number
  changes: SheetChange[]  // {row, col, oldValue, newValue}
  rowsCount: number
  cellsCount: number
  /** 应用后到撤销前，这些格是否被人改过（快照比对用） */
  appliedValues: unknown[] // 与 changes 等长，应用瞬间的"新值"快照
}

const undoStack = new WeakMap<SheetAdapter, SheetUndoEntry[]>()  // 栈顶 = 最后一次
```

- `push` 时若超过 3 条，丢弃栈底（FIFO 淘汰）—— 淘汰是**静默**的，但 `undo_last_sheet_edit` 的回执必须写明"可撤销深度 3"（见 §5.6），避免用户以为能一直撤。
- 同一 `planId` 不重复入栈（防双击应用）。
- 键仍是 adapter（WeakMap）⇒ 刷新失效口径不变、不新增持久化。

### 5.3 冲突判定：整批全或无

撤销前逐格比对 `appliedValues[i]` 与当前 `getCell(row, col)`：

| 情形 | 判定 | 动作 |
|---|---|---|
| 全部相等 | 无人工干预 | 整批回滚 → 出栈 |
| 任一不等 | 该格被人工改过（或又被另一 AI 计划改过） | **整批拒绝**，回执写明冲突格数；栈不弹出（用户可先撤更新的那一批） |

**为什么不做逐格跳过**：文档已有"半批执行毒化历史"这条已命名风险（索引第 29 件）；逐格跳过 = 制造"半撤销"——表里一半是 AI 改后、一半是撤后，且没有任何记录能说清哪一半是哪种，比拒绝更糟。全或无与既有行指纹口径（"预览与应用之间被改动即整批拒绝"，`sheet-tools.ts` §3.5）**同一姿态**，用户学一次就懂。

### 5.4 「AI 改动 vs 人工改动」区分视图

**不新增工具**（不加 `ui_undo`、不加 `list_ai_changes`），只加**卡面与标记**两层：

1. **已应用卡面追加一行**：
   `AI 改动 120 格（可撤销，深度 3 中第 1 层）· 其后人工改动 3 格`
   —— 人工改动数 = 应用后 `data-changed` 事件里、不在本批 `changes` 坐标集内的格子去重计数（`SpreadGrid` 已有 `data-changed` 订阅与 `bumpVersion`，见索引第 37 件 §8 风险 6）。
2. **标记（屏幕态高亮）**：AI 改动格加**临时底色**，人工改动格**不加**（只计数）。应用后保留到下一次 apply / 用户点"清除标记" / 页面刷新。**不写 cell style、不调 `conditionalFormats`** —— 后者会污染 `toWorkbookJson()` 产物（索引第 37 件 §8 风险 14，T-31 已用"产物字节一致"锁死）。这一条与挂账 L-23（预览高亮未做）合流：**预览态高亮与已应用态高亮是同一套绘制函数**，一次做两次用。
3. **撤销后**：被回滚的格清标记，其余不变；栈内其余层保留。

> 术语纪律：对用户只说「AI 改动 / 你的改动」，不说「脏格 / dirty cells」——后者是 SpreadJS 内部概念，且 `isProtected` 类的东西在这里不是安全边界（索引第 37 件 §8 风险 5）。

### 5.5 与 SpreadJS 事务的取舍对比（保留"不承诺 Ctrl+Z"）

| 维度 | A 自有反向补丁（本稿，现状延伸） | B `Commands.startTransaction/endTransaction` + `options.allowUndo` |
|---|---|---|
| 成熟度 | 已在跑（深度 1） | **未实证**（索引第 37 件 §8 风险 13 / TechPoint-U1；`d.ts` 位置已核但行为未验） |
| 与 `planId` 的关系 | 天然绑定（补丁就是计划的逆） | 无（事务只记"一次操作"，不记哪张计划） |
| 与用户撤销栈的关系 | 完全独立，互不干扰 | **共用**：用户的 Ctrl+Z 会把 AI 改动和人工改动混在一条栈上，"撤一次 AI 改动"可能只需一次，也可能被用户的中途编辑夹断 |
| 人工改动冲突判定 | 可做（逐格比对） | 做不了（拿不到"哪一笔记的是 AI"） |
| 刷新后 | 失效（WeakMap） | 同样失效，且 `allowUndo` 受实例影响 |
| 结论 | **主路径（唯一权威）** | 只作**增强**，且仅在实测通过后启用；**在此之前文档与文案不得出现"Ctrl+Z 可撤销"**（沿用索引第 37 件 §8 风险 13 的红线） |

> **2026-10-22 裁决通过（主会话按业界主流代裁，用户授权）**：撤销深度定 **3**（`SHEET_UNDO_DEPTH = 3`），并**维持"不承诺 Ctrl+Z"** —— 本稿与所有面向用户的文案都**不得**出现"可用 Ctrl+Z 撤销 AI 改动"。依据：业界（SpreadJS 事务 / Excel 撤销栈）确实以用户撤销栈为准，但本仓的 AI 改动必须能回答"哪一笔记的是 AI"，而共用撤销栈拿不到该信息 ⇒ 自有反向补丁作唯一权威，深度 3 覆盖"改错 → 再改 → 退回"这条最常见三步；SpreadJS 事务仅在实测通过后作增强。

## 6. count 预览走聚合器快路径 + 卡面补分布渲染

### 6.1 现状的两个缺陷（都可复现）

**缺陷一：先物化、后判限。** `planReplace` / `planUpdate` / `planNormalize` 都是"扫全表 → 把每个命中格 push 进 `changes[]` → 再看长度是否超 10 万"：

```text
// planReplace 的扫描段（sheet-tools.ts:1028-1044；planUpdate / planNormalize 同构：:1125-1209 / :1425 一带）
for (const row of scope.resolved.rows) {
  for (const col of columns) {
    ... changes.push({ row, col, oldValue, newValue: matched.next })
  }
}
if (changes.length > SHEET_WRITE_HARD_MAX_CELLS) return { ok:false, reason:'…超过硬上限…' }
```

300 万格命中 ⇒ **先建 300 万个对象**（每个含 4 个字段的旧/新值），再拒绝。这不是"慢"，是"先吃满内存再报错"；且 `preview=count` 与 `full-diff` 走**同一条**扫描路径（`preview` 只被 `normalizePreview`（`:1021-1027`）校验后存进计划，不影响扫描）。

**缺陷二：卡面承诺了不存在的分布。** 计数档文案是「只回**计数与分布**」（`SheetPreviewCard.vue:41`），而 `SheetWritePlan` 里**没有**任何分布字段（`types/ai.ts:396-417`），`planPreviewText`（`:873-894`）也不产出。用户被承诺了"分布"，屏幕上只有一个总数。

### 6.2 快路径算法（P0 档不物化）

```text
planCount(ctx, args):
  matchedRows = []; matchedCells = 0; skipped = 0
  groups = new Map<groupKey, {rows:Set, cells:int}>()     // 复用聚合器的分组原语
  for row in scope.rows:
     rowHit = false
     for col in columns:
        if match(cell(row,col)) and validate(...) pass:
           matchedCells += 1; rowHit = true
           bumpGroup(groups, groupKeyOf(row), col)
        else if validate fails: skipped += 1
     if rowHit: matchedRows.push(row)
     if matchedCells > HARD_MAX: return { ok:false, reason:HARD_MAX_文案 }   // 提前中止
  return plan{ changes: [], detail: 'none', rowsCount, cellsCount, skipped, distribution }
```

三处收益：
1. **内存 O(1) 级**（只有分组计数与行号集），不再为被拒的请求建 300 万对象；
2. **提前中止**在 `HARD_MAX + 1` 处，最坏情况多扫一格；
3. 分布与计数**同一次扫描**产出，不重扫（复用 `aggregateSheet`（`:652-710`）的分组与排序原语，抽成 `groupCounts(ctx, rows, cols, by)` 供两处调用）。

**明细档仍物化**（P1/P2 需要逐格 `old→new`）：`setPreviewLevel('sample-diff'|'full-diff')` 时按需**重算**——把 `plan` 的入参快照（`args`）留在计划里，`replan(planId, level)` 重跑同一确定性函数：

- 重跑前比对 `ctx.version`：变了 ⇒ 走既有「预览已失效」路径（`SheetPreviewCard.vue` 的 stale 分支），不静默套用旧结果；
- 重跑后 `planId` **不变**（同一份计划，只是明细粒度变了）—— 这对 §5 的撤销绑定是必须的；
- 物化超 `HARD_MAX` ⇒ 保持 count 档 + 卡面提示「明细不可用（超过 10 万格），可继续按计数确认」。

> 这条修改了现状的一条隐含不变量（"计划恒带全量 changes"），因此**必须**同步：`SheetWritePlan.changes` 改为可选 + 新增 `detail: 'none' | 'full'`；`SheetPreviewCard` 的 P1/P2 分支在 `detail==='none'` 时先请求重算（显示"正在加载明细…"）。类型改动落 `types/ai.ts`，与索引第 51 件 `resultView` 契约**无交集**（那是后端下行，这是前端内存态）。

### 6.3 分布口径

| 项 | 口径 | 理由 |
|---|---|---|
| 分组列 | 入参 `distributionBy`（字段编码，可选）；缺省 = **谓词首个字段**，无谓词则 = **投影首列** | 用户问"改了多少"时，最想看的分布通常就是筛选条件那一列 |
| 组数上限 | 显示 5 组 + 「其他 N 组」；内部计数上限 20 组（与 `aggregate_sheet` 的 `limit` 同口径） | 超 20 组的分布对决策无价值，只看总数 |
| 排序 | 按 `rows` 降序，同值按 key 字典序 | 稳定性（断言可比） |
| 数值 | `rows`（命中行数）+ `cells`（命中格数） | 二者不等时（一 row 多列命中）必须都显示，否则"影响面"会被低估 |
| 数据分级 | 分布键 = **业务值**（D2），但**只在浏览器渲染，不回灌**（`planAppliedText` 不含 distribution） | 一旦回灌，模型侧 D2 体积就多一块；模型此刻正在等待，本就不需要它 |
| 空分布 | 无命中 / 无分组列 ⇒ 不渲染分布块（不显示"其他 0 组"） | 空块比没有更让人困惑 |

## 7. 明确不做的清单（四条，各一句理由）

| 不做 | 一句理由 |
|---|---|
| **公式**（`apply_formula`） | 导出链 `buildRowsXlsxBlob` 自产 OOXML 只写 `<v>` 与共享串、`styles.xml` 仅 1 个 `cellXfs`，公式**写了落盘即丢**，且后端 `ExcelReader` 按值读、对下游零意义。 |
| **格式**（`format_range`） | 同一落盘缺口（格式不进 `cellXfs` 就不进文件），且会顺手把"预览高亮"这条**只读**的可核对性升级成"改样式"的写操作，扩大授权面而无产出价值。 |
| **结构变换**（插列 / 删列 / 转置 / 拆列 / 合并列） | 不是"风险高"，是**必然静默读错**：`ExcelReader.read` 按**列号**取字段（`for c in 0..fieldCodes.size()`），插一列令其后所有字段整体错位且无校验无告警。此禁令直到列映射改为按表头名匹配才能解除。 |
| **跨表**（跨 sheet 汇总 / 单表按列拆分） | 一 def 一 sheet（`findDataSheet` 跳过 `_` 前缀隐藏表），跨表 = 多个定义混进一个文件，直接破坏导出契约与 `_meta` 单表映射；要做必须先在导出链立"多表"概念，属另一个专项。 |

> 四条的共同点值得单列一句：它们的排除理由**都不是"AI 会做错"，而是"本仓的数据契约不支持"**。这意味着它们是**可解除的**（前提是先改造导出链或列映射），而不是永久禁区 —— 但解除的前提件不在本专项范围内，任何"顺手做一点"都是把静默错误带进主链。

> **2026-10-22 裁决通过（主会话按业界主流代裁，用户授权）**：上表四条**不做项**按原文定稿，一条不撤。依据各自已在表内给足（公式/格式 = 导出链落盘即丢；结构变换 = `ExcelReader` 按列号读必静默错位；跨表 = 破坏 `_meta` 单表映射）；共同性质是**"本仓数据契约不支持"而非"风险高"** ⇒ 解除的入口是导出链或列映射改造专项，不是本治理批。
