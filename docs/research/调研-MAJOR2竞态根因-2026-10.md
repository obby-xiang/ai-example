# 2. 间歇性解释
- 决定性量是**不到 30 ms 的排队/时序抖动**：投递链 `afterCommit`（`JobService:140-145`）→ `AsyncJobExecutor.execute:27`（`@Async`）→ 线程池 core4/max16/queue200（`AsyncConfig.java:58-71`，"job-async-"）。脚本侧是 POST→GET→DELETE 三次往返，执行器侧是线程入队 + `markRunning`(REQUIRES_NEW) + 若干 DB 读，两者同量级 ⇒ 取消标志落在 `:104` 前 = 绿，落在 `:104` 后 = 必翻。
- 翻转**落点**决定红法（同一竞态、四种签名）：落在循环前→EXPORT/PRECHECK 201；落在循环中→IMPORT/PUBLISH 得 `PRECHECK_NOT_PASSED`（本棒）；落在循环后→PASS；清场期撞上→`DELETE /api/tasks/{id} 500 Row was updated or deleted…`（`e2e-local-repro.log:78`，即 9211adc 热修项）。
- **本地 vs CI 差异不是配置**（batch-size/delay 两边同为 10/150），只是机器抖动：本地三次（`r137-guard/backend-boot*.log`，16:26-16:32 @9211adc）同族戏码全量重现——run1 `:863-865` 26 ms 后丢弃终态且 MAJOR-2 仍 PASS（翻写落在 4 次 POST 之后）；run3 `:864-866` 同样丢弃 + PASS；run2 无丢弃 ⇒ 翻写/取消时序换了方向，报出另一签名。CI 那 26 ms 窗口与本地同级，只是 CI（2 vCPU 共享、冷 JIT、H2 文件 IO）多偏 2~5 ms 就跨过门限 ⇒ 本地 PASS=31 与 CI 偶红完全自洽，非"本地无此竞态"。
