- 前置：B1 已闭环入库 `2a86e1b`（挂起即断 + `?lastSeq` 重连补帧 + delta 入档）；L0 刷新恢复修复（请求帧标记 req / kind 三值透出）同期施工中
- 依据：`docs/research/调研-多实例SSE扇出与HITL业界架构-2026-10-20.md` §6/§7；`调研-AI工具执行治理与互斥-2026-10-19.md` §6.4 P1-7/P1-8/P1-9；二十九棒后端勘察报告（agent-1274）；`docs/决策看板.md` 10-20 架构方向裁决
- 合并理由：B3 fencing 租约与 L1 资源租约共享同一 Redis 原语（`SET NX PX` + epoch + 续租 + 写回校验）；B3 承认 at-least-once ⇒ 依赖 L1 业务幂等键；UNKNOWN 对账语义两面共用。一张设施两头用，分开做会做两遍。

## 1. 范围

**做**：
- B2：事件日志 Redis Stream 化 + pub-sub 唤醒扇出 + 连接层无状态（任何实例可 serve 任意 run 的 reattach）；
- B3：续跑权 fencing 租约（epoch 单调）+ 跨实例决策路由安全（根治挂账「多实例确认误路由/跨实例租约未覆盖」）；
- L1：目标资源互斥租约（`lock:task:<taskId>` / `lock:job:<taskId>:<jobType>`，调研 P1-7）+ 业务幂等键（P1-8）+ F2 目标资源校验（`ToolTargetResolver`，校验 args 指向的资源存在且属本会话上下文）；
- 双实例测试 harness（8081/8082 共享 Redis + 桩上游）+ 实例面测试矩阵。

**不做**：L2 风险分级豁免（2B 族）；L3 批级状态机/DAG；`TaskSseService`（作业进度 SSE 面）多实例化（留痕为后续项）；挂起期线程驻留改造（维持池 20 口径）；前端零变更目标（B1 已把客户端切成重连模式，本专项对客户端透明）。

## 2. 核心设计

### 2.1 FrameStore 抽象与事件日志（B2 主件）
- 接口 `FrameStore`：`append(runId, frame) → seq`、`readFrom(runId, afterSeq, limit)`、`lastSeq(runId)`。实现 = Redis Stream 单实现（`XADD ai:xevents:<runId> MAXLEN ~ 6000` + `XRANGE`）；**单/多实例同一实现**（RunStore 本就在 Redis，不引内存环，消灭分支）。现有 `ai:events:<runId>` LIST 读取侧兼容期双读（新写只进 Stream；迁移见 §4）。
- `SseChatEmitter.emit` 降级为「FrameStore.append → `PUBLISH ai:wake:<runId>`（载荷仅上界 seq，不传帧体）→ 本地扇出」；本地扇出保留作同实例快路径。
- 新增 `FrameWakeListener`：`RedisMessageListenerContainer` 按**连接** subscribe `ai:wake:<runId>`（禁止每实例订阅全量频道）；收到唤醒 → `readFrom(>lastSentSeq)` → 推给本实例该 run 的连接；断连即 unsubscribe。pub/sub 丢消息无所谓（唤醒语义），最终一致靠客户端 `?lastSeq` 重连。
- `seq` 取号收敛：`INCR ai:seq:<runId>`（Redis 原子），废除进程内 AtomicLong 锚定（现行 `SseChatEmitter.java:767-787` 的首帧读锚 + 本地自增）。

### 2.2 fencing 租约（B3 主件）
- `LeaseService`（新建设施，B3/L1 共用）：`tryAcquire(key, ttl) → epoch?`、`renew(key, epoch, ttl)`、`release(key, epoch)`、校验一律 Lua 原子（GET 比对 epoch 后写）。
- 续跑租约：`ai:lease:run:<runId>`，TTL 30s，持有者在续跑期间每 10s 续租；`RunSnapshot` 增 `runEpoch`；续跑路径所有写回（快照/ledger/claim）带 epoch 校验，不匹配即拒（Camunda INVALID_STATE 同型）。
- `ConfirmGate.maybeTriggerResume` 从「查本地 latch」升级为「先 `tryAcquire` 租约」：抢不到 = 另一实例在跑，本实例只落决策不写执行；抢到了才 `ResumeService.resume`。`signal` 本地快路径保留（同实例决策仍直接唤醒），跨实例决策 = 落 Redis pending + 租约路径续跑。
- `ai:claim:`（claimExecution）与 `ai:resume:lock:` 归并进 LeaseService 语义（值从 instanceId 改 epoch）。
- 挂起期 TTL 续期归属：挂起线程死亡即无人续期——裁决：**挂起态 TTL 续期改由「读侧触发 + 24h 滑动」维持**（任何实例的 runs/current 读取、决策 POST、reattach 都 touch），不再依赖挂起线程；配合 L0 的 req 标记不改变挂起语义。

### 2.3 资源互斥与幂等（L1 主件）
- 资源租约键：`ai:lock:task:<taskId>`（任务级写操作互斥）、`ai:lock:job:<taskId>:<jobType>`（同类作业在途互斥），TTL 60s + 持有者续期 + 终态释放；走 LeaseService 同一实现。
- 落点：W/J/P 类工具（create_task / start_export / start_import / start_publish 等）执行前 acquire；冲突 = 工具结果 `blocked`（P0-1 信封已有该态）带码 `RESOURCE_LOCKED`，不抛异常不断流。
- F2 `ToolTargetResolver`：W/J/P/U 类工具执行前校验 args 的目标资源（taskId 存在、属于当前会话上下文可见范围、defCode 属于该任务）；失败 = `blocked` + `TARGET_INVALID`。与 F5 预检的关系：预检是只读前置展示，resolver 是执行前硬校验，两层并存。
- 业务幂等键：工具副作用执行以 `runId:toolCallId` 为幂等键（天然唯一）；执行记录落 `ai:ledger:`（既有），重放命中已执行记录直接返回原结果（at-least-once 收敛为幂等一次）。

### 2.4 UNKNOWN 对账语义（最小面）
- 跨实例「超时 ≠ 失败」：工具执行结果 UNKNOWN 时（P0-1 已有该态），对账顺序 = 先查 ledger 幂等键 → 再查资源租约持有 → 最后才允许重试语义上报；本专项只落地「ledger 优先对账」这一跳，完整对账器留 L3。

## 3. 契约变更

- **帧**：类型集不变；`heartbeat` 帧退役讨论不在本专项（挂起期已无连接可跳，流式期 5s 搭车心跳保留）。
- **端点**：无新增/无签名变更；`/health` 增报 `leaseOk`（Redis 租约设施自检）——仅观测面。
- **客户端**：零变更目标（重连 + `?lastSeq` 语义 B1 已备）；多窗口实时同步维持「操作/刷新时同步」口径不变。
- **Redis 键族新增**：`ai:xevents:`（Stream）、`ai:wake:`（频道）、`ai:lease:run:`、`ai:lock:task:`、`ai:lock:job:`；`ai:events:`（LIST）进兼容只读期。

## 4. 迁移与回滚

- 单实例部署行为不变（FrameStore 单实现 = Redis，本地扇出快路径保留）；A→B 已在 B1 完成，本专项不动连接语义。
- 事件日志迁移：新写只进 Stream；`readFrom` 兼容期先读 LIST 尾巴再读 Stream（按 seq 拼接去重）；TTL 到期旧 LIST 自然消亡，不做搬迁。
- 回滚 = revert 批次 commit；Stream/新键族残留无害（TTL 自清）。
- 灰度：本项目单部署形态，无灰度需求；双实例仅测试 harness 形态存在。

## 5. 验收口径

1. 门禁：后端/前端单测全绿（基数随 L0 入库刷新）、typecheck 0、build ✓、check-docs 6/6、脱敏 0 命中。
2. 双实例 PoC harness（`scripts/` 新增，8081/8082 + 共享 Redis + 桩 18399）：
   - 挂起在 A、决策落 B → 恰一次续跑（epoch  fencing 实证：双决策并发 = 一次执行一次拒）；
   - 挂起在 A、reattach 落 B → 回放齐 + 续跑帧经 wake 扇出到 B 的连接，丢帧率 0；
   - A 死亡（kill）挂起中的 run → B 侧读取/决策/接管续跑闭环；
   - 资源互斥：同 taskId 双 start_export 跨实例并发 → 恰一个 `blocked/RESOURCE_LOCKED`；
   - 幂等：同一 `runId:toolCallId` 重放 → 副作用不重复。
3. E2E 31 用例单实例面不回归；实例面变体用例进 harness 脚本（不进 CI 的 29 主用例，先脚本化）。
4. 性能口径：本地扇出快路径下 P95 帧延迟不回退（对比 B1 后基线，允许 ±10%）。

## 6. 风险与边界

- **Redis 信任边界**：pub/sub 不签名不加密，Redis 被控 = 全链路被控；登记为接受风险（内网部署前提），生产化另议 TLS/ACL。
- **at-most-once 边界**：帧下发 at-most-once（pub/sub 可丢），正确性由客户端 `?lastSeq` 重连兜底——客户端不重连则实时性降级但不丢正确性。
- **Stream 窗口 6000 与 delta 体积**：长 run 超窗口 = 尾段补不回（同 B1 登记的 3000 窗口风险，翻倍缓解不根治）；根治 = 正文持久层，不在本专项。
- **时钟**：epoch 单调由 Redis INCR 保证，不依赖墙钟；TTL 语义依赖 Redis 时钟，可接受。
- **挂起线程驻留**：池 20 上限不变，多实例 = 各实例独立 20，harness 不压测该上限。

## 7. 分批切分（施工顺序）

- **批① 设施先行**：双实例 harness 脚本 + FrameStore/Stream + wake 扇出 + seq 取号收敛（B2 主体）；
- **批② fencing**：LeaseService + 续跑租约 + maybeTriggerResume 改造 + 挂起 TTL 读侧续期（B3 主体）；
- **批③ 资源治理**：资源租约 + ToolTargetResolver + 幂等键 + UNKNOWN 首跳（L1 主体）。
每批独立走「施工 → 复审 → 收口 → 复核 → 提交官」流水线，批批入库推送。
