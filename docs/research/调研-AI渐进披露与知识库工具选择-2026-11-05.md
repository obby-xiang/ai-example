# 调研：AI 渐进披露与知识库工具选择（2026-11-05）

> **性质**：只读源码核查与官方资料调研，不含施工完成声明。本文仅新增研究文档，**未修改代码、未运行测试或服务、未执行 Git，未做模型/浏览器实测**。字符数、行数为静态文本计数；token、缓存命中率、检索质量和时延均尚未实测。行号对应当前磁盘内容。

## 1. 结论先行

本仓已有正确的渐进披露骨架：`ToolRegistry.forContext` 按页面、任务、步骤和功能开关裁剪 Schema，执行面复用同一判据；KB 也已有 `kb_search → kb_read_doc(next_offset)`。主要缺口不是“再增加压缩”，而是：

1. **System 静态重复与无条件领域文本过多**，工具已裁掉，对应规则仍常驻。
2. **KB 使用规则与特殊步骤的工具面不一致**：条件结构化交棒时 KB 工具被过滤，但“先调用 `kb_search`”仍无条件注入。
3. **KB 之外的截断结果缺通用回读句柄**；有截断标记不等于能取回原文。
4. 应采用的组合是 **短稳定核心 + 按需规则包 + 现有上下文工具裁剪 + 可回读结果 + 混合式 KB 路由**。Tool Search、向量检索和子 Agent 都有触发条件，不应默认堆上。

## 4. 混合式 KB 路由

这里的“混合”是 **宿主确定性路由 + 模型按需检索**，不等于必须同时上关键词和向量检索。

| 输入/状态 | 路由裁决 | 工具与上下文 |
|---|---|---|
| 创建、导航、选配置、条件、启动、审批等工作流 | 宿主页面/任务/步骤与风险门优先，模型不得用 KB 代替业务动作 | 保持 `forContext` 和执行前复查；当前批不扩权 |
| `QUERY_COND` 条件结构化交棒 | 只保留当前四个工具；**同步省略或改写 KB 强制检索规则包** | 不增加 KB 工具，不让 System 要求调用不存在的能力 |
| 明确术语/口头叫法 | 先精确查，未命中再检索 | `kb_lookup_term → kb_search`，不把近似词当命中 |
| 制度、流程、口径、FAQ、系统使用问题 | KB 工具实际披露时才加载“先检索”规则 | `kb_search`；snippet 不足用 `kb_read_doc(next_offset)` |
| 普通寒暄、无需私有知识的直接回答 | 不强制 KB | 减少空调用、时延和 token |
| 同句混合“解释制度 + 修改任务” | 拆成知识读取与业务动作，保持授权和步骤顺序 | 不在条件结构化批里偷偷加工具；在当前步骤允许的新模型步/新轮完成知识部分 |
| 未命中/低置信 | 原词、别名有界重查；仍无结果就明说 | 不用通用知识冒充官方口径，不无限循环 |

中文正则只能继续用于**创建参数补齐**，且要求唯一配置/主键/候选并完整消费输入；不得泛化成通用意图、KB 路由或授权判断。目录也可从全量常驻改为 `catalog cursor/docId` 按需读取；关键词 + 向量 + RRF 是后续独立优化项，必须由召回评估触发。

## 5. 本项目分阶段最佳方案（均为建议，未施工）

### 阶段一：先消除静态矛盾与重复

1. System 核心只留角色、安全/授权、披露与确认协议、数据边界和输出要求。
2. 创建流程只留一个权威版本；参数细节在 Schema，跨工具顺序在创建规则包。第 8/24/30、26/28/30 不再各自维护全文。
3. 表格/UI/表单/创建/KB 规则随实际工具披露加载；尤其让条件结构化交棒的 KB 文案与四工具面一致。
4. 保留类型化 form Schema 和现有执行闸，不做“提示词外置 DB 化”或削弱 Schema 来省字。

### 阶段二：补可恢复上下文与路由评估

1. 非 KB 长结果采用 `resourceId + section/chunkId + nextCursor/nextOffset + truncated`，提供有权限复核的 `read_result`；复用 KB 整页可见经验。
2. KB 目录改为按需/分页；保留 `doc_id §章节` 引用和未命中语义。
3. 建立混合路由样本：直接回答、精确术语、KB 检索、工作流、混合意图、条件交棒、未命中。
4. 工具规模真的过大时，在应用层增加轻量目录搜索；端点明确支持时才接原生 Tool Search。

### 阶段三：优化缓存与长任务，不倒置顺序

1. 稳定核心/稳定工具在前，语言、工作区、动态目录在后；按端点能力观测缓存读写。
2. 接近窗口再压缩，优先清有回读句柄的旧工具结果；保留目标、审批、资源 ID 和下一步的结构化笔记。
3. 只有复杂独立研究才使用子 Agent 并返回短摘要；只有检索指标证明需要时才引入向量混合/重排。

## 6. 评估指标与禁止项

- **披露**：各场景 System 字符/token、Schema token、固定前缀占比；未披露调用数、无效参数率、重复表单率。
- **路由**：期望工具选择准确率、直接回答准确率、混合意图顺序正确率、每请求工具调用数；`QUERY_COND` 交棒必须仍是四工具且无矛盾 KB 指令。
- **检索**：Precision@K、Recall@K、MRR；未命中拒答正确率、引用命中率、低置信原文复核率。
- **恢复**：截断后可回读率、游标连续率、整页结构尾保留率；不得只统计“已截断”。
- **任务**：端到端成功率、错误工具/越权执行数、重复创建/启动数、用户确认绕过数。
- **成本**：首 token/总时延、输入 token、缓存命中率（端点支持时）、向量/重排新增时延与成本。

**不做**：不靠扩大窗口或提高压缩频率解决静态膨胀；不把截断当回读；不为缓存恢复全量工具；不假定 DeepSeek/OpenAI 兼容端点支持私有 Tool Search；不把子 Agent、向量库或更多规则当默认答案。
