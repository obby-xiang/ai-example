## 0. 结论速览（九条硬口径）

1. **今天 AI 有「动作」没有「眼睛」，也没有「手」**：4 条工作区动作（`utils/frontend-tools.ts:648-707`）+ 15 类 `ui_event`（`types/tools.ts:159-193`）+ 11 个页面 handler（`types/workspace.ts:14-25`）都是**注册式**；但前端登记工具只有 2 个（`types/tools.ts:79`、`:82-107`），且 `workspace.snapshot()` 只给业务状态（`stores/workspace.ts:250-263`）——**页面上有哪些按钮、哪些禁用、校验错在哪，模型一概看不见**。
2. **`data-ai-*` 全仓零命中**：`grep data-ai-\|registerAiRegion\|ui_snapshot\|ui_click` 只命中调研稿本身（42 处），代码侧 0 处 ⇒ G1/G2/G3 三条 P0 差距（元素级感知 / 通用原语 / 区域围栏）**一条都没动**，本专项是纯新增面。
3. **7 个工具、零新帧**：`ui_snapshot` / `ui_click` / `ui_fill` / `ui_select` / `ui_scroll` / `ui_highlight` / `ui_request_upload`；全部走既有 `frontend_tool_request` → 前端执行 → `POST /api/ai/frontend-tool-result` → `frontend_tool_result`。前端工具名是 `string`（`types/sse.ts:288`）、`args` 是 JSON 字符串（`:289`），**帧字段一个不加**。
4. **六个「做」里只有一个要人**：`ui_request_upload` 等的是**用户手势**（规范级：`showPicker`/`showOpenFilePicker` 必须 transient activation），故它必须进「人工介入型前端工具」名单 ⇒ `ConfirmGate.suspendWaitSeconds` 返回 `null`（`:322-330` 现在只认 `generative_form` 一个名字）+ 前端在 `frontend_tool_request` 分支特判绕开 60s 预算（GF 已有同款样板：`stores/ai.ts:2754-2758`）。**其余六个动词都是毫秒级，照旧被 60s 预算包住**（`frontend-tools.ts:235`、`:358-365`）。
5. **consequential = 拒执行，不是「执行后提示」**：`ui_click` 命中 `data-ai-risk="consequential"` 时**一次不点**，回灌点名应改用的注册动作（`start_export` 等）。这条是整份设计的**安全性质**：通用原语因此**结构上不可能**成为绕过确认门的后门（`SpToolCallingManager.kindOf:982-990` 的「通道优先」事实在这里被利用而非被挑战）。
6. **快照闸 ≤2000 字符（R3 同值）+ 默认 20 行 / 硬顶 40 行**，恒定回「共 N 个元素（本次回 M 个）」；只回**已注册区域内、带 `data-ai-ref`、非 deny** 的元素；`password/file/hidden/cc-*` **根本不进快照**（不是「填了再拦」）。
7. **epoch 必须带加载期随机段**：`epoch = <nonce>-<counter>`（nonce = 每次模块加载的 6 位 base36）。只写单调计数器会让「刷新后 counter 归零」与「历史上下文里的旧 epoch」撞号——**这是刷新恢复场景唯一会假阳性的地方**，必须用 nonce 关死。
8. **撤销只给用户，不给模型**：深度 1（与表格专项 `SHEET_UNDO_DEPTH=1` 同口径），按钮落对话内操作摘要行；**不新增 `ui_undo` 工具**（工具数守住 7；模型改错了应当重填而不是悄悄回滚，且回滚对模型无信息增益）。与表格专项「`undo_last_sheet_edit` 是模型工具」的差异是**口径差异不是冲突**，理由见 §3.8。
9. **本专项不承诺「AI 能操作任何控件」，只承诺「注册区域内、已声明元素、受控动词、按风险分级」**；区域外仍是「不可见 = 不可操作」——这是设计目标。注入面（本仓第一注入面 = 工具结果与前端回灌，见安全防护调研 §4.1）在本专项被**放大一级**（从「模型说错话」到「模型点按钮」），故围栏与分级是**前置条件**，不是增强项（§8.1）。

### 1.2 不做（逐条给理由，防「顺手做了」）

| 不做 | 理由 |
|---|---|
| **像素级截图 / 坐标点击 / 虚拟光标动画** | 自有 Web 应用无必要；调研 §1.5 的成本·延迟·可靠性三项全劣；且画光标与既有「工具卡 + 通知」的反馈体系重复（§7.7 已裁：用「区域高亮 + 面板状态」表达，不做逐帧光标） |
| **让模型产 selector / XPath / HTML / `innerHTML`** | 把模型输出直接变成 DOM 查询 = 把注入面做成执行面（§8.1）；`ref` 只能查注册表，且 `ui_*` 的入参闸会**拒收** `selector`/`xpath`/`html`/`path` 一类键 |
| **通用原语点后果性按钮** | 等于绕过确认门（`kindOf` 通道优先事实的反面用法）；本稿以「拒执 + 指路」根治 |
| **操作 canvas 内部（SpreadJS 单元格）** | SpreadJS 在宿主 div 内自绘，单元格无 DOM 节点 ⇒ 快照/`ref`/`click` 对它完全无效；该面归表格专项的领域 API |
| **跨域 iframe 内操作** | 同源策略 + 无法做可信围栏；区域注册 API **拒绝**跨文档 root |
| **AI 代选本地文件 / 接受文件路径参数** | 规范级边界；`ui_request_upload` 的入参闸显式拒收任何 `path`/`filePath` 键（T-34） |
| **自动填密码 / 支付 / 隐藏字段** | OWASP LLM06 + 内置 deny 清单；且这些元素**不进快照**（不是「进快照再拒填」） |
| **「AI 渲染一个表单再写逻辑」替用户做界面已有的事** | 用户口径第 3 条；表单只用于补模型不知道的信息（既有 `generative_form`），不复刻界面 |
| **`ui_undo` / `ui_batch` 等第 8、9 个工具** | 工具数守住 7（Schema 开销 + 选择准确率）；撤销给用户按钮、批量由模型自己多调几次（有单轮配额） |
| **自动补全（扫 ARIA 生成临时 ref）** | 调研 §7.3 列为 C 方案；本稿批⑤ 只**评估**，不实施（零标注区域一律不可见 ⇒ 最安全默认值） |
| **像素级「按坐标猜」兜底** | 快照里没有 = 不可点；任何"点个大概位置"的分支都会把围栏变成摆设 |
| **持久化快照 / 持久化 ref** | 快照只在模型上下文里活一轮；`ref` 只在本页内存注册表里有效；刷新后必须重新 `ui_snapshot` |
| **把 AI 操作升级为「事务」** | DOM 不是事务（调研 §9.3）；本稿只承诺「最近 1 步反向补丁」 |

### 2.6 现状一句话判断

**通道齐备（四路由 + 三级兜底 + 统一预算 + 结局工厂 + L0 卡面重建），感知面为零、通用动词为零、区域围栏为零；而「写」这一侧的人围栏今天一个都没有（`:2760` 白纸黑字）。**
本专项不是「给 AI 装眼睛和手」，而是**在既有通道上加一层「界面契约」**：能看见的只是**已声明**的元素，能做的只有**受控**的动词，按**风险**分级，且**永远不能**替人按后果性按钮。

## 3. 核心设计

### 3.1 全局形态（三层，不推翻注册式）

```
┌─ 第 3 层：注册式语义动作（既有，保留并扩）─────────────────────────┐
│ WORKSPACE_ACTIONS(4) + 页面 handler(11) + 表格专项(8)              │
│ 有业务校验、有确认门、模型看得到「动作名」                          │
├─ 第 2 层：引用式通用原语（本专项核心，7 个工具名）──────────────────┤
│ ui_snapshot（看） + click/fill/select/scroll/highlight/request_upload│
│ 只新增 1 个「看」+ 6 个「做」；ref 不是 selector                    │
├─ 第 1 层：区域注册表 + 三道围栏 + epoch（本专项地基）───────────────┤
│ registerAiRegion({id, root, risk, ...})                             │
│ 元素声明：data-ai-ref / risk / label / fill / deny / option / undo  │
└─────────────────────────────────────────────────────────────────────┘
```

分工口径（**不是「通用原语取代注册动作」**）：
- 「有后果、有业务语义、需服务端校验」⇒ 注册动作（`start_export` / `start_publish` / `set_condition` …）；
- 「长尾、可逆、用户本来就会点」⇒ 通用原语（切 tab、展开、填筛选值、勾选、滚到某处、把用户送到上传入口）；
- 两者共用同一套 scope、结局工厂、回灌文本口径、尺寸闸、审计。

### 3.3 逐工具定义（名称 / 参数 / 副作用 / 确认 / 回灌口径）

#### 3.3.1 `ui_snapshot`

- **参数**：`regions`（可选，区域 id 列表；缺省 = 当前页面全部已注册区域）、`kinds`（可选，`button|input|select|toggle|link|all`，默认 `button,input,select,toggle`；按 **ARIA role** 过滤而非 HTML 标签，语义更稳）、`limit`（1..40，默认 20）。
- **作用面**：只遍历注册区域的 `root`（`root.querySelectorAll('[data-ai-ref]')`），**不做全文档遍历**。
- **回灌（纯文本，禁 JSON 块）**：

```
界面快照：导入向导 · 步骤「上传」  epoch=7f3a-12  区域 2 个（import.upload / import.grid）  共 9 个元素
[import.upload.templates]  button   "下载模板"        state=enabled
[import.upload.choose]     button   "上传 xlsx / zip" state=enabled
[import.upload.flush]      button   "保存草稿到服务端" state=disabled
[import.selectDefs.search] textbox  "搜索配置项"      state=enabled fill=allow value=""
[import.selectDefs.CURRENCY] checkbox "CURRENCY 币种"  state=checked
[import.mode.merge]        radio    "增量合并"        state=checked
[import.mode.replace]      radio    "整体替换"        state=unchecked
[import.grid.tab.CURRENCY] tab      "币种"            state=selected
[import.nextStep]          button   "下一步"          state=disabled
共 9 个元素（本次回 9 个；上限 40 行 / 2000 字符）
```

- **不返回**：区域外元素、无 `data-ai-ref` 元素、`data-ai-deny` 元素、`password/file/hidden/cc-*`、跨域 iframe 内元素、任何 `value` 不属于 `fill=allow` 的字段。
- **缓存**：同 `epoch` + 同参数命中缓存（只缓存 1 条），避免模型反复拉同一棵树。
- **不返回**：整页 HTML、任何可执行片段、任何 selector。

#### 3.3.2 `ui_click`

- **参数**：`ref`、`epoch`。
- **判定链**（§3.5/§3.6）：区域解析 → 上下文围栏 → 元素围栏 → **风险分流**：
  - `read`：直接 `element.click()`（白名单语义：导航 / 切 tab / 展开折叠 / 查询刷新——**不得**触发服务端写，标注责任见 §8.2）；
  - `mutate-local`：`click()` + 高亮 200ms + 记撤销点（仅 `data-ai-undo="retoggle"` 的元素）+ `touch`；
  - `consequential`：**一次不点**，回灌：

```
未执行：ref=export.start 属于后果性动作（data-ai-risk=consequential），通用原语不能点击它。
请改用注册动作 start_export（它会进确认门，由用户确认后才执行）。
```

- **回灌（成功）**：「已点击「上传 xlsx / zip」（ref=import.upload.choose，risk=mutate-local）。界面已同步（数据版本 #13）。可撤销：对话内「撤销」或让用户再点一次。」
- **副作用边界**：不改 `dataVersion` 之外的任何服务端状态；点击引发的页面内请求由页面自身负责（模型只拿到「点了 + 界面已变」的事实，拿不到响应体）。

#### 3.3.3 `ui_fill`

- **参数**：`ref`、`value`（字符串，≤200 字符）、`epoch`。
- **准入**：`input` / `textarea` / `[contenteditable="true"]` **且** `data-ai-fill="allow"`（缺省 deny）。密码/文件/支付/隐藏字段**本就不在快照里**，因此也不可达。
- **写值手法**：原生 setter（`Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set`）+ 派发 `input` / `change`（Vue `v-model` 只认这两个事件）；**不派发 `keydown`**（不模拟打字）。
- **写后回读**：`el.value !== value` ⇒ `failed`「值未生效（页面可能做了格式化或校验替换），请确认后重试」——**不谎报成功**。
- **回灌**：「已填写「开始日期」= 2026-01-01（ref=export.cond.startDate）。原值「2025-12-01」已记录，可撤销。」
- **不做**：类型猜测（数字字段不自动去千分位）、日期格式转换、批量填（模型多次调用，受单轮配额约束）。

#### 3.3.4 `ui_select`

- **参数**：`ref`、`option`（选项的**语义值**，非索引）、`epoch`。
- **路径 1（首选）**：区域在注册时给 `setters: { '<ref>': (option) => boolean }`。Element Plus 的 `el-select`/`el-radio-group` 是自绘弹层，盲点 DOM 不可靠（调研 §7.2），必须走 setter。
- **路径 2（回退）**：点开触发器 → 在 `[data-ai-option]` 中**精确匹配**（先严格，再 `trim` 后比较，不做模糊匹配）→ 点选 → 回读。
- **失败**：「未选择：下拉选项里没有「XX」。可选：增量合并、整体替换。」（选项清单来自快照/`data-ai-option`，≤10 项，超限只报计数）
- **回灌**：「已选择「增量合并」（ref=import.mode.merge）。原选择「整体替换」已记录，可撤销。」

#### 3.3.5 `ui_scroll`

- **参数**：`ref`（滚到元素）/ `container`（容器 ref）/ `delta`（像素，±2000 内）/ `block`（`start|center|end|nearest`）。
- **副作用**：只改视口，`dataVersion` 不变，不记撤销点。
- **回灌**：「已滚动到「发布结果」区域。」

#### 3.3.6 `ui_highlight`

- **参数**：`ref`、`note?`（≤60 字符，给用户的提示）。
- **副作用**：高亮环（**描边 + 图标 + 文案三重冗余**，不只靠颜色，WCAG 1.4.1）+ `scrollIntoView({block:'nearest'})` + `aria-live="polite"` 播报；`prefers-reduced-motion` 下取消过渡动画（静态描边）。
- **回灌**：「已高亮「上传 xlsx / zip」，请用户在左侧工作区查看。」
- 用途：把用户送到入口（上传/校验错误处/被禁用的按钮），是**降级为「引导用户自己做」**的载体（调研 §2 表末行）。

#### 3.3.7 `ui_request_upload`（本专项唯一「等人」工具）

- **参数**：`ref?`（缺省取区域 `uploadEntry`）、`accept?`（**只能收窄**，不能放宽页面的 `.xlsx,.zip`）。
- **行为**（**永不设置文件、永不经手路径**）：

```
① 校验：区域有 uploadEntry / 页面非只读 / 浏览器特性探测
② 高亮上传入口（同 ui_highlight 手法）
③ 在对话里渲染交接卡（UploadHandoffCard）：
   标题「需要你在左侧选择一个文件」+ 说明（accept、文件名需含配置项编码）
   主按钮「选择文件」（点击 = 用户手势）
   副文案「也可以点左侧高亮按钮，或把文件拖到高亮区域」
   次按钮「放弃」
④ 主按钮点击（手势内）：
   · 有 window.showOpenFilePicker ⇒ await showOpenFilePicker({types, multiple:false})
       用户取消 ⇒ catch AbortError ⇒ degraded「你取消了文件选择」；卡保留可重试
       拿到 handle ⇒ handle.getFile() ⇒ 交给页面 handler import.receiveFile(file)
       ⇒ 页面走既有 uploadOne(file)（= handleUpload 抽出的一行），完成匹配/回填/刷新编辑区
   · 无 showOpenFilePicker（Safari/Firefox/旧 Chromium）⇒ degraded「当前浏览器不支持在此处直接选择；
       请点左侧高亮的「上传 xlsx / zip」按钮，或把文件拖到高亮区域」
⑤ 页面侧联动：页面 uploadOne 成功 ⇒ notifyAiUploadDone(summary)
   ⇒ 若有活动交接 ⇒ 立即以 ok 回灌「用户已通过页面入口完成上传：币种.xlsx（匹配 1 个配置项）」并落卡终态
   （覆盖「用户嫌麻烦自己点了上传」这条真实路径，避免 AI 一直等）
⑥ 用户点「放弃」⇒ submitFrontendToolResult(cancelled=true) ⇒ FRONTEND_CANCELLED
```

- **三态回灌**（终态必属其一，不留空话）：

```
available（完成）：用户已选择文件「币种.xlsx」并交给导入向导；匹配 1 个配置项（CURRENCY），编辑区已刷新。
degraded（回退）：当前浏览器不支持在对话内直接选择文件 / 用户取消了选择。请点左侧高亮的「上传 xlsx / zip」，或把文件拖到高亮区域。
unavailable（不可用）：任务已结束，仅供查看；上传入口在只读页面不可用，本次未执行上传。
```

- **不做**：读文件内容、把文件名当数据回给模型（只回文件名，且 ≤64 字符）、任何 `path`/`filePath` 入参（Guard 拒收）。

### 3.4 `data-ai-*` 注册表规范

#### 3.4.1 区域注册契约（TS）

```ts
// frontend/src/utils/ai-regions.ts（新）
export type AiRisk = 'read' | 'mutate-local' | 'consequential'
export type AiVerb = 'click' | 'fill' | 'select' | 'scroll' | 'highlight'

export interface AiRegionOptions {
  /** 区域 id：`<pageId>.<region>`，与路由页 id 对齐（import.upload / export.conditions / tasks.list） */
  id: string
  /** 区域根元素；必须当前文档内（跨域 iframe / detached 节点直接抛错，fail-fast） */
  root: HTMLElement
  /** 区域默认风险，**必填**（缺省不允许注册 —— 最安全默认值） */
  risk: AiRisk
  /** 可选：区域级最大动词集（只能收紧，不能放宽元素级 risk 允许集） */
  verbs?: readonly AiVerb[]
  /** 可选：区域标签（进快照头行，给模型看的一句话） */
  label?: string
  /** 可选：`ui_select` 的 setter 表（key = 元素 data-ai-ref） */
  setters?: Record<string, (option: string) => boolean | Promise<boolean>>
  /** 可选：上传入口的 ref（`ui_request_upload` 缺省落点） */
  uploadEntry?: string
  /** 可选：把用户手势选中的文件交回页面既有上传逻辑 */
  receiveFile?: (file: File) => Promise<string>
}

export function registerAiRegion(options: AiRegionOptions): void      // 幂等：同 id 覆盖 + epoch+1
export function unregisterAiRegion(id: string): void                   // 卸载即注销 + epoch+1
export function listAiRegions(): readonly AiRegion[]                   // 快照遍历用
export function resolveAiRef(ref: string): { region: AiRegion; el: HTMLElement; risk: AiRisk } | null
export function currentAiEpoch(): string                               // '<nonce>-<counter>'
```

#### 3.4.2 元素声明

| 属性 | 取值 | 必填 | 语义与硬规则 |
|---|---|---|---|
| `data-ai-ref` | `<pageId>.<region>.<name>`，段字符集 `[a-z0-9-]+`；动态项用**业务键** 如 `export.defs.item.CURRENCY.toggle` | **是**（唯一的「可被看见」钥匙） | **禁止**：中文、可见文案、i18n key、序号/索引（`item-0`）、CSS 类名、时间戳/行号。**与 locale 无关**是本属性的第一性质 |
| `data-ai-risk` | `read` / `mutate-local` / `consequential` | 否（缺省继承区域 `risk`） | 元素级覆盖；`read` 的定义是**不产生服务端写**（切 tab/展开/查询刷新算 read；保存/提交/删除/发布/下载全部不算） |
| `data-ai-label` | ≤40 字符 | 否 | **给模型看的短标签，不是可见文案**；缺省推导链 `aria-label` → `title` → `textContent`（截 24 字符、空白归一）。**不参与 i18n**（切语言可变，但 `ref` 不变） |
| `data-ai-fill` | `allow` / `deny` | 否（缺省 deny） | 只有 `allow` 的输入框接受 `ui_fill`；**显式授权**是刻画「哪些框允许 AI 写」的唯一手段 |
| `data-ai-deny` | 无值（存在即生效） | 否 | **元素级硬禁用**：不进快照、任何动词都不接受（即使区域 risk=read）。用于「看起来可点、绝不能让 AI 碰」的元素（如「删除本任务」「清空全部」） |
| `data-ai-option` | 选项语义值（`MERGE` / `REPLACE`） | 否 | `ui_select` 回退路径的精确匹配锚点 |
| `data-ai-verbs` | 逗号分隔动词子集 | 否 | 元素级再收紧（只能减不能加） |
| `data-ai-undo` | `retoggle` | 否 | 声明「这个控件点两次可回到原状」（checkbox / tab / 展开），`ui_click` 才为它记撤销点 |

**内置 deny（不依赖标注，代码硬判）**：`input[type=password|file|hidden]`、`autocomplete^=cc-`、`[data-ai-deny]`、跨域 iframe 内元素、`<a download>`、`href` 指向非同源站点的元素、`element.isConnected === false`。

**fail-safe 三条默认值**（写进代码注释与工具描述）：
1. **没有 `data-ai-ref` 的元素不进快照**（不可见 = 不可操作）；
2. **区域未声明 `risk` 不允许注册**（`registerAiRegion` 抛错，fail-fast，禁止静默用默认值）；
3. **未声明 `data-ai-fill="allow"` 的输入框拒绝 `fill`**；未声明 `data-ai-option` 的选项不可被 `ui_select` 回退路径命中。

### 3.5 三道围栏判定链（顺序固定，前一道失败不再看后一道）

```
ui_* 调用
 ① 区域围栏：ref → registry 反查（ref 必须由「当前已注册区域」解析出元素）
    失败 ⇒ 拒绝「该 ref 不在当前页面（可能已切页或刷新），请重新 ui_snapshot」
 ② 上下文围栏：区域 page 必须等于 workspace.pageId；
    区域声明了 allowSteps/needsTask 时，复用 WORKSPACE_ACTIONS 的同口径判定
    （frontend-tools.ts:785-805 的三段：page / step / taskId）
    失败 ⇒ 拒绝「当前页面为 X，该控件属于 Y。请先导航到 Y 再操作」（附 ui_highlight 提示可选）
 ③ 元素围栏：内置 deny 清单 + data-ai-deny + data-ai-verbs 收紧 + isConnected + epoch 相等
    失败 ⇒ 拒绝并给唯一可行动理由
 ④ 风险分流：按 §3.6 判定该动词是否允许
```

**为什么三道都要**：①独自挡不住「同页里的危险按钮」；②独自挡不住「离开页面后旧 ref 仍被解析」；③独自挡不住「模型拿着导入页的 ref 去点导出页同名元素」。三者是**正交**的。

### 3.6 确认分级硬规则（本专项的安全性质）

| 元素 risk | `highlight` | `scroll` | `click` | `fill` | `select` |
|---|---|---|---|---|---|
| `read` | ✅ | ✅ | ✅（仅限「不发服务端写」的控件） | ❌ | ❌ |
| `mutate-local` | ✅ | ✅ | ✅（+ 高亮 + 撤销点） | ✅（需 `fill=allow`） | ✅ |
| `consequential` | ✅ | ✅ | **❌ 拒执 + 指路** | ❌ | ❌ |
| 未标 risk（区域也未给） | — | — | 不可能发生（区域注册即 fail-fast） | — | — |

**拒执文案必须点名「该用什么」**（`consequential → 注册动作` 映射表，单点常量）：

| 元素 ref 语义 | 指路动作 |
|---|---|
| 启动导出 / 预检 / 导入 / 发布 | `start_export` / `start_precheck` / `start_import` / `start_publish`（DANGER，进后端确认门） |
| 选择配置项 / 设查询条件 / 推进步骤 | `select_definitions` / `set_condition` / `confirm_step`（前端注册动作） |
| 打开导出结果编辑器 / 批量下载 | `open_export_file_editor` / `download_export_files` |
| 保存到服务端 / 删除 / 清空（无对应动作） | 「当前没有对应的注册动作，请提示用户手动完成」 |

**三条附加硬规则**：
1. **「执行后提示」式伪确认一律禁止**：consequential 的正确形态是**不执行**，不是「执行了再告诉用户」；
2. **单轮写动词配额 = 12**（`ui_click` / `ui_fill` / `ui_select` 合计；超限拒绝并要求拆轮）——防「一个 turn 里模型连发 20 个写动作，用户来不及看」，对齐调研 §3.1「批量动作要在每个 block 执行前检查」；
3. **每个写动词之间 80ms 节流**，且「AI 正在操作」条在期间可**中止**（中止 = 后续动词直接拒绝，已执行的不回滚）。

### 3.7 `ui_snapshot` 的内容与尺寸闸

快照是**新的一类上下文消耗点**，故闸门必须集中在一处（`utils/ai-dom-tools.ts` 的 `capUiSnapshot`）：

```ts
export const UI_SNAPSHOT_DEFAULT_ROWS = 20     // R3 同值（数据行口径的保守对齐）
export const UI_SNAPSHOT_MAX_ROWS = 40         // 硬顶（控件非业务行，取调研 §7.2 上界）
export const UI_SNAPSHOT_MAX_CHARS = 2000      // 硬顶，与 R3 同值，不可破
export const UI_SNAPSHOT_LINE_MAX_CHARS = 120  // 单行上限（label 截 24 / value 截 24）
export const UI_SNAPSHOT_VALUE_MAX_CHARS = 24  // 回显值的上限
export const UI_WRITE_VERBS_PER_TURN = 12      // 单轮写动词配额
export const UI_UNDO_DEPTH = 1                 // 与表格专项 SHEET_UNDO_DEPTH 同口径
```

规则（每条配断言，§5 有对应用例）：

1. **行数优先于字符数**：先按 `limit`（≤40）截，再按 2000 字符截；两者都触发时报最先触发的那个（沿用最小化调研 T-03 口径）。
2. **尾行恒在**（即便未截断）：`共 9 个元素（本次回 9 个；上限 40 行 / 2000 字符）`；截断时追加 `…[已截断：原 30 个 / 3,120 字符，已回 20 个]`。
3. **纯文本**：一行一个元素，`[ref] role "label" state[ fill=allow][ value="…"]`；禁 JSON 块、禁裸对象（对齐 R-166B「工具参数文案去 JSON 人话化」）。
4. **值回显的最小化**：只有 `data-ai-fill="allow"` 的元素才回 `value`，且 ≤24 字符（超出截断 + `…`）；`password/file/cc-*` 永无 `value`。
5. **工具描述与常量同源**：`ui_snapshot` 的 `description` 必须写死「最多 40 行 / 2000 字符」，并有单测锁死（防「描述说 20、实现 200」）。
6. **计入上下文预算**：2000 字符 ≈ 700~900 tokens（中文粗算），须在压缩专项 `reserve=13000`（`设计-上下文统计与压缩专项-2026-10-21.md:212`）里显式登记，否则换模型后预算失真。
7. **与 L1 的关系**：L1「清工具结果」会清掉旧快照文本 ⇒ 模型必须重取；`epoch` 保证「重取之后拿到的是新界面」。**不得**据旧快照断言当前值（写进工具描述）。

### 3.8 撤销（深度 1，与表格专项同口径）

| 面 | 设计 |
|---|---|
| 栈深 | **1**（`UI_UNDO_DEPTH=1`），后一次覆盖前一次 |
| 记什么 | `ui_fill` → 旧值；`ui_select` → 旧选项；`ui_click` → **仅** `data-ai-undo="retoggle"` 的元素记「再点一次」；`ui_scroll`/`ui_highlight` 不记 |
| 谁触发 | **只有用户**（对话内操作摘要行的「撤销」按钮 → `ai.undoLastUiAction()`）；**不提供 `ui_undo` 工具** |
| 为什么不给模型 | ① 工具数守住 7；② 模型改错了正确的动作是**重填**（信息更全），而不是悄悄回滚后让上下文与实际界面再次分叉；③ 撤销是「给用户的兜底」，让模型能撤销等于把「撤销」变成一条可被注入驱使的能力 |
| 与表格专项的差异 | 表格的 `undo_last_sheet_edit` 是**模型工具**：那是批级改动、模型需要知道「已回退到哪个版本」才能继续；控件面是单步、用户可见、无跨轮语义 ⇒ **口径差异，不是冲突** |
| 撤销本身 | 也写 `workspace.touch('已撤销：填写「开始日期」', 'AI')`；撤销后再撤 ⇒ 「没有可撤销的界面操作」 |
| 边界 | 只改 DOM/组件状态，**绝不**触发保存；刷新即失效（栈不持久化） |

## 7. 待裁选项（本稿新增的小裁面；已给的裁决不再列）

**裁 1 · 快照行数上界：20 还是 40**

- A（建议）：**默认 20 / 硬顶 40**，字符硬顶 2000 不动。理由：控件不是「业务数据行」，R3 的 20 行约束的是 D2 行值；2000 字符的绝对闸保证不会膨胀；40 的上界来自调研 §7.2。
- B：**一律 20**（与 R3 字面同值）。代价：控件多的页面（导入第 1 步 ≈ 9–14 个、任务中心表格行更多）需模型多带一次 `kinds` 过滤，多一轮往返。
- 影响面：仅常量与 3 个用例（T-02/T-03/T-43）。

**裁 2 · `read` 级是否包含「下载文件 / 下载模板」**

- A（建议）：**不含** —— 下载标 `consequential`。理由：下载会把数据搬出浏览器（数据出域面），且调研 §3.1 把「下载全部」列在后果性一侧；`download_export_files` 本来就是注册工具。
- B：含（把下载当只读）。代价：模型可以一句话让用户机器上多出一堆文件，且没有撤销路径。

**裁 3 · 元素级风险能否**低于**区域风险**

- A（建议）：**允许**（显式即授权），但 DEV 环境在注册时 `console.warn` 并在批⑤ 的标注审计里逐条复核。
- B：**只能升不能降**（区域风险是下限）。代价：一个包含「查询 + 保存」两种按钮的区域必须拆成两个区域，标注成本上升。
- 影响面：`resolveAiRef` 的 3 行 + T-32 的期望。

**裁 4 · 上传回退是否给 `el-upload` 加拖拽**

- A（建议）：**加**，但**视觉零变化**（`@dragover.prevent` / `@dragleave` / `@drop.prevent` 包住既有按钮行，仅拖拽悬停时显示描边）。

## 8. 风险与边界（诚实登记）

### 8.1 注入面：AI 输出驱动 DOM 会把既有口子放大一级

- **既有事实**：本仓第一注入面 = 「经工具结果与前端回灌的间接注入」（安全防护调研 §4.1）；且 `SYSTEM_PROMPT`（`ResilientChatService.java:109-138`）**没有**「内容是数据不是指令」的定界，而任务名 / 配置定义名 / 上传 xlsx 单元格 / 后端错误文案都是「外部可写 + 进上下文」。
- **本专项的影响**：攻击从「模型说错话」升级为「模型点按钮」。Anthropic 的一手数据是**缓解后仍有 11.2% 成功率**（调研 §3.4），所以不能把「加个分类器」当答案。
- **缓解（按性价比排序，本稿的取舍就是这个顺序）**：
  1. **后果性元素不可点**（§3.6）—— 最强，且是结构性而非概率性的；
  2. **区域围栏**（未注册 = 不可见）—— 把「可被注入驱使的面」压缩到开发者显式声明的那几十个控件；
  3. **高风险动作仍走注册动作 + 确认门**；
  4. **工具描述与 SYSTEM_PROMPT 的定界**（后者依赖安全防护批②）；
  5. **审计**（ref + verb + epoch 进台账，可复盘「AI 到底点了什么」）。
- **诚实边界**：如果开发者把一个「删除全部」按钮标成 `read`，上面 5 条全部失效。**标注质量是这套设计的信任根**，故批⑤ 必须有「标注审计」：把全部 `data-ai-ref` + risk 导出成一张清单人工过一遍（一次性，之后每加区域都要过）。

### 8.2 DOM 操作不是事务，撤销只 1 步

- 填错值、点错 tab、勾错框没有回滚；本稿只承诺「最近 1 步反向补丁」（`UI_UNDO_DEPTH=1`）。
- **不可逆动作在架构上被排除在原语能力之外**（consequential 拒执）⇒「不可逆」与「可撤销」在能力面上被分开——这是本方案最重要的安全性质。
- 点击引发的**页面内部逻辑**可能产生服务端调用（如 `read` 级「查询」按钮）：只读语义由**标注**保证，本稿不做事后探测（事后探测 = 又一层不可靠的判据）。

### 8.3 快照里的敏感字段

- 硬排除（不进快照）：`password` / `file` / `hidden` / `autocomplete^=cc-` / `data-ai-deny`；
- `value` 回显仅限 `fill=allow` 且 ≤24 字符；
- `label` 由「显式声明 → aria-label → title → textContent（截 24）」推导，**不拼接业务值**；
- 快照文本进 `result` ⇒ 前端帧与 Redis 台账都是全文（R4 双通道同源），**不会**因为本专项放宽任何脱敏口径。

### 8.4 快照过期与竞态

- 典型现场：模型 `ui_snapshot` → 用户手点了别处（`dataVersion` +1）→ 模型 `ui_click(ref)`。
- 处置：`epoch` 不等即拒；`isConnected===false` 即拒；**拒绝文案要求重新快照，不静默重试**（静默重试会让「点错」变成「点对」的假象）。
- `epoch` 必须含加载期 nonce（§0 第 7 条），否则刷新后「旧 epoch == 新 epoch」会放行一次**错位**点击。

### 8.5 确认疲劳

- 若每个 `fill` 都要确认，用户会无脑点「允许」，等于没有确认（业界共识）。故：**只有后果性动作要人**；本地可逆动作靠「高亮 + 撤销」；且本专项**没有新增一张「批准/拒绝」卡**（唯一的新卡是上传交接，它的「动作」是用户手势本身）。

### 8.6 提示注入的「快照污染」变体（新登记）

- 快照里回显的 `value`（用户自己填的查询条件）可能包含攻击者可控文本（例如从 xlsx 里粘过来的）。**它进的是工具结果，不是指令**；缓解同 §8.1，且 `data-ai-label` 由开发者声明 ⇒ 攻击者无法通过标签注入。登记为**已知残余**：若某页把用户数据渲染进按钮文案，label 推导链会把它带进快照（该页应在注册时显式给 `data-ai-label`）。

### 8.7 性能与可测性

- 快照只遍历注册区域（`root.querySelectorAll`），对象数 ≤ 几十，单次 ≤5ms（推断 C，须实测登记）；`kinds` 先过滤、区域次之、`limit` 最后（省得先截断后过滤导致「截断后为空」）。
- jsdom 无布局：`scrollIntoView` / `getBoundingClientRect` 在单测里为 0 ⇒ 单测只测「解析 / 围栏 / 分级 / 尺寸闸 / 撤销」，视觉交 E2E。
- `showOpenFilePicker` 在 jsdom 不存在 ⇒ 用 stub 注入做特性检测用例（T-34/T-35）。

### 8.8 能力边界（一句话）

**不承诺「AI 能操作任何控件」**；承诺「在注册区域内、对已声明元素、用受控动词、按风险分级」地操作。区域外「不可见 = 不可操作」是设计目标，不是缺陷。

## 9. 验收口径

1. **门禁**：前端 `vitest` 全绿 + `typecheck` 0 + `build` ✓ + `check-docs` 6/6 + 脱敏 0 命中；后端 `mvn test` 全绿。**基数以落盘前实跑为准**（表格稿登记 前端 512/512 · 26 文件、后端 702/702 · 112 suite —— **本稿未实跑，不得当实测引用**）。
2. **五句话走通**（实机，非单测）：
   - ①「帮我上传币种表」→ 交接卡出现 → 点「选择文件」→ 原生选择器弹出 → 选中后回灌「已上传并匹配 1 个文件」；
   - ②「导入模式改成增量」→ 单选变「增量合并」→ 摘要行「撤销」→ 回到「整体替换」；
   - ③「帮我把导出跑起来」→ **拒绝** + 「请改用注册动作 start_export」+ 确认卡路径仍可用；
   - ④「页面上现在能点什么？」→ 快照 ≤40 行 / ≤2000 字符，尾行带「共 N 个元素」；
   - ⑤「把开始日期填成 2026-01-01」→ 值生效 → `undo` 回旧值。
3. **不越权可断言**：consequential 元素点击次数恒 0；`password/file/cc-*` 在快照中零命中（种子词表负断言）；只读页所有动词零副作用；`workspace.dataVersion` 只由 `touch` 自增（`ui_scroll`/`ui_highlight` 后不变）。
4. **契约不扩**：`git diff` 上 SSE 帧类型集不变（15 种）、`POST /api/ai/frontend-tool-result` 请求体不变、`ui_event` 15 类不变。
5. **E2E**：主计数 29 → **32**；`verify-e2e.ps1` 与汇总文案同批对齐。
6. **三处注释同批订正**（否则代码与注释自相矛盾）：`stores/ai.ts:2760`「前端工具没有 HITL」、`utils/frontend-tools.ts:9-16`「2 个登记 / 7 个 FRONTEND」、`ConfirmGate.java:48-52`「只有 generative_form 无上限」。
7. **审计可复盘**：任取一轮，能从段回执 + `recentActions` 重建「模型看了什么快照、点了哪个 ref、哪个 epoch、结果如何」。
8. **标注审计（批⑤ 一次性）**：全部 `data-ai-ref` + risk 导出成清单，人工过一遍；`read` 清单尤其要逐条确认「不发服务端写」。
