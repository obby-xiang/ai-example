## 0 结论先行

**方案形态一句话**：用 JaCoCo 在本地把「每个测试类实际触达过哪些生产类」录下来形成**倒排表**（生产类 → 测试类），提交时用「**暂存树 + 未跟踪文件**」的变更集查表得到测试子集，**命中十六类兜底规则中的任一条就退回全量**；倒排表由夜间全量跑重建、选中运行增量刷新；合流级与 CI 永远跑全量。

```
录制（本地/夜间）                  选择（提交前）                        兜底（任一命中即全量）
JaCoCo agent + JUnit 扩展    →   map.json（类→测试类倒排）          →   F1–F13 规则表
  · 逐测试 + 逐类双 dump         · 输入 = staged ∪ untracked            · pom/yml/messages/迁移
  · VM 名归一（/ → .，剥 $）      · 键归一无键 ⇒ 全量                    · Spring 装配注解 ⇒ 全选 35 个上下文测试
  · 排除 mock/代理类             · 输出 includesFile（无命令行上限）     · 脚本自身变更/表不稳定/locale 面
        ↑                                                                     ↓
   夜间全量重建（保鲜 + 确定性校验）                            mvn test -Dsurefire.includesFile=<清单文件>
```

### 0.2 效率承诺（写实，不写兑现不了的数）

| 场景 | 现状 | 落地后（预期） | 依据强度 |
|---|---|---|---|
| 本地提交级后端 | 全量约 2:45（留痕 1419 例 2:20，外推 1674 例） | **15–60 s**（选中集约 12–60 个测试类 = 5%–23%） | 【推算】：扇出中位 2 类、p90 20 类【粗算】；下限 ≈ 12 类（9 个 conformance + 1–2 个上下文冒烟 + 1–2 个相关类）；上限受上下文测试被选中的比例支配 |
| 本地提交级总时长 | 约 7–8 分钟（后端双跑 5:30 + 前端 46 s + 类型检查 + build） | **约 2–3 分钟**（后端单 locale 选测 + 前端全量 46 s + typecheck + check-docs） | 【推算】 |
| 合流级 | 全量双 locale + 前端 + build + E2E | **逐字不变** | 设计约束 |
| CI（纯文档 PR） | 后端 + 前端 + E2E 全跑 | 只跑 docs + scan-history | A 期验收 |
| 风险 | — | ai/ 占 86% 测试（1447/1674）且是改动热点，落在 ai/ 高扇出类的改动会直接命中 F7/F10 ⇒ 全量，此时提交级无加速 | 设计上接受：宁可全量，不赌漏测 |

一句话：**加速来自"绝大多数改动只碰少数类"，不是来自"少跑一部分覆盖率"**；命中兜底时本方案不退化成"差不多"，而是明确退回全量并打印原因。

### 1.1 目标

| # | 目标 | 可验收的表述 |

### 1.2 非目标（明确不做，避免范围漂移）

| 不做 | 理由 |
|---|---|
| 合流级 / CI 全量改为选择集 | 用户已裁；选择集只让本地与提交更快，不减少门禁覆盖面 |
| 机器学习预测（PTS） | 无历史结果回流设施、样本量不足；冷启动等同全量 |
| 名字映射（`*Test` 与同名主类、包名匹配、`@DisplayName` 关键字） | 同名率仅 62/256 = 24%【粗算】，且漏掉跨类契约、夹具耦合、共享上下文 |
| 方法级选择 | surefire 以类为执行单位；方法级只增成本不改可跑量 |
| 为选择性测试改造成多模块 Maven / Bazel | 改造面远大于收益 |
| 前端 build / E2E 选择化 | 跨进程/打包链路，用例粒度粗 |
| 覆盖率门禁（`jacoco:check`） | 只用覆盖率做依赖观测，不引入覆盖率阈值 |
| 用"当前表重放历史提交"做验收 | 表记录的是今天的依赖，重放昨天的变更会把"今天新增的边"当成漏检，方法学错误（评审 M5） |

## 2 总体架构

### 2.1 管线（输入侧按评审 K1 改写）

```
┌─ 变更集（提交前） ────────────────────────────────────────────┐
│ A = git diff --cached --name-status --find-renames <merge-base>│  ← 暂存树（将要提交的内容）
│ B = git ls-files --others --exclude-standard                   │  ← 未跟踪（新增文件）
│ C = git diff --name-status <merge-base>                        │  ← 未暂存（可选项，见下）
│ changed = A ∪ B ∪ C   （去除非源码面：data/** 等）             │
└───────────────────────────────────────────────────────────────┘
                              ↓
┌─ 录制（夜间全量 / 本地选中运行） ─────────────────────────────┐
│ mvn -Ptestmap test -Dtestmap.enabled=true                     │
│   ├─ jacoco prepare-agent → argLine 注入 agent                │
│   └─ JUnit 扩展：逐测试 dump + 逐类 dump 合并                  │
│        VM 名归一 → 排除 mock/代理 → 写 target/testmap/raw/*.json│
└───────────────────────────────────────────────────────────────┘
                              ↓
┌─ 倒排表 map.json ─────────────────────────────────────────────┐
│ meta: {headSha, builtAt, jacoco, mode, testCount, prodCount,  │
│        deterministic: true}                                   │
│ tests: { 测试类FQN: [生产类FQN...] }                           │
│ index: { 生产类FQN: {tests:[...], blobSha:"<blob sha>"} }      │
└───────────────────────────────────────────────────────────────┘
                              ↓
┌─ 选择器 scripts/ci/select-tests.mjs ──────────────────────────┐
│ 分类 → 兜底判定（F1–F13）→ 键归一无键判定 → 倒排查表          │
│ → 并固定冒烟集/粘性失败/新增测试 → 过滤陈旧条目 → 规模封顶      │
│ 输出：includes.txt（类清单文件）+ selection/<treeSha>.json     │
└───────────────────────────────────────────────────────────────┘
                              ↓
        mvn -o test -Dsurefire.includesFile=target/selection/includes.txt
                     -Dsurefire.failIfNoSpecifiedTests=false
```

关于 C（未暂存改动）：提交级门禁跑在提交之前，正常情形是"全部已暂存"。把 C 并入是**单调放大**——多算改动只会多选测试、不会少选；同时选择器在 C 非空且命中 `backend|frontend` 源码时打印警告"有未暂存改动已计入"。若三者皆空 ⇒ 走 §3.5 的"空变更集"语义（只跑冒烟集，并明确打印"本次未跑全量"）。

### 2.2 倒排表落点：裁决项（建议落本地 + 夜间产物）

| 选项 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| 落仓（入库 `map.json`） | 任一机器开箱即用；可作评审证据 | 每次重建都产生数 MB JSON 的 diff；`docs` job 的命名纪律扫描会扫到它；多分支合并冲突 | **不采用** |
| 落本地（`backend/target/testmap/`，已被 `.gitignore` 排除） | 零仓库噪声；与构建产物同生命周期 | 换机器/清 target 后需重建（一次全量约 3 分钟 + 录制开销） | **建议** |
| 落 CI 产物（nightly artifact，本地按需下载） | 团队共享一份可信表 | 需下载步骤与权限 | 建议作为补充（B 期可选） |

### 2.3 保鲜机制（含评审 M3 的"不稳定表"处置）

| 触发 | 行为 | 过期/失效判据 |
|---|---|---|
| 夜间（或手动 `mvn -Ptestmap test`） | 全量录制，整表重建；连续重建两次做确定性比对 | 两次条目集差异 > 0 ⇒ 标 `unstable` |
| 每次选中运行（带 `-Ptestmap`） | 只更新本次跑到的测试类条目（增量写回），并刷新对应生产类的 blob sha | — |
| 提交时读表 | 表缺失 / `meta.jacoco !== 0.8.15` / `builtAt` 超过 7 天 / `meta.headSha` 与当前差 > 200 个提交 | 任一成立 ⇒ `--all` |
| 表内某生产类无键，或其 `blobSha` 与该文件当前 blob 不一致 | 该类的依赖边可能已变 | ⇒ 按无键处理，`--all`（F5） |
| 表标 `unstable` | 依赖边不稳定，选择集不可信 | ⇒ `--all`，同时该批不一致的测试类进永久冒烟集（F12） |

增量更新的意义：Ekstazi 的核心洞察是"只有被改动类触达过的测试才会改变依赖记录"，因此每次选中运行顺带刷新这批测试的条目，让表随代码演进自我修正；夜间全量是防止漂移累积的兜底。

### 2.4 兜底规则表（选择器内置，命中任一即全量）

| # | 触发条件 | 理由 |
|---|---|---|
| F1 | `backend/pom.xml`、`backend/maven-settings.xml`、任意 `pom.xml`、`.mvn/**` | 依赖与插件变化改变全仓编译/测试行为 |
| F2 | `backend/src/main/resources/**`（`application*.yml`、`messages_zh/en.properties`、`db/migration/*.sql`、`ai/**`） | 配置默认值、i18n、表结构横切全仓 |
| F3 | `backend/src/test/resources/**`（该目录当前不存在，规则预留） | 测试公共输入 |
| F4 | `docs/kb-samples/**` | 构建期被拷进 `classes/kb-samples` 作首启播种源（`backend/pom.xml:129-150`） |
| F5 | 变更含**新增/删除**的生产类；或某类无键；或该类 `blobSha` 与当前不一致 | 无覆盖历史 / 依赖边可能已变 |
| F6 | `backend/src/test/**` 下**非** `*Test.java` 的改动（夹具、基类、Helper） | 夹具耦合不在生产类倒排里 |
| F7 | 某变更类在表内的测试类数 > 50 | 已接近半仓，硬跑更便宜（当前 8 个类在此档：`AiProperties` 123、`RunRegistry`/`CancellationRegistry` 69、`SseChatEmitter`/`PendingToolCall` 64、`RunStore` 59、`ConfirmGate` 54、`RunSnapshot` 52）【粗算】 |
| **F10** | 变更触达带装配语义的类：`@Configuration`、`@Component`、`@Service`、`@Repository`、`@ConditionalOn*`、`@ConfigurationProperties`（按注解或类名后缀 + 所在包判定） | **Spring 上下文缓存陷阱**：上下文只建一次，装配代码只会记在"首个建该上下文的测试类"头上；surefire 默认 `runOrder=filesystem` 又不保证哪个类先跑 ⇒ 覆盖率表对装配边的归属是**偶然的**。故这类改动直接全选 35 个 `@SpringBootTest` |
| F11 | `scripts/ci/select-tests.mjs`、`scripts/ci/gate.mjs`、`scripts/ci/testmap/**`、录制扩展源码、`.github/workflows/**` | 选择器或门禁自身变了，旧表与旧规则的自洽性不可信 ⇒ 全量 + 重建表 |
| F12 | 表标 `unstable`（同 headSha 两次录制条目集不一致） | 依赖边不确定 ⇒ 全量，并把差异测试类钉进永久冒烟集 |
| F13 | locale/时区敏感面变更：`messages_*.properties`、`frontend/src/locales/**`、`**/TimeZone*`、`**/Locale*`、以及上面 F2 的 `application*.yml` | 本仓有 2 个测试类全局 `Locale.setDefault`（`AiControllerErrorBodyLocaleTest`、`GlobalExceptionHandlerTest`）【实测】，跨日/时区断言在单 locale 下不成立；此类改动在**合流级强制 en-US 全量**（提交级仍按选择集，但打印提示） |
| F8 | 兜底判定与冒烟集合并后选中结果**仍为空** | 空集是异常信号 |
| F9 | ~~命令行超长~~ → 由 `includesFile` 取代（评审 M8） | 清单文件不受命令行长度限制，本规则取消 |

**已核验不适用的漏测面**（评审 M3 要求写明）：JNI（`native` 方法）、`ServiceLoader` SPI、Java 序列化（`Serializable`/`ObjectInputStream`）在本仓 `backend/src/main` **0 命中**【实测】；Spring 的反射装配与 Mockito 运行时代理不构成"独立依赖边"，前者由 F10 覆盖、后者由 §3.2 的排除规则处理。

### 2.5 审计产物（评审 M1）

每次选择落两个文件：

```json
// backend/target/testmap/selection/<treeSha>.json   ← 用暂存树的 id 命名（git write-tree）
{
  "treeSha": "<SHA>",                         // 提交后可用 git rev-parse <commit>^{tree} 反查
  "base": "<merge-base sha>",
  "changedCount": 3,
  "changed": ["backend/src/main/java/com/example/configmgr/ai/run/ResumeService.java"],
  "rulesHit": ["F10"],                       // 空数组 = 按倒排查表
  "selected": ["com.example.configmgr.ai.run.ResumeServiceTest"],
  "smoke": ["com.example.configmgr.ai.conformance.FrameTypeSetFrozenTest"],
  "tableSha256": "<sha256>",
  "fallback": null                            // 或 "F7"
}
```

用暂存树 id 而不是 `HEAD` 命名，是因为提交级门禁跑在提交之前：`HEAD` 还是父提交，同一个 `HEAD` 下可以有多笔不同的提交；`git write-tree` 的输出随暂存内容变化，是"这次将要提交的内容"的唯一身份。

提交信息附一行摘要，例如：`门禁: 后端选测 23/256 类（表 8f2c1a9，F10 未命中）`。这一行同时是"事后可追"的唯一凭据——没有它，跨周无法回答"当时为什么没跑某个测试"。

## 3 后端方案（Maven + JUnit 5 + JaCoCo 逐测试倒排）

### 3.1 依赖与插件（profile 隔离，正常构建零变化）

- 插件：`org.jacoco:jacoco-maven-plugin:0.8.15`（`prepare-agent`）。版本必须自行钉——Spring Boot 父 POM **不管理** JaCoCo（实测 `spring-boot-starter-parent-3.5.14.pom` 内 jacoco 字样 0 命中）。**钉 0.8.15 而非 0.8.16**：0.8.16 目前只有 snapshot（`0.8.16.202610190836`，2026-10-19）<https://www.jacoco.org/jacoco/trunk/doc/changes.html>；0.8.15（2026-06-04）正式发布且官方支持到 Java 26，本仓 Java 21 在支持面内。
- 测试作用域依赖：`org.jacoco:org.jacoco.agent:0.8.15:runtime`（`RT.getAgent()`）与 `org.jacoco:org.jacoco.core:0.8.15`（`ExecutionDataReader`）。
- 隔离：以上全部写在 `<profile><id>testmap</id>` 内，扩展只在 `-Dtestmap.enabled=true` 时激活。不加 profile 时 pom 行为、`argLine`、依赖树逐项不变。
- profile 内固定 `forkCount=1`、`reuseForks=true`、`runOrder=alphabetical`（仅录制期；排序只为让同一 headSha 的两次录制可比，**不承担正确性**——正确性由 F10/F12 兜）。

离线约束（实测）：本机 `~/.m2` 无任何 `org/jacoco` 目录，而 `backend/pom.xml:24-26` 明示"之后构建保持 `mvn -o`"。B 期第一步是一次性联网拉 3 个构件或由离线仓预置，属依赖合规动作（开放点 O5）。

### 3.2 录制：范围、归并与归一（评审 K2/M2/M4/m3）

三层判定，缺一不可：

| 层次 | 规则 | 防的是什么 |
|---|---|---|
| **依赖定义** | **出现在 execution data 里的类即算依赖**（不要求探测点非全零）；另存 `hit` 标记只用于统计与排障 | 只用"命中"会漏掉"只加载不执行"的类：静态初始化、`@Configuration` 解析、SPI 装配、反射查找目标类（评审 M2） |
| **名称归一** | `getName()` 返回 **VM 名**（`com/example/Foo`），嵌套类是 `Outer$Inner`：① `replace('/','.')`；② 反复剥尾部 `$…` 归到最外类（`Outer$Inner$1` → `Outer`）；③ 同时保留原始名作第二键（仅用于排障，不参与选择） | 不归一则 `com/example/Foo` 与 `git ls-files` 推出的 `com.example.Foo` 永不相等，整张表失效（评审 K2） |
| **合成类排除** | 丢弃名称含 `$MockitoMock$`、`$ByteBuddy$`、`$$EnhancerBySpringCGLIB$$`、`$Proxy` 的类；只保留 `com.example.configmgr` 前缀 | 运行时代理会把"测试自己的桩"记成生产依赖，导致表随 mock 波动（评审 m3） |

**自测闸（fail-fast）**：录制器收尾时计算「归一后键集 ∩ `git ls-files 'backend/src/main/java/**/*.java'` 推出的 FQN 集 / 后者」，若 < 95% 直接让构建失败并打印差集样本。宁可当场红，不要带着半张表静默运行。

**异步污染（评审 M4）**：本仓约 46 个测试文件使用异步原语（评审口径；本次按 `CompletableFuture|CountDownLatch|Thread.sleep|await(|ExecutorService|Thread(` 更宽模式粗扫为 54 个，量级一致），而 JaCoCo 探针**没有线程归属**——异步回调可能在测试结束后才执行，把它的触达记到"下一个测试类"头上。三重处置：

1. **双 dump**：`afterTestExecution` 先取一次快照（不 reset），`afterAll` 再取一次并 `reset`，两者合并后归给当前类；这样"迟到但还没越过类边界"的执行不会丢。
2. **收尾窗口**：JVM 关闭钩子再 dump 一次，把最后一个类之后才完成的异步触达并入"最后一个测试类"（宁可多归，不可丢失）。
3. **确定性校验**：同 headSha 连录两次，条目集必须完全一致；不一致的测试类标 `unstable` 进永久冒烟集（F12）。这条同时是上面两条是否奏效的度量。

### 3.3 扩展形态

```java
// backend/src/test/java/com/example/configmgr/testmap/PerTestCoverageExtension.java
// 经 META-INF/services/org.junit.jupiter.api.extension.Extension 自动注册（不改 256 个测试类）
public final class PerTestCoverageExtension
        implements AfterTestExecutionCallback, AfterAllCallback, TestWatcher {

    // 仅当 -Dtestmap.enabled=true 时激活；否则全部空实现
    // 静态：Map<String testClassFqn, Set<String>> CACHE；Map<String, Boolean> HIT
    // afterTestExecution : snapshot(noReset) → 归并到当前测试类（含异步已回写部分）
    // AfterAll           : snapshot(reset=true) → 归并 → 清空；记录 testFailed
    // shutdown hook      : 最后一次 snapshot 并入最后一个类 → 写 raw/<pid>.json
    //
    // snapshot(bool reset):
    //   byte[] data = RT.getAgent().getExecutionData(reset);
    //   ExecutionDataStore store = new ExecutionDataStore();
    //   ExecutionDataReader r = new ExecutionDataReader(new ByteArrayInputStream(data));
    //   r.setExecutionDataVisitor(store);
    //   r.read();
    //   store.getContents()                       // 每个 ExecutionData 自带 id + VM 名
    //        .stream().map(ExecutionData::getName)
    //        .filter(n -> n.startsWith("com/example/configmgr"))
    //        .filter(n -> !isSyntheticProxy(n))  // $MockitoMock$ / $ByteBuddy$ / $$EnhancerBySpringCGLIB$$ / $Proxy
    //        .map(PerTestCoverageExtension::normalize)   // / → . ，反复剥 $… 归最外类
    //        .forEach(c -> CACHE.get(testClass).add(c));
}
```

四个实现要点：

1. **粒度取测试类而非方法**：surefire 只能按类跑，方法级只让表变大。参数化测试（6 个文件用 `@ParameterizedTest`）自然并入类条目。
2. **dump 点取类边界 + 测试结束双点**：`afterTestExecution` 取增量、`AfterAll` 取余量并 reset。256 次 reset 而不是 1674 次，IO 与解析成本低一个量级；代价是依赖"类内连续执行"，一旦开 `parallel` 就必须改为每线程独立 agent（属新问题）。
3. **并发与顺序前提**：profile 固定 `forkCount=1`、`reuseForks=true`、不开 `parallel`。
4. **失败也落盘**：`AfterAll` 用 `try/finally` 保证 dump；某次 dump 抛错 ⇒ 该类记"无数据" ⇒ 进冒烟集（宁多跑）。

### 3.4 表格式与规模（含评审 m2/m7）

```json
{
  "meta": {
    "builtAt": "2026-10-23T23:10:04+08:00",
    "headSha": "<SHA>",
    "jacoco": "0.8.15",
    "mode": "full",
    "deterministic": true,
    "testClassCount": 256,
    "prodClassCount": 252
  },
  "tests": { "com.example.configmgr.ai.run.ResumeServiceTest": ["com.example.configmgr.ai.run.ResumeService", "..."] },
  "index": { "com.example.configmgr.ai.run.ResumeService": { "tests": ["com.example.configmgr.ai.run.ResumeServiceTest"], "blobSha": "<blob sha>" } }
}
```

- `blobSha` = 录制时 `git rev-parse HEAD:<path>` 的结果；选择器比对时取**索引里的 blob**（`git rev-parse :<path>`，即暂存内容）与表内值，不一致即按 F5 全量（评审 m2）。用索引而不是工作树，是因为提交级门禁跑在"已暂存"的语义上；这同时覆盖了"工作树还有未暂存改动"的情形（那条路径由 §2.1 的 C 单调放大兜底）。
- `deterministic` 由两次重建比对得出（F12）。
- 规模估算：1674 个测试 × 平均 8–20 个生产类 ≈ 1.5–3 万对，JSON 约 1–3 MB、gzip 200–400 KB（估算，B 期实测替换）。

### 3.5 选择器的处理流程（评审 K1/K4/M8/m5）

```js
// scripts/ci/select-tests.mjs --base <merge-base> --map backend/target/testmap/map.json \
//   --out backend/target/selection/includes.txt [--all]
staged    = git("diff --cached --name-status --find-renames " + base)   // 暂存树
untracked = git("ls-files --others --exclude-standard")                 // 新增文件
unstaged  = git("diff --name-status " + base)                           // 单调放大，可关
changed   = union(staged, untracked, unstaged).filter(isSourceRelevant) // 排除 data/** 等运行时产物

if (hitFallback(changed)) return all(reason)        // F1–F7、F10–F13（F8 在末尾）
if (!map || isStale(map) || map.meta.deterministic === false) return all("表过期/不稳定")

classes = changed.filter(isMainJava).map(toFqn)
for (c of classes) {
  if (!map.index[c]) return all("F5 无键：" + c)
  if (map.index[c].blobSha !== indexBlobSha(c)) return all("F5 blob 变更：" + c)   // git rev-parse :<path>
}
tests = union(classes.map(c => map.index[c].tests))
tests ∪= ALWAYS_RUN                                // §3.6
tests ∪= changed.filter(isTestJava).map(toFqn)     // 新增/改动的测试必跑（K1）
tests ∪= stickyFailed                              // 7 天窗口内的失败集（m6）
tests  = tests.filter(existsInIndex)               // K4：过滤磁盘/索引里已不存在的陈旧条目，并列出被剔除者
if (tests.length === 0) return all("F8 兜底与冒烟后仍为空")
if (tests.length > 0.6 * map.meta.testClassCount) return all("选中 > 60%")
writeIncludesFile(tests)                            // 一行一个 FQN（M8，无命令行上限）
return { tests, fallback: null, reasons: [...] }
```

规则顺序有意如此：**兜底判定先于查表**，任何"不确定"在查表之前就退化成全量。三个细节按评审固定：

- **K1**：`isSourceRelevant` 先剔除 `data/**`（仓库根 27 个未跟踪运行时文件，实测）、`*.log`、`backend/target/**` 等；不剔除会把"本地跑过的东西"当成源码改动，直接触发全量。
- **K4**：`existsInIndex` 用 `git ls-files` 的测试类集合判断（索引口径，与"将要提交的内容"一致），缺文件说明表里有陈旧条目（测试被删/改名），剔除并在输出里列出来；`-Dsurefire.failIfNoSpecifiedTests=false` 是第二道保险。
- **M8**：输出改成 `includesFile` 清单文件（`-Dsurefire.includesFile`，surefire 2.13 起提供），彻底没有命令行长度退路。

**空变更集语义（m5）**：`changed` 为空 ⇒ 只跑固定冒烟集，并在输出里明确打印"未跑全量（变更集为空）"；F8 收窄为"兜底判定 + 冒烟集合并后仍为空"。

### 3.6 固定冒烟集（不参与倒排博弈，评审 m1）

| 集合 | 内容 | 理由 |
|---|---|---|
| 帧契约 | `ai/conformance/` 下的全部 9 个测试类：`CancelLedgerConformanceTest`、`ChatTurnFrameSequenceConformanceTest`、`FrameContractFalsificationTest`、`FrameTypeSetFrozenTest`、`ReattachLastSeqConformanceTest`、`SessionBusyFrameIsolationConformanceTest`、`SseFrameSequenceConformanceTest`、`ThreeArgAssemblyConformanceTest`、`ToolFrameSequenceConformanceTest`（**用目录 glob 生成，不手抄清单**，避免新增契约测试被漏） | 跨类契约断言无法从"改了哪个类"推出 |
| 上下文装配 | 1–2 个 `@SpringBootTest`（如 `AiConfigUnavailableSpringTest`） | F10 之外的兜底；上下文测试通常也会被自然选中 |
| 粘性失败 | 最近 **7 天**内失败过的测试类（`target/selection/last-failures.json`，按时间窗过期，评审 m6） | 对应 Develocity"永远选最近失败的测试" |
| 新增测试 | 无倒排数据的测试类（含本次新增的 `*Test.java`） | "没记录就一律跑" |
| 不稳定类 | F12 判定的 `unstable` 测试类 | 依赖边不可信 ⇒ 永久常跑 |

### 3.7 Spring 上下文测试的处理（评审 K3 + 本仓最大成本项）

实测结构：35 个 `@SpringBootTest` 类 / 236 例；留痕那一跑里 30 个此类类占 54.4 s / 136.2 s = **40%**【留痕】。而 Spring `TestContext` 框架**按配置缓存上下文**：一套上下文只建一次，装配阶段加载/初始化的类只会被"第一个触发该上下文的测试类"记录到，后续复用上下文的测试类在覆盖率上几乎看不到这些类。加上 surefire 默认 `runOrder=filesystem` 不保证顺序，"装配边记在谁头上"是偶然的。

因此本方案不依赖"装配边被正确归属"，而是用 **F10** 直接覆盖：变更触达 `@Configuration`/`@Component`/`@Service`/`@Repository`/`@ConditionalOn*`/`@ConfigurationProperties` 的类 ⇒ 全选 35 个上下文测试。`runOrder=alphabetical` 只让录制可复现，不承担正确性。

两条后续选择（B 期实测后二选一）：

| 做法 | 说明 | 何时用 |
|---|---|---|
| 顺其自然 | 上下文测试随倒排 + F10 被选中 | 默认 |
| 上下文降档 | 把"完整上下文测试"从选择集剔除，只留 1–2 个冒烟类；完整上下文测试只跑合流级与夜间 | 仅当 B 期实测"上下文集 > 60% 时间"且提交级仍超 3 分钟（O6） |

**不建议**在提交级彻底不跑上下文测试：Bean 装配错误是全仓最贵的一类缺陷，且不体现在单元测试覆盖率里。

### 3.8 失败与异常的默认行为

| 异常 | 行为 |
|---|---|
| map 不存在 / JSON 解析失败 / `deterministic=false` | `--all`，原因 `map-missing` / `map-invalid` / `map-unstable` |
| 变更集为空 | 只跑冒烟集，打印"未跑全量（变更集为空）" |
| 某测试类无条目 / 磁盘上已不存在 | 前者进冒烟集；后者从选中集剔除并列出（K4） |
| `-Dtest` 与 includesFile 均找不到类 | `-Dsurefire.failIfNoSpecifiedTests=false` 兜底；选择器列出未解析名 |
| 录制时 `RT.getAgent()` 抛异常 | 整表不生成；选择器退化为 `--all`，日志写明"录制不可用" |
| 归一后键集与源码 FQN 集重合 < 95% | **录制即失败**（fail-fast，K2 自测闸） |

## 5 CI 与本地门禁集成

### 5.1 三层形态

| 层 | 触发 | 跑什么 | 目标时长 |
|---|---|---|---|
| L1 提交级（本地，提交官） | 每笔提交 | 后端选择集 + 冒烟集（默认 locale）；前端全量；`vue-tsc`；`check-docs`；i18n 残留 | 约 2–3 min |
| L2 合流级（本地，入库前） | 合流/合并 | **与今天逐字相同**：后端全量双 locale、前端全量、typecheck、build、check-docs、必要 E2E；F13 命中时强制 en-US | 现状 |
| L3 CI（PR / push main） | PR 与 main | A 期后按变更集决定跑哪些 job；**被选中跑的后端/前端 job 仍是全量** | 现状 |

关键点：**CI 不使用选择器**。CI 全量是 L1 选择集的兜底——本地漏掉的在 PR 上仍会被全量抓住。

L1 的具体命令（评审 K1/M1/M8 落位）：

```bash
BASE=$(git merge-base origin/main HEAD)
TREE=$(git write-tree)          # 暂存树 id：提交前唯一标识"将要提交的内容"

# 1) 算选择集：staged ∪ untracked ∪ unstaged（后者单调放大），输出 includes 清单 + 审计 json
node scripts/ci/select-tests.mjs \
  --base "$BASE" \
  --map backend/target/testmap/map.json \
  --out backend/target/selection/includes.txt \
  --audit "backend/target/testmap/selection/${TREE}.json"

# 2) 后端：有清单按清单跑；选择器判 --all 时清单只含一行 ALL
if grep -qx 'ALL' backend/target/selection/includes.txt; then
  (cd backend && mvn -o test)
else
  (cd backend && mvn -o test \
     -Dsurefire.includesFile=target/selection/includes.txt \
     -Dsurefire.failIfNoSpecifiedTests=false)
fi

# 3) 前端与静态门禁：全量
(cd frontend && yarn test && yarn typecheck)
node scripts/ci/check-docs.mjs
```

注意：提交级用的是**暂存树**，因此选择器必须在 `git add` 之后运行；若工作树有未暂存改动，选择器会并入（放大）并打印警告。

### 5.2 A 期：CI 按变更集跳 job（评审 M7）

- 新增 `changes` job；给 `backend` / `frontend` / `e2e` 加 `if:`；`docs` 与 `scan-history` 保持无条件。
- **diff 基准按事件区分**：`pull_request` 用 `github.event.pull_request.base.sha`；`push` 用 **`github.event.before`**（推送前一个提交）。`before` 为全零串（新分支/强制推送）时退回 `git merge-base` 或直接全跑——这条不写，push 到 main 时基准会算错，进而跳过本该跑的 job。
- **`e2e` 的 `if` 用 `!cancelled()` 而不是 `always()`**：`if: ${{ !cancelled() && needs.changes.outputs.e2e == 'true' }}`。官方明确推荐用 `!cancelled()` 替代 `always()` 做"无论如何都要跑"的作业，同时它能避免 backend 变红后 e2e 白跑 25 分钟<https://docs.github.com/en/actions/reference/evaluate-expressions-in-workflows-and-actions>。
- 耦合项同前：`docs/kb-samples/**` → 后端；`frontend/src/locales/**` → 前端；`pom.xml`/`package.json`/`yarn.lock`/`vite.config.ts`/`vitest.config.ts`/`tsconfig*.json` → 对应侧；`.github/workflows/**`、`scripts/**` → 全部。

### 5.3 GitHub required checks：真实风险是"假绿"（评审 M7 修正）

官方口径：**被 `if` 跳过（job 级 skip）的作业会把自己的状态报成 `Success`，即使它是必需检查，也不会阻止合并**<https://docs.github.com/en/pull-requests/reference/status-checks>。所以风险不是"PR 卡住"，而是**"该跑没跑却报绿"**——这比卡住危险得多，因为它会静默放行。

| 风险 | 表现 | 处理 |
|---|---|---|
| 假绿 | 必需检查被跳过 ⇒ 报 Success ⇒ 合并被放行 | 只把**永远会跑**的作业设为 required（`docs` + 一个汇总 job）；`backend`/`frontend`/`e2e` 不作为 required |
| 汇总 job 自欺 | 上游 skipped 时汇总若只写 `success()` 就变成"永远绿" | 汇总 job 用 `if: ${{ !cancelled() }}` + 显式读取 `needs.*.result`，把 `success/failure/skipped` 三类都写进 summary；skipped 必须打印"因变更集不相关而跳过" |
| 变更集输出丢失 | 汇总时拿到空字符串，误判为"无改动" | 汇总 job **断言** `needs.changes.outputs` 非空；归档 `changes` 的命中规则与文件清单 artifact |
| 路径过滤 vs 条件跳过 | workflow 级 `paths` 过滤会让检查停在 Pending（另一种坑） | 本方案只用 **job 级 `if`**，不启用 workflow 级 `paths`/`paths-ignore` |

## 6 风险与对冲

### 6.1 六类关联（评审新增异步面），逐条给机制

| 关联类型 | 覆盖率倒排能否覆盖 | 本方案的对冲 |
|---|---|---|
| 间接覆盖（改 A，测 B 因 A 的副作用红） | **能**——倒排记录"实际执行过的类" | 这就是选覆盖率而非静态分析的理由 |
| 共享 Spring 上下文（改 Bean 定义） | **不可靠**——上下文缓存让装配边只落在首个测试类，且顺序不定 | **F10**：装配注解类改动 ⇒ 全选 35 个上下文测试；`runOrder=alphabetical` 仅保可复现 |
| 跨类契约断言（帧类型集/帧序） | **不能** | `ai/conformance/` 9 个类进冒烟集（目录 glob，新增自动纳入） |
| 共享状态面（静态单例、Redis 键族、H2 数据） | **部分不能**——覆盖率看不到"状态" | 粘性失败（7 天窗）+ 夜间全量 + 合流级全量 + flake 重试（§6.3） |
| 夹具耦合（改 `AiConfigTestFixture`） | **不能**——夹具不在生产类倒排里 | **F6**：`backend/src/test/**` 下非 `*Test.java` ⇒ 全量 |
| 异步污染（回调在测试结束后触达） | **部分不能**——探针无线程归属 | 双 dump + JVM 收尾窗口 + F12 确定性校验；条目不稳即进永久冒烟集 |

### 6.2 倒排表腐化

| 腐化形态 | 症状 | 对冲 |
|---|---|---|
| 表过期 | 选中集偏小 | 7 天 / 200 提交双重判据；夜间重建；选中运行增量刷新 |
| 改了类但依赖边变了 | 改 A 后 B 红却未选中 | **`blobSha` 比对**：类文件 blob 变了就按无键走 F5 |
| 名称不归一（VM 名/嵌套类） | 整张表匹配不上 | `/`→`.` + 剥 `$`；录制期 95% 自测闸 fail-fast |
| 表不稳定（异步/顺序敏感） | 同 headSha 两次结果不同，选择随机 | F12：标 `unstable` ⇒ 全量 + 该类永久冒烟 |
| 表被手工改/损坏 | 行为不可解释 | 表只由录制器写；选择器校验 `meta` 与 `tableSha256` |
| 表缺失 | 首次体验差 | 缺表即全量，并提示 `mvn -Ptestmap test` 重建 |

### 6.3 flake 与选择集的交互

| 现象 | 影响 | 处理 |
|---|---|---|
| 选择集跑得少 ⇒ 遇 flake 机会少 | flake 更难被发现 | 夜间全量是唯一稳定的 flake 发现面 |
| 选中集混入已知 flaky 测试 | 无关变更被误判为红 | `known-flaky` 清单（仓内有 L-19 类历史）跑 1 次重试，重试仍红才算红 |
| 粘性失败长期粘住 | 选择集膨胀 | 粘性集改为 **7 天时间窗**（评审 m6），过期自动退出；超 20 个类打印警告 |

### 6.4 其他风险

| 风险 | 对冲 |
|---|---|
| 逐测试 reset 在并行/多 fork 下失效 | profile 固定 `forkCount=1`、不开 parallel；文档写明"改并行即失效" |
| 录制开销未知 | B 期第一道验收"录制全量 ≤ 2× 基线"；超了先优化（按类聚合后立即丢原始数据） |
| 选择器自身是新代码（RTSCHECK 曾在三个 RTS 工具查出 27 个 bug） | 选择器只"减少跑的量"，不"决定是否合流"；合流级全量是硬保险；F11 禁止用它评自己 |
| 依赖引入（离线构建） | 一次性拉取或预置离线仓；钉 0.8.15（0.8.16 仅 snapshot） |
| `includesFile` 参数名/版本 | 用 `-Dsurefire.includesFile`（surefire 2.13 起）；本仓解析到 3.5.5，支持 |

## 7 分期与验收

### 7.1 A 期：CI 按变更集跳 job（0.5–1 人日）

- 改动面：`.github/workflows/ci.yml`（`changes` job + 3 个 `if` + `e2e` 的 `!cancelled()` + 汇总 job）；可选 `scripts/ci/changed-files.mjs`（零依赖）。
- 验收：
  1. 纯 `docs/**` 的 PR：`backend`/`frontend`/`e2e` skipped，`docs`/`scan-history` 绿，且**汇总 job 明确写出"skipped 及原因"**（防假绿）；
  2. 任意 `backend/src/**` 改动的 PR：`backend` 与 `e2e` 均执行；
  3. `push` 到 main 时用 `github.event.before` 作基准；新分支（before 全零）时全跑；
  4. 一次"backend 必红"的演练：`e2e` 因 `!cancelled()` + 条件不满足而不启动（不白跑 25 分钟），汇总 job 报红。

### 7.2 B 期：后端倒排 + 选择器（3–5 人日，**只用于本地提交级**）

- 改动面：`backend/pom.xml` 的 `<profile>testmap</profile>`；`backend/src/test/java/.../testmap/` 扩展与录制器（约 250 行）+ `META-INF/services`；`scripts/ci/select-tests.mjs`（约 300 行，零第三方依赖）；选择器纯函数部分的 Node 单测。
- 验收：

| # | 判据 | 阈值 |
|---|---|---|
| B0 | **键归一自测**（K2） | 归一后键集与 `git ls-files` FQN 集重合 ≥ 95%，否则构建失败 |
| B1 | 录制全量耗时 | ≤ 2 × 基线（基线约 2:45 ⇒ ≤ 5:30）【推算基线】 |
| B2 | 倒排覆盖 | 有非空条目的测试类 ≥ 95%；无条目者自动进冒烟集 |
| B3 | 选择器耗时 | ≤ 2 s（3 万对规模纯 JSON 查表） |
| B4 | 选择集规模 | 典型单类改动选中类中位数 ≤ 25%、p90 ≤ 50%（命中 F7/F10 的全量不计） |
| B5 | **结构性缺陷注入**（M5） | 6 类各 ≥1 例，**选择集必须变红**；不变红即判选择器 bug（见下） |
| B6 | 兜底正确 | F1–F13 逐条构造 1 例，全部退化为全量且原因正确 |
| B7 | 确定性（m3） | 同一版本（同 tree）连录两次，条目集差异 = 0 |
| B8 | 合流级不变 | L2 命令逐字相同，双 locale 全量仍绿 |

**B5 的六类注入**（替换原先"重放历史提交"的错误方法学，评审 M5）：

| # | 注入方式 | 命中的漏测面 |
|---|---|---|
| 1 | 把某个被反射调用的方法**改名**（保留旧名调用点不动） | 反射/只加载不执行（M2） |
| 2 | 改 `application.yml` 的某个**默认值**（如超时/批大小） | 配置横切（F2） |
| 3 | **新增一个 `@Configuration`** 并在其中装配一个新 Bean | 上下文缓存归属（K3/F10） |
| 4 | 改 `messages_zh.properties` 的某个 **key 名** | i18n 面（F13） |
| 5 | 让某个测试**留下 Redis 键/静态状态**，让后续测试依赖它 | 共享状态面 |
| 6 | 断言**跨日/时区**（把 `Clock`/`ZoneId` 边界推到日界） | 时区面（F13） |

每条注入都要求：选择集必须红；若选择集绿而全量红，记为该类缺陷的选择器 bug，修兜底规则后重跑。**阈值（M6）**：30 例注入中不允许连续 2 例同类漏——这是"自检"，不是上线门槛。

### 7.3 C 期：前端 related + 两级门禁 + 夜间兜底（1–2 人日）

- 改动面：`frontend/package.json` 增 `test:related`；`scripts/ci/gate.mjs` 做 `--tier commit|merge`；夜间 workflow（若采纳 O2）；影子模式开关（选择集与全量同跑）。
- 验收：
  1. 提交级端到端 ≤ 3 min：后端 ≤ 90 s（降档后 ≤ 60 s）、前端 ≤ 60 s；命令用 §5.1 的 staged 基准；
  2. 合流级输出与今天逐项一致（含 F13 的强制 en-US）；
  3. **影子期（正式门槛，M6）**：2 周约 **380 笔**提交，选择集与全量同跑（只多 **1–1.5 分钟**），判据 = **漏检 ≤ 1 笔 / 300 笔**；每一笔漏必须给出根因归类（反射/夹具/状态/时区/超限/其他），并**回填**到兜底规则或冒烟集，回填后重新起算窗口；
  4. 夜间全量连续 14 天成功，倒排表重建 ≥ 10 次且 `deterministic` 全部为 true。

影子期为什么只多 1–1.5 分钟：选择集先跑（约 25–60 s），再跑全量（约 2:45），两者串行；这份成本只持续两周，换来"漏检率"这个唯一能证明选择器可信的数字。

### 7.4 依赖关系

- A 期与 B/C 互不阻塞（A 改 workflow，B/C 改 pom 与脚本）。
- B 期必须先于 C 期的两级门禁（C 的提交级复用 B 的选择器）；C 期的前端部分可先做。

|---|---|---|---|
| O1 | 倒排表落仓还是落本地 | **落本地** + 夜间 artifact 可选；不落仓（数 MB diff + 命名扫描噪声） | §2.2 |
