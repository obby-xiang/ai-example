## 根因

`registerPageHandler('export.setConditions')` 的第一个失败分支返回**字符串**：

```ts
if (!defCode) {
  return '缺少 defCode，未设置条件'      // ← 字符串
}
```

`runPageHandler` 用 `interpretHandlerOutcome` 解读：**字符串 = 成功 + 该文本**（兼容旧执行器的
既定语义）。于是缺 `defCode` 的调用被落成 `outcome: 'ok'`，工具卡显示成功、模型收到成功语义，
而实际上一个字节都没写 —— 与后续 R2–R5 建立的"参数错误必须结构化失败"口径相反。

## 修改

### `frontend/src/views/ExportWizardView.vue`

```ts
if (!defCode) {
  // R6：必须结构化失败 —— 字符串会被 interpretHandlerOutcome 当成功，缺参变成假成功
  return { ok: false, reason: '缺少 defCode，未设置条件（未落库、未改动页面条件）' }
}
```

该分支仍在 `isReadOnly` 检查之后、`conditions` 校验与任何 `draftModels` / `touchedConditions` /
`tasksApi.setCondition` / 工作区写入之前 ⇒ **零写不变**。

### 注释/契约同步

- `frontend/src/utils/frontend-tools.ts` 的 RC-3 参数要求表注释：删除已过时的"原文示范
  `缺少 defCode 或 conditions.fields`"引用，补一条硬约束 —— **页面 handler 的参数错误必须返回
  结构化 `{ ok:false, reason }`**，字符串会被当成功。
- `interpretHandlerOutcome` 文档：注明"字符串兼容解读只用于**已执行后的事实陈述**；参数错误 /
  确定性失败必须结构化"。
