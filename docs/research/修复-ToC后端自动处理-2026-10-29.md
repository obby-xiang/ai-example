## 一、规格口径（本版唯一口径）

1. **用户可见产出 = 正文任一字符 + 已上屏的思考帧。** 隐藏思考（`app.ai.reasoning.display-enabled=false`）
   只进记忆、不上屏，**不计入**可见产出：
   - 普通自动重试、空回复仅模型步一次重试、`retry-model-step` 重跑都不得被它阻断；
   - 零可见产出时失败码不得附带 `_AFTER_PARTIAL`；
   - 可见正文 / 已上屏思考仍一律不得重试（派生码照旧 `_AFTER_PARTIAL`；帧序不得让 `retry` 落在
     reasoning delta 之后）。
2. **页面选中集三态（`ContextBuilder` 与 `TaskSlotResolver` 同一口径）**：
   - `null` = 未同步：无 `selectedDefs` 键、不在 `export`/`import` 向导页、或 `selectionSynced != true`
     （任务详情未水合 / 旧客户端）⇒ 允许回落任务条目/历史；
   - **空列表 + `selectionSynced=true` = 权威空值**（详情已应用、用户取消全部勾选）⇒ 不得回落历史；
   - 非空列表 = 页面权威勾选。
3. **挂起期手动改步骤必须是后端同步，而不是提示词承诺**：续跑交棒前按 `taskId` 读 `TaskService` 的
   权威 `type/currentStep/status`，并据此重算披露、槽位与工作区状态；批内结算用的上下文仍冻结；
   任务读失败只 WARN 保留旧值。
4. **规则冲突统一（提示词 / YAML / 注解回落三面）**：
   - 规则 10「页面级动作失败即停」保留第 29 条零副作用一次纠正例外；同参数/同目标仍禁止；
   - `confirm_step` 的 YAML 描述与 `AiTools` 注解**同批**补同一例外，`version 2026-10-27.6 → .7`；
   - 任务已完成（COMPLETED）本身不是下载/打开编辑器授权；不自动下载；
   - 未设筛选显示「未设筛选 = 全量」**仅 EXPORT**（导入没有 QUERY_COND 步，不得渲染导出语义）；
   - 挂起期手动改步骤：后续跑按任务权威步骤同步，**不新增 HITL、不自动重发**；
   - 高危确认（DANGER / `create_task` / `start_*`）、确认卡、不重复副作用等约束一项未放宽。

## 三、R2 返修（复核 Important 1/2 + 同族 3/4）

### 3.1 续跑交棒前同步任务权威值（Important 1）

调用链（真实代码）：

```
POST /confirm | /frontend-tool-result
  → AiController.applyWorkspaceContext(runId, context)        ← 见 3.2
  → ConfirmGate.submitDecision / submitFrontendResult         ← 决策落库
  → maybeTriggerResume → ResumeService.resume(...)
      → AiContext context = snapshot.getContext()             ← 批内冻结的那一份
      → buildResumedPrompt/resolvePending(context, …)         ← 批内判定/披露：不改（不扩权）
      → refreshRunContextAfterBatch(settledInBatch)           ← 仅刷新类工具（navigate/create/confirm）
      → syncAuthorityForHandoff(runId, nextHopContext, history)
          → RunContextRefresher.syncTask(context)             ← 按 taskId 读 TaskService.findByIdRaw
          → TaskSlotResolver.enrich(context, "", history)     ← 槽位重算
      → rewriteWorkspaceState(history, nextHopContext, runId) ← 工作区段换权威值
      → driveResumed(…, handoffContext, resumeHistory, …)     ← 下一跳披露面按新步骤
```

实现要点（`ResumeService`）：
- 有在飞工具批：`refreshRunContextAfterBatch` 之后、`rewriteWorkspaceState` 之前插入
  `syncAuthorityForHandoff`；`snapshot.setContext(nextHopContext.toMap())` 随该分支已有的
  `saveStatusUnlessCancelled` 落库。
- 无在飞工具（重跑/手动续跑）：同样同步 + 重写工作区段；历史有变化时一并写 `messageJson`。
- **fail-safe**：任务读不到/读异常只 WARN 保留旧值（`syncTaskBeforeHandoff` 捕获），不阻断续跑、
  不扩披露面；`TaskSlotResolver` 未注入 = 不重算（既有轻装配零改动）。
- 安全性未依赖本次改动：`start_*` 的预检 `reportHash` 仍覆盖 `taskId/type/status`，状态变了照样
  `PRECHECK_STALE` 拒绝；本项是正确性/信任问题，不是授权问题。

### 3.2 两条写入口携带最新工作区上下文（同族 3，后端）

### 3.3 续跑槽位重算 + selectionSynced 三态（同族 3）

- `ContextBuilder.SELECTION_SYNCED_KEY = "selectionSynced"` 进入 extra 白名单（闸门保留、模型可见
  的页面事实）；`ContextBuilder.pageSelectedDefs` 与 `TaskSlotResolver.pageSelectedDefCodes` 同一规则：
  **空列表且 `selectionSynced != true` ⇒ 视为未同步**（回落任务条目/历史），避免未水合窗口误抹。

  旧槽位/历史选择都不得复活（单测锁住）。

  `export.taskDetailReady` / `import.taskDetailReady` 探针（与 `utils/frontend-tools.ts` 同源、
  无任务/未注册 ⇒ false）计算；`API 层` `frontend/src/api/ai.ts` 的 `confirm` / `frontendToolResult`
  把 `buildContext()` 作为可选 `context` 拼进请求体（无活动 pinia ⇒ 不带，绝不阻断请求）。
