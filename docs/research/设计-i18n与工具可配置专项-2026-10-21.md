## 0. 结论速览（六条硬裁决）

| # | 裁决 | 一句话依据 |
|---|---|---|
| D1 | 前端用 **vue-i18n v11 + Composition API**（`createI18n({ legacy: false })`），Locale 文件按 namespace 单文件、en 侧动态 `import()` | 调研 §2-Q1：Legacy API v11 弃用/v12 移除，`tc/$tc` 已移除 |

## 1. 范围

**做**：

- **前端 i18n 底座**：`vue-i18n@11` 接入（Composition API）、`useLocaleStore`（locale/loaded/副作用）、zh-CN 与 en-US 两套 locale 资源、Element Plus `ElConfigProvider` + Day.js locale 联动、`<html lang>`、`document.title`、axios `Accept-Language` 拦截器；
- **全量文案抽取**（本专项的主体工作量）：`frontend/src/` 14 个 `.vue` + 40 个 `.ts` 里的用户可见中文文案，按 `common/tasks/export/import/definitions/data/ai/tool/errors` 九个 namespace 归位；模型生成内容**不抽取、不翻译**（附录 A.3）；
- **后端错误码收口**：散落字面量 → 单一 `ErrorCodes` 常量类；`ApiResponse` 增 `args`/`traceId`；`messages_zh.properties`/`messages_en.properties` + `MessageSource` 兜底；`AcceptHeaderLocaleResolver`；`application/problem+json` 双形态面；
- **工具定义外置**：`ToolDefinitionSource` 抽象 + `ToolCallback` 装饰器；阶段 A（classpath YAML）落首批全部 18 个工具；阶段 B（DB 表 `ai_tool_def` + `ai_tool_release`）落版本/标签/发布回滚；
- **工具用户侧 i18n**：帧内 `toolKey` 正式化，前端 `tool.<tool_key>.*` 三段回落；`ToolMeta.displayName`（= description 前 20 字）退役；
- **守卫**：残留中文 lint（CI 可跑）与 `error.code` 三表对账用例。

**不做**：

- 不做工具描述**多语言**（一条工具一份英文/中文之外的二份描述）——见 §3.4 裁决与 §8 待裁 B；
- 不整体切 ProblemDetail（`spring.mvc.problemdetails.enabled` 保持不设，避免 Spring 内建异常改形打红既有断言）；
- 不做账号级语言偏好（无身份体系；`ai_setting` 表属模型配置专项，届时再接）；
- 不做模型生成内容的二次翻译、不做历史消息回溯翻译；
- 不做 prompt 管理平台（Langfuse/LangSmith）接入——只借其「不可变版本 + 标签指针」模型；
- 不做 MCP 化（工具外置不以上 MCP 为前提，调研 §2-Q3.3）。

### 2.3 工具定义现状

- **声明方式 = 注解，描述全中文写死在注解里**：`ai/tools/AiTools.java`（608 行）用 Spring AI `@Tool(name, description)` + `@ToolParam(description, required)` 声明 **18 个**工具（`list_config_defs`、`get_config_def`、`list_tasks`、`get_workspace_state`、`check_job_status`、`get_row_count`、`create_task`、`start_export`、`start_precheck`、`start_import`、`start_publish`、`open_export_file_editor`、`download_export_files`、`navigate_to`、`select_definitions`、`set_condition`、`confirm_step`、`generative_form`），另有 7 个 record（`FieldQueryCondition`/`FieldCondition`/`FormSpec`/`FormField`/`FormOption`）承担**内层 schema 的类型化镜像**。
- **装配路径 = 运行期反射扫描**：`ai/tool/ToolRegistry.java:31-78` `@PostConstruct` 遍历全部 bean，`method.getAnnotation(Tool.class)` 取 name/description，再 `MethodToolCallbackProvider.builder().toolObjects(bean).build()` 生成 `ToolCallback` 存入 `callbackMap`；`forContext(ctx)` 按 `@ToolScope` 标签裁剪（`:83-93`）。
- **展示名是 description 的截断派生**：`ToolRegistry.java:56-58` → `meta.setDisplayName(description.length() > 20 ? substring(0,20) : description)`，`AiToolsController.java:67` 把它作为 `GET /api/ai/tools` 的 `displayName` 下发。**工具描述一改，UI 展示名跟着变**——模型侧与用户侧文案在代码层是同一根字符串。

- **无工具元数据表**：只有 3 个 Flyway 迁移（`V1__schema.sql`、`V2__staging_base_version.sql`、`V3__ai_feedback.sql`），`ai_feedback` 是唯一"AI 侧外置表"；`spring.jpa.hibernate.ddl-auto: validate` + H2 文件库 ⇒ **新表必须同时给 Flyway 迁移与完全对齐的 JPA 实体**，否则启动即失败。
- 只读诊断面已存在：`GET /api/ai/tools?page=&taskType=&step=`（`AiToolsController`），是"读库后披露对不对"的现成取证口。
- 系统提示词片段亦中文：`ai/tool/ContextBuilder.java:77-108`（`## 当前工作区状态`／`页面：`／`已选配置项:`／`额外上下文:`），且 `PAGE_LABELS`（`:55-60`）与前端 `stores/workspace.ts#PAGE_LABELS` **靠注释互相对齐**（`:52-53` 自述「改动必须两侧同改」）。

### 2.4 一句话现状判断

**前端"零 i18n + 四份重复工具文案 + 双受众字符串"，后端"零 MessageSource + 零 ProblemDetail + 错误码六处散落 + E2E 硬绑中文文案"，工具"注解硬编码 + 展示名派生自 prompt 文案 + 无版本化外置"。** 因此本专项的**真正难点不是翻译**，而是先把三件契约（`error.code`、`tool_key`、`locale` 归属）钉住，再搬文案。

## 3. 核心设计

### 3.1 前端 vue-i18n 接入

**版本与兼容**（事实源 `frontend/package.json`）：

| 依赖 | 现版本 | 与 vue-i18n v11 的关系 |
|---|---|---|
| `vue` | ^3.5.13 | v11 支持 Vue 3.3+，**兼容** |
| `element-plus` | ^2.9.3 | `ElConfigProvider :locale` 与 `element-plus/es/locale/lang/*` 静态导入（体积小） |
| `pinia` | ^2.3.0 | locale 状态入 store，避免双源 |
| `dayjs` | ^1.11.13 | 需 `dayjs/locale/zh-cn` + `dayjs/locale/en`，切语言时 `dayjs.locale()` |
| `vitest` / `vue-tsc` / `typescript` | 4.1.11 / ^2.2.0 / ^5.7.2 | 新增 `unplugin-vue-i18n` **不引入**（改为纯 JSON + 运行期 `setLocaleMessage`，零编译期插件） |
| `vite` | ^6.0.7 | 动态 `import()` 由 Vite 原生切 chunk |

**新增依赖**：`vue-i18n@^11`（1 项，runtime）。**不引入** `@intlify/unplugin-vue-i18n`（避免 vite 插件链改动与 yaml/编译期预编译带来的构建面风险——调研 §2-Q1.2 已说明键用点分层级即可，无需编译期优化）。

**目录组织**（不按业务域拆文件，按 JSON 顶层 namespace）：

```
frontend/src/locales/
  zh-CN.json      ← 首屏静态 import（默认语言，必须同步可用）
  en-US.json      ← 首次切到 en 时 import()（懒加载，见下）
  index.ts        ← createI18n 装配 + loadLocale() + 已加载集合
```

- **key 规范**：`<namespace>.<域>.<语义>`，禁止中文当 key、禁止按文件路径机械生成；
  - `common.*`（按钮/状态/单位：`common.action.confirm`）、`tasks.*`、`export.*`、`import.*`、`definitions.*`、`data.*`、`ai.*`（面板 chrome）、`errors.*`（**与 `error.code` 一一对应**，见 §3.2）、`tool.<tool_key>.title|summary|param.<p>|enum.<V>`（工具用户侧，见 §3.4）。
- **懒加载**（官方 `loadLocaleMessages` 形态）：`zh-CN` 在 `main.ts` 静态 import 并 `createI18n({ legacy:false, locale, fallbackLocale:'zh-CN', messages:{'zh-CN': zhCN} })`；`en-US` 在 `localeStore.setLocale('en-US')` 时 `await import('./en-US.json')` → `i18n.global.setLocaleMessage('en-US', m)` → `await nextTick()`；`loadedLocales: Set` 防重复加载。**不做路由守卫级懒加载**：本应用 6 个路由共用一份 chrome，按 locale 整包懒加载已足够，过度切分反而增加抖动面。
- **Element Plus**：根组件外不再用 `app.use(ElementPlus,{locale})`（那是静态值），改为 `App.vue` 顶部 `<el-config-provider :locale="elLocale">`，`elLocale` 由 `computed(() => locale === 'zh-CN' ? zhCn : en)` 派生（两者均静态 import，`element-plus/es/locale/lang/zh-cn` 与 `.../en` 体积各 ~1KB）。
- **Day.js**：切语言时 `dayjs.locale(locale === 'zh-CN' ? 'zh-cn' : 'en')`；`en` 语言包无需 import（dayjs 内建 en）。
- **`<html lang>` 与 `<title>`**：`document.documentElement.lang = locale`；`document.title = t('common.app.title')`；路由 `meta.title` 改存 key（`meta.titleKey`），由 `router.afterEach` 统一 `document.title = t(meta.titleKey)`。
- **`Accept-Language`**：`api/http.ts` 的 `axios.create` 加请求拦截器 `config.headers['Accept-Language'] = localeStore.acceptLanguage`（`zh-CN` / `en-US`）。**该头当前后端不消费**（无 `LocaleResolver`），属新增发送、零行为变更（见 §3.2 落地后才生效）。
- **状态单一源**：`useLocaleStore`（`stores/locale.ts`）持 `locale / availableLocales / loadedLocales / acceptLanguage`，`setLocale()` 内串行做四件事（i18n / html lang / localStorage `cm.locale` / dayjs+elLocale 派生）。**组件禁止直接改 `i18n.global.locale`**。
- **SSE 帧不回溯**：切语言只影响**后续渲染**；已落库的历史消息正文与工具结果原文保持原语言（附录 A.2 末条）。工具卡摘要、错误卡、状态徽标等 chrome 因 `t()` 是响应式，**会即时重渲染**——这与主流产品一致（UI chrome 立即切换，内容不回溯）。

### 3.2 后端：`error.code` 稳定化 + `messages` 兜底 + ProblemDetail 双形态

**a) 错误码单一源（硬件，可独立于 i18n 先做）**

新建 `common/ErrorCodes.java`（`final class` + `public static final String`），把 §2.2 六处字面量收口，按面分三组：

| 组 | 成员（现值搬迁，不改字面量） | 载体 |
|---|---|---|
| HTTP 面 | `BAD_REQUEST`、`RESOURCE_NOT_FOUND`、`JOB_ALREADY_FINAL`、`TASK_FINALIZED`、`DUPLICATE_TOOL_CALL_ID`、`UNKNOWN_TOOL_CALL`、`UNKNOWN_RUN`、`SESSION_BUSY`、`SUSPEND_POOL_SATURATED`、`AI_UNAVAILABLE`、`AI_REDIS_UNAVAILABLE` | `ApiResponse.code` / AI 裸对象 |
| 工具面 | `ToolOutcome.CODE_*` 15 个（`TOOL_EXECUTION_FAILED`、`TOOL_RESULT_MISSING`、`RESOURCE_NOT_FOUND`、`ILLEGAL_ARGUMENT`、`TOOL_ALREADY_CLAIMED`、`SCOPE_NOT_DISCLOSED`、`CONFIRM_TIMEOUT`、`FRONTEND_TIMEOUT`、`RUN_CANCELLED`、`FRONTEND_CANCELLED`、`UPSTREAM_FAILED`、`PRECHECK_FAILED`、`PRECHECK_UNAVAILABLE`、`RESOURCE_LOCKED`、`TARGET_INVALID`） | `ToolResultEnvelope.code` / SSE `tool_result.code` |
| 数据面 | `PRECHECK_NOT_PASSED`、`PRECHECK_STALE`、`FORM_RESULT_REJECTED`、`FORM_SCHEMA_REJECTED`、`AI_RUN_FAILED` | issues 文案 / 400 体 / SSE error 帧 |

`ToolOutcome` 的 `CODE_*` 常量**保留为别名**（`public static final String CODE_TOOL_EXECUTION_FAILED = ErrorCodes.TOOL_EXECUTION_FAILED;`）——零破坏地把"码的定义地"从枚举挪到常量类。

**b) `messages_zh.properties` / `messages_en.properties`（兜底件）**

- `application.yml` 增：`spring.messages.basename=messages`、`encoding=UTF-8`、`fallback-to-system-locale=false`；**只给两份**（`zh` / `en`），区域变体靠 `messages_zh_CN → messages_zh → messages` 链自然回落（调研 §2-Q2.2）。
- **键约定**：`error.<CODE>`（人读文案）、`validation.<field>.<rule>`（`@Valid` 的 `{key}`）。**只覆盖用户可见面**：18 个工具码 + 11 个 HTTP 码 + 5 个数据面码 ≈ 34 条；**不搬日志**（2007 处引号中文里的绝大部分）。
- **`message` 的解析位置**：`GlobalExceptionHandler` 与 `AiController` 的错误体工厂统一走 `ErrorBodyFactory.of(code, args, request)`：
  - 有 `messages` 键 → `messageSource.getMessage(code, args, LocaleContextHolder.getLocale())`（**zh 值与该码此前的硬编码中文逐字一致**，E2E 10 处断言不破）；
  - 无键 → 保留调用方传入的原文（兜底，绝不回显裸 key——这是调研 §2-Q2.2 点名的坑）。
- **`AcceptHeaderLocaleResolver`**：`@Bean LocaleResolver`，`setDefaultLocale(zh_CN)` + `setSupportedLocales(List.of(zh_CN, en_US))`；**默认 locale = zh** ⇒ 不带 `Accept-Language` 的既有调用方（E2E、curl、桩）行为不变。
- **`LocaleContextHolder` 的 ThreadLocal 陷阱**（调研 §2-Q2.5）：本项目挂起/续跑跑在 `app.ai.suspend.pool-size=20` 的专用池与 `sse-write-*` 池上，**locale 在请求线程解析后必须显式作为参数下传**（进 `ErrorBodyFactory`，或进 `RunSnapshot.locale` 仅作观测），**不得**在池线程里读 `LocaleContextHolder`。这是本专项的已知坑，写进施工交底。

**c) ProblemDetail：双形态，不整体切换**

- 现状约束（实测）：前端 `api/http.ts:42-44` 用 `typeof body.success === 'boolean'` 判信封，AI 裸对象靠 `code` 字段；E2E 按 `message` 文案与 `.ok`/`.data` 断言。**整体切 `application/problem+json` 会同时打红前端全部错误分支与 E2E 半数量用例**。
- 裁决：**新增**一条内容协商通道，**不改默认形态**：
  - 请求头 `Accept` 含 `application/problem+json` → 错误响应改 `ProblemDetail`：`type = urn:cfg:error:<CODE>`、`title`（= messages 的短标题）、`status`、`detail`（= 本地化 message）、扩展成员 `code` / `args` / `instance`（= 请求 URI）/ `traceId`；
  - 否则维持 `ApiResponse` 信封（**并补 `args`、`traceId` 两个 `@JsonInclude(NON_NULL)` 字段**，存量响应字节不变）。
- **`spring.mvc.problemdetails.enabled` 保持不设**：一旦开启，Spring 内建异常（`HttpMessageNotReadable`/404/405）的响应体形态会整体变 ProblemDetail，直接打红 E2E 的形态断言。**这条写进"不做"清单**。
- 收益：第三方/脚本消费者可按 `type`/`code` 稳定分支（RFC 9457），而自家前端零改动；代价是多一条 advice 分支与一组内容协商用例（§6 M5）。

### 3.3 工具定义外置：`ToolDefinitionSource` + 装饰器 + 版本标签

**抽象（阶段 A 就能把接口钉死，避免阶段 B 返工）**：

```java
public interface ToolDefinitionSource {
    /** 当前快照（启动加载一次，请求路径零 DB/IO）。 */
    ToolSnapshot load();
    /** 快照版本标识（日志/诊断/缓存键用）。 */
    String version();
}
```

`ToolSnapshot` = `Map<toolKey, ToolDefinitionOverride>`；`ToolDefinitionOverride` 是自有 record（对齐 LangChain4j `ToolSpecification` 的可序列化语义，落 Spring AI 时映射为 `DefaultToolDefinition`）：

```java
public record ToolDefinitionOverride(
        String toolKey,          // 稳定标识，永不变，如 doc.search
        String modelName,        // 模型侧 name（当前必须 == @Tool(name)，见校验 4）
        String description,      // 模型侧 description（单语）
        String inputSchemaJson,  // 模型侧 JSON Schema canonical
        String titleKey,         // 仅 UI 用：i18n key（tool.<toolKey>.title）
        String lang,             // 模型侧语言标签：zh | en（不随用户 locale 变）
        String implRef,          // 绑定：bean#method（诊断用；执行仍走原 ToolCallback）
        String version, String status, String changeNote) {}
```

**装配（装饰器，不改 Spring AI 内部）**：`ToolRegistry` 建 `callbackMap` 后包一层

```java
final class OverriddenToolCallback implements ToolCallback {
    private final ToolCallback delegate;        // 原 MethodToolCallback
    private final ToolDefinition definition;    // 外置 definition（name/description/inputSchema）
    public ToolDefinition getToolDefinition() { return definition; }
    public String call(String toolInput) { return delegate.call(toolInput); }   // 执行路径原样
}
```

`getToolDefinition()` 是 Spring AI 送模型的那一份（`name/description/inputSchema`），`call()` 仍是原方法。**执行零改动**——这正是"注解做缺省、外置做覆盖"的落地形态（调研 §5.1/§5.2）。

**阶段 A（本专项首批）：classpath YAML**

`backend/src/main/resources/ai/tools.yaml`：

```yaml
version: 2026-10-21.1
lang: zh
tools:
  - toolKey: list_config_defs
    modelName: list_config_defs
    description: "列出系统中的配置定义（编码/名称/层级/字段数），可按层级筛选"
    inputSchema: { ... }        # 由脚本从 @ToolParam 首次导出，此后以 YAML 为准
    titleKey: tool.list_config_defs.title
    status: published
```

- 迁移手法 = **脚本抽取**：施工首步写一次性脚本（不进 CI）从 `AiTools.java` 的注解导出初版 YAML，逐条人工复核；`lang: zh` 即当前状态，**行为等价**（description 一字不改）。
- 校验（启动期 fail-fast）：① `toolKey` 唯一且不可变（与 `@Tool(name)` 的 `modelName` 必须存在映射）；② YAML 内 schema 与原方法签名生成的 schema **对账**（比较 property 名/类型/required 集合，不一致则启动失败并打印 diff）；③ `description` 长度上限（建议 ≤ 1024）；④ `titleKey` 存在；⑤ `status=published` 才进快照。

**阶段 B（有运营/租户需求时）：DB 不可变版本 + 标签指针**

```sql
-- V4__ai_tool_registry.sql（Flyway；H2 方言，与既有 V3 同风格）
CREATE TABLE ai_tool_def (
    id                BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    tool_key          VARCHAR(64)  NOT NULL,   -- 稳定标识，永不变
    version           INT          NOT NULL,   -- 该 tool_key 内自增
    model_name        VARCHAR(64)  NOT NULL,   -- 模型侧 name（英文 snake_case）
    description       VARCHAR(2048) NOT NULL,  -- 模型侧 description（单语，lang 指明）
    lang              VARCHAR(8)   NOT NULL DEFAULT 'zh',
    input_schema_json CLOB         NOT NULL,   -- canonical JSON Schema
    title_key         VARCHAR(128) NOT NULL,   -- 仅 UI：tool.<tool_key>.title
    impl_ref          VARCHAR(128),            -- bean#method，诊断用
    status            VARCHAR(16)  NOT NULL,   -- draft / published / archived
    eval_ref          VARCHAR(256),
    change_note       VARCHAR(1024),
    created_by        VARCHAR(64),
    created_at        TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uq_ai_tool_def UNIQUE (tool_key, version)
);

CREATE TABLE ai_tool_release (
    label      VARCHAR(32) NOT NULL,           -- production / staging / tenant-x
    tool_key   VARCHAR(64) NOT NULL,
    version    INT         NOT NULL,
    updated_by VARCHAR(64),
    updated_at TIMESTAMP   NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT pk_ai_tool_release PRIMARY KEY (label, tool_key),
    CONSTRAINT fk_ai_tool_release FOREIGN KEY (tool_key, version)
        REFERENCES ai_tool_def (tool_key, version)
);
```

- **版本语义**：`ai_tool_def` 的行**不可变**（改文案 = 插新 version，旧行永远可回滚）；`ai_tool_release` 是**指针**——发布 = `UPDATE … SET version = N`，回滚 = 指回旧 N（Langfuse/LangSmith 模型，调研 §1 表）。
- **缺标签**：`load()` 找不到 `production` 指针 → **启动期 fail-fast（生产 profile）**；`dev`/本地允许 `app.ai.tools.missing-label=fallback`（回落 YAML/注解）并 WARN。**禁止静默回落**（调研 §1「缺标签直接 404，不静默回退」）。本仓单实例、无多租户 ⇒ 只启用 `production` / `staging` 两个 label。
- **读路径零 DB**：启动加载一次进内存快照；刷新 = 显式 `POST /api/ai/tools/reload`（仅本机/诊断面，与既有 `GET /api/ai/tools` 同一 controller）或应用重启。**不做定时轮询**（本项目单实例，轮询只增抖动面）。
- **发布校验清单**（写进服务层，事务内）：schema 合法（`jsonschema` 自校验）→ `tool_key` 未改 → 必填参数未删 → `model_name` 全局唯一 → 与 Java 方法签名对账通过 → `description` 非空且 ≤2048。
- **DDL 约束联动**：`spring.jpa.hibernate.ddl-auto=validate` ⇒ 必须同时提交 `ai_tool_def` / `ai_tool_release` 的 JPA 实体（字段名、长度、可空性逐项对齐），否则**启动即失败**（这条在施工交底里标红）。

### 3.4 工具文案三层分治 —— 「模型看中文还是英文」的关键裁决

| 层 | 内容 | 语言由谁决定 | 通道 | 本仓落点 |
|---|---|---|---|---|
| **模型侧** | `description`、`inputSchema` 的 property description、工具返回值文本、系统提示词片段 | **注册表 `lang` 字段固定，单语，永不随 UI locale 变** | 后端注册表 / `ContextBuilder` | `ai_tool_def.description` + `lang`；`AiTools` 返回值 |
| **用户侧** | 工具卡标题、折叠摘要、参数标签、枚举展示值、审批/表单按钮 | **当前 UI locale** | 前端 i18n | `tool.<tool_key>.title` / `.summary.<verb>` / `.param.<name>` / `.enum.<VALUE>` |
| **协议侧** | SSE `tool_start`/`tool_result`/`confirm_request`/`error` 帧 | **不带语言**：只带 `code` + `args` + `toolKey` | 帧字段 | 新增 `toolKey`（可选，缺省按 `name` 映射） |

**裁决 A（硬）：模型侧单语，且不随用户切。** 依据 = 附录 A.1/A.2：主流产品一律"单语系统提示词 + 一条跟随用户语言的指令"，没有一家按用户语言整份切换提示词；把描述翻译成用户语言不能修复多语言带来的能力损失（arXiv 2601.05101：阿语提问下工具准确率降 5–10%，**与描述语言无关**）；多语言描述还会让同一工具产生多份 prompt 前缀，直接放大缓存失效与评测矩阵（Pydantic AI/Anthropic 缓存顺序：tools → system → messages）。

**裁决 B（本批取值 = 保持中文单语；英文单语为待裁项，见 §8-3）：**

- 现状事实：模型侧**整条面**（18 个 description + 全部工具返回值 + `ContextBuilder` 的提示词片段）已是中文单语，且 29 条 E2E 与既有评测基线以中文为基线；
- 附录 A 的证据只支持"**单语**"与"**不随 locale 切**"，**不支持**"必须英文"（A.7 明确：无 A/B 直接证据）；
- 因此**切英文是一次独立决策**，须配评测重跑与基线迁移，不应被 i18n 专项顺带。注册表用 `lang` 字段把选择权留在数据层，切语言 = 发一个新 `version`（可回滚），不改代码。

**用户侧三段回落（与 MCP `title → annotations.title → name` 同型）**：

1. 前端 `t('tool.<toolKey>.title', locale)` 命中 → 用之；
2. 未命中 → 用帧/事件里后端给的 `titleKey`（若下发了 `title` 兜底文本则用文本）；
3. 仍未命中 → 用 `toolKey` 原文（保证"永远有字"，不出现空标题）。

**`ToolMeta.displayName` 退役**：`ToolRegistry.java:56-58` 的"取 description 前 20 字"改为 `titleKey`（来自快照）；`AiToolsController` 的 `displayName` 字段**保留但值改为 `titleKey`**（新增 `titleKey` 字段、`displayName` 标记 deprecated 一个批次）——避免打红 `AiToolsDisclosureEndpointTest` 与证据文档里的 `tools[]` 口径。

**双受众字符串的强制二分**（§2.1 的雷）：`WorkspaceActionRecord.summary` 拆两字段——

```ts
interface WorkspaceActionRecord {
  key: string            // 稳定动作键，如 'selectDefs'（前端 i18n: workspace.action.<key>）
  args: Record<string, unknown>
  modelSummary: string   // 送模型的一句话（单语，与 UI 无关，走英文/中文由 §3.4 裁决决定）
  at: number
  source: WorkspaceActionSource
}
```

UI 渲染用 `t('workspace.action.' + key, args)`；`buildContext` 送 `modelSummary`。**抽取时若只搬一侧，等于静默改 prompt**——这条列为施工禁令。

### 3.5 对话区三类文本边界（附录 A.3 落地到本仓）

| 层 | 本仓例子 | 通道 | 落点 |
|---|---|---|---|
| 静态 chrome | 批准/拒绝/取消/提交、`已提交，同步中…`（`AiPanel.vue:488`）、输入框 placeholder（`:734`）、空态建议词（`:1258`）、健康标签（`:1264-1269`）、`工具名 + 状态词` 兜底（`tool-summaries.ts:180`） | 前端 i18n | `ai.*` / `tool.*` |
| 模型生成内容 | 回答正文、模型自拟的卡标题/预检摘要 | 模型 token，**不二次翻译** | 不改 |
| 系统/协议通知 | SSE `error` 帧、限流、工具失败、审批超时/取消、前端工具回执 | `code + args + toolKey`（+ 本地化 `message` 仅兜底） | `errors.*` 由 `code` 渲染 |

**切换语言的可见边界（写进验收口径）**：切语言后 ① 全部 chrome 立即变；② 已生成的消息正文与工具结果原文不变；③ 未决卡（确认门/表单）保留原语言——因为其标签来自 chrome 而参数值来自 args（数据不翻译）。这与 ChatGPT/Claude 的实际行为一致。

## 5. 迁移与回滚

- **前端**：文案抽取是**纯搬移**（默认 locale = zh-CN，渲染结果逐字相同）⇒ 每个页面搬完后 `diff` 浏览器截图 + `yarn test` 应零变化；`en-US.json` 缺失的键在 `en` 下回落 `zh-CN`（`fallbackLocale`），**允许分批补齐**，不阻塞。
- **后端**：`ErrorCodes` 搬迁只改"引用处"，字面量不变 ⇒ 响应字节不变（可用 E2E 前后 `http.txt` 对比）；`messages_zh` 的 34 条值逐字复制现有硬编码文案 ⇒ zhs 语义不变；`messages_en` 可后补，缺键回落 zh。
- **工具注册表**：三态等价性 = **注解（今天）⇒ YAML（阶段 A）⇒ DB（阶段 B）**，每一跳都必须有"输出字节等价"的对照用例（§6 M6-1）。回落链：DB（有 `production` 指针）→ YAML（`missing-label=fallback`）→ 注解；**生产 profile 不允许跳级回落**。
- **回滚**：以批为单位 `revert`；新表/新列/新 properties 残留无害（空表 = 今天行为；`messages_en` 无消费者则不影响）；前端 `cm.locale` 残留只影响下次默认语言。
- **灰度**：本项目单实例、无登录体系 ⇒ **不做灰度**；工具描述变更靠"版本 + 标签指针"实现可回滚（这是本专项唯一需要发布纪律的物件：改 description 即改 prompt，会击穿缓存，必须走"插新 version → staging 自检 → 移 production 指针"）。

### 7.3 为什么 i18n 应排在最后（论证）

**结论：i18n 排在「模型配置」「上下文统计」之后；但其中"`error.code` 收口"应剥离前置，先于两者。**

1. **改造面重合度最高**：i18n 要动 `AiPanel.vue`（2973 行、333 个非注释中文行）与 `stores/ai.ts`（3120 行）；两个专项的新增文案**全部落在同一批文件**。i18n 先做 ⇒ 这两文件被 i18n + 两专项共改三轮，每轮都要重跑 297 处文案断言与浏览器验收。
2. **文案是"搬移 + 一次性定稿"的活，最怕追加**：i18n 的价值在"抽完就冻"；先做等于给一个还在长的界面拍照，随后每批新文案都要再走一遍"加键→补 en→跑残留扫描"。
3. **码表一次性定稿更省**：`ErrorCodes` + `errors.*` + `messages_xx` 需要一次成型；模型配置会新增 4–6 个码、上下文统计会新增 2–3 个提示型码。码表先做 ⇒ 三次改同一张表。
4. **反方案的代价可以量化**（替代排序 A = i18n 先行）：
   - `AiPanel.vue` + `stores/ai.ts` 将被改 3 轮 → 预计 **+0.5～1 人日**返工（按现有 333 + 68 个非注释中文行的抽取量级估）；
   - 297 处文案断言要复核 3 次（每次约 0.3 人日）；
   - 设置页 200+ 条新文案要"先硬编码再迁移"，或反过来阻塞该专项 P2 —— **两者都不划算**；
   - 收益仅为"用户早 1–2 周看到英文界面"，而本产品当前**无英文用户**（附录 A.2：切语言只影响后续轮次，不解决任何当期缺陷）。
5. **唯一必须前置的**：`error.code` 收口 + `args`/`traceId` 字段（§3.2-a）**零文案变更、零 UI 变更**，却是后续三专项的共同地基（模型配置的新码、上下文统计的提示码、工具治理的 blocked 码都往里加）。建议把它作为**独立小批先行**（约 0.5 人日 + 1 组对账用例），不绑在 i18n 批里。
6. **工具外置与 i18n 的顺序**：`tool_key` 稳定性是 `title_key` 的前提 ⇒ **工具外置（模型侧）先于工具用户侧 i18n**；但工具外置本身不产生用户可见文案，故可与 i18n 同批（i18n 批内先做外置再抽 UI 文案）。

### 7.4 建议的全局顺序

`error.code 收口（独立小批）` → `模型配置 P1/P2/P3` → `上下文统计` → **`i18n + 工具可配置`（工具外置 → 前端底座 → 逐模块抽取 → 守卫）**

## 9. 风险与边界（诚实边界）

- **静态扫描 ≠ 全界面无残留**：`check-i18n-residue` 只能证"源码里没有中文字面量"，证不了"en 下没有中文渲染"（数据值、模型正文、后端下发的 `reason`/`message` 都会带中文）。真正的验证必须做浏览器双语截图（M8-7）。**本专项不承诺"en 下零中文"**，只承诺"chrome 层零中文 + 残留清单化"。
- **后端下发文案的残留面**：`tool_result.reason`、`confirm` 相关 message、作业 issues 文案都是后端中文；§3.2 只把**错误码面**做了 code+兜底，业务文案（如"作业 #12 已是终态"）仍是中文单语。彻底解决需要"业务文案也 code 化"（更大工程），本专项**不做**，登记为已知边界。
- **改 description 即击穿 prompt 缓存**：tools 位于 prompt 前缀最前（tools → system → messages），任何 description 变更都会让整段前缀失效。故本专项规定"改文案 = 发新 version + 移指针"，**禁止**"保存即生效"式编辑（调研 §2-Q3.2）。
- **schema 外置与 Java 签名双源**：外置 `inputSchema` 与 `@ToolParam` 反射生成的 schema 存在漂移风险；缓解 = 启动期对账（M6-7），**根治** = 阶段 B 后只信库、注解不再参与（本专项不做到那一步）。
- **`LocaleContextHolder` 在池线程丢失**：本项目挂起/续跑/SSE 写出都在专用池，必须显式传 locale；这是"看起来能跑、偶发英文/中文串味"的经典坑，已列入 M4-5。
- **Flyway 序号竞争**：上下文统计的 `chat_session_usage` 与本专项的 `V4__ai_tool_registry.sql` 会抢同一个版本号；**先入库者拿号，后者顺延**（施工时以工作树实际为准，不做预留）。
- **`ddl-auto=validate` 的硬约束**：DDL 与 JPA 实体任一字段不齐即启动失败；这是保护也是风险（本地开发最容易踩）。
- **vue-i18n v11 与 Vue 3.5 的兼容未实测**：调研给了官方 breaking changes 结论，但**本仓未实跑**；施工首步必须 `yarn install` 后 `yarn build` 实跑确认（列为批②的第一条验收）。
- **未验证项（不得当结论引用）**：①切换 UI 语言对模型工具选择准确率的影响（无 A/B 数据）；②`en` 文案的术语质量（需产品/领域专家校，本稿只给 key 规范）；③外部用户是否真的需要英文（产品判断，非技术判断）。
