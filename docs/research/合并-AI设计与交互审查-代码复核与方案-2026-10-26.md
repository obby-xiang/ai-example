## 1. 合并口径与结论

### 1.1 判定等级

- **确认**：当前代码可直接证明机制成立；性能量级、真实模型服从率等仍需实测。
- **部分确认**：核心事实成立，但原因、范围或措辞需收窄。
- **误报/驳回**：当前代码或官方资料有反证，不进入施工。
- **已修待复验**：代码与测试断言已在仓，但指定环境未覆盖，不能写“已闭环”。
- **待裁**：涉及既有用户裁决、保存策略或新产品语义，不能由实施者代选。
- **待实测**：只有性能 profile、真模型采样或生产同构环境能定性。

### 1.2 总体结论

1. Issue #15 的若干机制事实成立，但 **Critical/High 定级和若干修法不能照单采纳**。当前最优先的不是“开放自动重试”，而是失败现场丢失、条件语义反转、恢复无出口、确认卡语义失真和结果完整性。
2. “无 SSE 心跳”是误报；真缺口是**压缩、上游静默和慢工具期间没有独立于上游事件的服务端保活**，以及 `POST /chat` 没有建连/首帧超时。
3. “已输出/工具执行后不重试”是有意的安全边界。正确方向是保存现场、按工具台账只重跑模型步，以及必要时的“失效替换”，不是整轮重放。
4. “成功后乐观发 done”不可采纳。轮终态与内容载入状态必须分开；取消不得被 DONE 覆盖的不变量不变。
5. 批量下载完整性、条件空值校验、保存校验结果属于工程正确性，**不需要等待业界标准证明**。
6. 虚拟滚动、关闭 park、统一四态、提高重试次数、25 步是否偏低均不能直接立项为缺陷；需用户裁决或实测。

## 4. 业界依据如何转成项目方案

完整 URL 与访问边界见 `docs/research/调研-AI与工作区交互业界对照-2026-10-26.md`。本方案只采用以下原则：

1. **重试**：AI SDK 的当前模型步重试、LangGraph pending writes、RFC 9110 非幂等重试限制共同支持“按错误类型 + 副作用 + 审批 + 预算”判断；不支持整轮盲重放。
2. **恢复**：AI SDK resume、AG-UI interrupt/resume 支持稳定 ID、持久状态和幂等恢复；不支持把恢复变成再发一条用户消息。
3. **压缩**：官方资料支持状态/生命周期和真实已用时间，不支持伪造百分比。摘要角色必须明确，不能伪装用户输入。
4. **HITL**：MCP、OpenAI Agents、CopilotKit 支持按风险/参数确认、服务端审批状态和原子消费；不支持所有写操作一律确认。
5. **表单**：GOV.UK 一屏一问只适合线性低耦合；NN/g 明确相互依赖条件不宜强拆，故本项目采用常用一屏 + 高级渐进披露。
6. **性能**：web.dev/Vue/Lighthouse 提供长任务、INP、DOM 和虚拟化依据；阈值用于测量，不等于预先认定必须换库。
7. **可访问性**：MDN log/aria-busy 与 WCAG 是硬约束依据；计时应 aria-live=off，避免每秒打断读屏。
8. **正确性**：条件校验、下载完整性、保存结果诚实性由项目数据不变量直接决定，不借“业界”降低优先级。
