## 0. 全局性研究（跨产品横向对照）

### 0.1 AI 输出与消息操作条（Northbase，12 个产品、233 个实例的实测统计）
来源：https://www.northbase.design/patterns/ai-output 【设计规范旁证】

覆盖产品：ChatGPT、Claude、Gemini、Perplexity、Microsoft Copilot、GitHub Copilot、v0、Notion AI、Google Docs、Airtable、Retool、Atlassian Rovo。

- **100% 的产品允许用户在中途停止生成**（"100% let users stop generation mid-response"）。
- 消息操作条：**6 个系统使用 4–5 个图标的紧凑操作条**。Claude 显示 `Copy`、thumbs up、thumbs down、`Regenerate`；GitHub Copilot 把反馈放在最前，然后是 `Copy`、`Regenerate`；Retool AI 最简，只有 thumbs up / thumbs down。
- **没有任何一个独立 AI 聊天产品在回答旁显示 AI 头像**。ChatGPT、Claude、Gemini、Perplexity、Microsoft Copilot、v0 全部靠左对齐文本区分 AI 回答；仅 2 个集成型产品有头像（GitHub Copilot 灰色机器人图标、Retool AI 紫色 "Hi" 圆）。
- 加载态：**50%（6/12）用极简指示**（ChatGPT 单个脉动黑点、Claude 品牌橙色星芒、Gemini 骨架行）；**6/12 会描述 AI 正在做什么**而不是只显示 "Thinking"（ChatGPT "Searching for tech news today"、Perplexity "Reviewing sources · 10"、"Building tables"）。
- 代码生成场景 71% 用分栏布局，纯聊天很少用分栏。

### 0.2 AI 聊天界面解剖与消息状态机（setproduct 设计指南，作者自称日更使用 Claude.ai / ChatGPT / Cursor / Cline / Perplexity / Venice 两年）
来源：https://www.setproduct.com/blog/ai-chat-interface-ui-design 【设计规范旁证】

九个区域：① 会话列表 ② 会话头部（模型选择、可原地编辑的标题、分享、每会话设置）③ 消息流 ④ 用户消息（可编辑）⑤ 助手消息（Markdown/代码块带复制按钮）⑥ 输入区 ⑦ **停止 / 重新生成控件** ⑧ 每条消息操作（Copy、Edit、Like、Dislike、Share、Branch from this point；桌面 hover 出现，移动端常驻）⑨ 建议/追问 chips。

关于会话列表的原文判断：「这个模式现在已成为预期——如果你的 AI 聊天没有它，用户会以为历史丢了。」

七种消息状态：`Queued` / `Thinking·Reasoning`（可折叠，默认收起，要老实标注 "Thinking"/"Reasoning"/"Searching the web"）/ `Streaming` / `Complete` / `Error`（要区分网络、限流、内容过滤、上下文超限、超时，**"绝不要把错误都塌缩成通用的 'Something went wrong'"**）/ `Regenerating`（旧回答要么消失、要么收进 "Previous response" 手风琴、要么做成**横向 carousel**；作者判断 carousel 是正解，因为保留了用户可能想比较或复制的旧版本）/ `Stopped`（保留部分输出、标记为中断、提供 `Continue` 和 `Regenerate` 两个明确动作，**"不要删除部分输出"**）。

流式细节：光标（caret）是成本最低的"还活着"信号；滚动规则是「只有当视口在底部 100px 内才自动滚，用户一往上滚就锁定位置并显示 `Jump to latest` 悬浮按钮」；`Stop generating` 必须放在消息流底部、靠近输入框、大到不需要瞄准，**streaming 结束必须立刻隐藏**。

### 0.3 AI 功能的八个状态（AI UX Playground 指南，2026-10-02）
来源：https://aiuxplayground.com/guides/ai-feature-launch-states 【设计规范旁证】

八个状态：`Empty` / `Thinking` / `Streaming` / `Partial` / `Error` / `Refusal` / `Handoff` / `Limits`。

- 空态要求：一行说明这个功能干什么（用人话说，不是模型术语）、**给 3–6 个基于用户自身上下文的起始任务**、展示输入期望（问题/文件/URL/选中内容）、提前暴露会破坏首次尝试的限制（文件大小、语言）、**把光标放进输入框并显示快捷键**。
- 流式：Send 变 Stop；停下时保留已到达内容；用户往上滚就停止自动滚；为迟到元素（引注、代码块、表格）预留空间；**结束时 Stop 变回 Send 并由 Copy/Retry 出现**；**屏幕阅读器只播报"回答开始"和"回答结束"，不要播报每个 token**。
- 错误：说清发生了什么、重试有没有用；确认保留了什么（输入、先前输出、文件）；**只给一个主恢复动作**；AI 改动了东西就给恢复点；错误码和日志放次级。
- 限制：**在撞墙前警告**、给出本地时间的重置时刻、说明还有什么能用、保住进行中的工作、把"等待"当作真实选项。
- 反模式清单包含：中途就亮出 Copy/Share（用户会复制半截答案）；Markdown 流式重排（表格从竖线突然变网格）；自动滚动把正在读的人拽回底部。

### 0.4 中断与恢复模式（AI UX Playground，2026-07-10）
来源：https://aiuxplayground.com/pattern/interrupt-and-resume 【设计规范旁证】

四态流程：`Generating` → `Interrupted`（Stop 取消后续 token，**部分文本留在屏幕上也留在上下文里**）→ `Resuming`（Continue 从断点续写）→ `Redirecting`（暂停状态下编辑或发新 prompt，不丢线程）→ `Complete`（清掉 Stop/Continue/光标）。
关键 UX 元素：Stop、Partial、Continue、Context（显示线程完好）、Composer、Complete。
反模式：停止就丢弃部分答案；恢复时假装模型还记得其实不在上下文里的内容；没有可见的中断态（任务还在跑但 UI 看着像空闲）。

产品对照表（原文）：ChatGPT = "Stop generating; edit or regenerate; voice mode barge-in"；Claude = "Interrupt streaming replies and retry or continue the thread"；语音助手 = 打断（barge-in）；编码 agent = 取消运行并从 checkpoint 或修改后的指令续跑。

### 0.5 会话历史搜索模式（AI UX Playground，2026-07-28）
来源：https://aiuxplayground.com/pattern/conversation-search 【设计规范旁证】

产品对照（原文）：ChatGPT「跨会话标题与消息正文搜索」；Claude「历史浏览 + 线程内查找式检索」；Notion AI「搜索覆盖 AI 聊天与工作区页面」；Obsidian「对保存的 AI 辅助笔记与聊天做全文搜索」。
反模式：只匹配标题忽略正文；结果跳进会话但不高亮命中的那一轮；只有语义搜索没有关键词兜底；把别人的/工作区的会话暴露进个人搜索结果。
关键词 vs 语义：「关键词适合精确报错和 ID，语义适合记得话题但记不住词」。

## 1. ChatGPT（OpenAI）

### 1.1 删除 / 归档会话 【官方文档实证】
来源：https://help.openai.com/en/articles/8809935-deleting-and-archiving-chats-in-chatgpt

- **入口**：打开聊天历史（侧栏）→ 目标会话的 `•••` 更多选项 → `Delete` → **确认删除**。
- **删除的后果（关键，回答"清空是否删服务端记录"）**：
  - 立即从账号视图移除；
  - OpenAI **在 30 天内**将其从系统中永久删除，除非已被去标识化并与账号解绑，或出于安全/法律义务需要保留更久；
  - **ChatGPT 内和 OpenAI Support 都无法恢复**；合规工具仍可能按组织留存策略访问合格的工作区数据。
- **归档 ≠ 删除**：`•••` → `Archive`，**无需确认**；归档只是从常规侧栏移出，**仍在账号里、仍可搜索**，留存期不变。查看路径：`Settings > Data controls > Archived chats`（或 `View archived chats`）→ `Unarchive` 或 `Delete`。
- **批量**：`Settings > Data controls > Archive all chats` 或 `Delete all chats` → 阅读确认信息后继续；**Delete all chats 不可撤销**；会影响当前账号/工作区（含 projects 里的会话）。
- 删除会话**不会**删除单独存在 Library 里的文件；使用过已连接应用数据的会话，删除会移除该会话内保留的连接应用数据，但不删应用里的原始数据。

### 1.2 错误态与重试 【官方文档实证】
来源：https://help.openai.com/en/articles/7996703-troubleshooting-chatgpt-error-messages

- `"There was an error generating a response."` → 官方建议 **点击 "Regenerate" 按钮**（同时给出重启浏览器/设备、关闭 VPN、试其他浏览器或隐私模式、换网络等）。
- 卡在 `Thinking…/Generating…/Working…` 无限转圈：给出了独立的排查条目（说明这是一个被官方承认的独立状态问题）。

### 1.3 Stop generating / 编辑消息 / 分支 【官方文档实证】
来源：https://help.openai.com/en/articles/6825453-chatgpt-release-notes

- release notes 明确记录：**"Stop generating: Based on your feedback, we've added the ability to stop..."**。
- **"Cleaner edit-message flow: Android now makes it clearer when you're editing..."**（编辑消息流程被反复打磨）。
- **"Hover over a message, click More actions (⋯), and select Branch in new chat to start a separate..."** —— 从某条消息分支出新会话。
- 会话聚合：把"past chats、projects、images、documents"集中到一个地方查看（侧栏演进）。
- 临时会话（temporary chat）控制项在 release notes 中有增补（"Saving a temporary chat: When a conversation becomes useful for the future..."）。

### 1.4 临时会话 【评测文章旁证】
- 来源：https://findskill.ai/learn/temporary-chat/ —— 桌面端入口与网页/移动端位置一致；macOS 应用是「点窗口顶部的模型名 → 选 Temporary Chat」，网页与移动端是「开新会话后在屏幕顶部模型选择器附近打开开关」，并且**有可见的指示器**。
- 来源：https://nexasphere.io/blog/how-to-manage-chatgpt-chat-history —— 临时会话不进历史，OpenAI 仍保留最多 30 天用于安全审查。

### 1.5 快捷键 【评测文章旁证】
来源：https://fastshortcuts.com/shortcuts/chatgpt/ 、https://chatgpttrainer.co.uk/chatgpt-faqs/ 、https://www.reddit.com/r/ChatGPT/comments/1wy2n55/
- 新会话：`Ctrl+Shift+O`（Mac `Cmd+Shift+O`）
- 显示/隐藏侧栏：`Ctrl+Shift+S`
- 打开搜索（会话搜索对话框）：`Ctrl+K`
- 焦点进侧栏：`Tab`；侧栏内上下移动：`↓` / `↑`
- 社区评价：「`Ctrl+Shift+O` 是我按得最多的一个」。

### 1.6 单条消息操作 【评测文章旁证】
来源：https://www.techtarget.com/whatis/definition/ChatGPT 、https://latenode.com/blog/ai-technology-language-models/chatgpt-openai-models-gpt-4-gpt-4-5-o1-o3/how-to-use-chatgpt 、https://whizi.io/resources/why-chatgpt-switched-to-a-weaker-model/
- 用户可：换个 prompt 追问 / **Regenerate 重生成** / Share 分享 / 用 thumbs up / thumbs down 点赞点踩。
- 每条回答下方的小工具条包含 copy、thumbs、retry（"try again"），ChatGPT 里这个菜单还能「把同一个问题重发给指定的另一个模型」。

## 2. Claude（Anthropic）

### 2.1 删除 / 重命名会话 【官方文档实证】
来源：https://support.claude.com/en/articles/8230524-delete-or-rename-a-conversation

- **入口（Web）**：左侧边栏 → 「Chats and tasks」/ Recents → hover 目标会话 → 右侧 `⋮` 按钮 → Delete（或选择）→ **再次点击确认按钮**。
- **批量**：侧栏「Recents」下点 `View all →` → 右侧 `Select` → `Select all` → `Delete Selected`；**弹确认框**提示形如 `"Delete 198 chats? This cannot be undone."`，点 Delete 才执行。
- **移动端**：iOS/Android 在会话列表里**长按**会话 → `Rename` 或 `Delete`；打开中的会话则是**右上角 `⋯` → Delete → 确认**。
- **删除后果（关键）**：**立即**从会话历史移除，并在**30 天内从后端系统删除**；账号其他数据（如 projects、账号信息）保留到你自行删除或注销账号。
- 彻底清除所有 Claude 数据只能**注销账号**，注销永久不可恢复。

### 2.2 会话搜索与记忆 【官方文档实证】
来源：https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context

- 可以让 Claude **检索你过去的会话**并在新会话里引用相关信息。
- **在开始新会话时，可以通过 `+` 菜单关掉 memory**——「If you turn off memory in the "+" menu when you start a new chat, Claude doesn't use memory in that chat, doesn't search your past chats from it」。这是一个很典型的「按会话粒度控制上下文来源」的设计。

### 2.3 消息操作条与流式中断 【设计规范旁证】
来源：https://www.northbase.design/patterns/ai-output 、https://aiuxplayground.com/pattern/interrupt-and-resume
- Claude 操作条 = `Copy` + thumbs up + thumbs down + `Regenerate`（4 个图标）。
- 中断行为：「Interrupt streaming replies and retry or continue the thread」。
- 加载态：品牌橙色星芒动画；用于「简单 Q&A」场景，无需文字状态。

### 2.4 用量限制的提示方式 【设计规范旁证（引官方帮助中心）】
来源：https://aiuxplayground.com/guides/ai-feature-launch-states （该节 Sources 列出 Claude Help Center 的 "Troubleshoot Claude error messages" 与 "Manage usage credits"）
- Claude 的会话限制每 5 小时重置；撞到限制时，**提示里写明何时重置**；开用量额度的付费用户会看到"Claude 正用你的额度继续"的变体文案，所以撞限制变成计费变化而不是任务中止。
- 反面清单：任务中途硬停、不说时间只说 "Try again later"、撞限制时丢掉正在生成的回答。

### 2.5 快捷键 【评测文章旁证】
来源：https://fastshortcuts.com/shortcuts/claude/
- 开始新会话：`Ctrl+Shift+O`
- 切换聊天历史侧栏：`Ctrl+Shift+S`
- 聚焦消息输入框：`Ctrl+Shift+;`
- 复制 Claude 的最后一条回复：有独立快捷键

### 2.6 删除后记忆是否残留 【评测文章旁证】
来源：https://calmara.app/blog/deleting-claude-chat-does-not-delete-memory
- 删会话后对话从历史消失，但**由该对话产生的 memory 条目不会随之删除**，要单独去 `Settings > Memory` 删。
- 这一点对「清空对话」语义设计很关键：**"清空会话"与"清空从会话学到的记忆"是两个不同的动作**。

## 3. Gemini（Google）

### 3.1 会话列表 / 重命名 / 删除 / 分支 【官方文档实证】
来源：https://support.google.com/gemini/answer/13666746

- **入口**：gemini.google.com → 侧栏显示 **pinned 与 recent chats**（被隐藏时点顶部 Menu 展开）。
- 支持：**搜索会话、Pin / Unpin 会话、Rename 会话、删除会话**。
- **Branch a new conversation from a chat**：可以从对话中的某个点**分支出一个新会话**，然后回到主对话继续。（官方明确："Deleting a branched chat doesn't delete the original chat. Deleting the original chat doesn't delete a branched chat."）
- **删除后果（关键）**：从 pinned & recent chats 里删除会话时，**它也同时从 Gemini Apps Activity 中被删除**，并且**删除该会话里创建的内容（如 Canvas 文档与 apps）**。反过来，如果 Activity 数据被删，该活动也不会出现在 recent/pinned chats。
- 可以让 Gemini 按话题或时间引用你过去的会话；引用到过去会话时，回答下方 "Sources and related content" 里会出现 **"Previous chats"** 标签（官方也承认这个标签偶尔会误显示）。
- **企业/学校账号限制（官方明写）**：使用工作或学校账号时，Gemini Apps Activity **由 Google Workspace 管理员控制，你无法删除会话**。「you can't delete chats」。
- 前置条件：个人账号、18+、Keep Activity 与 Memory 都开启。

### 3.2 临时会话 【官方文档实证（引官方隐私说明）+ 评测旁证】
- 官方帮助页（https://gemini.google.com/faq）把「Manage & delete your activity in Gemini Apps」列为独立主题。
- https://its.umich.edu/communication/collaboration/google/update/delete-and-start-temporary-chats-google-gemini 【评测文章旁证】：桌面端「点击左上角 New chat 旁边的 Temporary chat」。
- https://www.mediapost.com/publications/article/408175/ 【评测文章旁证】：Temporary Chat 不出现在最近列表、不进 Gemini Apps Activity、不用于训练，**保留最多 72 小时后删除**。
- https://redact.dev/blog/turn-off-gemini-apps-activity 【评测文章旁证】：`gemini.google.com` 上点 New chat 旁边的 Temporary chat。

### 3.3 批量删除的缺失 【评测文章旁证】
来源：https://github.com/lorenzoalali/Google-AI-Studio-Bulk-Delete-UserScript
- 原文判断：「Google 不提供一次批量删除 Gemini 或 Google AI Studio 多条会话的方式」，因此社区写了 userscript 来批量删除。
- 另有 https://ai.nd.edu/news/july-roundup-delete-chats-gemini-notebook-and-a-peek-inside-claudes-brain/ 记录「终于支持删除单条会话，还支持 pin 与 rename」——说明**单条删除是很后期才补齐的**。
- **企业账号下更早连"删除"按钮都没有**：https://support.google.com/a/thread/390850907/ 记录 Workspace 超管反馈「Delete 按钮从 Gemini 网页版聊天历史中消失」。

### 3.4 误删与确认设计的反面教材 【评测文章旁证】
- https://support.google.com/gemini/thread/433011292/ 「Delete Activity wipes your entire chat history without clear indication」：用户关掉活动记录后，弹出的后续对话框只预览了很少几条，结果点下去把**整个聊天历史**删了。这是"确认框预览不可靠"的典型事故。
- https://www.reddit.com/r/GoogleGeminiAI/comments/1mo9zxd/ ："Delete Activity" 会在无预警的情况下清空整个聊天历史。

## 4. Microsoft Copilot（消费版 / Microsoft 365 Copilot / Copilot Chat）

### 4.1 「清空上下文」的做法居然是打一句话 【官方文档实证】
来源：https://support.microsoft.com/en-us/microsoft-365-copilot/write-a-great-prompt-in-microsoft-365-copilot

官方提示原文：**"Start fresh — Avoid interrupting and type 'new topic' when switching tasks."**
也就是说 Microsoft 官方把「换任务时清上下文」的推荐做法写成**在对话里输入 `new topic`**，而不是让你去找按钮。

【评测文章旁证】旁证与解释：
- https://www.shelf.io/blog/how-to-prevent-microsoft-copilot-from-giving-bad-answers/ ：「All you have to do is type 'new topic' before asking Copilot to summarize a new document or task. This clears the previous context.」
- https://www.ascendientlearning.com/training-resources/tutorials/microsoft-copilot-chat-tutorial ：把「Changing topics mid-conversation without starting a new chat」列为常见错误——「Earlier context bleeds into the new topic」。
- https://www.sfu.ca/copilot 等机构页也复述了同一条建议。

**读法**：这是"没有显式清空按钮，改用对话指令清空"的一条明确证据；对做产品的人来说，它更像一个**反面案例**（状态不可见、不可靠、不可发现）。

### 4.2 生成后的动作条：Keep / Retry / Discard / Refine 【评测文章旁证】
来源：https://www.computerworld.com/article/3479705/how-to-use-microsoft-copilot-for-writing-in-microsoft-365-word-outlook-onenote.html
- Word/OneNote 中，Copilot 生成的草稿下方**带工具栏**，可 `Keep it`（保留）、`Retry`（重试）、`Discard`（丢弃）、`Refine`（细化）。
- 另一处（https://techwisegroup.com/weekly-tech-tips/copilot-microsoft-word/）："Rewrite with Copilot" 用**左右箭头在 3 个生成版本之间切换**，再 `Replace` / `Insert below` / `Regenerate` / `Adjust tone`。

### 4.3 Regenerate 与引用展开（官方埋点字段即功能清单）【官方文档实证】
来源：https://learn.microsoft.com/en-us/microsoft-365-apps/privacy/diagnostic-events-microsoft-365-copilot-chat

官方诊断事件表里直接出现这些用户动作，等于一份官方功能清单：
- `RegenerateClicked` —— 用户点了「Regenerate response」按钮
- `ReferenceEntityExpandClicked` / `SeeMoreReferencesClick` / `SeeLessReferencesClicked` —— 用户在回答底部的**引用列表**上展开/折叠、看更多/看更少
- `RepresentationClick` —— 用户点了回答里的实体链接（人或文件名）
→ 说明 M365 Copilot 的每条回答下方有**可展开的引用列表**与 **Regenerate** 按钮。

## 5. VS Code Chat / GitHub Copilot Chat（面板型编程助手，与本项目形态最接近）

### 5.1 新会话 / 清空 / fork / 重命名 的斜杠命令与快捷键 【官方文档实证】
来源：https://code.visualstudio.com/docs/agents/reference/ai-features-cheat-sheet

- 快捷键：**`Ctrl+N` = Start a new chat**；`Ctrl+Alt+I` 打开 Chat view；`Ctrl+I` 编辑器内联聊天；`Ctrl+Shift+Alt+L` 快速聊天。
- 斜杠命令（官方表格原文）：
  - **`/clear` — "Start a new chat and archive or mark the current chat as done."**（注意：**清空 = 开新会话 + 把旧会话归档**，不是销毁）
  - **`/compact` — 压缩上下文**
  - **`/fork` — "branch the conversation with its history"**
  - **`/rename <name>` — 重命名本地会话**
  - `/plan`、`/explain`、`/fix`、`/tests`、`/doc`、`/init`、`/debug`、`/troubleshoot`、`/help` 等
- 长会话与成本的官方建议：「**Check context usage, compact the conversation, or start a new chat for an unrelated task**」。
- 安全提示原文（重要）："Agents can save edits directly to the session's folder or worktree. **Manual permissions does not ask for confirmation for every file edit.**"（手动权限模式也**不是每次编辑都确认**——确认门粒度不是"每一次写操作"）

### 5.2 会话管理全景（官方长文，信息密度最高）【官方文档实证】
来源：https://code.visualstudio.com/docs/agents/run/sessions/manage-sessions

- **会话（session）与 chat 是两级结构**：session = 一次任务的单位（工作区 + 代码改动 + 一个或多个 chat）；每个 chat 有自己的对话历史与上下文。
- **多 chat 并行（peer chats）**：在支持 Agent Host 的会话里，用 `Ctrl+T` 或右键会话 → `New Chat in This Session` 新建**同级 chat**；每个 chat 有自己的历史、标题、agent/模型；共享同一工作区。**新 chat 是空白的，不继承其他 chat 的历史**（要继承就 fork）。
- chat 上的操作：切换、改模型、重命名（独立于 session 标题）、**Close（隐藏，不删除）**、**Delete Chat（永久删除）**、拖拽分屏、`Ctrl+K Ctrl+←/→` 在分组间移焦点。
- **归档 ≠ 删除（官方明确两次）**：archive/mark as done 把会话移出活跃列表，**不删除**，可随时恢复；`Delete` **永久且不可撤销**（官方带 Caution 提示：删除前先提交 worktree 改动，否则只存在于该 worktree 的未提交文件可能丢失）。
- **自动清理**：可配 `chat.agentSessions.autoMarkAsDoneMergedSessionsAfterDays` 与 `autoDeleteMarkedAsDoneMergedSessionsAfterDays`（PR 合并后先标记完成、再宽限期后删除，**建议值 15 天**）；手动标记完成的会话**不会**被自动删除。
- **fork**：`/fork` 复制整段历史；或 hover 某条请求 → `Fork Conversation` 按钮，**只复制到该检查点为止**。fork 继承历史还能保住 prompt cache 降成本。fork 出的 session 标题前缀 `Forked:`。
- **复制粒度**：`Copy`（单条 prompt 或回答，**Markdown 内容包含回答正文、thinking 步骤和 tool calls**）、`Copy All`（整个会话）、`Copy Final Response`（只复制最后一次 tool call 之后的最终 Markdown）。
- **导出**：`Chat: Export Chat...` 命令导出包含所有 prompt 与回答的 JSON 文件。
- **上下文用量控制**：聊天输入区的 **context window control**，悬浮显示 **token 数、按类别的用量拆解、本会话消耗的总 AI credits**；随对话增长实时更新。
- **压缩**：上下文填满时 VS Code 会**自动压缩**（可用 `github.copilot.chat.summarizeAgentConversationHistory.enabled=false` 关闭）；手动压缩两种方式——输入 `/compact`（**可带保留指令**，例如 `/compact focus on the database schema decisions`），或点 context window 控件 → `Compact Conversation`。**「要完全重置上下文，就开一个新会话。」**
- **任务栏徽标**：应用图标 badge 统计「有未读结果且已不在生成中 / **正在等你输入（waiting for your input）** / PR 上 CI 失败」的会话数；**仍在生成中的未读会话不计入**。这一条对"多任务并行 + HITL 等待"的产品极有参考价值。
- **跨应用发现**：VS Code 能发现 Copilot CLI、GitHub Copilot app、**Claude Code、Codex** 创建的本地会话并继续；外部会话默认隐藏，可按 None / Recent / Last 24 Hours / Last 7 Days / All 过滤。打开外部 Codex 会话时若另一应用还开着，会显示 **"This chat is open in another app"** banner，并禁用发送/排队/重发。
- **导出/分享 safety**：agent 给另一个会话发消息**总是需要用户确认**；agent 不能给自己正在跑的 chat 发消息；批量发送有上限。

### 5.3 侧问题（side chat）与上下文引用 【官方文档实证】
来源：同上（Manage agent sessions / Chat 参考）
- `Ask side questions`：`/btw <question>` 或选中回答里的文字 → `Ask Question`；侧聊在旁边的分组打开，**继承源对话作为隐藏上下文**，但**不渲染进侧聊记录**；每个问题创建一个新侧聊；侧聊只在 Agents window 的 Copilot 与 Claude 会话可用。
- `@` 提及、`#` 引用（`#file`、`#changes`、`#commit:`、`#output`）、拖拽文件、Add Context 都是加上下文的方式。

### 5.4 Visual Studio 的 Copilot Chat（同一体系的另一种落地）【官方文档实证】
来源：https://learn.microsoft.com/en-us/visualstudio/ide/copilot-chat-context-references

- **会话历史面板**：每个条目显示 **会话标题 + 最近一条消息预览 + 最后更新时间**，点条目直接跳进那个会话。
- **新线程**：`Create new thread` 按钮或 **`Ctrl+N`**；**切换线程** `Ctrl+PgUp`（上一个）/ `Ctrl+PgDown`（下一个）；`Ctrl+Shift+T` 展开线程下拉。
- **上下文窗口指示器**：以 **donut 环形图**出现在聊天输入区或编辑器里，**点开看确切百分比**和用量构成拆解（如"对话消息"与"工作区文件"各占多少）。
- **压缩**：`Summarize conversation`（点 context window 指示器触发）或 `/compact`；压缩后**保留早期轮次的摘要而不是完整记录**。
- **官方最佳实践**（原文三条）：① 用新线程开始新任务的对话；② 想留在同一线程就上下文高时用 Summarize conversation；③ **"Delete requests that are no longer relevant or that didn't give you the desired result."** —— 官方建议**删除不相关的单条请求**。
- **References 下拉**：每次回答下方有 References 下拉，列出 Copilot 生成该回答时引用了哪些上下文，「这能帮你改进提问」。官方明确说"Copilot Chat displays the context it used after every result"。
- 内联聊天可 `Continue in chat window...` **把内联对话提升到主聊天窗口以保留历史**。

### 5.5 VS Code 上下文概念页 【官方文档实证】
来源：https://code.visualstudio.com/docs/agents/concepts/context
- 官方定义："Context window and compaction. The context window is the maximum amount of information a language model can process in one request. The user message, ..."（把「用户消息 + 上下文 + 压缩」作为一等概念在文档里讲清楚）

### 6.1 中断 / 回滚 / 排队 / fork 【官方文档实证】

- **打开面板**：Mac `Cmd+I`、Windows/Linux `Ctrl+I`。
- **中断**：「Click the **Stop** button to stop Agent mid-task. This lets you redirect or start a different approach.」
- **撤销改动**：「Hover over a previous message and click **Restore Checkpoint** in the bottom right to roll back all changes Agent made after that point. **Restoring reverts files only; it does not remove messages from the conversation.**」——文件回滚与对话回滚被**刻意分开**；「**To shorten the conversation itself, fork the chat from an earlier message.**」

- **子 agent**：Agent 可派生 subagent 并行处理研究/shell/浏览器任务，各自独立上下文窗口并返回结果到主对话。
- **会话检索作为工具**：Agent 可以**自己查询你过去的会话**获得上下文（"Conversation search is available as an agent tool"）。

### 6.2 侧聊 【官方文档实证】
来源：https://cursor.com/help/ai-features/side-chats

- 打开方式：输入 `/side`、选中文字或 diff → `Ask in Side Chat`、快捷键 Mac `Shift+Cmd+S` / Win/Linux `Shift+Ctrl+S`。
- 父对话历史作为**隐藏参考上下文**复制进去，**不渲染在侧聊记录里**。
- `X` 关闭 = **archive（归档），不是删除**；「The durable thread stays usable until you archive it by closing it.」
- 侧聊不嵌套；侧聊随父会话存续。
- **与 fork 的区别（官方明确）**：fork 是把父对话**复制**成新会话；从某条消息 fork 只复制到那条消息并丢掉之后的（含后续 subagent）。侧聊只是把父历史作为隐藏上下文喂给模型，**不复制父对话记录**。

### 9.1 问答面板的「新建会话」+ `/clear context` + 历史记录 【官方文档实证】

## 12. 上下文管理与其他产品的可借鉴点

### 12.1 上下文用量指示器（多家官方文档）【官方文档实证】
- VS Code：context window control，悬浮看 token 数与按类别拆解（见 5.2）。
- Visual Studio：donut 环形指示器，点开看百分比与构成（见 5.4）。
- Treasure Data AI Studio：https://docs.treasuredata.com/products/ai-studio/chat/in-session-memory ——「Studio displays a context usage indicator that shows how much of the available context window is in use」，web/desktop 显示百分比，移动端同位置；接近上限时**自动压缩**。
- Archestra：https://archestra.ai/docs/platform-chat ——上下文可视化环**在第一轮消息后才出现**，颜色随填充升级（<50% 绿、≥50% 黄、≥75% 橙、≥90% 红），悬浮显示已用 token 与剩余。
- Omniscio：https://docs.omniscio.com/library/ ——Context Details 弹出层拆解"当前是什么在占满上下文"，并带**上下文用量警告的 in-chat 提示条**。

### 12.2 压缩（compaction）的中途反馈 【评测文章旁证】
- https://github.com/openclaw/openclaw/issues/47666 ：「When compaction runs mid-conversation, the bot goes silent for 10-30 seconds with no visible feedback to the user. On Discord ... this looks like the bot crashed」→ 建议加 typing indicator。
- https://docs.flashduty.com/en/ai-sre/sessions ：压缩时聊天流里出现状态行「Compacting conversation context…」并显示已用时间与进度，完成后自动消失；完成的最直接指示是**头部的上下文占用百分比掉下来了**。
- https://claudeissues.com/issue/30115-feature-show-progress-indicator-during-context-compaction ：Claude 桌面应用压缩时有进度条与百分比，CLI 无反馈「which can make it appear frozen」。
- https://ai-tools.dartmouth.edu/blog ：Dartmouth Chat 的 **Compact Now**「replaces every message in the chat with a summary, keeps only the most recent message intact, and **you can't undo it. Dartmouth Chat asks you to confirm first.**」→ 破坏性压缩**要确认**。

### 12.3 确认门 / 审批（HITL）的官方做法 【官方文档实证】
- **Claude Code permissions**：https://code.claude.com/docs/en/permissions
  - 三类规则：**allow / ask / deny**；**评估顺序是 deny → ask → allow，取第一个匹配**，所以 deny 永远压过 allow。
  - Hooks 文档（https://code.claude.com/docs/en/hooks）：「Uses hookSpecificOutput to **allow or deny a permission request on behalf of the user**」「Use PreToolUse decision control to allow, deny, ask, or defer the tool」。
  - agent loop 文档（https://code.claude.com/docs/en/agent-sdk/agent-loop）：「The SDK evaluates the active mode together with your allow and deny rules in a fixed order, described in How permissions are evaluated.」
  - 简读：**这是一个可配置的、有序的、可被外部程序接管的确认门**，而不是"弹窗问一下"。
- **VS Code approvals/permissions**：见 5.1 官方警示——手动权限模式**不等于每次编辑都确认**；不同 mode 有不同默认。
- **Cursor Plan 模式**：需要你批准计划后才能改文件（6.1）。
- **Windsurf**：terminal allow/deny list + 企业可强制最大自动执行等级；Turbo 模式下**不在 deny list 上的命令会立即执行**（7.4）。

### 12.4 审批 UX 的两条关键约束 【评测文章旁证】
- https://www.linkedin.com/posts/omidsaffari_if-your-ai-agent-asks-for-approval-after-activity-7479565426801369088-Z3zy ：
  「**If your AI agent asks for approval after the tool call, you do not have HITL.** You have cleanup with a nicer button. **The gate has to sit before the side effect**: Before the refund. Before the email. Before the CRM write. **The reviewer should not approve "continue?"** They should approve a specific proposed action with the exact context: **What tool will run. What...**」
- https://permissionprotocol.com/agent-incident-tracker/ghostapproval-wiz-symlink-hitl-bypass-july2026 （Wiz 研究 GhostApproval）：
  - 「symlink-following + **UI misrepresentation** bypasses HITL in Claude Code, Amazon Q, Cursor, Antigravity, Windsurf」
  - 「**Claude Code internally detected the risk but showed only the decoy filename in its approval dialog.**」
  → 审批界面**必须展示真实解析后的目标**（真实路径/真实参数），否则确认门形同虚设。
- https://mcpmarket.com/tools/skills/hitl-approval-workflow ：给出 Pending / Approved / Rejected 三态的审批工作流与审计轨迹做法。
- https://www.tamer-ai.dev/en/human-in-the-loop/ ：「Every dangerous action waits for your **explicit** approval — sent to your phone, not buried in a terminal.」→ 审批要**推送出去**而不是埋在同一个界面里。

### 12.5 引用与来源展示 【官方文档实证 + 旁证】
- M365 Copilot：引用列表可展开/收起（`SeeMoreReferencesClick` / `SeeLessReferencesClicked` 官方埋点）。
- Visual Studio Copilot：每个回答下方 References 下拉。
- Gemini：回答下方 "Sources and related content"，引用过去会话时打 "Previous chats" 标签。
- Perplexity：步骤在回答到达后**折叠成一行 "Completed 2 steps" 摘要**（https://aiuxplayground.com/guides/ai-feature-launch-states）。

### 12.6 可访问性（流式场景）【评测文章旁证 / 设计规范旁证】
- https://medium.com/@marketing_58999/making-ai-chatbots-accessible-for-screen-reader-users-a-developer-guide-8f77a92407d5 ：「**Set `aria-live="off"` during token streaming and switch to `"polite"`** (or update a separate completion region) **when the full response is ready.**」
- AI UX Playground（0.3）：「For screen readers, **announce when the response starts and when it finishes, not every token.**」
- https://www.webdesignhot.com/design.md/twitch/ ：聊天流用 `role="log" aria-live="polite"` 播报新消息；模态用 `role="dialog" aria-modal="true"` 加 focus trap。
- VS Code 官方在 AI settings reference 里专列 accessibility 设置：https://code.visualstudio.com/docs/agents/reference/ai-settings
- 通用可访问性检查清单（含"自定义快捷键要写进文档、避免与浏览器/系统快捷键冲突"）：https://qapractices.com/documentation/accessibility-testing-tools/

### 12.7 错误态与恢复点 【设计规范旁证】
- https://aiuxplayground.com/guides/ai-feature-launch-states （Error 一节）：Lovable "Try to fix"（**向前修复**：出错后让 agent 读日志尝试修），Cursor "Restore Checkpoint"（**向后回滚**：回滚该点之后的文件改动但保留对话）。作者结论：「nothing the person said is lost」。
- 反模式：`"Something went wrong"` 后面没有下一步；请求失败时**清空输入框**；静默自动重试导致重复干活或重复扣额度。

### 12.8 重试的实现细节（第三方插件源码级证据）【评测文章旁证】
来源：https://github.com/copilot-emacs/copilot.el
- `copilot-chat-retry` 重生成上一条回答时：**"it deletes the dead turn on the server and re-sends the request. The original exchange stays put until the new answer arrives and then is replaced, so the buffer ends up with a single clean exchange, and a failed regenerate leaves the original ..."**
→ 这是一个很实用的实现参考：**重生成时先保底显示旧答案，新答案到达再替换；重生成失败不丢原答案。**
- 上下文引用管理：`copilot-chat-add-file-reference` / `copilot-chat-add-region-reference` / **`copilot-chat-clear-references`（丢弃待发送的引用）**。
