## 0. 结论速览（九条硬口径）

1. **SpreadJS 是真的，不是纸面集成**：`frontend/package.json:16-18` 三个包精确钉版 `17.1.5`（`spread-sheets` / `spread-excelio` / `spread-sheets-resources-zh`），懒加载入口 `frontend/src/utils/spreadjs.ts:45-66`，宿主组件 `frontend/src/components/SpreadGrid.vue`。**用户口径与仓内现状一致**；两点须提前知悉（§2.1）：**License 是评估模式**（`VITE_SPREADJS_KEY` 仓内留空，`frontend/.env.example:9-10`）、**没有独立"在线表格"页**（表格只出现在导出结果页与导入上传页两处）。
2. **AI 只发意图，执行在前端**：复用既有四路由前端工具执行器（`frontend/src/utils/frontend-tools.ts:484-508`）+ 页面能力注册表（`frontend/src/stores/workspace.ts:269-282`），执行器**不 import 任何视图**，经 `registerPageHandler('sheet.*')` 取到表格适配器。
3. **"前端工具没有 HITL"是既有硬事实，写工具必须把它改掉**：`frontend/src/stores/ai.ts:2760` 注释白纸黑字"前端工具没有 HITL：立即在浏览器执行并回灌结果"；后端 `SpToolCallingManager.kindOf`（`:982-990`）**通道优先于风险** ⇒ 前端通道工具永远进不了确认门。故写工具的确认只能**落在前端**（§3.4 选项 A，理由与代价见 §7-裁 1）。
4. **确认是"人围栏"而不是"超时围栏"**：新增写工具加入"人工介入型前端工具"名单，`ConfirmGate.suspendWaitSeconds`（`:322-330`）返回 `null` ⇒ 帧不带 `timeoutSeconds`，一直等到用户点"应用/取消"。既有先例只有 `generative_form` 一个名字（同函数 `:326`）。
5. **8 个工具 = 谱系 §⑦ 六项建议 × 谱系 §6.3.3"细粒度胜出"的双重投影**：读侧 4 个（`read_sheet_summary` / `aggregate_sheet` / `inspect_columns` / `review_cells`）+ 1 个双档工具（`normalize_column`，`commit=false` 只出建议、`commit=true` 才执行）+ 写侧 2 个（`replace_values` / `update_rows`）+ 1 个撤销（`undo_last_sheet_edit`）。**原稿的 `transform_cells` 已拆解退役**：它的 9 个 op 被分派到三处（trim/case/width→`normalize_column`；replace/regex→`replace_values`；fill_down/fill_series/set_value/clear→`update_rows`）——依据是 SheetCopilot 消融实验（"整合式动作参数一多，Exec@1 显著下降；同一能力拆细后提升"，谱系 §6.3.3）。`apply_formula` / `format_range` / **结构变换** / **去重执行** 明确裁掉（理由见 §1.2）。
6. **尺寸闸单点（读侧）**：`capSheetResult()`（`utils/sheet-tools.ts`）是唯一回灌出口，硬闸 `≤20 行 / ≤2000 字符` + 恒定"共 N 行/共 N 处" + 截断标记；**行数优先于字符数**（沿用 `ToolResultLimiter` 口径）。写侧不再"超限即拒"，改分层上限 + 二次确认（§3.3bis、§7-裁 6）。
7. **写操作只改浏览器内存**：不落服务端文件、不触发保存、不碰作业；落库仍是用户点"保存到服务端"（`ExportWizardView.vue#saveEdits:1054`）这条**既有人的动作**。AI 的最大权限边界 = 内存态 + 一次单步撤销。
8. **零新帧类型**：`frontend_tool_request` / `frontend_tool_result` 契约不动；用户的"拒绝"沿用既有 `cancelled=true` ⇒ `FRONTEND_CANCELLED`（`ConfirmGate.java:91-93`）。
9. **参数模型收敛为一个五元组**：`scope × predicate × operation × value × preview`（`commit` 恒为 `confirm`，写工具不给模型"跳过确认"的选项）。`predicate` **复用既有 `FieldQueryCondition`**（后端 `AiTools.java:466-469`、前端 `types/condition.ts:56-69`），**不新造 DSL**；`scope` 的 `rowKeys` 在本仓**暂不可用**（导出结果表与上传表都来自 xlsx，行上没有 rowKey），因此行定位靠 **`selection` 优先、`predicate` 次之、`rows` 行号仅限同一次调用**，并配 **行指纹校验**（§3.5）兜住"预览与应用之间表格被改动"。歧义五例不走自由文本往返，一律走既有 `generative_form(scenario=CLARIFY)`（`AiTools.java:496-543`）。

### 1.2 不做（逐条给理由，防"顺手做了"）

> 谱系 §⑦「明确不做」已从 6 条扩到 8 条（新增"结构变换""跨 sheet 汇总/拆分"）——本表已吸收这两条（见末两行）。

| 不做 | 理由 |
|---|---|
| **`apply_formula`（AI 写公式）** | ① 本仓表格列由**字段定义驱动**（`applyColumnsToSheet`），没有自由公式位；② 导出链 `buildRowsXlsxBlob`（`utils/excel.ts:540-636`）自产 OOXML，只写 `<v>` 值与共享串、`styles.xml` 只有 1 个 `cellXfs` —— **公式写了落盘即丢**；③ `readRows`（`:361`）读的是值，后端 `ExcelReader` 按表头认列，公式对下游零意义；④ 调研 §3.3 已把"通用公式引擎"列为不做 |
| **`format_range`（AI 改格式/美化）** | 同上 ②③（格式不落盘）；且调研 §3.3 明确不做"自动排版/美化"。**保留的替代**：预览态**高亮改动格**（纯前端绘制，不写 cell format）—— 这是"可核对性"，不是"排版" |
| 整表 / 整个 xlsx 进模型 | R8：D4 一律不走上下文；与 `tool-result.max-rows=200/max-chars=8000` 及压缩专项 L1 直接冲突 |
| AI 直接改单元格且无确认 | 与 FR-5.3 复核清单冲突；业界 2025–2026 全在"计划/预览 + 撤销"方向 |
| AI 触发保存 / 发起作业 | `saveEdits` / `start_export` 等仍是人/既有确认门的动作；本专项不新增任何落库路径 |
| AI 改配置定义 schema | 定义是全局结构（引用/模板/预检规则），调研 §3.3 不做 |
| 非当前激活标签页的表格操作 | 导出结果页是 `el-tabs`，非激活 tab 的 `SpreadGrid` 可能未挂载（`loadedGrids` 懒加载，`ExportWizardView.vue:821-849`）；"打开某 defCode 的编辑器"是 `open_export_file_editor` 的职责，不重复 |
| **插列 / 删列 / 转置 / 拆列 / 合并列（结构变换）** | **不是"风险高"，是"必然静默读错"**：`ExcelReader.read` 按**列号**取字段 —— `fieldCodes` 来自 `_meta`（`ExcelReader.java:31`、`readMetaSheet:71`）或表头行（`:33`），读取循环为 `for (c = 0; c < fieldCodes.size(); c++) { code = fieldCodes.get(c); cell = row.getCell(c); }`（`:54-62`）。**插一列 ⇒ 其后所有字段整体错位一列，且无校验、无告警**，写回 / 预检 / 发布全链路静默污染。此禁令直到"列映射改为按表头名匹配"才能解除（谱系 §6.4 硬结论、§7.3 新增不做第 7 条） |
| **AI 触发排序 / 筛选** | 排序筛选本身"AI 适配度高"（谱系 F2-10/11），但**本仓不该由 AI 做**：① 数据浏览页已有服务端排序/筛选；② 表内排序会让**行号漂移**，而 AI 写操作的行定位正依赖行号/选区（本仓无 rowKey）。用户手动排序不被禁止，但由 §3.5 的行指纹校验兜底（预览与应用不一致即拒） |
| **去重的"执行"（自动删重复行）** | 本仓预检已把主键重复判 **ERROR**（`PrecheckJobRunner`），AI 的职责是**报告哪几组重复**（`review_cells` 已覆盖），而不是替用户删除。且 SpreadJS **无 dedupe API**（谱系 §6.4 三缺口之一），执行版只能是"读列→建索引→`deleteRows`"，属 `delete_rows` 的批③ 范围（§7-裁 7） |
| **跨 sheet 汇总 / 单 sheet 按列拆分** | 一 def 一 sheet（`findDataSheet` 跳过 `_` 前缀隐藏表，`utils/excel.ts:756-766`）；跨表 = 多个定义混进一个文件，破坏导出契约与 `_meta` 单表映射（谱系 F7-39/40、§7.3 新增不做第 8 条） |

### 2.2 前端工具通道机制

- 注册表：`types/tools.ts:79` `FrontendToolName`（今日只有 2 个：`open_export_file_editor` / `download_export_files`），`FRONTEND_TOOLS:82-107` 2 条描述符（含 `args` 规格 + `scopePatterns`）。
- 四路由派发（`utils/frontend-tools.ts:484-508`）：①登记工具（参数校验 `validateArgs:148` + scope `matchesScope:121` + 执行器）②工作区动作表 ③ui_event 同名 ④**页面能力 handler**（`getPageHandler`）。
- 结局单点工厂 `makeExecution:100`（`ok === (outcome === 'ok')`）；执行器可返回**结构化** `{ok:false,reason}` 如实报失败（`interpretHandlerOutcome:1019`）。
- 统一预算：`FRONTEND_TOOL_TIMEOUT_BUDGET_MS = 60_000`、`deriveFrontendToolBudgetMs:278`（服务端上限 − 回灌 POST 上限）。**这意味着"人在环"的工具绝不能被这套预算包住** —— 只有 60s，用户来不及点。
- 回灌唯一前置：`stores/ai.ts#runFrontendTool:3059` → `executeFrontendTool` → `submitFrontendToolResult:3117`；轮次纪元守卫 `:3094`；用户侧终止走 `cancelled=true`（`ConfirmGate.java:91-93`）。
- 已有前例（本设计直接复用其形态）：`generative_form` 在 `frontend_tool_request` 分支被**特判**绕开通用执行器（`stores/ai.ts:2754-2758`），走 `openGenerativeForm:2127` → 用户填 → `submitGenerativeForm:2208`。**"人工介入型前端工具"在本仓已存在一条完整样板链路**。

### 2.3 `open_export_file_editor` 打开的是什么（用户问点的正面回答）

**它打开的不是独立"编辑器组件"，而是导出向导第 3 步（结果）里的那个结果标签页**：

1. handler 注册于 `ExportWizardView.vue:1323-1360`，名 `export.openEditor`（常量 `PAGE_HANDLER_OPEN_EXPORT_EDITOR`，`frontend-tools.ts:78`）；
2. 流程 = 任务绑定闸门（`ensureTaskBoundForTool:1115`）→ 结果存在性 → 切到第 3 步（只读态走零写 `viewStep(2)`，否则 `goStep(2)`）→ `activeTab = defCode` → `ensureGridLoaded(defCode)`（`:821`，内部 `tasksApi.downloadFile` + `grid.loadFromXlsx`）；
3. 即 **SpreadJS 早已在这里**：`SpreadGrid` 用 ExcelIO 打开下载到的 xlsx（`blobToWorkbookJson`），并按字段定义重建列校验器。

结论：本专项**不需要新组件、不需要新页面**——AI 操作面就是"它已经能打开的那张表"。工具只需拿到该 `defCode` 对应的 grid 适配器。

### 2.4 确认门现状与"前端工具无 HITL"的硬事实

- 后端 `SpToolCallingManager.kindOf:982-990`：**先判通道**（FRONTEND ⇒ `KIND_FRONTEND`），**再判风险**（DANGER ⇒ `KIND_CONFIRM`）。故今日**任何** FRONTEND 工具即使标 DANGER 也进不了确认门（`awaitConfirm:603` 只服务 `KIND_CONFIRM`，放行后 `executeOnce` 走**后端**执行）。
- 等待上限只区分三种（`ConfirmGate.suspendWaitSeconds:322-330`）：`KIND_CONFIRM` 无上限；`generative_form` 无上限（**按名字**）；其余前端工具 `frontend-tool-timeout`（默认 120s）。
- 前端两道闸门扩展点已就位：`FrontendToolGuard`（下发前 `inspectArguments` / 回灌前 `inspectResult`，`FrontendToolGuard.java:30-93`），**挂起机制对工具名零知识**，新增复核器只需加一个 Bean。
- 数据最小化的现状：唯一硬约束是 `app.ai.tool-result.max-rows=200 / max-chars=8000`（`ToolResultLimiter`，**模型侧**）；前端帧与台账是全文（双通道分离）。R3 的 20 行/2000 字符是**产品阈值**，比外层兜底更严。

### 2.5 现状一句话判断

**通道齐备、内容面为零、且"写"这一侧今天连 HITL 的位置都没有。**
本专项不是"新增能力"，而是**在既有通道上补一层"表格内容契约"**：读要能看见（但只给采样）、写要先给人看（人点过才落内存）、所有回灌必须过同一把尺寸尺。

补一句（本次谱系修订）：**写侧缺的不只是 HITL，还有粒度** —— 原稿拟的单个 `transform_cells` 把"替换/条件更新/归一化/填充"塞进一个 `ops[]`，正是谱系 §6.3.3 用实验证据否掉的整合式形态；真正的缺口是"三个各自参数面很窄、共用同一套预览与确认"的工具。

## 3. 核心设计

### 3.0 参数模型（五元组：所有表格工具共用一套形参）

| 槽位 | 取值域 | 本仓落地与注意 |
|---|---|---|
| `scope` | `selection`（当前选区）/ `sheet`（整表）/ `columns`（列集合）/ `rows`（Excel 行号区间）/ `predicate`（条件命中行）/ ~~`rowKeys`~~ | 选区唯一可靠来源 = `sheet.getSelections(): Range[]`（`gc.spread.sheets.d.ts:24996`）。**`rowKeys` 在本仓暂不可用**：导出结果表与上传表都来自 xlsx（`SpreadGrid#loadFromXlsx`），行上无 `rowKey`；因此**缺省顺序 = selection → predicate → rows**，且 `rows` 只允许"同一次调用内即时使用"（不跨调用记忆行号） |
| `predicate` | 既有 `FieldQueryCondition`：`{scopeKeys?: string[], fields?: [{fieldCode, operator, value}]}` | **不新造 DSL**。后端 `AiTools.java:466-469`、前端 `types/condition.ts:56-69` 逐字段同形；算子固定 11 个（`EQ/NE/CONTAINS/LIKE/STARTS_WITH/IN/EMPTY/NOT_EMPTY/GT/GTE/LT/LTE`）。**代价**：前端当前只有 `conditionSummary`（`:272`）回显、**没有求值器** ⇒ 本专项需新增 `matchesCondition(row, condition)`（纯函数），并与后端 `ConditionEvaluator` 做一致性用例（§5 T-23）。`scopeKeys` 在表格面**忽略**（它是服务端地区/项目范围过滤，屏幕表已限定单一 def） |
| `match`（仅 `replace_values`） | `wholeCell`（默认）/ `contains` / `prefix` / `wildcard` / `regex`，配 `ignoreCase`（默认 true） | SpreadJS `SearchFlags` 只有 `ignoreCase/exactMatch/useWildCards/blockRange`（`d.ts:43202`），**无 regex** ⇒ 正则走应用层 `RegExp`；`wildcard` 与 `regex` **互斥**（不得同时给） |
| `operation` | 每个工具自带**枚举**（不是自由文本）；`replace_values` 只有"替换"，`update_rows` 有 `literal/fillDown/fillSeries/template`，`normalize_column` 有 `trim/case/width`（可执行）+ `space/number/date`（仅建议） | 枚举值本身即模型可见 Schema（延续本仓"类型化入参让 Schema 自带形状"的手法，`AiTools.java:429-482`） |
| `value` | 字面量 / 模板 `"${a}-${b}"` / 引用同表其他列 / 枚举选项 | 枚举型字段按定义里的 `optionsJson` 校验，非法值进 `skipped` 而不是静默写入（§3.5） |
| `preview` | `count`（默认）/ `sample-diff` / `full-diff` | 三档定义与合规换算见 §3.3bis |
| `commit` | **恒为 `confirm`** | 写工具**不提供** `auto`；模型无权跳过人确认（原稿 `dryRun=false` 的"参数保留但无效"一并废弃） |

**歧义处置（谱系 §6.3.2 的五个真实歧义 → 本仓判据）**

| 用户原话 | 判据（可断言） | 处置 |
|---|---|---|
| "把空格去掉" | 命中值里存在**词中空格** | 只能出建议（`normalize_column` 的 `space` 规则不可 `commit=true`）；卡片列出 ≤5 条命中值，问"是否一并删词中空格" |
| "把这一行删了" | `scope` 缺省且**无选区** | 不猜：回"请先选中要操作的行（或用条件描述哪些行）"；有选区则以 `selection` 为准并在卡上回显行号 |
| "日期统一一下" | 出现歧义样本（如 `01/02/2026`、`20260105`） | `normalize_column(rule=date)` **只建议不执行**；必须走 `generative_form(scenario=CLARIFY)` 列出 ≤5 条样本 + 两种解释让人选 |
| "状态改成已发布" | `preview=count` 的影响面 ≥200 行且用户未指定范围 | 卡片强制"影响面模式"+ 二次确认（§3.3bis P0 大档），不必反问 |
| "把重复的删掉" | 命中主键重复 | 回"当前不支持自动去重；这是 N 组重复主键，可用 `review_cells` 查看明细"（`delete_rows` 属批③ 待裁） |

### 3.2 逐工具定义（名称 / 参数 / 副作用 / 确认 / 回灌口径）

#### 3.2.1 `read_sheet_summary`（↔ 调研 P0「数据行可查」，裁剪为"选区摘要"）

- 参数：`defCode`(必填)、`scope`(`selection|sheet|columns|rows`，默认 `selection`；无选区且未给 scope ⇒ 拒绝并请用户选行)、`columnCodes`(`columns` 时必填，≤5)、`rowRange`(`rows` 时必填，Excel 行号)、`predicate`(选填，缩到条件命中行)、`limit`(1..20，默认 5)
- 作用面：**当前激活标签页**的 `defCode` 表格；非激活/未挂载 ⇒ `degraded`（提示先打开该标签，不代开）
- 回灌（形如，纯文本、**禁 JSON 块**）：

```
表格：CURRENCY（工作表「币种」）  版本 #12
范围：scope=predicate · region = XN（命中 812 行 / 共 1,842 行）
规模：数据行 1,842 行 × 8 列；选区 B2:D41（40 行 × 3 列）
列（前 8 列 / 共 8 列）：code(编码)、name(名称)、region(地区)…
空值：name 空 3 行；region 空 0 行
重复主键：code 重复 2 组
采样（前 5 行，投影 3 列）：
  第 2 行 | code=CNY | name=人民币 | region=XN
  …
共 1,842 行，本次回 5 行（采样上限 20 行 / 2000 字符）
```

- 数据分级：D2 取样（**首个"业务行可进模型"的通道**）⇒ 必须配 D2 授权记录（见 §8 风险 1）+ 配置开关（§7-裁 4）
- 不返回：整列原文、超 20 行、任何未选投影列
- **条件回读前移**（谱系 §7.2：NL→条件回读提到 P2 前置）：回灌首行固定回读 `scope` 与命中数，于是"条件是否被正确理解"永远可见；写工具的卡片首行同样如此

#### 3.2.2 `aggregate_sheet`（↔ 调研 P0「聚合」；兼作**计数级预览**引擎）

- 参数：`defCode`、`predicate`(选填，`FieldQueryCondition`)、`groupBy`(columnCode，选填)、`columnCode`(度量列，选填)、`metrics`(`count|distinct|blankRate|min|max|sum`，默认 `["count"]`)、`limit`(分组显示上限，1..20，默认 20)
- 回灌：条件回读首行 + ≤20 组的分组表 + 总计 + `共 N 组（本次回 M 组）`；数值聚类只回聚合值，**不回原始行**
- **升档理由（谱系 §7.1）**：它一物两用 —— 既是 F8「分组聚合」的替代（本仓不做透视），又是 §3.3bis 的 **P0 计数级预览**（0 行业务数据、不触 D2）。因此它不再只是"读工具"，而是**所有写操作的前置闸**：任何写工具的 `preview=count` 都复用本工具的聚合器（同一段代码、同一口径）。
- 设计取舍：**默认回答形态是聚合，不是"给我看几行"**（对齐数据最小化 §4.1b）；`read_sheet_summary` 是例外路径且要带理由

#### 3.2.3 `inspect_columns`（↔ 调研 P1「导入映射诊断」，裁剪为"表头诊断"）

- 参数：`defCode`
- 回灌：`已匹配 6/8 列` / `缺失：生效日期、备注` / `多余：备注2、_unknown_col9` / `疑似映射（≤5 条）：列「名 称」→ 字段 name（理由：空白差异）；列「REGION」→ region（大小写）`
- 复用既有判据：`readRows().missingHeaders` + `normalizeHeader`（`utils/excel.ts:365-391`）；**只给建议，不改文件、不改定义**
- 与后端 `ExcelReader:89-109` 的"精确匹配 + 静默丢弃"互为补面：这里把"静默"变"可见"

#### 3.2.4 `review_cells`（↔ 调研 P0「预检问题可读」，落在**本地**校验）

- 参数：`defCode`、`scope`(`sheet|selection`，默认 `sheet`)、`predicate`(选填，只看命中行的问题)、`limit`(1..20，默认 5)
- 实现：直接复用 `SpreadGrid#validateLocal`（`:341`）→ `validateRows`（`utils/excel.ts:163`），**不出网、不落库**
- 回灌：`按字段聚合：name 必填缺失 4 处、region 枚举非法 1 处；主键重复 2 组` + `前 5 条：第 7 行 name「」必填为空；第 9 行 region「XX」不在可选值…` + `共 12 处`
- 与后端 `start_precheck` 的分工写清：**本地校验 ≠ 服务端预检**（服务端只查三族且全 ERROR，`PrecheckJobRunner`），本工具不替代预检、不声称"能过预检"
- **兼作"异常值标记"的读数面（谱系 F6-36）**：本仓服务端预检只查三族（必填/主键/引用），本工具补的是"类型 / 枚举 / 日期"这一族，因此它是"AI 能指出数据哪里不对劲"的最短路径；但它**只报告、不修复**（修复走 `normalize_column` / `update_rows`）。

#### 3.2.5a `replace_values`（↔ 谱系 F1 查找替换族，6 子场景）

- 参数：`defCode`、`scope`(同 §3.0)、`predicate`(选填)、`columnCodes`(必填，1..5)、`match`(`wholeCell`(默认)`|contains|prefix|wildcard|regex`)、`ignoreCase`(默认 true)、`search`(必填)、`replace`(必填，允许空串=删除子串)、`preview`(`count`(默认)`|sample-diff|full-diff`)
- 语义（**写在描述里，让模型一次说对**）：`wholeCell` = 整格等于 `search` 才替换；`contains` = 子串替换（保留非命中片段）；`prefix` = 前缀替换；`wildcard` = `*`/`?` 通配（`*` 可匹配任意长度）；`regex` = JS 正则（卡面必须回显正则原文）
- 卡面必显示：`match` 的中文 + `ignoreCase` + `search`→`replace` 的**原文**（正则尤其要原样显示 —— 谱系 F1-4「要回显正则给人看」）
- 典型问句："把状态是『停用』的都改成『禁用』"（`wholeCell`）/ "把名字里带『测试』两个字的去掉"（`contains` + `replace=""`）
- 回灌（应用后）：

```
已应用（用户已确认）：replace_values 改动 128 格 / 42 行
范围：CURRENCY 全表 · 条件「region = XN」（命中 42 行 / 共 1,842 行）
规则：整格相等 · 区分大小写=false · 「停用」→「禁用」
样例（前 3 处，Excel 行号）：第 5 行 status「停用」→「禁用」；第 8 行 status「停用」→「禁用」；第 12 行 …
跳过：2 格（校验器拒绝：status 枚举不存在「已停用」）
未保存：改动仅在浏览器内存，需用户点「保存到服务端」才落库；可撤销（undo_last_sheet_edit）
共 128 格
```

#### 3.2.5b `update_rows`（↔ 谱系 F3-18 条件更新；含 F2-17 填充语义）

- 参数：`defCode`、`scope`(默认 `predicate`)、`predicate`(`scope=predicate` 时必填)、`set`(必填，≤5 条)，每条 `{columnCode, mode:`literal|fillDown|fillSeries|template`, value?|template?|start?|step?}`、`preview`
- `mode` 语义：`literal` = 写成定值；`fillDown` = 用上方最近的非空值补空；`fillSeries` = 等差数列（`start`/`step`）；`template` = 模板字符串引用同表其他列
- **`fillDown` / `fillSeries` 属"补值"，卡面必须加一行警示**（谱系 F6-35：补值 = 伪造业务事实）：
  `注意：本次会用其他行的值补齐空单元格（共 312 格），请确认这些空缺确实应当补值。`
- 典型问句："把 region=XN 且 status=OLD 的行的 status 改成 NEW"（`literal`；条件回读首行必为 `region = XN 且 status = OLD`）
- 回灌（应用后）：同 3.2.5a 的形状，第二行改为 `范围：条件「region = XN 且 status = OLD」（命中 312 行 / 共 1,842 行）`，第三行改为 `规则：status ← 「NEW」`

#### 3.2.5c `normalize_column`（↔ 谱系 F6 数据质量族；**一工具双档**）

- 参数：`defCode`、`columnCodes`(必填，1..5)、`rules`(必填，≤3)：`trim|case|width`（**可执行**）与 `space|number|date`（**仅建议**）、`case`(`upper|lower`，`rule=case` 时必填)、`commit`(默认 **false**)、`preview`
- 两档语义（由 `commit` 决定，不拆两个工具名）：
  - `commit=false`（读侧，**不需要确认**）：只回"各规则将影响多少格 + 分布 + ≤5 个样例"，**零写入**；用于回答"这列脏不脏、脏在哪"
  - `commit=true`（写侧，**强制人确认**）：只允许 `trim/case/width` 三类"规则确定且可逆"的归一化；带 `space/number/date` 一律被后端 Guard 拒（见 §3.4）
- 为什么这三类可执行：`trim`（含 NBSP 等不可见字符）与 `case` 直接影响**主键判重**与**必填判空**（谱系 F6-30/31 判"最高/高"）；`width`（全角→半角）是本仓中文录入的最常见脏数据且双射可逆。其余（补缺、日期猜测、文本转数字）会**猜业务事实**，只出建议。
- 回灌（`commit=false`）：

```
归一化建议（未做任何修改）：CURRENCY.code
- trim：132 格（含首尾空格，其中 4 格含不可见字符 U+00A0）
- case → upper：27 格（小写混排）
- width：0 格
样例（前 3 处，Excel 行号）：第 7 行 code「CNY 」→「CNY」；第 19 行「cny」→「CNY」；…
提示：这些值会让主键判重把「CNY」与「CNY 」当成两条记录。执行请让 AI 用 commit=true 并确认。
共 159 格
```

#### 3.2.6 被裁掉的候选（说明 8 个工具里为什么没有它们）

其一，**`apply_formula`（写公式）** 与 其二，**`format_range`（改格式）**：裁剪不是省事，而是**物理上落不了盘**：导出与保存都走 `buildRowsXlsxBlob`（自产 OOXML、单一样式、仅值）。若硬做，用户会看到"AI 说加了公式/变色了"，下载后打开却是裸值 —— 直接违反本仓"结局不谎报"的红线。若某天要做，前置是**改导出链**（换 ExcelIO 保存会带评估版水印表、后端会当数据表读，见 `SpreadGrid.vue:328-338` 注释与证据 V3），属独立专项，不在本稿。

其三，**结构变换（插删列/转置/拆列/合并列）**：不是"风险高"而是"必然静默读错"（`ExcelReader.java:54-62` 按列号取字段，见 §1.2 表）。用户在 AI 里说"加一列备注"时，正确答复是"请改配置定义后重新导出/导入"，不是"我帮你插一列"。

其四，**`mark_rows`（条件标记）不独立成工具**：它的自然实现是 `conditionalFormats.addRule`（`d.ts` 谱系 §6.4 复核值 23660），但**样式不落盘**（`buildRowsXlsxBlob` 单一样式，`utils/excel.ts:610-616`）⇒ 用户会看到"标红了"、下载后却没有颜色。本稿把它降级为**预览态高亮**（写工具卡片里给改动格上色，纯前端绘制、不写 cell 样式、应用后清屏），并明确它不是"给用户改颜色"的能力（谱系 F3-20 的"预检可视化"由 `review_cells` 的聚合 + 预览高亮共同承担）。

其五，**去重的执行版**（自动删重复行）：见 §1.2；`delete_rows` 本身留到批③ 待裁（§7-裁 7）。

### 3.3 数据回灌的尺寸闸（单点 + 可断言）

唯一出口函数（`frontend/src/utils/sheet-tools.ts` 新模块）：

```ts
// ── 读侧（不变） ─────────────────────────────────────────────
```

规则（每条都配断言，§5 表内有对应用例）：

1. **行数优先于字符数**：先按行截到 20，再按字符截到 2000（沿用最小化调研 T-03 口径）；两者都触发时报最先触发的那一个。
2. **"共 N"恒在末尾**（即便未截断）——`共 1,842 行，本次回 5 行`。
3. 截断必有标记：`…[已截断：原 37 行 / 3,120 字符，已回 20 行]`。
4. 回灌是**纯文本**，禁止 JSON 块、禁止裸对象（对齐 R-166B「工具参数文案去 JSON 人话化」口径）。
5. 工具 **description 里写死"最多 20 行"**，与常量同源（防"描述说 20、实现 200"；最小化调研批 1 验收 #4 的同一要求）。
6. 双通道无需额外处理：本层自限 2000 字符 ≪ 前端帧 64KB 与 `ToolResultLimiter` 的 8000 字符，故**不需要** `truncated` 帧字段。
7. **三档共用同一把尺**：P0 只回计数与分组（不含行值）；P1 的行值与样例计入 2000 字符预算；P2 的 diff **不经过本函数**（它只在前端卡里渲染，0 行进模型）——因此任何写工具的 `preview=full-diff` 回灌文本里都不得出现逐行 old→new 列表。

### 3.3bis 预览三档（与数据最小化 R3/R8 的换算）

| 档 | 参数值 | 给人看什么 | 进模型的数据量 | 何时用 |
|---|---|---|---|---|
| **P0 计数级** | `preview=count`（**默认**） | 「将影响 1,240 行 / 2,480 格 · 分布：region=XN 812 行、region=SH 428 行」 | **0 行业务数据**（只有计数与分组；由 `aggregate_sheet` 同一聚合器产出） | 所有写操作的**第一档**，无条件先出 |
| **P1 采样 diff** | `preview=sample-diff` | 「前 20 条：第 12 行 status「停用」→「禁用」…」 | **≤20 行 / ≤2000 字符**（最小化 R3） | 人点"看样例"、或 P0 的命中数与用户描述差异大时 |
| **P2 全量 diff** | `preview=full-diff` | 卡片逐行渲染，可筛选/翻页（可上万行） | **0 行**（数据不经模型，走前端卡） | 大批量、要逐条核 |

**大批量（如 3 万行）的合规路径**（三步，全程 D2 不出浏览器）：

1. `update_rows(preview=count, predicate=…)` → 回灌「将影响 30,000 行 / 60,000 格」（**0 行数据**）；
2. 卡片切 **P2 全量 diff**（逐行可翻页，数据只在浏览器） + **大批量二次确认**（勾选「我了解影响范围」）：
   `本次将修改 30,000 行 / 60,000 格（超过 200 行）。请勾选「我了解影响范围」后再点「应用」。`
3. 用户确认 → 前端用 `setArray` **分块写**（`suspendPaint` 一次、按 500 行分块） → 回灌**仅计数**：「已应用（用户已确认）：update_rows 改动 60,000 格 / 30,000 行」。

**结论**：模型永远看不到 3 万行 —— 它只签一张"变更集"（`planId` + 计数 + 分布）。这正是谱系 §6.3.4 的换算结论，也与 Excel「绿标签 + 高亮格 + 变更摘要」、Claude「改后高亮所有改动格」同构。

**唯一硬拒绝线**：`格数 > SHEET_WRITE_HARD_MAX_CELLS(100,000)` ⇒ 拒绝并提示缩小 predicate（不是静默截断、也不是自动拆批）。

**自动拆批仍然不做**：分批必须由模型在**看到计数后**主动发起（每批一次确认），不允许引擎偷偷切段 —— 半批执行且不告知正是谱系风险清单里的"毒化历史"。

### 3.5 只读守卫、撤销与刷新失效

- **只读守卫**（两处，缺一不可）：① 执行器入口判 `readOnly`（页面能力返回 `{readOnly:true}` 即拒）；② 应用前再判一次（预览卡停留期间用户可能点了"保存并结束"）。理由：`sheet.options.isProtected` 挡得住键盘，**挡不住** `setValue`。
- **行指纹校验（新增，必做）**：本仓表内行**没有 rowKey**，行定位靠行号/选区，而用户随时可能手动排序、筛选、插入或删行（AI 不做这些，但人可以做）。因此 `plan` 生成时对每个目标行取**指纹**（`SHEET_FINGERPRINT_COLUMNS=2`：该行前 2 个"主键列或首列"的值拼接），应用前逐行复核；任一不符即**整批拒绝**并回灌：
  `表格在预览期间已变动（第 12 行的主键值已改变），本次未应用任何改动。请重新发起。`
  方向刻意保守：**宁可多拒一次，不可改错一行**。
- **撤销双轨（承接 §2.1）**：① 自有反向补丁（主路径，确定性；应用前把 `{r,c,old}` 存为反向补丁，深度 1、`planId` 绑定，`undo_last_sheet_edit` 应用之；无补丁 ⇒ 如实回"没有可撤销的 AI 修改"）；② 增强 = 若 §8 风险 13 的实测成立，则 `apply` 包在 `Commands.startTransaction/endTransaction`（`d.ts:32739/:32706`）内，让用户 Ctrl+Z 一次撤掉本次 AI 修改。**补丁仍保留** —— 因为 undo 栈会被用户后续编辑推进、且受 `options.allowUndo`（`:13978`）影响。两轨不互相替代。
- **刷新失效（与 L0 的硬交点）**：预览计划活在前端内存，刷新即丢。`restoreSuspendedSnapshot` 会给"请求帧已发、仍 PENDING"的条目重建卡（L0 裁决），于是刷新后会出现一张**点不动的待决卡**（写工具**无超时**）。收口：恢复路径识别"人工介入型前端工具 **且** 本地无对应 plan" ⇒ 渲染"预览已失效（页面刷新导致）"卡 + 唯一按钮**放弃**（提交 `cancelled=true`），文案要求模型重新发起。**此条必须与批② 同批测**（§5 T-17）。

## 7. 待裁选项（A/B + 建议）

**裁 1 · 确认落点**

| | A 前端内确认（把 `generative_form` 形态一般化） | B 后端确认门 + 前端二次下发 |
|---|---|---|
| 改动 | 后端 1 处名字集合 + 前端 store/AiPanel | 改 `kindOf` 二维（通道×风险）+ `PendingToolCall.kind` 语义 + `awaitConfirm` 放行后转 `awaitFrontend` 二次挂起 + 续跑结算（`resolvePending`）+ 前端 kind 三值过滤 + L0 `req` 位 |
| 卡片能否看到 diff | **能**（diff 在浏览器算，卡在浏览器画） | **不能**（后端只有模型参数；业务值不能为出卡而回传后端） |
| 风险 | HITL 出现两个落点（后端门 / 前端门），需在文档与卡面统一形态 | 触碰 4 个已闭环批次的契约面，回归面大 |
| 建议 | **采用 A** | 留作批③（若将来要求"AI 写操作必须有服务端审计门"） |

**裁 2 · 写工具粒度与确认机制**（谱系已改变原裁面）

- **粒度：已定 = 三个细粒度写工具**（`replace_values` / `update_rows` / `normalize_column(commit=true)`）。依据：SheetCopilot 消融实验（整合式动作拆细后 Exec@1/Pass@1 提升；参数一多模型就猜不准，谱系 §6.3.3）。**不再把"单工具 `transform_cells`"列为可选案**。
- **确认机制仍待裁（两案）**：
  - A1（建议）：**单工具内部挂起** —— 模型只看到一次调用，工具内部走"计数→（可选样例）→人确认→应用"；模型无法绕过确认。
  - A2：拆成 `preview_*`（只读，回 diff 摘要 + planId）+ `apply_plan(planId)`（写）两个阶段工具。优点：模型可据摘要改参重来；缺点：多一次往返 + 多一条"跳过预览直接 apply"的越权路径（需再加一道 Guard）。
- 建议 A1（理由：与"一次计划、一次批准"一致，且越权面最小）。

**裁 3 · 公式与格式**

- 建议：**都不做**（§3.2.6 的落盘证据）。若用户坚持，须先立"导出链改造"专项（换 OOXML 产物形态），本专项不承接。

**裁 4 · 开关默认值**

- 读（D2 取样）：建议**默认开** + 硬闸 20 行/2000 字符 + 可按环境关（关后工具直接 `unavailable`）。
- 写：建议**默认关**（按环境开启），对齐 Airtable/模型配置专项"管理员可整体关 AI"的取舍。
- 落点：`application.yml` 的 `app.ai.sheet.*`（若裁"要开关"），开关名与文案进 i18n 批③。

**裁 5 · 作用面与行定位**

- 作用面：只作用于**当前激活标签页**的表格（跨 defCode = 逐表调用，每次一次确认）。
- 行定位：`rowKeys` **当前不可用**（xlsx 来的行没有 rowKey）⇒ 默认 `selection`，其次 `predicate`；`rows` 行号仅在"同一次调用内、且指纹校验通过"时可用。
- 待裁：是否值得为"能按业务键定位"先在表格面引入 rowKey 列（隐藏列）？**建议不做**（会把展示态混进数据面，且与 `_meta` 列序强耦合）。

**裁 6 · 大批量上限档位**

- 方案 i（建议）：**分层上限 + 二次确认** —— ≤2000 格：卡片逐条 diff；>200 行：卡片切"影响面模式"并勾选二次确认；>100,000 格：硬拒绝。
- 方案 ii（原稿）：>200 行 / >2000 格**一律拒绝**。
- 建议 i：ii 会把谱系里权重最高的"3 万行批量修订"判死，而 §3.3bis 的 P2 全量 diff（0 行经模型）本就是为它设计的安全通道。**注意：这是对原稿的显式反转**，须在裁决记录里留痕。

**裁 7 · `delete_rows`（条件删除）是否做**

- 谱系 §6.3.3 把它列为五件之一，但 §7.1 的"建议做 6 项"**不含**它。
- 建议：**批③ 另裁**。理由：① 本仓删除的语义落点在导入侧暂存（`ConfigStagingRow.opType=DELETE`），前端删行只是"少一行"，两条语义并存会混淆；② 删除不可逆（相对"改值"），却同样只需要一张卡，确认成本被摊薄而风险升高；③ 真要做，必须配 P2 全量 diff + 二次确认 + 指纹。
- 若裁"做"：参数 = `predicate` + `preview` + `commit`（恒 confirm），回灌必须含"删除后行数 N → M"。

**裁 8 · `normalize_column` 一工具双档 vs 拆两工具**

- 方案 i（建议）：**一个工具名 + `commit` 二值**（读档零确认、写档强制确认）。
- 方案 ii：拆 `normalize_column`（建议）+ `normalize_column_apply`（执行）两个名。
- 建议 i：`commit` 只有两值、不增加选择复杂度，且让"先看建议再说执行"在同一轮完成；ii 的代价是工具数 +1（Schema 开销 + 工具表条目 + i18n 首批再 +1 行）。

## 8. 风险与边界（诚实登记）

1. **数据出仓面首次打开**：`read_sheet_summary` 是本仓**第一个**把业务行送进模型的通道（此前 18 工具全是 D0/D1）。缓解：R3 硬闸 + 投影 + 版本号 + 配置开关；**前置流程件** = 一份 D2 授权记录（谁批准、范围、字段 allowlist），按 R8 要求随批① 归档。未附该记录前，批① 不得合并。
2. **预览态不可持久**：刷新/换会话即失效；已按 §3.5 收口，但"用户填到一半刷新"是**必然发生**的（与 GF 表单同族），文案必须直说"预览已失效，请让 AI 重新发起"，不许假装还活着。
3. **无超时的代价**：写工具卡可无限期待决（与既有确认门一致）。**已知过度保守**方向安全；但"永远不被清理"的待决卡需靠用户放弃或停止本轮（`POST /api/ai/cancel`）收尾。
4. **屏幕数据非权威**：AI 改的是浏览器内存，用户可能不保存就关页面 / 或先下载未保存版本（`buildXlsx` 用的是 grid 当前内容，`:866`）。回灌必须写明"未保存"；不得出现"已保存到服务端"字样。
5. **`isProtected` 不是安全边界**：程序化写入可绕过，故只读守卫必须在前端执行器与后端 Guard（回灌复核）两层。
6. **性能**：批量写需 `suspendPaint/resumePaint` 且**抑制逐格事件**（否则 N 次 `data-changed` → N 次 `bumpVersion`）。未抑制 = UI 卡顿（登记为可断言项：T-12 断言 `data-changed` 恰好 1 次）。
7. **列映射仍是精确匹配**：`inspect_columns` 只给建议，不改 `ExcelReader`；"AI 自动映射并改文件"越界（调研 P1 明确"只给建议"）。
8. **评估版水印**：`VITE_SPREADJS_KEY` 留空时导出链自产 OOXML 已规避（`SpreadGrid.vue:328-338`），但若将来改用 ExcelIO 保存会引入水印表——本专项不碰导出链。
9. **不承诺跨轮一致**：与"服务端数据工具幂等"不同，屏幕摘要会因人工编辑而变（版本号是唯一可观测信号）。
10. **行号会漂移**：本仓表格行无 rowKey，用户手动排序/筛选/插删行都会让预览时的行号失效 ⇒ 已用指纹校验兜底（§3.5）；**未覆盖的残余**：若两行的"前 2 个指纹列"恰好相同（例如该表只有一个文本列且值重复），指纹无法区分 ⇒ 这类表只允许 `scope=selection` 且卡片提示"本表行无法唯一识别，请逐段操作"。
11. **大批量主线程**：3 万行 × 2 列 = 6 万格 `setArray` 仍是一次同步写；必须 `suspendPaint` + 按 500 行分块 + 单次 `data-changed`。**验收登记**：3 万行应用耗时需实测并记录（目标 P95 ≤ 1.5s，实测值随批② 补登记；超时不得静默延长，只能调低 `SHEET_WRITE_HARD_MAX_CELLS`）。
12. **`predicate` 双端求值器漂移**：前端 `matchesCondition` 与后端 `ConditionEvaluator` 是两份实现，任何一方改语义都会让"卡上说命中 312 行、实际只改 280 行"。缓解：T-23 一致性用例常绿 + 算子清单写进两处注释并互相引用。
13. **undo 事务未验**（TechPoint-U1）：`Commands.startTransaction/endTransaction`（`d.ts:32739/:32706`）+ `options.allowUndo`（`:13978`）能否把一次 `setArray` 折叠成一条撤销记录，**未实证**；不成立时只有 `undo_last_sheet_edit`（自有补丁）。不得在文档/文案里承诺"Ctrl+Z 可撤销"直到实测通过。
14. **`mark` 若用 `conditionalFormats` 会污染 `toJSON`**：条件格式规则会进 `toWorkbookJson()` 的产物（保存链路用的是 `toXlsxBlob`，暂不受影响，但测试与后续导出链改造会踩）。故标记一律走"屏幕态高亮 + 应用后清屏"，不调 `conditionalFormats.addRule`；T-31 用"产物字节一致"锁死。

## 9. 验收口径

1. **门禁**：前端 `vitest` 全绿（基数按落盘时实测，当前登记为 512/512 · 26 文件）+ `typecheck` 0 + `build` ✓ + `check-docs` 6/6 + 脱敏 0 命中；后端 `mvn test` 全绿（当前 702/702 · 112 suite）。
2. **四句话走通**（实机，非单测）：
   ① "这任务里 CURRENCY 有多少行 / XN 地区几行？" → 聚合回"共 N 行"，且**不含**未投影列原文；
   ② "这几行为什么不合规？" → `review_cells` 回聚合 + ≥1 条可定位明细（Excel 行号 + 字段 + 原因）；
   ③ "把 name 里的 XN 改成 西安" → **计数级卡**（影响 N 格/K 行）→（可选）点"看样例"看 ≤20 条 → 应用 → 回"已应用…未保存"；再对另一次点"取消" → 回"未改动任何单元格"且表格**像素级不变**；
   ④ "把 region=XN 且 status=OLD 的 status 改成 NEW" → 卡片**首行即条件回读**「region = XN 且 status = OLD」+ 影响面 → 应用。
3. **两层上限都可断言**：应用层 R3（≤20 行/≤2000 字符/必回"共 N"）有单测；通道层仍由 `ToolResultLimiter`（200/8000）兜底；写侧分层上限（2000 格 / 200 行 / 100,000 格）各有用例（T-14、T-31）。
4. **不越权**：拒绝即零写（adapter 写调用计数 = 0）；只读壳下写工具零写；`config_data_rows` 版本与暂存区行数在任何 AI 表格操作后**均不变**（对账断言）。
5. **契约不扩**：`git diff` 上 SSE 帧类型集不变（15 种不变）、`POST /api/ai/frontend-tool-result` 请求体不变。
6. **E2E**：主计数 29 → 31，`verify-e2e.ps1` 与汇总文案同批对齐（既有挂账 `:360`）。
7. **文档同批**：`stores/ai.ts:2760` 的"前端工具没有 HITL"注释、`frontend-tools.ts` 文件头"7 个 FRONTEND / 2 个登记"的口径、`ConfirmGate` 类注释"只有 generative_form 无上限" —— **三处注释必须同批订正**（否则代码与注释自相矛盾）。
8. **大批量合规**：用 3 万行的样例表跑 `update_rows(preview=count)` → 回灌文本**不含任何行值**（负断言：种子词表零命中）、卡片可翻页、需勾选二次确认、应用后回灌仅计数。
