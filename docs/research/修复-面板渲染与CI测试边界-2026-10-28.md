## 1 生产 ①：用户消息函数 ref 只挂用户消息 + 同元素早退

### 1.1 问题

流式回答期间（每帧一次 patch），**用户消息被反复标脏**：单一 `measureUserMsgOverflow` 每帧都要进一次"重量用户消息"的集合判定；同时**非用户块**（助手正文）也被登记进"用户消息正文元素表"，让脏集合与元素表都混进了不该有的 id。

### 1.2 根因

两处叠加：

1. 模板对**所有** `part.kind === 'text'` 的块都挂了同一个函数 ref（旧行 `:ref="userBodyRefFor(m.id)"`）—— 助手正文块也在内。
2. `setUserBodyRef` 收到元素时**无条件** `userBodyEls.set(id, el)` + `markUserMsgDirty(id)`（`AiPanel.vue:2028`–`:2036`）；而 Vue 的**函数 ref 在每次 patch 都会回调**，即使元素没换。

⇒ 一个 delta 帧（助手消息重渲）就产生一次"用户表新增 + 脏标记"，于是 `measurePasses` 里出现非空 id 集。

### 1.3 修改

- `:ref="m.role === 'user' ? userBodyRefFor(m.id) : undefined"`（`AiPanel.vue:319`）—— 只有用户消息的正文块登记，其余给 `undefined`（不建 setter、不登记）。
- `setUserBodyRef` 加早退：`userBodyEls.get(id) === el` 直接 `return`（`AiPanel.vue:2030`–`:2033`）⇒ 只有**挂载**与**换元素**（展开/收起重建）才标脏。

### 1.4 证据

- 用例：`frontend/tests/ai-panel-batch7a.spec.ts:392`「布局只测新增/变化消息：流式助手 token 不重复量全部用户消息」。
- 断言：一帧 `delta` 之后 `debugOf(wrapper).measurePasses.slice(baseline)` 必须**每条都为空集**（`:407`–`:408`）。
- **RED → GREEN**：旧码下这一帧会把助手块登记 + 标脏 ⇒ 该窗口出现非空 id 集 ⇒ RED；现为 GREEN。用例本身的"夹具自检"（`:405`–`:406`：帧必须落在已在屏的宿主里）保证红不是夹具造出来的假象。

### 1.5 边界

- 早退只覆盖"同一 id 同一元素"；元素换绑仍标脏，**没有**取消重量（收起态下 `scrollHeight` 仍为内容自然高，量取稳定这一前提未被改）。
- 未改 measure 判据：184 px 溢出阈值、`userMsgOverflowed` 只在集合真变化时换引用、展开/收起单独量该条 —— 全部原样。
- 未跑该整文件 / 前端全量：本条只有单点回执。

## 2 生产 ②：`mdStreamTick` 并进 `partMemo` 的流式正文依赖

### 2.1 问题

上游**停吐**（或流式中断）时，75 ms 防抖窗口内被合并掉的最后一段增量**不现身**：正文停在倒数第二帧，"末帧丢失"表现为回答末尾少一截 / 少一次换行。

### 2.2 根因

链路是"tick 变了 ⇒ 缓存必然未命中 ⇒ 但组件根本没被重渲"：

1. 流式 markdown 的缓存键含 `mdStreamTick`（`AiPanel.vue:2743`），flush 回调 `setStreamFlushHandler` 每落地一次就 `mdStreamTick.value += 1`（`:2727`–`:2730`）。
2. 但 `partMemo` 的 `text` 分支只把 `part.text / part.streaming / part.truncated / …` 列为依赖（`:3610`）—— **tick 不在里面**。
3. 停吐时文本已经是最新值、再没有下一帧来推动文本变化 ⇒ `blockMemo` / `messageMemo` 判定"没变"直接跳过重渲 ⇒ 已经算对的新 HTML 永远没人读。

⇒ **落地信号不在文本里**，这是判据与信号不同源。

### 2.3 修改

```ts
if (part.kind === 'text') {
  deps.push(part.text, part.streaming, part.truncated, part.noticeCode, part.originalChars, part.returnedChars, part.truncatedReason)
  if (part.streaming) {
    deps.push(mdStreamTick.value)   // 只有流式块吃这个依赖
  }
  return deps
}
```

（`AiPanel.vue:3609`–`:3616`）**历史块（`streaming === false`）不带该依赖** ⇒ 历史缓存不被 tick 搅动（与 `markdownHtml` 里"只有 `message.streaming` 才走流式缓存"同口径）。

### 2.4 证据

- 用例：`frontend/tests/ai-panel-parts-render.spec.ts:5787`「项7（aj14d）：流式块 75ms 防抖（首帧立即 + 窗口内合并 + 静默满窗落地）+ 块级稳定 key 跨闭合不变」的**组件装配面**（`:5819`–`:5845`）。
- 断言链：窗口内必须仍显示首帧、**不含增量**（`:5836`–`:5837`）；把时钟推过窗口 + flush 之后，**增量必须上屏**（`:5841`）。
- **RED → GREEN**：去掉本依赖时 `:5841` 红（DOM 停在首帧），加上后 GREEN —— 这正是"75 ms 末帧可落地"的单点。
- 时钟钉在 `performance.now` 上（`:5824`），窗口判据不靠机器快慢。

### 2.5 边界

- 只对**流式**正文块生效；tick 变化会让所有**正在流式**的正文块各重渲一次（停吐是低频事件，代价可接受但**未压测**）。
- 未改防抖本身：`STREAM_DEBOUNCE_MS = 75`、块级稳定 key（`data-fence-key`）、流式缓存容量/TTL、markdown 渲染器 —— 一行未动。
- **不声称**"所有末帧场景都能落地"：真实网络断流、SSE 静默超时、页面隐藏期间停吐等路径未在真实浏览器验证。

## 3 生产 ③：GF `defaultModel` 只取 schema 默认值

### 3.1 问题

两个方向的错判，同一根因：

- **草稿被当成"没填"**：刷新/草稿恢复回来、值由 `initialValues` 灌入的高级字段，被判定为"未填"⇒ 该字段落在长尾第 7 张之后时被折叠 —— **把用户自己的数据藏了起来**。
- **枚举首选被当成"已填"**（旧口径的另一侧代价）：枚举字段的初值恒有值（schema 首个合法选项），若把它算作"已填"，高级条件就**永远摊开**、渐进披露失效。

### 3.2 根因

`defaultModel` 直接取了 `initialModel()`（旧 `FormRenderer.vue:437`），而 `initialModel()` 会把 `initialValues` 合进 base（`:400`–`:430`）。⇒ **对照基线里含用户数据**，`hasUserValue`（`:518`–`:527`）对草稿字段必然返回 `false`。

### 3.3 修改

- 抽出 `schemaDefaults()` = `buildInitialValues(props.schema)`（`FormRenderer.vue:391`–`:393`）—— **只含 schema 默认值，不含任何用户数据**。
- `model` 仍 = `initialModel()`（`schemaDefaults` 之上叠加形状相符的 `initialValues`，`:400`–`:436`）⇒ 表单的**初值口径不变**。
- `defaultModel = schemaDefaults()`（`:442`）⇒ 基线只含 schema 默认值。净效果：**草稿算已填**（与基线不同）、**枚举首选仍不算已填**（与基线相同）。

### 3.4 证据

- 用例：`frontend/tests/gf-renderer.spec.ts:425`「必填 / 已填值的高级字段不折叠（不藏用户的东西）」，夹具 `initialValues: { f6: '已经填了' }`。
- 断言：`#gf-field-f6` 必须存在（`:430`）且值必须是"已经填了"（`:431`）。
- **RED → GREEN**：旧码（基线含 `initialValues`）下 f6 被判"未填"⇒ 折叠 ⇒ 元素不存在 ⇒ RED；现在存在 ⇒ GREEN。
- **枚举半边没有独立断言**（如实）：由同一 `hasUserValue` 读数推演 —— `defaultModel[field.key]` 即枚举初值，`model[field.key]` 也是 ⇒ 相等 ⇒ 仍算未填。相邻的 `gf-renderer.spec.ts:404`「常用条件同时在场；长尾可选条件折叠…」用的是全文本字段，**不覆盖枚举**。

### 3.5 边界

- 只改"用户是不是真的填过"的**对照基线**；不改 `model` 初值（枚举初值仍落进 model、仍可提交）、不改校验 / 联动显隐 / 提交载荷 / 只读回放。
- 只读态与 CLARIFY 本来就不折叠（`:540`–`:542`），不受本改影响；`FILTER_COMMON_FIELD_COUNT = 6` 与三条不折叠例外（必填 / 已填 / 有错）原样。
- **未跑**该整文件 / 前端全量。
