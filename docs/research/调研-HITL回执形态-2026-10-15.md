# 调研 · HITL/生成式表单回执形态（业界）· 2026-10-15

> 调研问题：HITL 确认门 / 生成式表单（generative_form）在用户动作完成后，回执应渲染结构化只读 UI 还是展示原始 JSON？
> 结论：**业界没有一家把原始 JSON 当回执默认展示；完成态一律渲染结构化只读 UI，JSON 折叠进「技术细节/开发者视图」或消失。** 本件为 R-166B/v7.9 设计裁决依据。

## UX 准则

- Smashing Magazine《Practical Interface Patterns For AI Transparency》：Thinking Toggle（progressive disclosure 到 raw 视图，**须先脱敏**，避免泄露内部字段名与 token）+ Audit Trail（结果页给 receipt 入口）。
- 摘要行公式：Action Word + Specific Item + Limits，优于"操作成功"。

## 对本项目的建议口径（已被用户裁决采纳，见 裁决-回执原卡只读态-2026-10-15.md）

1. 卡面=动作+对象+关键值；状态词对齐 `已批准/已提交/已拒绝/已超时`。
2. 已提交值默认渲染只读 label-value UI；值做可读化（枚举中文标签、文件→文件名、布尔→是/否）；以用户实际提交值为准而非原始 tool params。
3. 原始 JSON 不放卡面默认视图；如保留则折叠进「原始参数」且脱敏（内部键名/token/签名 URL 不外露）。
