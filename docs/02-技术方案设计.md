## 1. 总体架构与关键决策

### 1.1 架构总览

```
┌─────────────────────────── 浏览器（每页签一个 Session） ───────────────────────────┐
│  左：业务工作区（Vue Router 多页面/向导）      右：AI 对话栏（常驻组件）            │
│        │  REST(JSON, X-Session-Id)                  │  POST /api/ai/chat (SSE)    │
│        │  GET  /api/sse?sessionId= (EventSource) ◄──┤  两条通道都收 SSE 事件       │
└────────┼────────────────────────────────────────────┼────────────────────────────┘
         ▼                                                ▼
┌────────────────────────── 后端 Spring Boot 3.5.14 ────────────────────────────────┐
│  适配层：  TaskController / CatalogController / AiController / SseController       │
│  ──────────────────────────────────────────────────────────────────────────────── │
│  AI Runtime（Spring AI 1.1.8 高层 API）：                                          │
│    ChatClient(OpenAiChatModel) + MessageChatMemoryAdvisor(InMemory ChatMemory)     │
│    每轮按会话上下文动态注入 @Tool 工具对象（渐进式披露）+ 动态系统提示词             │
│    工具 = 业务服务层的薄适配（与 REST 同一服务层）                                  │
│  ──────────────────────────────────────────────────────────────────────────────── │
│  业务层：  TaskService(状态机) / ExportRunner / ImportRunner / ValidationService    │
│           CatalogService / ConfigDataService / SessionRegistry / EventService      │
│           ProgressManager(内存进度+取消) / ExcelIO 适配在前端                       │
│  ──────────────────────────────────────────────────────────────────────────────── │
│  存储：H2 文件库（任务/配置定义/字段/数据行/范围字典）   内存：会话/进度/SSE emitter │
└───────────────────────────────────────────────────────────────────────────────────┘
```

**联动模型（核心）**：
- **单一事实源**：任务/步骤/进度只存在于后端。REST 与 AI 工具是同一业务服务层的两个适配面 → 天然解耦（FR-S03）。
- **视图同步用推送（SSE）**：状态变更 → `EventService` 向会话广播任务快照/进度/活动事件 → 工作区和对话栏各自渲染。
- **AI 上下文用拉取**：每轮请求注入轻量状态摘要 + 工具现查明细（业界 Cursor/Copilot 模式；参考三份架构咨询的共识“pull 优于 push”，避免 token 膨胀与旧数据决策）。
- **导航主权归前端**：AI 事件只携带任务快照，前端在首页时自动进入向导、否则弹通知（FR-S04）。

### 1.2 关键决策记录（ADR 摘要）

| # | 决策 | 备选 | 理由 |
|---|---|---|---|
| D1 | AI Runtime 全后端，用 Spring AI 高层 `ChatClient + ChatMemory + @Tool + Advisor` | ①手写 OpenAiApi Agent Loop（kimi-1 方案）②前端 Runtime | 硬约束"能用 Spring AI 就不自研”。已实验验证：deepseek-flash 回放含 tool_calls 的 assistant 历史（不带 reasoning_content）返回 200，高层路径可行；工具全部在后端执行，无需 HITL 暂停-恢复 |
| D2 | 关闭 deepseek-flash 思考模式：`extra-body: {thinking: {type: disabled}}` | 保留思考并透出思维链 | 实验验证该参数被接受且彻底消除 reasoning_content；助手类任务无需思维链，省 token、降延迟、规避思考模型历史回放的兼容坑 |
| D3 | Excel 生成/解析/打包全部在前端（SpreadJS ExcelIO + JSZip） | 后端 Apache POI | 硬约束“能用现成组件不自研”；参考项目验证：模板含原生 Excel 数据校验、导出保留在线编辑结果；“检查/导入/发布"仍在后端（校验的是前端提交的结构化行数据） |
| D4 | 任务数据用「暂存区」方案（status=STAGED + task_id） | 临时表 | 同表状态位实现简单、可审计、发布=范围内替换；满足“导入后未发布”的隔离要求 |
| D5 | 不引入 Redis | 嵌入式 Redis | 单实例演示系统，会话/进度均为单机内存态；H2 文件库承担持久化。引入 Redis 只增加运维复杂度（NFR-02） |
| D6 | SSE（EventSource + POST-SSE）而非 WebSocket | WebSocket | 单向推送足够；POST-SSE 承载 AI token 流（fetch+ReadableStream 解析），EventSource 承载会话事件通道；参考项目同款已验证 |
| D7 | 工具渐进式披露三层防御：按任务类型动态注册工具 + 系统提示词列当前步骤约束 + 工具执行层步骤守卫 | 全量工具 | 参考三份架构咨询结论：动态注册是最有效的越权防线，提示词约束引导，执行层兜底 |
| D8 | 会话=内存 ChatMemory（MessageWindowChatMemory, 窗口 30），sessionStorage 只存 sessionId | 持久化对话 | 需求明确：页签内唯一、不持久化、刷新不丢；服务重启清空可接受 |
| D9 | 任务参数整体存 JSON CLOB（task.params），含各步骤状态与结果 | 多张明细表 | 步骤结构因任务类型而异，JSON 灵活；行数据量级（≤千行）完全可控 |
| D10 | Maven 项目级 settings（阿里云镜像 + spring 源站排除名单）；前端无 .npmrc（走 yarn 全局镜像） | 全局配置 | 参考项目踩坑结论：华为云镜像同步滞后导致 Spring AI 拉取失败 |


## 4. 任务状态机与步骤

```
任务状态（粗粒度）：WAITING(等待用户) / EXECUTING(后台执行中) / SUCCESS / FAILED / CANCELLED
"为什么在等"由 current_step + 步骤内状态表达（参考架构咨询：避免 WAITING_FOR_XXX 状态爆炸）

EXPORT_CONFIG:  SELECT_CONFIG → SET_CONDITION → EXECUTE_EXPORT(→SUCCESS)
IMPORT_CONFIG:  SELECT_CONFIG → PREPARE → CHECK → IMPORT → PUBLISH(→SUCCESS)

步骤守卫（服务层统一校验，REST 与工具共用）：
- 未选配置不得进入后续步骤
- 导出：EXECUTE 中不得改选择/条件
- 导入：无数据不得检查；检查有 ERROR 不得导入；未导入不得发布
- 允许回退：PREPARE 可重做（覆盖数据）→ 重新检查 → 重新导入（清空旧暂存）→ 发布
- 后台操作互斥：同一任务同时只允许一个操作在执行

依赖顺序：导入/发布按 CONFIG_DEF.depends_on 拓扑排序执行（被依赖者先行）
```

**耗时模拟**：每个配置项处理 `200ms + 行数×8ms`（进度事件驱动，前端不伪造）；导入/发布含事务性写入。

## 6. SSE 事件契约

**会话通道**（GET /api/sse?sessionId=，EventSource，25s 心跳）：

| event | data | 触发 |
|---|---|---|
| state | `{cause:CREATED/UPDATED, task:TaskDTO}` | 任务创建/步骤推进/选择/条件/数据提交等任何状态变化（REST 或工具触发） |
| progress | `{taskId, op, phase, percent, current, total, perConfig[], message}` | 后台操作进度心跳（每配置项+内部细分） |
| activity | `{source:AI, tool, text}` | AI 工具执行的活动卡片（对话栏渲染） |
| notice | `{level, text}` | 警告/错误提示 |

**AI 对话通道**（POST /api/ai/chat，fetch 流式）：

| event | data | 说明 |
|---|---|---|
| token | `{text}` | 增量文本 |
| done | `{status:finished/error, finishReason}` | 结束 |
| error | `{message}` | 异常（含重试提示） |

## 7. AI Runtime 设计（Spring AI 1.1.8）

```java
// 装配（AiRuntimeConfig）
@Bean ChatMemory chatMemory()            // MessageWindowChatMemory.builder().maxMessages(30).build()  (默认内存仓库)
@Bean ChatClient chatClient(OpenAiChatModel model, ChatMemory memory) {
    return ChatClient.builder(model)
        .defaultAdvisors(MessageChatMemoryAdvisor.builder(memory).build())
        .build();
}
```

**每轮对话流程**（AiChatService，POST /ai/chat → SseEmitter + 专用线程池）：
1. 会话互斥校验（同会话上一轮未结束则拒绝）；
2. `SessionRegistry` 取会话 → 活动任务 → 构建动态系统提示词（角色/行为准则/**当前状态摘要**/当前步骤约束/可用操作说明，全中文）；
3. 按上下文组装工具对象（**渐进式披露**）：
   - 基础（总是）：`get_current_state / list_task_types / list_config_items / get_config_item_fields / create_task / list_recent_tasks / open_task / get_task_progress / cancel_task`
   - 导出任务：`set_selected_configs / get_query_fields / set_query_conditions / start_export / get_export_summary`
   - 导入任务：`set_selected_configs / get_prepare_status / submit_config_data / start_check / get_check_results / start_import / get_import_summary / start_publish`
4. `chatClient.prompt().system(sys).user(msg).advisors(a->a.param(ChatMemory.CONVERSATION_ID, sessionId)).tools(工具对象...).stream().chatResponse()` → 逐 token 发 `token` 事件；工具在模型内部循环自动执行（OpenAiChatModel 内置 ToolCallingManager）；
5. 工具执行时通过 `ToolContext` 携带 sessionId → 变更后发 `state`/`activity` 事件 → 工作区实时联动；
6. 流结束发 `done`；MessageChatMemoryAdvisor 自动读写会话记忆。

**工具实现规约**：@Tool 方法返回紧凑结构（LinkedHashMap/记录），复杂入参用 JSON 字符串 + 描述约束；每个变更类工具：步骤守卫 → 调服务层 → 发事件 → 返回摘要。

**会话生命周期**：sessionId（UUID）由前端生成存 sessionStorage；后端 `SessionRegistry`（ConcurrentHashMap + lastAccess，@Scheduled 每 5 分钟清理空闲 >2h 的会话并 `chatMemory.clear(sessionId)`）。

## 8. 校验规则引擎（检查/导入/发布共用）

## 9. 前端设计

**布局**：`App.vue` = 左侧 router-view（flex-1，业务工作区）+ 右侧 `AiPanel`（宽 400px，可折叠，Tailwind 布局）。

**路由**：`/` 首页（任务类型卡片 + 最近任务）；`/task/:id`（向导，按任务类型内部渲染导出/导入向导）；`/tasks` 任务中心。

**状态管理（Pinia）**：
- `useTaskStore`：当前任务快照（由 REST 响应与 SSE state 事件共同驱动）、活动任务导航逻辑；
- `useAiStore`：消息列表（历史 + 流式）、活动卡片、发送/停止/清空；
- `useProgressStore`：进行中操作的进度（SSE progress 事件）；
- `useSessionStore`：sessionId（sessionStorage）、SSE 连接管理、启动时恢复（GET /session/state + /ai/history → 若有活动任务自动导航）。

**SpreadJS 集成**（`utils/excel.js` + `components/SpreadGrid.vue`）：
- 表头写入视口第 0 行（ExcelIO 不导 colHeader 区的坑，参考项目已验证）+ 冻结首行；
- 枚举/范围列：DataValidation list（导出为 Excel 原生下拉）；数值列 number validator；必填列 formula validator；布尔列 CheckBox cellType；
- `buildWorkbook(fields, rows)` / `readRows(spread)`（表头归一化：trim/去 `*` 前缀/忽略大小写 + 类型转换）；
- `toXlsx(spread)`（ExcelIO.save）+ `zipAndDownload(files)`（JSZip）；
- 模板 = buildWorkbook(fields, [sampleRow]) → toXlsx；多模板 → zip；
- LicenseKey 经 `VITE_SPREADJS_KEY` 注入（评估模式仅水印，功能可用）。

**导入上传**：el-upload 选择文件（xlsx×N 或 zip×1）→ 前端解包/解析（excelio.open + readRows）→ 按文件名（去扩展名）匹配已选配置项编码 → 逐个 POST /tasks/{id}/data；未匹配文件列表报错。

**导出下载**：结果页签为 SpreadGrid（可编辑）；勾选配置项 → 各自 toXlsx → 单个直接下载 / 多个 JSZip 打包；「全部下载」固定全选打包。
