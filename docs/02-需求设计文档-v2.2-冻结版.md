## 1. 背景与目标

### 1.1 业务背景

企业在实施/运维过程中存在大量**动态配置数据**（参数字典、阈值规则、地区/项目级业务配置等），具有以下特征：结构随业务演进频繁变化、按"全局/地区/项目"分层生效、配置间存在依赖与引用关系、变更需要受控（校验→暂存→发布→可追溯）。传统方式是实施人员手工维护 Excel 再导入系统，效率低、易出错、不可追溯。

### 1.2 建设目标

1. **配置即元数据**：配置项结构（字段/类型/校验/层级/依赖/引用）完全由元数据驱动，新增配置项零代码上线。
2. **实施任务化**：导出/导入/变更全程以"任务"为载体，状态可查、进度可见、异常可恢复、结果可追溯。
3. **AI 辅助实施**：常驻 AI 助手理解当前工作区上下文，可代为导航、选配置、填条件、发起任务；破坏性操作必须经人确认（HITL），AI 行为全程可留痕。
4. **生产可用（demo 口径）**：具备版本回溯、无主体操作流水、多实例与可观测能力；**本期不做认证授权与数据权限**（【DC-10 修订】原"生产可用：具备认证授权、数据权限、审计、版本回溯、高可用与可观测能力，满足企业合规要求"→ 新"无认证授权、无数据权限；审计降为无主体操作流水；**安全边界：demo 仅限内网/本地受信环境使用**，不按企业合规验收"；生产化时按 DC-09 原 A2/A6 恢复认证与权限）。

### 1.3 范围

- 本期包含：配置定义管理、配置数据浏览、导出配置任务、导入配置任务（检查/暂存/发布）、任务中心、AI 对话助手、版本管理、无主体操作流水（【DC-10 修订】原"认证授权与审计"→ 新"无主体操作流水"：认证登录、角色与权限不再属于本期范围）。
- 本期不包含：配置运行时下发到业务系统的通道（由下游系统自行拉取/API 查询）；工作流引擎级多级审批；用户体系、角色（RBAC）、数据权限与认证登录（【DC-10 修订】新增排除项——demo 无用户/角色/权限，面向内网/本地受信环境）；**发布审批流（FR-3.6）整体不在本期范围**——仅保留审批接口与实体预留，M2 再议，本期发布由执行方直接执行并全量留痕。
  （【DC-09 修订】A1：原"工作流引擎级多级审批除外，本期为单级审批（接口预留）"→"发布审批流本期不含，仅接口预留、M2 再议"）

## 2. 主体与权限口径（DC-10）【DC-10 修订】

**本期无用户体系、无角色（RBAC）、无数据权限、无认证登录。**（【DC-10 修订】原 §2"角色与权限【新增】"整节 → 新 §2"主体与权限口径"：原 3 角色表（操作员/管理员/只读审计）、原权限模型"RBAC + 数据权限（按层级 GLOBAL/REGION/PROJECT 只读/可写两级）"、原"AI 工具调用继承同一权限上下文，不得越权"**整节移除**。）

1. **无主体**：系统不设用户、角色、权限与登录入口（原 Spring Security 表单登录 + BCrypt 方案随 DC-10 一并移除），API 不区分调用主体，也不存在"越权"语义，验收中不再设越权项。
2. **无主体操作流水**：原审计保留但降级——去掉"操作人"与 IP 字段，保留来源（界面/AI）标记，优先级降为 P2，见 §3 AuditLog 与 FR-6.1。
3. **HITL 确认门保留不变**（FR-5.3）：它属于交互安全（破坏性操作需人确认），**不属于权限体系**，不受本裁决影响。
4. **AI 工具不携带权限上下文**：原 FR-5.5"AI 权限约束"整条移除（见 §4 FR-5 节末标注）；"AI 与人工走同一服务层、同一路径、业务校验一致"的**业务校验口径保留**（由 FR-5.4 承载）。
5. **安全边界声明**：本 demo **仅限内网/本地受信环境**使用，不得部署于公网或非受信网络；相关约束落入 §5 非功能需求"安全"行。
6. **转生产恢复口径**：出现真实多用户/合规要求时（即 DC-10 推翻条件触发），按 DC-09 原 **A2**（3 角色 + 按层级只读/可写数据权限）与 **A6**（Spring Security 表单登录 + BCrypt，OIDC 预留配置口）恢复；本版移除属 demo 期取舍，不构成对原能力的否决。

## 3. 领域模型

| 实体 | 说明 | 关键属性 |
|---|---|---|
| ConfigDefinition 配置定义 | 配置项元数据 | 编码、名称、层级（GLOBAL/REGION/PROJECT）、字段集、依赖（dependsOn DAG）、状态（启用/停用）、版本 |
| ConfigField 字段定义 | 配置项的字段 | 编码、类型（文本/长文本/数字/布尔/日期/枚举/引用）、必填、枚举选项、引用目标（defCode.field）、是否业务键、**是否敏感（sensitive 元数据标记）** |
| ConfigData 配置数据 | 已发布生效数据 | 定义编码、范围（地区/项目）、行数据（JSON）、版本号、状态（PUBLISHED）、生效时间 |
| StagingData 暂存数据 | 导入未发布的草稿 | 按任务隔离，发布后清除 |
| ConfigVersion 配置版本【新增】 | 每次发布的快照 | 版本号、diff 摘要、发布人、发布时间（审批人字段预留，M1 不启用审批故留空）；**回滚以快照为数据源重新走导入发布通路，不设回滚指针与独立回滚审批** |
| Task 任务 | 一次导出/导入实施过程 | 任务号、类型、状态机、当前步骤、参数（选择集/条件）、创建人 |
| Job / JobItem 作业 | 任务内的异步执行单元 | 类型（EXPORT/PRECHECK/IMPORT/PUBLISH）、状态、进度、逐项明细、行级校验问题 |
| AiSession AI 会话 | 页签级 AI 对话 | 会话 ID、页签绑定、**消息历史（存 Redis，滑动 TTL，默认 6 小时）**、待确认交互、TTL |
| AuditLog 无主体操作流水【新增】（【DC-10 修订】原"审计日志【新增】/全量操作流水"→ 新"无主体操作流水"） | 全量操作流水（无主体） | 动作、对象、前后值摘要、来源（界面/AI）、时间；**无"操作人"字段、无 IP**；以**审计表 + 按对象/时间检索页**提供查询，不建报表体系 |
| Approval 审批单【新增，本期预留】 | 发布审批 | 任务/批次、申请人、审批人、结论、意见；M1 不启用，仅保留实体与接口定义 |

（【DC-09 修订】A5：ConfigField 增加 sensitive 字段级元数据标记，仅标记留口，不实现掩码规则引擎与加密存储）
（【DC-09 修订】A3：ConfigVersion 原"含回滚指针、回滚走审批"→"回滚以快照为数据源重新走导入发布通路，无独立回滚流程与审批"）
（【DC-09 修订】D1：AiSession 原"消息历史（持久化）"→"消息历史存 Redis，滑动 TTL 默认 6 小时，无长期留存"）
（【DC-09 修订】A4：AuditLog 明确"审计表 + 检索页"从简口径，不建报表体系）
（【DC-09 修订】A1：Approval 原为本期实现实体→降为接口/实体预留，M1 不启用）
（【DC-10 修订】原 AuditLog"操作人、动作、对象、前后值摘要、来源（界面/AI）、IP、时间；以审计表 + **按人**/对象/时间检索页提供查询"→ 新"动作、对象、前后值摘要、来源（界面/AI）、时间；以审计表 + **按对象/时间**检索页提供查询"：去掉"操作人"与 IP 两个字段、去掉"按人"检索维度；条目实体名由"审计日志"改为"无主体操作流水"；优先级由 P0 降为 P2（对应 FR-6.1））

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-2.1 | 配置多选；选择时自动拓扑排序提示依赖项（未选中的依赖项导出正式区数据为准） | P0 |
| FR-2.2 | 按所选配置的字段动态生成查询条件表单（类型感知：枚举下拉、日期选择器等）；支持字段级条件（EQ/NE/LIKE/IN/范围） | P0 |
| FR-2.3 | 异步导出：实时进度（SSE）、逐配置项明细、可取消；导出结果支持在线编辑（SpreadJS）、单文件下载、勾选打包、全部打包（ZIP） | P0 |
| FR-2.4 | 字段级敏感标记【新增】：字段定义支持 sensitive 元数据标记，仅作标记留口与界面展示；**不实现脱敏、不做掩码、不提供可配置脱敏规则引擎**（【DC-09 修订】A5：原"导出数据脱敏，标记为敏感的字段按角色脱敏、脱敏规则可配置"→"字段级 sensitive 元数据标记，仅标记留口，不实现掩码规则引擎"；优先级 P1 不变）（【DC-10 修订】原"不实现按角色掩码"中的"按角色"措辞随 DC-10 无角色而失效 → 新"不做掩码"；脱敏口径不变） | P1 |
| FR-2.5 | 导出量大时的分片与限流保护【新增】：单任务行数上限可配，超限需审批 | P2 |

（【DC-09 修订】A1：原向导步骤"…→ 导入（暂存）→ 提交审批 → 发布"→"…→ 导入（暂存）→ 发布；提交审批为预留环节"）

| 编号 | 需求 | 优先级 |

## 6. 验收标准（摘要）

1. 导出/导入/发布全链路可走通且全程留痕（任务、版本、操作流水三位一体；审批留痕在审批流 M2 启用后适用）（【DC-09 修订】A1：原"任务、审批、版本、审计四位一体"→"任务、版本、审计三位一体，审批留痕后置"）（【DC-10 修订】原"审计"→ 新"操作流水"：名称随无主体操作流水口径调整，三位一体结构不变）
2. 发布语义正确性：多范围并存时范围内替换互不误伤；并发发布冲突被检测并提示。
3. 故障恢复：导出/导入执行中重启服务，恢复后任务状态正确、可续看进度。
4. AI 全链路：渐进披露生效（不适用工具不出现）、HITL 确认/拒绝行为正确、会话在 Redis TTL（默认 6h）内刷新与重启不丢（无长期留存）、token 与工具调用数据可入库查询（不提供统计报表）（【DC-09 修订】D1/A4：原"会话刷新与重启不丢、token 与工具调用可审计"→"TTL 内不丢、无长期留存；token 与工具调用仅入库查询，无报表"）（【DC-10 修订】原"渐进披露生效（**越权**工具不出现）"→ 新"（不适用工具不出现）"：披露口径保留，越权语义随无权限体系移除）
5. 自动化测试套件全部通过（详见《04-测试用例文档》），核心链路 E2E 可一键重复执行。
