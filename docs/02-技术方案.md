## 2. 关键架构决策（ADR 摘要）

### ADR-1 动态结构的存储模型：通用行表 + JSON
配置项结构完全动态（字段集合/类型/必填/选项随时变化），若为每个配置建物理表则需 DDL 权限且变更成本高。决策：
- `config_def` 表存定义，字段集合以 JSON 存 `fieldsJson`；
- `config_row` 通用行表存数据，业务字段以 JSON 存 `dataJson`，加 `defCode/scope/published/batchId` 结构列。
- 查询条件在内存过滤（中小规模最优）；大数据量可平滑演进为“条件→SQL 视图/列式存储/搜索引擎”（详见 docs/03-实现方案.md §扩展性）。

### ADR-2 分层级模型：层级挂在定义上 + 行携带“范围”
“一个配置项只属于一个层级”→ 层级是配置定义的属性（GLOBAL/REGION/PROJECT）。REGION/PROJECT 下同一配置有多份数据（每地区/项目一份），用行的 `scope` 列表达维度。导出/模板中 scope 体现为“范围”列。

### ADR-3 未发布数据模型：batchId + published 标志
导入落库即为草稿（published=false + batchId），发布时同批次转生效（published=true）并**删除**同定义旧生效数据，保证唯一生效版本。相比“临时表”方案：不需要第二套表结构/两套解析逻辑，数据演进路径最短，且天然支持“发布前预览草稿”。

### ADR-4 AI Runtime 放后端 + 框架合规（能用 Spring AI 的绝不自行实现）
- API 密钥仅后端持有（环境变量 `DEEPSEEK_API_KEY` 注入，不入仓库，前端无感）；
- **协议/循环/Schema 全部交给 Spring AI**：工具 = `@Tool` 注解方法（JSON Schema 自动生成）；Agent 循环 = ChatClient 流式 + 模型内部 ToolCallingManager；历史 = MessageChatMemoryAdvisor + 自定义 ChatMemory（H2 持久化）。业务只需在官方扩展点做两件事：组合包装 DefaultToolCallingManager（HITL 确认门 + 工具执行前后 SSE 可见性）；
- 前端只负责渲染流式输出 + 执行后端下发的 `ui_event`（与用户点击同一 store action）。
- 借鉴前端 AI Runtime 思想（Kimi 参考文档）：上下文快照随消息上传、工具结果驱动 UI、workspace 版本号。

### ADR-5 状态同步：事件总线 + 契约层（解耦双向）
- **业务 → AI**：契约层注册上下文快照提供者，发送消息时聚合摘要级快照 {page, step, selectedDefs, conditions, taskId/batchId, workspaceVersion}；用户手动操作经事件总线通知 AI 面板“工作区已更新”（数据版本随快照上传，AI 挂起期间用户改动可感知）；
- **AI → 业务**：工具执行返回 `ui_event`，AI 面板只经事件总线转发，契约层（唯一映射点）写入与用户点击相同的 store action → 两侧状态必然一致；
- **解耦**：AI 面板与工作区互不 import；移除任一方，另一方完整可用（AI 操作由后端工具直连业务服务执行，工作区操作与 AI 无关）。

### ADR-6 会话生命周期：页签唯一、H2 持久化（刷新/重启不丢）
sessionId 由前端 `sessionStorage` 生成（页签唯一）：新页签=新会话（无历史）、同页签刷新保留、关页签即销毁。会话存储为内存 Map（热）+ H2 `ai_session` 表（冷，消息与上下文快照 JSON）：刷新页面与**后端重启**后对话历史均不丢；空闲 30 分钟内存与库同步清理。系统提示词每轮重建不入库，推理内容仅流式展示不入库。

### ADR-7 渐进式披露：工具按页面注册
工具元数据（ToolMeta）携带 pages 白名单与 confirm 标记；系统提示词与请求 toolCallbacks 只包含当前页面工具 → 模型视野收敛（省 token）、工具权限被页面隔离（防越权）。通用工具（get_ui_state/navigate_to_page/list_config_defs）全页面可见。

### ADR-8 HITL（人在环）：确认门 + 超时/断连默认拒绝
破坏性工具（导入/发布/写数据/改定义）标记 confirm=true：组合包装的 ToolCallingManager 在执行该工具前注册确认门并挂起（boundedElastic，不占 Netty 事件循环）、下发 confirm_tool 卡片；用户确认/取消经 `POST /api/ai/confirm`（普通 JSON）释放确认门，原 chat SSE 流继续推进；**客户端断开（completeWithError 触发）自动释放确认门并终止流**，杜绝线程泄漏。未确认即发新消息 → 自动视为拒绝（AG-UI 超时安全默认）。普通读操作与导出为 autoExec。

### ADR-9 进度方案：SSE 进度中心 + 任务持久化快照
参考项目无独立进度通道（其文档自述），本系统自建：ProgressHub（topic=export:{id}/import:{id}）推送 progress/done 事件 + 订阅即回快照（刷新可恢复）+ 心跳保活；任务状态/文件清单落 H2，服务重启后可查。行级推进 + 可配置模拟延迟使“大数据量可见进度”。

### ADR-10 Excel 互通：POI 生成/解析，SpreadJS 在线编辑，DV 经隐藏 sheet 规避 255 字符上限
- 后端模板：说明 sheet + 数据 sheet（表头+示例行+原生下拉数据验证）；
- SELECT 选项写入隐藏 sheet（`选项_{字段}`），DV 公式引用，规避 Excel List 公式 255 字符限制（参考项目教训）；
- 表头匹配：中文名或字段编码归一化匹配，容忍必填标记；未知列→警告；缺列→错误；
- 导出文件名为 `{编码}.xlsx` → 可直接回传导入，形成“导出→导入”闭环（zip 打包同规则）。

## 4. AI Agent 循环（Spring AI 官方实现）

1. 用户消息 + 上下文快照 → 合并影子状态 → 重建系统提示词（含当前页工具清单）；
2. `ChatClient.prompt().system(...).user(...).toolCallbacks(当前页).toolContext({session,sink,services}).advisors(记忆).stream().chatResponse()` —— 工具自动执行循环由 OpenAiChatModel 内部 ToolCallingManager 完成（协议与回填全由框架处理）；
3. 每个 ChatResponse：`getOutput().getText()` → delta 事件、`getMetadata().get("reasoningContent")` → reasoning 事件（思考折叠展示）；
4. HooksToolCallingManager（官方 manager 的组合包装）在每次工具执行前/后下发 tool_start/tool_result；confirm 工具执行前挂起确认门；
5. 客户端断开 → SSE completeWithError → 自动释放确认门 + 终止流（线程无泄漏）。

## 6. 数据模型

| 表 | 关键字段 | 说明 |
|---|---|---|
| config_def | code(唯一)/name/level/fieldsJson/dependsOnJson/enabled/sortOrder | 动态配置定义 |
| config_row | defCode/scope/dataJson/batchId/published | 通用数据行 |
| import_batch | defCodesJson/orderJson(拓扑)/filesJson(每文件状态)/status/progress | 导入批次 |
| export_task | defCodesJson/conditionsJson/filesJson/status/progress | 导出任务 |
| ai_session | sessionId(主键)/messagesJson/contextJson/lastAccess | AI 页签会话持久化 |

批次状态机：`CREATED→CHECKING→CHECKED→IMPORTING→IMPORTED→PUBLISHING→PUBLISHED`（异常→FAILED）。
文件状态机：`UPLOADED→CHECKED→IMPORTED→PUBLISHED`（异常→ERROR/SKIPPED）。

## 8. 安全设计

- API 密钥仅后端（环境变量 `DEEPSEEK_API_KEY` 可覆盖默认值）；
- 工具按页面隔离（渐进披露）+ 破坏性操作确认门（HITL）；
- zip 上传防路径穿越（规范化后前缀校验）；文件名严格匹配配置编码；
- 工具结果回灌模型前截断，防上下文污染；会话空闲清理；
- CORS 仅开发放开（同源代理为主路径）。

## 9. 主要风险与应对

| 风险 | 应对 |
|---|---|
| SpreadJS 商业授权 | 未授权为评估模式（水印）；`VITE_SPREADJS_KEY` 预留注入（.env.local 不入库）；功能不受影响（17.1.5 实测） |
| 推理模型 reasoning_content 回传 400 | Agent 循环回填时置空（已实现+测试验证） |
| 流式单帧多工具调用异常（1.1.8 合并器限制） | parallel_tool_calls=false |
| LLM 长输出超时 | 读超时 180s（WebClient 流式） |
| 内存过滤条件在大数据量下的性能 | 演进路径见 docs/03-实现方案.md §扩展性 |
| AI 输出不稳定 | 工具强约束（schema 自描述）+ 确认门兜底 + 错误如实回灌 |
