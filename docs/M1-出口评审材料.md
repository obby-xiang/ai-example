> 用途：M1（单实例里程碑）出口评审会主持人用材料。评审由业务方主持、逐项人签字。
> 材料性质：结论数据由指挥官汇总核对（文中标【指挥官已核】）；证据文档指针均为仓库内**真实存在**的文件，供评审现场调阅原件。
> 脱敏口径：本材料不含密钥（如有引用一律 `***`）、不含真实用户名、不含内网 IP；仓库与本机相关位置一律以占位符（`<MAIN_V2>`、`<MAVEN_HOME>`、`<MEMURAI_HOME>`）表述。

## 四、M2 候选清单摘要

M2 候选池在 M1 出口前已收敛成形，涵盖四类：**门禁与测试**（E2E 进门禁的路线 a、GF6 默认关闭）、**订阅与持久化**（R1 慢订阅者、R2 seq 持久化、§13.2#2 压测、表单态入镜像）、**守卫与配置收紧**（条件写操作符校验前移、CORS 白名单配置化、预检查后替换窗口收紧、原型键黑名单同步）、**清理与产品决策**（AiController 死代码清理、系统提示词未引导 `generative_form`、O2 产品决策）。其中 §13.2#2 压测与 pub/sub 订阅者离线兜底随 M2 多实例激活包一并落地（DC-11 既定路径）。上述各项的具体范围、批次与验收口径由 M2 计划阶段细化，本材料仅作清单摘要，不展开。

## 五、评审议程建议

1. **陈述基线**——主持人开场；指挥官/技术负责人陈述评审基线：HEAD `61286e2`、工作区干净且与 `origin/main-v2` 同步、CI 近 5 次 run 连续 success。
2. **逐项过出口标准**——按「二、对照表」四项六行逐行宣读结论，需要时可现场调阅对应证据文档原件与 `scripts/verify-e2e.ps1` 输出。
3. **复核结论确认**——宣读 GLM-5.3 异厂商独立复核报告（`docs/evidence/M1-出口复核-GLM-5.3.md`，**已落库**，总结论「通过（附保留）」）的逐条结论，并同步宣读 DS-V4-Flash 的 E2E 带 key 复跑确认（`docs/evidence/M1-E2E复跑确认-DS-V4-Flash.md`，27/27 全绿，闭合 GLM 报告保留项 #1）；表中「独立复核状态」列已按报告回填，评审现场直接引用结论文号。
4. **备查项处置**——就「三、备查观察项」①②③ 逐项形成处置意见：①记入会议记录、不阻塞，复核列填写口径 M2 统一；②**升格处置：M2 承接＝必须动作**，§13.2 清单表更新纳入 M2 首个任务；③不阻塞，主表回填与一致率总账建立记 M2。
5. **M2 排期意向**——就「四、M2 候选清单摘要」确认优先级与锚点，特别是 §13.2 清单表更新的承接安排（实际开放 10 项，纳入 M2 首个任务）。
6. **签字**——业务方、技术负责人、复核人逐栏签署，形成 M1 出口结论（通过／有条件通过／不通过）。
