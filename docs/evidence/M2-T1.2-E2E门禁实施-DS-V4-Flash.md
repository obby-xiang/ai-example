### 1.1 桩的关键设计（S1–S4 落地要点）

- **端点面**：`POST {AI_BASE_URL}/chat/completions` → `text/event-stream`；非该路径的 GET/POST 回 200 JSON（探活用）。
- **响应面**（预制 SSE，形态对齐本仓历史 DC-14 实验遗留的桩与帧样本）：
  - 工具轮：`{role:assistant,content:''}` → `tool_calls[{index:0,id,type,function:{name,arguments}}]` → `{}` + `finish_reason='tool_calls'` → `[DONE]`；
  - 文本轮：分片 `content` → `{}` + `finish_reason='stop'` → `usage` 帧（含 `prompt_tokens_details.cached_tokens` / `completion_tokens_details.reasoning_tokens`）→ `[DONE]`。**满足硬规范②"正常收尾必须有终帧"**。
- **收敛四契约**（设计草案 §3.3，硬要求；后端工具循环无迭代上限）：
  ① 目标工具必须出现在本请求 `tools[]` 才允许发起调用（未披露即文本收尾）；
  ② 每会话轮次上游调用上限 6，越界只发文本；
  ③ 上下文中已有 `role=tool` 即"续轮"，只发文本（不回灌工具调用）；
  ④ 任何解析失败一律文本收尾，不猜、不静默发工具调用。
  `--self-check` 的第 5/6/7 项就是对①②③的**模拟循环自证**（逐路由"首轮→工具调用、续轮→文本"，断言调用数 ≤6 且必然终止）。
- **回显实现**（对应 GF1-A6/GF4-A5b 的会话记忆断言）：取本请求最后一条 `role=tool` 的内容，按"JSON 对象 / 双层字符串 / 前缀混合"三形态反解（`extractJsonObject`），逐行输出 `key=值`；反解不到则给固定收尾句。
- **路由表 6 条**（每条都带 `requiresTools`，披露清单先行）：

  | 路由 id | 触发（用户消息含） | 披露前置 | 发出的调用 |
  |---|---|---|---|
  | GF-FILTER | `scenario=FILTER` | `generative_form` | `generative_form{form:{scenario:'FILTER',fields:[keyword(text,required)+minRows(number)+effectiveDate(date)+amount(number)+scope(enum XN/HD)]}}`（**union 模板**一供 GF1/GF3/GF4；只有 `keyword` 标 `required:true`，否则 GF4 的改值重发只带 keyword+scope 会被回灌闸门 400 拒） |
  | GF-CLARIFY | `scenario=CLARIFY` | `generative_form` | `generative_form{form:{scenario:'CLARIFY',fields:[exportScope(enum ALL/SELECTED)+includeInactive(boolean)]}}` |
  | TC17-PUBLISH | `start_publish` | `start_publish` | `start_publish{taskId}`（DANGER ⇒ 产品挂确认门） |
  | TC16-EXPORT | `start_export` | `start_export` | `start_export{taskId}`（DANGER ⇒ 产品挂确认门） |
  | TC16-NAVIGATE | `导出向导` | `navigate_to` | `navigate_to{page:'export',taskId}`（FRONTEND 通道 ⇒ 产品下发 `frontend_tool_request` 等回灌） |
  | TC15-LIST-DEFS | `配置定义` | `list_config_defs` | `list_config_defs{}`（只读 ⇒ 执行后文本收尾，供 TC15 的 `delta ≥ 1`） |

  `taskId` 由用户消息里的「任务 &lt;n&gt;」提取，路由参数用整串占位符 `${taskId}` 替换为数字。
- **违规模式**（裁决 #8：默认关闭，仅缺陷注入开启）：`--violate-form-keys`（FILTER 模板丢字段）、`--violate-form-type`（字段类型改 `html`）。

## 7. R3 回退预案（**仅写入，未实施**；裁决 #10）

**触发条件**：首次真实 CI run 中，出现以下任一事实即触发：
1. `pwsh`（脚本第 9 步）在 ubuntu runner 上因 `Add-Type -AssemblyName System.IO.Compression.FileSystem`（或 `System.Net.Http`）不可用而失败；
2. 脚本里 `"$tmp\<文件名>.xlsx"` 一类反斜杠拼接在 Linux 上导致读/写/打包/上传失败（如 `Test-Path`/`Copy-Item`/`ZipFile::Open` 报错或产物找不到）；
3. `services: redis` 的端口映射未能让宿主后端连上 `127.0.0.1:6379`（就绪门在 90s 内不过且 `/health` 报 `redis.available=false`）。

**回退动作（按顺序、最小改动）**：
1. `e2e` job 的 `runs-on` 由 `ubuntu-latest` 改为 `windows-latest`；
2. 删除 `services:` 段，改为一个"启动本机 Redis"的 step（Windows runner 自带 `redis` 不可用时的候选：`choco install redis-64`、或下载 Memurai/Redis for Windows 可移植包后 `Start-Process`，并以 `redis-cli ping` 作为就绪判据）；
