> 来源=agent-cray3idr/output.log（2026-10-26 归档）· 六问排查稿（思考块「共 N 字」由来与可算真实耗时）
> 性质：本次只读分析/调研的**脱敏副本**，属历史证据；为**分析稿**，结论以 `docs/research/` 总册与「规格复核补正」为准。仅做本机路径/仓库名/个人用户名占位与空白清理，**技术结论、计数、状态词一字未改**。

## 结论先行

1. **「共 N 字 · 点击展开」不是产品决策，而是 2026-10-15 视觉重做时的“无数据替代方案”**：demo 写的是「已用 3 秒 · 点击展开」，本仓当时既没有思考帧、也没读帧时间，于是用 `text.length` 补位，注释里写明“不伪造时长”（`frontend/src/components/AiPanel/AiPanel.vue:3086-3095`）。
2. **帧里没有“耗时”字段**。但**每一帧都带 `atMs`（服务端钟）**，包括 `message_start/message_end{kind:'reasoning'}` 与每个思考 `delta`，且这些帧都进归档。所以“完成后耗时”**不需要后端新增字段**，只要前端把这两个 `atMs` 存到段上（当前是直接丢弃的）。“进行中计时”只需要前端自建 1 秒 tick（仓库现在没有任何 JS 秒表，`工作中…` 是 CSS 动画）。
3. **唯一真正缺数据的是历史回放/已完成轮刷新**：`/history` 根本不返回思考内容（也没有段级时间），刷新后思考卡整块消失。要在这条路径显示耗时，才需要后端新增暴露字段（含段起止），属新需求，不建议夹带。

## 二、四条路径的数据充分性与耗时口径

| 路径 | 现有数据 | 能否只靠前端可靠实现 | 口径说明 |
|---|---|---|---|
| **流式（首轮实时）** | `message_start(kind=reasoning).atMs`、每片 `delta.atMs`、`message_end(kind=reasoning).atMs` | **能**（需新增段级可选字段，前端内部改动） | 起点建议取“首个 reasoning 帧的 `atMs`”（≈ 模型开始想）；终点取 `message_end(reasoning).atMs`。进行中秒表**不能**用“服务端 atMs − 客户端 Date.now()”（钟可能不同步），应用客户端锚点：首帧到达时记 `Date.now()`，完成时**切成服务端差值**（`end.atMs − start.atMs`）显示，避免两次口径漂移 |
| **续跑（HITL 决策后 / 工具轮后再思考）** | 每段各有独立 `message_start/end(kind=reasoning)`（新 emitter 或 CAS 复位后重开） | **能** | 天然“一段一张卡、一段一份耗时”；人工等待与工具执行**不计入**任何思考段。**需你定口径**：是“每卡各自的思考时间”，还是“同消息多张卡求和”；若同消息多段，则一条气泡里会出现多张思考卡（现状即如此） |
| **断线重连（同页 reattach，lastSeq>0）** | 内存里的 part 对象保留；补发的是 `delta`（带原始 `atMs`） | **能** | 起点不丢；断线空档会被计入（与服务端 atMs 差一致）。若在段开着时断线，完成态仍准确 |
| **刷新恢复（在途轮）** | `restoreInFlightRound` 清段 + `lastSeq=0` 全量重放；镜像存 `parts` 原样 | **能，但有边界** | 起点帧会重放 → 可按原始 `atMs` 重建。**例外**：轮次帧数超 `STREAM_WINDOW=6000`（`RedisFrameStore.java:81`，`MAXLEN ~` 近似裁剪）时起点可能已被裁掉 → 只能显示“≥N 秒”或不显示，**不得回落到“从当前时刻起算”**（会假报 0） |
| **历史回放 / 已完成轮刷新** | `toHistoryItem` 不含 reasoning 文本、不含段级时间；前端历史只建 text+tool 段 | **不能** | 现状是**思考卡整块消失**（不是“没有耗时但有正文”）。要在这条路显示思考卡与耗时，必须后端加暴露字段（文本可复用已存的 `metadata.reasoningContent`；**段起止需新持久化**）——属新增字段/新需求，需你裁决是否本批做 |

一句话：**“进行中计时 + 完成后耗时”在实时/续跑/重连/刷新在途这四条路上，纯前端可做，后端零改动；历史回放这条路缺数据，且思考卡本身现在是消失的。**

## 五、建议交互方案（供审，未实施）

### 方案 A（推荐，纯前端）
1. **数据**：`ReasoningPart` 增可选 `startedAt?: number`、`endedAt?: number`、`lastFrameAt?: number`（均服务端 `atMs`）。
   - `parts.ts`：reasoning 段首帧写 `startedAt`（建议取该帧 `atMs`，等价于“模型开始想”）；每片 `delta` 刷新 `lastFrameAt`；`message_end(kind=reasoning)` 写 `endedAt`（需在该分支判 `kind` 后再封口）。`done/error` 若没有 `message_end`，用 `lastFrameAt` 兜底。
   - 这些字段随镜像自动存活（`stores/ai.ts:891-901`），无需改镜像版本。
2. **文案**：摘要改为
   - 进行中（`part.streaming && ai.loading`）：`思考中 · N 秒`
   - 已结束：`已用 N 秒`
   - 无 `startedAt`（旧桩/旧归档/起点被裁）：进行中只显示「思考中」（不带数字），已结束**不显示耗时**（不伪造）。
   词条走 i18n（新增 2-3 个键，zh/en 对称；`{n}` 占位两侧同名）。
3. **开合**：**保留**卡头点击 + chevron + `v-show` 展开体，只删摘要里的“共 N 字 · 点击展开/收起”；顺手补 `aria-expanded`（与工具卡头 `339` 对齐）。
4. **秒表**：只在“存在 streaming 的 reasoning 段”时起 1 个 `setInterval(1000)`，段结束/面板卸载即清。
   - 注意：`AiPanel.vue` 是 3700 行单组件，面板级 `nowTick` 会**每秒重渲染整棵消息树**。建议抽一个小卡头子组件（同目录已有 `ContextPill.vue` 等先例）自持计时器；或至少让 tick 只影响该 `<span>`。
   - 不必复用 `utils/polling.ts`（那是轮询语义，带在途守卫/dirty flag，过重）。

后端在 `message_end(kind=reasoning)` 增 additive `durationMs`。**不推荐为首选**：`atMs` 已有，等于同一事实存两份，还要双端 conformance 同步。只有当你决定“历史回放也要耗时”时，后端才**必须**动：在 `toHistoryItem` 暴露思考段（文本复用 `metadata.reasoningContent`）+ 持久化段级起止（新字段）。
