## 5. 实机自验抓到的两处缺陷（**已修**，非纸面推测）

### ① preflight 关闭 ⇒ 纯 `border-*` 不显（圆环不可见的真因）
- 现象：首轮实机 dump `iconRing = "0px none rgb(26,127,69)"` —— 声明 `border-[1.2px]` 后 **border-top-width 仍是 0**。
- 根因：仓库 `tailwind.config.js` 关掉 preflight（`corePlugins.preflight=false`），**无全局 `border-style:solid`**；Tailwind 的 `border-[1.2px]` 只出 `border-width`，style 恒 `none` ⇒ 环不画。v7 蓝本依赖 preflight，故在 demo 正常、在本仓照抄即失效（模板既有写法 `border border-solid border-[#eef0f3]` 正是本仓的约定）。
- 修法：三态环一律显式 `border-solid`（`AiPanel.vue:1059-1071`）。
- 复验：`iconRing = "1px solid rgb(26,127,69) | radius 50% | box border-box"`；运行态环 `"1px solid rgb(37,99,235) | bottom rgb(205,220,255)"` + `animation: spin 1s infinite`。
  （声明 1.2px/1.6px，Chrome 的 computed `border-*-width` 一律取整成 1px —— v7 蓝本同值同法，表现一致。）

### ② hover 与"选中态任意变体"同特异度 ⇒ 命中顺序漂移（选中态会被悬停吃掉）
- 现象：`[&.is-on]:text-[#2563eb]` 写法下，实机悬停选中按钮时颜色仍是 `#1f2328`（悬停灰）。
- 根因：`.x.is-on`（0,2,0）与 `.x:hover`（0,2,0）**同特异度**，胜负取决于 Tailwind 产出顺序；该顺序随全仓候选集变化（本地单文件 temp 构建里 is-on 在后、dev server 里在前，实测已不一致），**不可依赖**。
- 修法：**按态整体换色板**（选中态不挂任何 `hover:*`）：`ICON_BTN_IDLE` / `ICON_BTN_ON_BLUE` / `ICON_BTN_ON_RED` 三串互斥绑定（`AiPanel.vue:409-452`）；`is-on` 只留给 SVG 填充（`[&.is-on_svg]:fill-current` 特异度 0,2,1 恒压 `[&_svg]` 0,1,1，实测生效）。
- 复验（悬停中换态）：`{color: rgb(37,99,235), bg: rgb(239,244,255), fill: rgb(37,99,235)}` —— 蓝族且悬停不回退，与 v7 `.is-on:hover` 同表现。

> 附带发现（非缺陷，记档）：`getComputedStyle` 在 150ms `transition` 期间读的是过渡起点值，样式探针须等 ~450ms 再读（v1 探针即因此误判）。
