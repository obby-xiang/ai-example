## 4. 已知残留 / 待跟进（如实登记）

1. **刷新后有 ≤2s 的「等待人工确认」窗口**：快照里的 `atMs` 是陈旧帧口径，按口径①不再折算，倒计时须等挂起流首个心跳（`ConfirmGate.HEARTBEAT_SECONDS = 2s`）校正。用户口径已明示「restoreSuspendedSnapshot 后等首个心跳校正」，本批如实照办；若要消除这 2s 空窗，需引入服务端钟偏移的持久化（本批未做，登记为去向）。
2. **陈旧帧判新是时间启发式**（`FRESH_FRAME_TOLERANCE_MS = 5000`）：若在确认帧到达后 5s 内刷新/重挂，该帧会被误判为新鲜而折算一次（回满值），随后首个心跳按 `min` 校正、不回退（≤2s 内收敛）。彻底消除需给帧加"实时/回放"显式标记（需后端配合，登记为去向）。
3. **后端 TIMEOUT 的工具卡 tag 仍是「会话已失效」**：`expired` 一态承"空历史降级"与"后端超时"两义，本批只把**本地作废**分流为「已超时作废」；后端超时那条仍有 tag/徽标口径不一致（徽标已是「! 已超时」）。属 R-160 词表旧账，未在本批扩面。
4. **409 且 3s 内 `runs/current` 也不给结局**：保留提交态（按钮继续禁用，同 id 不再提交）+ 一条提示，不伪造任何裁决；收口出口是刷新页面或后端结局帧到达。
