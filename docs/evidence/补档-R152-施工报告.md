## finish 返回值方案与调用方适配

- 方案：`JobProgressService.finish` 由 `void` 改 `boolean`，返回值 = 本次是否**实际落写**终态（作业仍 PENDING/RUNNING 才 true；已被先到者胜守卫拦下 = false）。原「先到者胜、后到者不覆盖」语义零变化；两分支 heartbeatRegistry.clear 统一（原即两分支都清）。
- 调用方适配清单：`finish`（作业终态写）**唯一调用方 = `JobTerminalWriter.apply`**（`grep` 全仓实证）；`JobWatchdog` 走 `terminalWriter.complete` 非直调 finish；`finishItem` 是配置项级、与本次无关。故仅需适配 JobTerminalWriter 一处。测试侧 `JobProgressServiceTerminalGuardTest` 4 用例以 void 语句调用，返回被忽略仍编译通过，未改。

## 主修语义

`JobTerminalWriter.apply`：`wroteTerminal = finish(...)` → 仅当 true 才 `taskService.applyJobOutcome` + `taskSseService.publish(JOB_DONE)`。迟到 COMPLETED 被 finish 拦下（作业已 CANCELLED）时返回 false ⇒ 任务态**不翻回 COMPLETED**、**不发 JOB_DONE**（理由：作业行已是 CANCELLED，再发 COMPLETED 的 JOB_DONE 会让前端收到与库态矛盾的结局事件）。事件语义裁定 = 丢弃时不发。

## StaleJobRecoveryRunner 核查结论（只核查+说明，未改）

- 它**不经 `JobProgressService.finish`**（`jobRepository.save` 直写 + `taskService.applyJobOutcome` 直调），故不自动获益。
- 它**不产同类矛盾态**：①只扫 PENDING/RUNNING（仅存在于非终态任务——终态任务被 `assertTaskNotFinalized` 拦着建不了新作业）；②恒置任务 FAILED（从不置 COMPLETED）；③CANCELLED 任务的作业已是 CANCELLED，不在扫描集。故无需改其行为。

`JobService.java:72-94`：`CANCELLED`→409；`ACTIVE/FAILED`→`:80-81` return 放行；`COMPLETED`→核最终作业，无成功最终作业→`:93` 放行。即 **FAILED→重新发布→COMPLETED 的 rework 流合法**（新 PUBLISH 作业 finish 真落写 → applyJobOutcome(COMPLETED) → 任务 FAILED→COMPLETED）。本修法未给 `applyJobOutcome` 加任何单调闸，rework 流原样保留，符合禁止方案。
