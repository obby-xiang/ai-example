## 4. 错误卡族内联（demo v7.7 裁决区 08 改后口径）

**铁律落地**：错误卡**内联于对话流、按错误发生的位置插入，绝不做顶部固定** ⇒ 卡挂在**出错那一轮的消息**上
（`ChatMessage.errorCard`，store 写入）⇒ 面板在该轮元信息行之后渲染。实测 `position: static`、
`insideMessageFlow true`、`sameRowAsBubble true`（`s5c-evidence.json`，真机断网轨 + 注入轨各一次）。

判据 = 按错误码分派：**429 → 红族 / content_filter → 灰族 / context_length_exceeded → 蓝族 / 其余沿用红卡**。

### 映射表（store 现有错误产生点 → 变体）

| 现实错误产生点（`stores/ai.ts`） | 码 / 形态 | 承载 | 卡变体 | 真实性 |
|---|---|---|---|---|
| SSE `error` 帧（`handleFrame` case `'error'`，:2008） | `frame.code`（如 `UPSTREAM_STREAM_ERROR` / `AI_RUN_FAILED`） | `notice` 单行槽（口径不变）+ **内联卡** | 按码分派；未分类 ⇒ **通用红卡** | **真实路径**（上游 503 实测走此路） |
| 开流前失败（`handleChatError`，:1191+） | `ApiError.code`；缺省 = HTTP 状态码字符串（**429 额度即此形态**） | 同上 | 按码/文案分派 | 真实路径（`code='429'` 无后端产出点 ⇒ 注入+单测） |
| 网络异常（`handleChatError` 非 ApiError 分支） | 无码，`error.message`（如 `Failed to fetch`） | 同上 | **通用红卡** | **真实路径**（`page.route` abort 实测，见 §6 轨三） |
| 断流 ADR-6（缺 done/error 终帧） | `streamInterrupted` | 顶部 `alert-interrupted`（S5c 前既有独占） | **不出卡**（demo 铁律原文明确排除） | 真实路径 |
| 409 `SESSION_BUSY` | 码 | 顶部 `alert-busy-conflict`（蓝）+ 一键重挂 | **不出卡**（避免与顶部 Alert 重复报同一件事） | 真实路径 |

1. **`check-docs` ⑤ 需删除入索引**：该断言按 `git ls-files` 全量逐个读文件，删掉一个**已跟踪**文件后，
   只要删除未进索引就必然红（`frontend/src/styles/ai-chat.css => 文件缺失或被删除`）。
   故本批**只把这一条删除暂存进索引**（`git add frontend/src/styles/ai-chat.css`，**未 commit**，工作区其余改动全部未暂存），
   之后 6/6 绿。撤销方式：`git restore --staged frontend/src/styles/ai-chat.css`（随后 ⑤ 会重新变红）。
   ⚠️ 副作用：`git diff`（未暂存）不再显示该文件，`git diff HEAD` 才含它 —— 报告/证据若用 `git diff --numstat` 统计，
   ai-chat.css 的 `-362` 需按 `git diff HEAD` 口径取。
2. **dev server 5202 的 tailwind.config.js 是启动时快照**：5202 在本批 config 改动**之前**启动，Vite 的 PostCSS
   插件不热更 config ⇒ 5202 的 CSS 里**没有** config 派生的 `animate-caret/breathe/fade-out`

3. **hljs 配色口径变化**（§2a 表）：卡面 1a 要求的「单口径」结果，代价是 keyword/title 的 **bold** 与 comment 的
   **italic** 一并交给库主题（github.css 不给这两项设 weight/style）。若指挥官要保留粗体/斜体而只统一色值，
   需改回「手写样式」或给库主题加一层（两条路都与本卡纪律冲突，故按卡面执行）。
