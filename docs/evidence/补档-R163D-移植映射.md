## 五、表格专项差异（demo 128–130 vs AiPanel.vue:1602-1622）

| 属性 | demo v6 | 真实现状 | 后果 |
| --- | --- | --- | --- |
| display | 未声明（=table） | **block** | ⚠️ 根因：块盒宽=容器宽，6 列压碎一字一竖行 |
| overflow-x | 无 | auto（挂 table 自身） | ⚠️ 无效：块宽恒=容器宽，永不触发滚动 |
| table-layout | fixed | auto（H2 改的） | 方向相反；窄容器下都救不了 6 列 |
| th white-space | 无 | nowrap | 真实唯一有效改进，保留 |
| 滚动容器 | 无（3 列不需要） | 无（display:block 错误代偿） | 双方都缺真正 wrapper |
| .md-body 根容器 | 无 wrap 声明 | overflow-wrap:anywhere + word-break:break-word（1503-1504） | ⚠️ 长英文标识符被任意断开 |

**结论**：照抄 demo 不能解决 6 列（demo 只演示 3 列窄表）；正确方案 = wrapper(overflow-x:auto) + table{display:table;width:max-content;min-width:100%} + th nowrap，是「超 demo」方向。wrapper 落地硬约束：markdown.ts ALLOWED_TAGS 无 div，注入 `<div class="md-table-scroll">` 会被 DOMPurify 剥离——须加白名单 + 渲染层断言（renderMarkdown 输出含 wrapper）。需同步改写断言：spec:1764（table-layout:auto）、:1855-1857（display:block/overflow-x/th nowrap）、G1 取样源（.md-body 迁 ai-chat.css 后 G1 从 AiPanel.vue?raw 改读 ai-chat.css）。

单元格 padding/表头灰底/font-size 三项 demo 与真实已一致，无需改；td 建议 `word-break:normal;overflow-wrap:anywhere`（有意偏离 demo 原值 break-word，理由=长 token 兜底）。
