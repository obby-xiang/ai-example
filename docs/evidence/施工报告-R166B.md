## 1. 四项逐条修法

### RC-1 · GF 回执摘要取「已提交值」（`AiPanel.vue`）

**现状**：`hitlReceiptSummary` 对 `generative_form` 无分支，走通用「args 前三键值」—— GF 的 `args`
是**表单定义**（`form.scenario/title/fields`），摘要于是把整份 schema 当内容印出来。

**修法**：新增 GF 专用摘要（`AiPanel.vue:2437 generativeFormSummary`，由 `:2463 hitlReceiptSummary`
按 `part.name === GENERATIVE_FORM_TOOL` 分派）：
- 只读 `part.submittedValues`；**字段名**走 `args.form.fields[].label`（`:2384 formFields`，保持 schema
  序，取不到则回落字段 key）；**值可读化**（`:2412 readableFormValue`：布尔→是/否、数组→顿号列表、
  空值→（空）、对象→（复杂值））；
- 取前 **3** 项，超出以 `…` 示意；`submittedValues` 缺失/空 ⇒ 降级 `生成式表单 · 表单已提交`；
- **任何路径不再出现 `scenario / title / fields / form` 等 schema 键，也不再出现 `key=value` 形态**。

### RC-2 · submittedValues 写回不依赖 activeForm 身份（`stores/ai.ts`）

**现状**：`submitGenerativeForm` 把「写回 submittedValues」挂在 `activeForm?.toolCallId === form.toolCallId`
守卫之后；结局帧（`frontend_tool_result`，`:2764`）先把 `activeForm` 置 null ⇒ 值整条丢失（只读渲染
吃 `submittedValues`，本会话内缺失，要等刷新由后端 resultText 补回）。

**修法**：抽出 `:2188 writeSubmittedValues(toolCallId, values)`（按 toolCallId **直接定位工具段**写回），
`:2221` 在 `outcome.ok || duplicate` 分支**先写回**再判身份；身份守卫只留给 `form.status/error` 这类
必须择主的本地态（红队问题 6 的"防瞬时覆写"语义不削弱，失败态回填仍要 `activeForm` 仍在场）。

### RC-3 · 参数错误文案人话化（`utils/frontend-tools.ts`）

**现状**：两处把 `JSON.stringify(args)` 拼进错误文案（`:781` 工作区动作、`:925` ui_event 动作）。

**修法**：新增两张**参数要求表**（`:747 WORKSPACE_ACTION_REQUIRED_ARGS` / `:758 UI_EVENT_REQUIRED_ARGS`）
+ `:774 missingArgsHint`；两个落点改为 `:819` / `:963`：
- 工作区动作 ⇒ `设置查询条件的参数不完整：缺少 defCode 或 conditions.fields`（用户示范句逐字）；
- ui_event 动作 ⇒ `set_import_mode 的参数不完整或类型不符，未驱动工作区：缺少 mode 或它不是 MERGE / REPLACE`
- 表外动作回落一句可行动文案；**任何路径不再含 `{` / `"` 等 JSON 特征字形**（测试逐条断言）。

### RC-4 · 复制页签隔离三层握手（`stores/ai.ts` + `AiPanel.vue`）

**现状**：R-166 口径⑤ 用 `performance.getEntriesByType('navigation')[0].type` 判页签旅程
（`navigate` ⇒ 起新会话）。真机实测**复制页签 = `back_forward`** ⇒ 判据作废：复制页签连
`sessionStorage` 一起继承，两页签共写同一后端会话。`navigationType()` 及 `initSessionId` 里的
清 id/清镜像分支**整体删除**（`initSessionId` 现只做"取不到就建"）。

**修法**（三层，`ai.ts:261~470` 模块级）：

| 层 | 落点 | 口径 |
|---|---|---|
| ① pageId | `PAGE_ID_KEY = ai-tab-page-id`（`:261`）+ `ensurePageId/rotatePageId` | 每页签 `crypto.randomUUID()` 存 sessionStorage；随刷新保持；**判为复制品时轮换**（同源广播里两页签必须可区分） |
| ② Web Locks | `SESSION_LOCK_PREFIX = ai-session-`（`:263`）+ `:386 probeSessionLock` | `navigator.locks.request('ai-session-<sessionId>', { ifAvailable: true })`：拿到 ⇒ 原页签（持锁至文档销毁）；回调收 `null` ⇒ 该会话被别的页签持有 ⇒ **复制品** |
| ③ BroadcastChannel | `OWNERSHIP_CHANNEL_NAME = ai-session-ownership`（`:265`）+ `:456 bindOwnershipRelease` | 原页签 `pagehide` 广播 `released` 并释放锁；被判为复制品的**空白**页签接手（`transfer`-式让渡） |

判定与分流：`:2406 ensureTabOwnership`（面板挂载时调用一次，幂等）
- 锁到手 ⇒ `tabOwnership = 'owner'`，广播 `claim`；
- **环境无 Web Locks**（旧浏览器 / jsdom）⇒ `'unsupported'`，按**恢复**处理（保守），
  **同步收口并返回 `null`**（`:2759` 面板据此**不 await** —— 既有 onMounted 时序一格不动，见 §4.2）；
- 锁被占 ⇒ `'duplicate'`：`clearMirrorRefs()` + `:2345 adoptFreshSession()`（换新 id + 清屏 + 复位
  轮次/挂起/时钟，**不碰后端**，即**不删原页签的服务端记忆**）+ `rotatePageId()` + 认领新会话锁。
- 让渡：`:2458 onOwnershipMessage` 只认 `released`，且仅当本页签是 `duplicate`、`messages` 空、
  未在跑轮 ⇒ `:2475 takeOverSession`（**先锁探活**再换 id + 读回历史，探不到不认账）。

`resetSession` 的本地重置段抽成 `adoptFreshSession()`（两处共用），新建对话后补一句
`tabOwnership = 'owner'` + 认领新会话锁。

  后他页签可接手）。

## 4. 已知残留 / 如实登记（含对既有口径的有意改动）

1. **同页签内"手输地址/书签"式硬导航 = 恢复（不再起新会话）**：`navigationType()` 删除后，"同一页签
   换一条导航"不再被判成新会话。这与刷新同族（页签身份未变），是三层握手的必然推论；**行为有变，如实登记**：
   若后续裁决要求"手输地址也起新会话"，需另立判据（不可回退到被证伪的 navigation type）。
2. **无 Web Locks 环境（旧浏览器 / jsdom）＝旧的"保守恢复"**：判定不可用 ⇒ 不换会话（可能两页签同会话，
   即复制页签隔离在旧浏览器上不生效）。`ensureTabOwnership` 因此**同步返回 `null`**，面板 `await` 只在
   有锁能力时发生 —— 这是为**保住 onMounted 既有挂载时序**（实测：无条件 `await` 会让既有 panel 测量类
   用例偏移一个 microtask 而红，见施工过程）。
3. **锁探活是"限次重试"启发式**（`LOCK_PROBE_ATTEMPTS = 3` × `LOCK_PROBE_RETRY_MS = 150`）：为覆盖
   "刷新时旧文档的锁可能尚未随文档销毁释放"。代价 = 复制页签的最坏判定延迟 ~300ms；若原页签恰在此窗口
   内关闭，复制页签会**直接接管**原会话（= 让渡语义，非损坏）。
4. **让渡（接手原会话）有"未产生内容"闸**：复制页签只要已在自己的会话里说过话（或轮次在跑），就不接手
   —— 换会话会让用户眼前内容跳变。代价 = 该页签放弃原会话的自动接手（用户可用刷新重新判定）。
5. **让渡广播不是权威**：`takeOverSession` **以锁为准**（探活通过才换 id），广播只是触发；锁被占时
   广播被忽略（已锁测试）。
6. **`BroadcastChannel` / `navigator.locks` 缺失时静默降级**（均按最小面探测）：不抛错、不影响主对话；
   只是让渡/隔离能力弱化。
7. **面板未新增任何用户可见文案**：本批是数据链路-only，`tabOwnership` 不进 UI（也不进镜像/持久化）；
   复制页签的用户可见表现 = "开出来就是一个空会话"。
8. **未做真机取证**（本批无浏览器实跑）：三层握手为浏览器特性，playwright/jsdom 无法覆盖 Web Locks 与
   跨页签真实语义 —— 本批证据面 = 单测（同语义桩）。真机复制页签/关闭让渡的实测建议并入 S6 批的
   回归清单（或由指挥官另行排）。
