### 4.1 模板（每主题一行，10 列）

| 验证 | 命令 / 测试类 / 指标 | “人工确认” |

### 4.2 防堆字六条

1. **对比只写一次**：集中在 D5-§5 的“能力 × 业界”表；各能力节最多 3 行摘要（主流一句 / 差距一句 / 理由一句）+ 引表行号。
2. **分级填写**：P0 主题填满 10 列；P1 填 6 列（主流/证据/现状/差距/理由/验证）；P2 只写“主流一句 + 做/不做结论”。
3. **同源合并**：同一机制多能力点共用一行（HITL 的 A08/A09；租约的 A11/A12；输入的 A17/A23），避免 27 份重复对比。
4. **结论必须可行动**：每行结尾只能是“改 / 不改 / 不做”之一，并给判据；禁止“业界也这样”这种无行动句。
5. **不引入第二事实源**：对比表不复制表体、帧字段、键族；需要时只引 `D3-§4`/`D4-§4`。
6. **偏离单独登记**：所有“我们和主流不一样”的地方进“偏离登记表”，正文只引编号；否则每个能力节都要重复解释一次。

### 4.3 样例（A09 HITL，压缩到 3 行正文 + 表行）

- 主流：AG-UI 用“中断结束 run + 新 run resume + responseSchema + expiresAt”，LangChain 给 approve/edit/reject/respond 四决策；本仓是 approve/reject + 取消、同 run 续跑、无 responseSchema/expiresAt。

- 理由/代价：2026-10-17 直裁“H1 仅两钮、修正走会话”；代价是用户需重新描述、无法批量编辑参数；验证：`03-hitl.spec.ts`、`ConfirmGate*`、`ai-tool-receipt.spec.ts`。
