## 二、修法选型理由（方案 ①，非 ②）

1. **方案 ②（缺环境即 skip）会把「没跑」伪装成「绿」**：本域用例数只能靠 spec 自己写闸，新增域 spec 忘写就再次漏网；且 CI 日志里大量 skip 无法证明「每域都跑到」。方案 ① 把「哪些 spec 归哪个域」集中到 config，CI 一步一域，漏网是可见的（某步收集 0 条会立刻暴露）。
2. **域与域之间不只是端口差异**：14 系要换桩 + KEK、15 要双 JVM 同 DB、16-kqc 系要换桩 + 专用后端参数、17b 要整棒缩阈值、11c 要换桩。这些只能靠「各自 config + 各自步骤」表达，skip 闸无法表达「必须跑到」。
3. **12a/12b 必须从主栈切片里拿出来（对看板建议的一处修正）**：`frontend/e2e/support/helpers-vl.ts:146` 的 `assertSingleApiBase()` 强制 `E2E_API_BASE`/`E2E_APP` 等于 VL 域栈（18930/19001），在主 config 的 183xx 栈下会直接抛「后端基址不一致」。因此新增 `playwright.vl.config.ts`（`E2E_EXTERNAL=1`，主 harness 不起 183xx，由 spec 自起 189xx），而不是硬塞进主 config。看板 L-107 写的「主切片含 12a/12b」在代码事实上不成立。
4. **real 档不缩水**：`testIgnore` 分 stub/real 两套。real 模式保留 `14b` 的 X-07 与 `16-kqc` 的 K-10/C-13（它们不依赖域桩，跑主栈），`--grep @real` 仍收集 9 条，未被误伤。
5. **看板「50 条」是下限估计**：按当前 HEAD 实际跨域收集是 **161 条**（13 系实际 48 条而非 23 条），本修法覆盖全部 161 条，不是只挡 50 条。
