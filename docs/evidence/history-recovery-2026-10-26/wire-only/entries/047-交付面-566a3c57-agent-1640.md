## L-101：机制设计

录制器侧（**夜间/本地录制即重估点**）：

1. **复现即续**：本次可比录制仍不一致的类 → `cleanStreak=0`，留在冒烟集；
2. **连续 N 次干净即移出**：曾在集合内、连续 `cleanRuns`（默认 2）次可比录制无差异 → 移出冒烟集；
3. **时间窗兜底**：距最后一次复现超过 `maxAgeDays`（默认 7）→ 过期移出（成本必须随时间收敛）；
4. **修既有口径缺口**：不可比录制（换 tree / 生产源码变了）**原样保留**集合并只走时间窗 —— 旧实现把它当「无差异」整批清空，与 §3.6「永久常跑」自相矛盾。参数 `-Dtestmap.unstable.retire.cleanRuns` / `-Dtestmap.unstable.maxAgeDays`（或 `-D` 覆盖）。

选择器/门禁侧（**可视化**）：`costEstimate` + 提交级一行警告，判据口径对齐看板 L-101。

实测（本机，静默时段，2026-10-24）：

- 干净连录两次（`rec-3` 基线 / `rec-4` 比对）：**`deterministicDiff = 31/265`（11.7%）** → `unstableTests` 31 类、`unstableHistory` 31 条、`retired 0`、`unstablePolicy{cleanRuns:2,maxAgeDays:7}`。与 B 期 `33/261` 同量级 ⇒ **「只在夜间静默录」并不能消除 unstable，机制（重估+窗）才是必需项**。
- 同一笔单类改动（`UsageDetails`）：带 31 类 unstable 选中 **51 类（冒烟 48）**；剥掉 unstable 选中 **21 类（冒烟 18）**。
- 后端实跑：**65s → 70s（墙钟）**；用例体合计 **39.4s → 63.6s（+24.2s）**。
- 选择器输出（真实）：
  - `[select] 成本估算（录制期上界）：选中 51 类 ≈ 36.5s，其中冒烟 48 类 ≈ 36.5s；全量墙钟 ≈ 195.7s`
  - `[select] ⚠ unstable 拖慢（L-101）：31 类 ≈ 34.2s，占冒烟成本 94%（策略：连续 2 次干净 / 7 天窗）`
  - 门禁：`[gate]   ⚠ unstable 拖慢（L-101）：31 类 ≈ 34.2s，占冒烟成本 95%；冒烟合计 41 类 ≈ 35.8s`
- **估算口径的取舍（实测标定）**：按「占全量墙钟比例」折算会把 24.2s 说成 74.4s（偏差 2.8×，墙钟含 Spring 上下文建构与 Maven 启动），故结论行改用**录制期耗时之和（上界，实测 1.4× 偏保守）**，`wallScaledSeconds` 只留作对照。
