### 缺口 0（头号，实测确认，先于所有测试缺口）：`ui:on` 动态披露在生产路径上**不生效**

不是"少测了"，是"机制不可达"，且现有单测因**绕过闸门直调**而看不见：

1. 前端 `stores/workspace.ts:247` 把 `uiRegionCount` 放进 `context.extra` 上报；
2. 后端 `AiController.java:327` 先过 `ContextFieldGate`，而 `ContextFieldGate.extra()` 只留 `ContextBuilder.ALLOWED_EXTRA_KEYS`（= `pageId/selectedDefs/importMode/dataVersion/contractVersion/recentActions`），**`uiRegionCount` 被丢弃并计入 downgraded**；
3. `ResilientChatService.toContext()` 用**闸后** context 建 `AiContext` ⇒ `ToolRegistry.uiRegionsPresent()` 恒见"缺失" ⇒ **恒 fail-open** ⇒ 7 个 `ui_*` 对 `tasks/definitions/data` 页（审计明确要求零区域的页）**永远披露**；
4. `/api/ai/tools`（`AiToolsController:56`）直接 `extra=null` ⇒ 同一方向 fail-open，第二条通路也不收窄；
5. 单测 `ToolRegistryUiScopeTest` 用 `AiContext.of(..., Map.of("uiRegionCount",0))` **直构上下文**，永远不经过闸门 ⇒ 绿灯；
   `ContextBuilderExtraTest.uiRegionCountIsADeliberateWhitelistException` 只锁"不进模型载荷"（正确），但没人锁"进得了披露判定"（不成立）。

**这正是"批② 防护合流（10-21）"与"批4-A visop（10-23）"的跨批集成缺口**：新机制依赖一个早于它存在的白名单，双方各自绿。
**修法需裁决**（设计性二难）：① 闸门加"tag 专用旁路"（不进模型载荷但进 buildTags）；② 或前端改从 `/api/ai/tools` 拿披露集再本地收窄（但模型侧仍看到全量）。**测试侧必须补一条"经 HTTP 全链"的用例**（桩可承载：发 `page=definitions` + `uiRegionCount=0`，断言 `/api/ai/tools` 与真实轮次下发的 tools 里 `ui_*` 缺席）。

## ④ 我认为最痛的 10 条缺口

1. **缺口 0：`ui:on` 动态披露在生产路径不可达**（闸门吞键 + `/tools` 恒 fail-open + 单测直构上下文绕过闸门）——机制宣称与事实不符，且三层测试都看不见。
2. **RLD 18 条全是 jsdom 模拟刷新**，用户点名第一场景在真进程里 **0 守卫**；"修好了又坏"的概率最高。
3. **STP 桩级只有 P-14 一条台账断言**：停止后的"能发下一条 / 卡收敛 / 归档有收敛信号"三个 P0 全在 jsdom 里自证。
4. **`ui_*` 七工具桩级 0 条**（桩路由 0 条）：AI 操作工作区这条主链路从未在真进程端到端跑过。
5. **`irreversible` 协议半段全空**（`verify-e2e.ps1` grep = 0）：批4-D 的确认卡复选框只在组件里被测，帧/快照/历史三通道无人锁。
6. **SSE 解析器零单测**（`parseSseFrame` 已导出却无 spec）：乱码/分片/多字节边界是最便宜的 P0，也是最容易出线上怪的。
7. **L-65 禁用控件点出"假成功"**：已知会造成"回执与事实不符"，却无任何测试（连既有行为都没锁）。
8. **`ui_*` 挂起中停止/刷新无测试**：第三种挂起形态，P-05/P-06 只覆盖 CONFIRM/FORM。
9. **网络离线面整体不存在**（源码 grep 0）：断网时"发送/重连/文案"全空白。
10. **多实例 M-01…M-06/M-10 有单测无执行**：多实例是 P0 级（M-02 决策打错实例），但 harness 从未跑过，等于"设计已验、部署未验"。

## 总量判断

**当前覆盖率**：按蓝本口径 **约 152/154 条有载体（99%）**；按"载体强度"加权则是 **接口级真进程 58%（90/154）、jsdom 降级 27%（41）、纯单测 15%、真机 0%**——即"清单几乎点满，但深水区没人下水"。若把 visop/工作区交互这块蓝本外新面算进来，**实际场景覆盖约 55%~60%**（我按"机制 × 层"粗估：六机制在单测层约 85%、桩层约 12%、真机层 0%）。

**补全量级**：**7 批、约 150 条新用例**（V1 34 / V2 30 / V3 26 / V4 24 / V5 18 / V6 12 / V7 10），外加 **1 个机制缺陷修复（缺口 0）**、**4 条挂账转红测**、**2 个待裁决点（披露修法、UI 载体）**；若裁决"不加 CDP 载体、不用真 key"，则上限固定在 **约 150 条两层（单测+桩）**，真机 41 条与 nightly 18 条须以"明确不覆盖"入册，不能计入"覆盖全"。
