## 2. Phase 2：根因链

### 2.1 主数据流

1. `groupParts(parts, messageId)` 为每个 activity 段生成一个 `Block`，并写入 `defaultExpanded = defaultExpandedOf([part])` — `frontend/src/utils/blocks.ts:85-109`。
2. `defaultExpandedOf` 在 `frontend/src/utils/blocks.ts:60-63`：
   ```ts
   part.requiresAction || (isReadOnlyCard(part) && readOnlyDefaultExpanded(part))
   ```
3. `readOnlyDefaultExpanded` 在 `frontend/src/utils/blocks.ts:363-366`：
   ```ts
   return state === 'rejected' || state === 'expired' || state === 'failed' || state === 'cancelled'
   ```
   这就是“四类例外展开”的**唯一数据源**。
4. `AiPanel.vue` 的 `isBlockExpanded` 在 `frontend/src/components/AiPanel/AiPanel.vue:2152-2158`：
   - `manual` 显式值优先；
   - 仅当 `turnStillOpen(block) && readOnlySuccessCard(block)` 时强制展开；
   - 否则 `resolveBlockExpanded` 回落到 `defaultExpanded`。
5. `readOnlySuccessCard` 在 `frontend/src/components/AiPanel/AiPanel.vue:2170-2173`：
   ```ts
   isReadOnlyCard(part) && !readOnlyDefaultExpanded(part)
   ```
   即“回合未结束保持展开”的时序保护**只覆盖成功态**；例外态永远进不了 `turnStillOpen` 分支。
6. `readOnlySummary` 在 `frontend/src/components/AiPanel/AiPanel.vue:2628-2638` 对四类例外返回空串。它们现在默认展开所以无感；一旦改为默认折叠，卡头将只剩徽标 + chevron，丢失“徽标 + 人话摘要 + chevron”的既有折叠卡头口径。

### 2.2 结论

根因是**两处协同的特判**：
- 纯函数层：`readOnlyDefaultExpanded` 把四种非成功终态列为默认展开；
- UI 层：`readOnlySuccessCard` 用 `!readOnlyDefaultExpanded` 把“回合未结束不收”的时序保护限定在成功态。

只改注释或只改 UI 条件都不够；必须让“所有已决只读卡”共享同一默认折叠和同一回合时序。

### 2.3 不应误收的边界

`frontend/src/utils/blocks.ts:306-316` 的 `NON_DECISION_STATUSES = {pending, blocked, unknown}` 明确把三者挡在只读卡之外，继续走普通工具卡。本次不应改动：
- `requiresAction=true` 的待决门卡：`resolveBlockExpanded` 仍然强制展开（`blocks.ts:70-73`）；
- `pending/blocked/unknown`：不是 `hitl-receipt`，不受本次“终态默认折叠”影响；
- 普通工具卡、思考卡、用户长消息折叠：无按 `rejected/expired/cancelled/failed` 特判的分支。

- demo 的 `decide()` 当前只对 `approved/submitted` 调折叠；只改静态样张而不改动态路径，会导致 A1 超时、A2/A3/A4/A6 取消仍不折叠。
