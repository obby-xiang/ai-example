## 2. A/B 是否被采用

### A：卡头左侧加图标

**被采用，但不是统一做法。**

| 位置 | 图标语义 | 说明 |
|---|---|---|
| [AI Elements `ToolHeader`](https://github.com/vercel/ai-elements/blob/main/packages/elements/src/tool.tsx) | 固定 `WrenchIcon` | 所有工具共用同一图标，身份靠名称区分；状态另用 Badge |
| [prompt-kit `Tool`](https://github.com/ibelick/prompt-kit/blob/main/components/prompt-kit/tool.tsx) | 状态图标 | 图标随 `input-streaming/input-available/output-available/output-error` 变化，不表达工具类别 |
| [assistant-ui `ToolFallback`](https://r.assistant-ui.com/tool-fallback.json) | 状态图标 | 无边框单行；图标是 Loader/Check/X/Alert，不是工具图标 |
| [assistant-ui `ApprovalCard`](https://github.com/assistant-ui/assistant-ui/blob/main/packages/ui/src/components/react/assistant-ui/elements/approval-card.tsx) | 动作图标 | 唯一使用“图标容器”的实现：36px 圆角方块，内部放 `TerminalIcon` 或业务传入的 `Trash2Icon` |
| [CopilotKit 默认工具卡](https://github.com/CopilotKit/CopilotKit/blob/main/packages/react-core/src/v2/components/WildcardToolCallRender.tsx) | 无工具图标 | 左侧是 chevron + 8px 蓝点；蓝点更像状态装饰，不承载工具语义 |

结论：如果 A 的定义是“卡头左侧有图标”，3/4 库有；如果要求“图标表达卡片类型/工具类别”，只有 AI Elements 的固定 Wrench 和 assistant-ui ApprovalCard 的 action icon 接近。prompt-kit/assistant-ui ToolFallback 的左侧图标主要表达运行状态。

### B：卡片顶侧/左侧突起标签，内部放图标

**在四库的 Tool/Confirmation/Form 相关组件中未找到采用证据。**

- 没有负 margin、绝对定位跨边框、ribbon/tab 形结构。
- assistant-ui `ApprovalCard` 的图标块最接近“图标容器”，但它是头部正常流内的 `size-9 rounded-xl`，不突起、不跨边框。
- assistant-ui ToolGroup 的 `outline/ghost/muted` 是整张卡的边框/底色变体，不是突起标签。
- CopilotKit 的蓝点是 `h-2 w-2` 圆点，不是标签，也没有容器。
- AI Elements 的 Badge 是卡头内部的行内胶囊，不是卡片外沿标签。

因此，B 在这四个开源 AI Chat UI 库中没有一手先例；不能据此说“业界主流采用 B”。

## 3. 对四类卡可迁移的规律

| 卡类型 | 可迁移规律 | 直接参照 |
|---|---|---|
| 工具卡 | 用 A 的“左侧类别图标 + 独立状态指示”比“图标即状态”更利于区分卡片类型。图标放卡头左端，状态用文字/图标 Badge 放名称后或右端；不要把状态只做成颜色。 | AI Elements 固定 Wrench + Badge；prompt-kit 状态图标 + pill；CopilotKit 右端状态 pill |
| 确认卡 | 最成熟的结构是 assistant-ui ApprovalCard：图标容器（36px）+ 标题/副标题 + 描述/命令/明细 + 右对齐决策按钮；破坏性操作换红色 tint 和红色主按钮。图标容器是可行的，但应放在卡头内部，不需要突起。 | assistant-ui ApprovalCard 文档与源码 |
| 表单卡 | 没有独立的“表单卡头”标准。表单字段放在卡 body，提交按钮放 footer 右端；字段校验状态用行内提示，不要新造一种卡头。若必须有卡头，复用工具卡/确认卡的“图标 + 标题 + 状态”。 | assistant-ui `useToolArgsFieldStatus`；CopilotKit HITL 表单示例 |
| 已决回执 | 决策后把按钮区替换为单行回执：图标 + 文本，保留原卡头与卡片轮廓。assistant-ui 用 `role="status"`、`Finished/Denied`、绿色 Check/灰色 X 是可直接迁移的实现；AI Elements 用 accepted/rejected 文案；CopilotKit 需业务自己实现。 | assistant-ui ApprovalCard footer；AI Elements Confirmation；CopilotKit HITL Complete 分支 |

对 36px 左右紧凑卡头的直接影响：prompt-kit 的 `px-3 py-2 + text-sm` 约 36px，说明“16px 左图标 + 名称 + 小 pill + chevron”可以塞进 36px；但 assistant-ui 的 36px 图标容器本身就会占满卡头高度，不适合 36px 卡头。若目标是紧凑卡头，A 的裸图标可行，B 的“突起标签内放图标”会进一步压缩横向空间，且没有一手先例。
