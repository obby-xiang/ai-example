## 7. `workspace.ts` 的 `isCurrentTaskReadOnly` 全文

`frontend/src/stores/workspace.ts:348-360`：

```
348  async function isCurrentTaskReadOnly(workspace: ReturnType<typeof useWorkspaceStore>): Promise<boolean> {
349    const status = workspace.taskStatus
350    if (status === 'CANCELLED') {
351      return true
352    }
353    if (status !== 'COMPLETED' || workspace.taskId === null || workspace.taskType === null) {
354      return false
355    }
356    const finalJobType = workspace.taskType === 'IMPORT' ? 'PUBLISH' : 'EXPORT'
357    const jobs = await jobsApi.listJobs(workspace.taskId).catch(() => null)
358    const latest = jobs?.filter((job) => job.jobType === finalJobType)[0]
359    return latest?.status === 'COMPLETED'
360  }
```

- **CANCELLED**：`:350-352` 恒 `true`（不看作业）。
- **COMPLETED**：`:353-355` 前置（非 COMPLETED、无 taskId、无 taskType → `false`）；再拉作业列表复核。
- **FAILED**：`:353` 直接落 `status !== 'COMPLETED'` → **返回 false（视为可写）**，与后端"FAILED 放行"一致。
- **类型映射**：`:356` `IMPORT → 'PUBLISH'`，其余（含 EXPORT 与未知类型）→ `'EXPORT'`。
- **"最新一条 COMPLETED"取值方式（含口径偏差，需注意）**：`:358` 只按 **jobType** 过滤（**不过滤 status**），取数组首个；顺序依赖 `GET /api/tasks/{id}/jobs` 的 `createdAt DESC, id DESC`（`jobs.ts:13` 注释 + `JobService.findByTaskId:275` → `findByTaskIdOrderByCreatedAtDescIdDesc`，`JobRepository.java:15`）。因此实际判据是"**该类型的最近一条作业恰好是 COMPLETED**"，而**不是**"最近一条 COMPLETED"——若最近一条 PUBLISH/EXPORT 作业是 FAILED/CANCELLED，即便更早有一条 COMPLETED，本函数也返回 `false`（非只读）。
  与之对比，后端守卫（`JobService.java:86-88`、`TaskService.java:198-201`）用的是 `findFirstByTaskIdAndJobTypeAndStatusInOrderByIdDesc(finalJobType, {COMPLETED})` = "**存在** COMPLETED 的最终作业"。**前端与后端在此处口径不等价**（前端看最新一条作业，后端看任一 COMPLETED 作业）。
