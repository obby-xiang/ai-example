2. **suspended 帧单独到达不再产生挂起语义**（批1 锁定"只更新已存在段" + 翻转后无投影可写）：仅当 `confirm_request`/`frontend_tool_request` 缺失时可见，后端同批必发 request 帧 ⇒ 生产不可达 → 落点：若后端存在"只发 suspended"路径，③b 用段状态机补"公告即建段"。
3. **error 帧现在会收掉挂起卡**（行为改善：此前会留一张点了只 404 的死卡），同时 `pendingToolCall` getter 不再返回它（输入区提示语随之回到普通文案）。
4. **镜像里旧消息的段可能带 `streaming: true`**（批1 写的 v2 镜像 + `sanitizeMirrorResidues` 只收 `requiresAction` 不封口）：刷新后段级 streaming 假态会进内存，影响后续 `openStreamPart` 的续段判断（仅工具/续流路径，已 done 的消息不受影响）→ 落点：镜像读取侧补封口，或 ③b 段状态机规范化。
5. **复制按钮位置变化**（N10 要求）：由"正文之后、工具卡之前"移到消息末尾 → 落点：CDP 冒烟人工确认视觉可接受。
6. **`<details>` 展开态仍不持久化**（R4-1，④批范围）：reasoning 块迁进 parts 循环后仍是原生 details，DOM 重建即丢展开态。
7. **重复终帧被 seq 幂等跳过时不复位 `loading`**（按卡面"重复帧不写任何状态"实现）：实轮里由 `send()`/`reattachActive()` 的 finally 兜底复位 → 落点：如后续发现"重放 done 后 loading 卡住"，在该分支前置 `if (isTerminalFrame(frame)) this.loading = false`。
