### 3. 「打开」操作链路

`TaskCenterView.vue:90` → `restoreWizard(row)` 定义在 `TaskCenterView.vue:368-371`：

1. `const target = await taskStore.restoreWizard(row.task.id ?? 0, row.task.type)`；
2. `await router.push(target)`。

- `stores/task.ts:358-364` `restoreWizard`：`type = taskType ?? currentTask?.type ?? fetchTaskType( taskId )`；`IMPORT → { name: 'import-wizard', query: { taskId } }`，否则 `export-wizard`（`router/index.ts:10-16, 28-39`）。任务中心调用时**总是传 `row.task.type`**，因此不发生额外的 `fetchTaskType` 请求。

### 5. 侧边栏 / drawer 的引用面

抽屉是 `TaskCenterView.vue` 内的内联 `el-drawer`（`:145-220`），**不是独立组件，没有任何其他文件引用它**。`openDetail` 仅在 `TaskCenterView.vue:47` 被调用一次；`detailVisible` 仅在 `:145`、`:257`、`:377` 出现。任务中心之外另有一个无关的抽屉在 `DefinitionsView.vue:78`（`openDetail` 见 `DefinitionsView.vue:341-343`）——同名函数但独立，不受影响。

但 store 侧**删除不干净**，存在以下外部引用：

| store 成员 | 抽屉之外的使用者 |
|---|---|
| `openTask` | 无（仅 `TaskCenterView.vue:379`） |
| `closeTask` | `stores/task.ts:257`（`removeTask` 内部，`currentTaskId === taskId` 时调用） |
| `refreshCurrent` | `stores/workspace.ts:367, 377, 400`（`goto_step`/`select_defs`/`run_job` 的 ui_event），以及 store 内部 `setImportMode:270`、`startJob:282`、`cancelJob:295`、`watchPublishOutcome:338` |
| `watchPublishOutcome` | `stores/workspace.ts:403`（发布冲突异步形态） |
| `currentTask` | `stores/task.ts:359`（`restoreWizard` 缓存层）、`:369`（`resolveWizardRoute` 缓存层） |
| `currentTaskId` | `stores/task.ts:211`（`refreshCurrent` 唯一入口）、`:256`（`removeTask`） |
| `currentJobs` / `currentFiles` / `issues` / `issuesTotal` / `issuesLoading` / `detailLoading` / `publishConflict` | 仅在抽屉模板内（`TaskCenterView.vue:146,148,153,169,193,203`）+ store 内部；`publishConflict` 的向导侧对应物是 `ImportWizardView.vue:288` 的**同名局部 ref**，与 store 字段无关 |
| `getTaskOverview`（`api/tasks.ts:20`） | 唯一调用点是 `stores/task.ts:217` |
| getter `latestJob`（`task.ts:111-112`）、`hasRunningJob`（`task.ts:114-115`） | 全仓无调用点（列表用的是 `row.latestJob` 字段） |
