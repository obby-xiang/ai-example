## 6. 去重解释核实：+80 vs “+380~450”

以 lockfile 实测的闭包算账：

```
三个钉版包的依赖闭包（当前 yarn.lock 内）= 146 条
  ├─ 复用 HEAD 已有条目（复用，不需新增）=  62 条
  ├─ 预置 alternation（复用已有条目，仅加别名）=  4 条
  └─ 真正新增条目                        =  80 条
146 - 62 - 4 = 80   ← 与 diff 的 +80 完全吻合
```

被复用的 **62 条**几乎全是既有 vite 工具链：`@rollup/rollup-*` 24 条 + `@esbuild/*` 25 条 + `rollup, esbuild, postcss, nanoid, picocolors, fdir, magic-string, source-map-js, fsevents, @jridgewell/sourcemap-codec, @napi-rs/lzma-linux-x64-gnu` 13 条（`@napi-rs/lzma-linux-x64-gnu` 来自 `rollup@4.64.0` 的 optionalDependencies，见 `frontend/yarn.lock:1763`）。抽样验证“是否 HEAD 已有”：

| 抽查对象 | HEAD 状态 | 当前状态 |
|---|---|---|
| `vite` | 6.4.4 已有 | 复用（仅加别名） |
| `esbuild` / `rollup` | 0.25.12 / 4.64.0 已有 | 复用，条目内容不变 |
| `@rollup/rollup-win32-x64-msvc`、`@esbuild/win32-x64` 等平台包 | 已有 | 复用 |
| `magic-string`、`source-map-js`、`postcss`、`nanoid`、`picocolors`、`fdir` | 已有 | 复用（新条目的 dep spec 直接命中 HEAD 别名：`magic-string@^0.30.21`、`source-map-js@^1.2.1` 等） |
| `parse5`、`whatwg-*`、`saxes`、`data-urls`、`tough-cookie`、`undici` 等 jsdom 链 | **不存在** | 需新增（jsdom 30 这代是全新依赖集） |

**判定**：去重/复用解释**方向成立、且可精确量化**——32% 的闭包（62/146）直接复用、再加 4 条别名预置，正好把原本 146 条闭包压缩为 80 条净增。但施工报告引用的“独立工程全量安装推断 +380~450 条”**在本仓库的证据里无法复现，且量级不合理**：三个包在当前解析空间下的**整个闭包只有 146 条**，380~450 相当于它的 2.6~3.1 倍；即便把整套 `package.json`（含 vue/vite/tailwind/element-plus）从零重装，总量也只会落在 ≈318 条（238 + 80）这一量级。因此差异的成因是**那个预期数字本身被高估**（可能计入了全新 lockfile 的总行数、或 npm 式嵌套/非去重树），而不是存在额外的隐藏复用。
