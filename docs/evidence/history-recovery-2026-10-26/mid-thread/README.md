### 1.3 覆盖率算法与语料快照

- **行指纹**：每行 `NFKC` → 空白折叠 → `trim`，丢弃长度 <6 的行，取 `md5[:16]`；候选覆盖率 = 候选行指纹在语料中出现的比例。
- **语料**（写入前冻结）：**2,076 个文件 / 184,309 条行指纹** = 仓内 `git ls-files -co --exclude-standard -- '*.md' '*.txt'` **954 份** + wire 里 `Write/Edit/MultiEdit` 落过且仍在盘上的仓外 `.md`/`.txt` **1,122 份**。
- **为什么先冻结**：落笔前先算覆盖率与清单 hash，新写的 `entries/` 不进语料，避免「把自己的产物判成重复」。
- **已知偏差**：语料只收当前仍在盘上且可读的落盘件；已删除的落盘件（会把缺口算多）与改写式复用（会把已覆盖误判成缺口）都不在判据内。多数件覆盖率 0–6%，说明文本基本只存在于 wire。

### 1.4 链的合并规则

- 同一 `(会话, agent)` 内按出现顺序，以**标题 token 的 Jaccard ≥ 0.34** 贪心聚类；token = 标题 ASCII 词（≥3 字符）+ 中文 2/3-gram；**先归一化轮次标记**（第 N 轮 / 第 N 批 / r7 等）再比。
- 结果：482 条消息 → **396 条链**（39 条多段链，最多 12 段）；经硬复核后主仓 358、同源 10、待判 9、排除 19。
- 主仓链覆盖 **51 个会话 / 198 个 agent**（硬锚点 189 个、上下文推定 20 个）。

## 6. 与「末条归档 138 件」（`wire-only/`）的关系

- 两者**按定义不相交**：`wire-only/` 收每 wire 的末条，本目录收末条之前的中间稿；同一条消息不会同时出现在两边。
- 交叉点可核对：主仓 14 条链所在 wire 的**末条**已入 `wire-only/entries/`（§4 列写明编号）；其余 344 条链的末条**不在** 138 件内（多因末条 <8KB 或标题非 H1）。
- 因此：**138 件 ≠ 全部末条**（末条层也有缺口），**358 链 ≠ 全部中间稿的定稿件**，**482 条 ≠ 缺陷数 / 裁决数**。三者都是覆盖层计数。
- 父级 README 的 51 件证据附件与 4 件研究稿是**已落盘件**的收编；本目录是**未落盘的 wire 文本**的收编；同源附录是**分支/评测**面。同一主题可能多层都有，引用须指明层与时点。

- **实测到真实密钥并已剔除**：有 11 条正文出现过同一枚 `sk-…` 形式的长 key（某次 PoC 的环境变量值）。全部替换为占位符，**本目录不含原值**，也不再复述其值、长度之外的信息。

- **不读不抄**：未读 `.env` / 凭据 / SSH 私钥；未复制用户消息原文（只记「相邻用户轮是否含决断类字样」的布尔）；未复制 `think`；排除会话的标题/正文/路径清单不入库。

## 9. 未决边界

- **已删除会话不可证**：索引里 23 条 `deleted:true` 与 6 条目录已丢失的会话无 wire，不能声明「无遗漏」。
- **末条层也有缺口**：主仓仅 14 条链的末条进了 138 件；其余末条（如若干调研/复核件的收尾）未入任何归档，属 `wire-only` 层的补漏面，本层不越层收录。
- **思维链未判**：`think` 约 191MB 未作交付文本；若某结论只写在 reasoning 里，本方法查不到。
- **工具结果不在面内**：调研素材可能只存在于工具结果或仓外源码。
- **覆盖率是启发式下界**；**分类是启发式**（单 agent 按标题/正文标题关键词判定，未双人复核；「施工复核」偏多、「分析」偏少是已知偏差，引用以正文为准）。
- **25 条上下文推定不是硬证据**：它们没有路径锚点，只有任务提示与作业面证据；若要求零推定，主仓硬证据为 333 条。
- **9 条待判未计入**：正文仍在 wire，本目录只留定位与摘要；若后续判定其属项目，可再提升。
- **同源 10 条不计入主仓**：它们是 ai-example 分支合流/评测面，不能与本主仓成果混算。
- **不构成当前事实**：全部件是 2026-10-07 ~ 10-26 之间某时点的中间文本；同一「PASS / 已修复」在后续轮次可能已被推翻，引用须带时点 + HEAD。
