# 你的 #12 提问：有结构定义，为什么不按结构渲染？

## 项目实况（子智能体逐文件核实）

**结构定义确实存在，但链路断在两处：**

| 层 | 现状 |
|---|---|
| 参数 schema | **有，且 18 个工具全是静态的**——Spring AI 从方法签名（`@Tool`/`@ToolParam` + record 类型）自动生成标准 JSON Schema（`AiTools.java:23-27`）。除 `generative_form` 内层由模型产出 FormSpec 外，无动态参数结构 |
| schema → 前端 | **断了**。`/api/ai/tools` 只回 `name/displayName/riskLevel/channel/scopePatterns`，**不含 inputSchema**；前端 `types/tools.ts:82-108` 是一份**手写镜像**（注释自称"核对源=AiTools.java"） |
| 输出结构 | **根本没有**——18 个工具**全部返回纯文本 String**（`String.format` 拼的"任务 #123 已创建"之类），无 outputSchema、无 JSON 输出 |
| 唯一例外 | `generative_form`：模型产出 FormSpec → 前端 `FormRenderer.vue` **已经是 schema-driven 逐字段渲染**——项目里其实已有你说的这种渲染的先例 |

所以答案是：**输入侧"可以按结构渲染"（schema 静态、前端还有手写镜像可用），是展示层没做；输出侧"没有结构可渲染"（全纯文本），想做先得改后端返回类型。** 动态结构只有 generative_form 一家，且它已经被正确渲染了。

## 业界主流怎么做（实证来源）

**主流 AI 聊天 UI 都不用 schema 渲染工具参数：**
- **Vercel ai-elements `Tool`**：`ToolInput` 就是 **pretty-print JSON + 语法高亮**，`ToolOutput` 走 CodeBlock——有状态机+折叠，但**无官方 schema→键值表组件**（[elements.ai-sdk.dev](https://elements.ai-sdk.dev/components/tool)）
- **ChatGPT / Claude**：自然语言摘要行（"Searched 5 sites"）+ 可展开的格式化 JSON，不画表单
- **MCP**：工具全带 `inputSchema`，但客户端只把它给**模型侧调用和校验用**，不拿来画 UI；2025-2026 的 schema-driven 正道是 **MCP Apps**——工具用 `_meta.ui.resourceUri` **自带 HTML/JS 界面**在沙箱 iframe 里渲染，配 `outputSchema`+`structuredContent` 校验（[MCP Apps 官方博客](https://blog.modelcontextprotocol.io/posts/2026-01-26-mcp-apps/)）
- **Open WebUI/lobe-chat/chatbot-ui**：一律可折叠 JSON 代码块；Open WebUI 社区也在抱怨裸 JSON（[issue #21440](https://github.com/open-webui/open-webui/issues/21440)）；**没有任何主流聊天 UI 用 react-jsonschema-form 只读态渲染工具参数**

**规律**：schema 的职责是"模型调用 + 参数校验"，不是"渲染"。要结构化展示，正路是**工具显式声明 UI**（MCP Apps）或**结果→组件映射**（generative UI）——你们的 `generative_form` 恰好就是这条正路。
