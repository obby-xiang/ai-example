## 3. Critical（1 条，必须修）

### C-1 `DataBrowserView.reload()` 把「查询/刷新」变成"重置筛选"

**证据链（全部实读）：**
- 右上「刷新」`DataBrowserView.vue:11` 与主查询键「查询」`:50` 都绑 `@click="reload"`。
- `reload()` `:308-327` 在拿到定义后**无条件**执行 `applyDefSelection(current)`。
- `applyDefSelection()` `:231-245` 会 `scopeType = def.level`（:233，用户选的 REGION/PROJECT 被覆盖）、`scopeKey = ''`、`draftModel = emptyDraftModel()`（:235）、`page = 0`（:237）。
- 表单 `:model-value="draftModel"`（:58）⇒ 屏幕上刚填的条件被清空；请求参数 `condition = buildQueryCondition(draftModel)`（:200）⇒ 条件为空。
- 对比 HEAD：旧 `reload()` 只有 `serverCount = null; await loadData()`。

**后果：**
1. 点「查询」= 先清空条件/范围、回到第 1 页，再发一次**未过滤**查询（用户以为在过滤，实际是全量）；范围条件同样丢失。
2. 点「刷新」丢掉用户已设的范围/条件/页码（Y-58 只要求补拉定义，没要求重置视图）。
3. 每次「查询」都多打一次 `GET /definitions`（重复请求）。

**修法（最小改动，拆开"取定义"与"拉数据"）：**

```ts
async function refreshDefinitions(): Promise<void> {
  const list = await fetchDefinitions()
  if (!list) return
  defs.value = list
  if (defCode.value && list.some((d) => d.code === defCode.value)) return // 保留范围/条件/页码
  const next = (typeof route.query.defCode === 'string' ? route.query.defCode : '') || list[0]?.code || ''
  if (next) { defCode.value = next; applyDefSelection(next) } else { defCode.value = '' }
}

async function reloadData(): Promise<void> {
  serverCount.value = null
  if (defCode.value) await loadData()
}
```
- 「刷新」→ `await refreshDefinitions(); await reloadData()`（或 `defs` 为空/加载失败时才补拉，即规格括注的变体）。
- 「查询」→ 只 `reloadData()`（如需回第一页，单独 `page.value = 0`）。
- `resetAll()` → 保留其"先重置状态"语义，末尾只 `reloadData()`，不必重拉定义。
- 补一条测试（现有 Y-58 用例抓不到此回归）：设 `scopeType='REGION'` + 一条字段条件 → 点「查询」→ 断言 `listData` 收到 `{scopeType, conditions}` 且 `scopeKey/条件/页码` 未被清空；再点「刷新」断言筛选仍在。
