## R1-13 结论：评审属实，已按最小改动修复

### 根因（已用真实 Spring 上下文证实）

`application.yml:23` 的 `spring.messages.basename=messages` 只是“候选 basename”。Spring Boot 3.5.14 的 `MessageSourceAutoConfiguration` 受 `ResourceBundleCondition` 约束：它会在 classpath 上查找 `<basename>.properties`。仓库里只有 `messages_zh.properties` / `messages_en.properties`，没有 `messages.properties`，因此条件不成立，自动配置整体不启用，应用上下文里只剩 Spring 框架兜底的 `DelegatingMessageSource`（空 MessageSource）。

后果链：`ErrorBodyFactory.lookup()` 取不到任何 message → `NoSuchMessageException` → 回落调用方中文原文。所以 `Accept-Language: en-US` 的 404 响应仍是 `配置定义 不存在: ...`。

### 为什么没有采用 `basename=messages_zh,messages_en`

实测该方案会破坏英文，不能采用。`ResourceBundleMessageSource` 会把每个 basename 当作根束：对 `en_US` 先解析 `messages_zh`，命中存在的 `messages_zh.properties` 就直接返回中文，永远到不了 `messages_en`。用真实依赖类探测输出：

```
zh_CN -> 任务已终态，不可再修改
en_US -> 任务已终态，不可再修改
en_GB -> 任务已终态，不可再修改
```

因此否决；也没有复制 zh 文案做基座。
