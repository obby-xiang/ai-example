## 2) tip Esc：项目完全没有 composer tip 的 Escape/hidden 清理

### demo v2（有完整状态机）

- `docs/demo/chat-ux/composer-decisions.html:382-416`：
  - `keydown` Escape → 对 `button:hover, button:focus` 的 `.tip` 加 `hidden`；
  - `mouseover` / `focusin` → 移除 `hidden`；
  - `mouseout` / `focusout` → 移除 `hidden`。

### 当前 AiPanel.vue（没有）

- 全前端 `grep -rn 'Escape' frontend/src` 只有 `AiPanel.vue:2119-2123` 的 **mermaid 查看器**处理器，且只在 `mmdViewerOpen` 时注册（`2125-2133`）。
- composer tip：`AiPanel.vue:753`（停止）/ `763`（发送）使用 `TIP_CLASS`；`frontend/src/utils/markdown.ts:268` 只有 `opacity-0` + `group-hover/tip:opacity-100` + `group-focus-visible/tip:opacity-100`，**没有 hidden 类**。
- 项目中**没有** composer tip 的 Escape 处理器或 hidden 清理；浏览器实测 Esc 后 tip 仍 `opacity:1`、class 不变。
- 本批 diff 新增了 composer tip 的 span，但没有同步 demo 的 Escape/清理；旧 composer 没有 tip，因此这是**本批新增 composer UI 的行为遗漏**，不是页面壳层问题。

### 最小同步点

- 对齐 demo v2 的**一个共享 tip-hide 状态机**：
  - Escape 隐藏当前 `button:hover, button:focus` 的 tip；
  - `mouseover` / `focusin` / `mouseout` / `focusout` 恢复；
- app tip 是 `opacity-0`/group-hover 体系，隐藏需要能覆盖 opacity 的类（demo 的 `hidden`/display:none 即可），不能只改 opacity；且必须成对做“隐藏 + 恢复”，否则 Esc 后 tip 会卡死。
- 不要逐按钮各写一套；一个共享 helper/监听即可。

### 对 mermaid 全局 Escape 的影响

- mermaid 的 Escape 是独立监听，只在查看器打开时注册（`AiPanel.vue:2125-2133`），只 `closeMmdViewer()`。
- 新增 tip Escape **只要不 `preventDefault`/`stopPropagation`**，两个监听可并存：tip 隐藏不影响 mermaid 关闭；mermaid 打开时 tip handler 即使运行也只隐藏 tip。
- 不要用会阻断传播的全局 Escape 替换 mermaid 监听。
