## 根因实锤：不是作用域死掉，是**相对路径 + 作业 CWD**，且作业错误从未被上报

证据链：

1. **作业确实发出去了**（所以不是找不到命令/变量）：`backend/target/b23l1-artifacts/instance-b.log:305`
   `08:06:48.515 ... reattach runId=de1b35f2-... status=SUSPENDED lastSeq=4 回放帧数=0` —— 这是后台长连接的请求（`:304` 的 08:06:43.990 是 4s 快照那次）。两次都在 B 侧落日志，作业脚本块执行到了 `GetAsync`。
2. **哨兵没写出来**：`backend/target/b23l1-artifacts/` 下只有 3 字节的 `wake-B-snapshot.sse.txt`，没有任何 `wake-B.ready.*`。
3. **CWD 实锤**：`Start-Job` 子进程的当前目录不是调用方目录。本机实测：
   ```
   main cwd=<REPO>
   job cwd=<DRIVE>/<USER>\Documents
   rel exists=False
   ```
   而三跑命令传的是 `-ArtifactDir backend/target/b23l1-artifacts`（相对路径，见主会话 wire 的 `task.terminated` 记录），于是 `$readyFile` 在作业里解析成 `<DRIVE>/<USER>\Documents\backend\target\b23l1-artifacts\wake-B.ready.<runId>`。
4. **为什么主线程只看到 30s 超时**：作业内 `$ErrorActionPreference` 默认是 `Continue`，`Set-Content` 的路径错误不终止作业；作业继续阻塞在 `$resp = $task.Result`，State 一直是 `Running`，所以既没有哨兵、也没有 Failed 可报。离线复刻该写法得到的真实错误：
   `Could not find a part of the path '<DRIVE>/<USER>\Documents\backend\target\b23l1-artifacts\wake-B.ready.relative-test'.`

## 修法（仍只改 `scripts/b23l1-dual-instance.ps1`）

1. **`:66-69`**：`New-Item` 之后把 `$ArtifactDir` 解析成绝对路径（`Resolve-Path -LiteralPath`）。哨兵、日志、证据路径从此与作业 CWD 无关；摘要行会打印绝对证据目录（仅值的形态变化，格式不变）。
2. **`:310-333` 新增 `Wait-WakeReady`**：替换掉内联轮询。除哨兵/超时外，每跳检查作业 `State`；一旦 `Completed/Failed/Stopped` 且无哨兵，用 `Receive-Job -ErrorVariable` 取错误流原文并 FAIL：
   `B 侧 SSE 订阅未就绪：后台长连接作业已结束（state=Failed）：<真实错误>`；超时分支保持原文案。
3. **`:428-430`**：作业脚本块首行加 `$ErrorActionPreference = 'Stop'` —— 作业内任何写盘/连接错误立即终止为 `Failed`，不再「带病继续跑」。
4. **`:477-479`**：用例改为 `Wait-WakeReady $job $readyFile $WakeReadyTimeoutSec $BaseB $runId`。
5. 上一轮的 `Read-Sse` 空响应防御保留（快照 4s 超时仍返回 0 帧，不报空值调用）。
