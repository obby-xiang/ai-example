## 七、方案分歧自决（请复审关注）

1. **`STALE_FENCE` 的 frame code 复用 `TOOL_ALREADY_CLAIMED`**，`status=BLOCKED`、`executed=false`、文案独立（「本轮写回权已转移，本次未执行（本实例持 epoch X，fence 已推进到 Y，续跑权已被接管）。如需重做，请让用户在接管方完成后重新发起。」）。理由：前端被限定只增两支，新造 `STALE_FENCE` 码会落到默认「不在披露范围」，比复用更误导；语义上"另一实例已接管本轮"与既有文案同向。若复审要求独立码，需同步前端第三支。
2. **阻断文案带机器码前缀**（`RESOURCE_LOCKED：…`、`TARGET_INVALID：…`），与既有 `SCOPE_NOT_DISCLOSED：…` 风格一致；两句口径原文完整包含在文本内，并各补一句"下一步"。
3. **`settleBlocked` 不写 `reason`**（按裁决清单），只写 `code/resultText`；`code` 显式落库，故不受 `effectiveCode()` 的 BLOCKED→SCOPE 兜底影响。
4. **目标校验失败开放**：仓储异常按放行处理 + WARN（"查不了 ≠ 不存在"，与锁 `UNAVAILABLE` 同口径）；已单测 `repositoryFailureFailsOpen`。
5. **资源锁只覆盖四件 `start_*`**：`create_task` 无 taskId（它创建目标），无键可锁，不加锁也不校验（有对照用例）。
6. **锁续租**：created 的租约交 `markDriving`（设计稿"持有者续期"），`release` 即停续租；重入无释放权、不续租覆盖创建者。
7. **`resolvePending` 钩子只在 `punresolved? → 已终态 && outcome==unknown && 非 FRONTEND` 触发**；采纳时写回 `outcome/code/executed/executedBy`，不采纳只更新文案。
