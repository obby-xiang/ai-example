## 四、③未做满的部分（被禁止面挡住，需你裁决）

`deleteRun` 的 **12 键里只做了 8 键同 tag**。剩下 4 键不加 tag 不是我偷懒，是"加了就是回归"：

| 键 | 为什么不能在本批加 tag |
|---|---|
| `ai:events:` / `ai:seq:` / `ai:xevents:` | 键名有**第二个拼装点**在 `RedisFrameStore`（`streamKey` 用自己的 `STREAM_PREFIX`；`seqKey`/`legacyListKey` 各自拼前缀+runId，`RedisFrameStore.java:107-117`）。只改 `RunStore` 会变成"写方 XADD/INCR 在旧键、续期/删除在新键" ⇒ 长挂起时事件日志失去续期、`deleteRun` 删不到真键 —— 比不加 tag 更糟 |
| `ai:lease:run:` | `ConfirmGate.runIdOf`（`ConfirmGate.java:661-665`）用 `key.substring(LEASE_RUN_PREFIX.length())` **反解 runId**；加 tag 后反解出 `{run:<id>}` ⇒ `stillDriving` 读不到快照 ⇒ 每拍"判据转假"并释放租约（续跑权静默丢失） |

放行后可一步补齐（3+1 行，都不用改逻辑）：
```java
// RedisFrameStore.java
streamKey(runId)      -> RunStore.runScopedKey(STREAM_PREFIX, runId)
seqKey(runId)         -> RunStore.runScopedKey(RunStore.SEQ_PREFIX, runId)
legacyListKey(runId)  -> RunStore.runScopedKey(RunStore.EVENTS_PREFIX, runId)
// ConfirmGate#runIdOf：先剥 {run:...}（或统一改由 RunStore 提供 key→runId 的反解口）
// RunStore：eventsKey/seqKey/xeventsKey/runLeaseKey 改 runScopedKey，deleteRun 收回成一条 12 键 DEL
// SessionKeyRegistry：帧三族与租约改 runScopedKey
```
现状下 **Cluster 硬错误已全部消除**（ACQUIRE / FENCED_SET / IDEM_PUSH / deleteRun 都不再 CROSSSLOT），只是 deleteRun 的原子性覆盖 8/12，另外 4 键是**单键删**（Cluster 安全、无同槽要求）。

## 五、迁移风险（按严重度）

1. **升级即断档（高）**：8 族键名变了，升级前已存在的 `ai:run:*`/`ai:pending:*`/`ai:claim:*`/`ai:ledger:*`/`ai:idem:*`/`ai:req:*`/`ai:decided:*`/`ai:fence:run:*` 变成**孤儿**（无读方，只能等 24h 滑动 TTL 自然消亡）。**跨越升级时刻的挂起轮（人在等待中的确认卡）会"消失"**，且 `ai:runs` 索引里残留成员靠 `allRunIds()` 惰性剔除。本批无双读/搬迁（不在允许面内）⇒ 建议**发布窗内无在途挂起**，或后续补一次一次性搬迁脚本。
2. **fence 连续性（低）**：新键名下 fence 从 0 起算，与老 fence 不可比；但因为老键不再被写，不会出现"旧 epoch 打赢新 fence"。真正的隐患是第 1 条的孤儿轮若被运维手工恢复。
3. **取号语义微变（低）**：`ACQUIRE` 从 1 次 `EVAL` 变成"GET + INCR + 单键 EVAL"（快路命中/占用时只 1 次 GET）。热路径是每轮续跑/每次工具执行的资源锁，可接受；`ai:lease:epoch` 仍无 TTL、仍须落在 `noeviction` 节点（未变）。
4. **profile 误用（中）**：`application-cluster.yml` 只给拓扑与超时；`spring.data.redis.host/port` 仍在 base 里，cluster 生效时被忽略（Spring Boot 以 cluster 优先）。**不要**把键名按 profile 分叉 —— 本批正是"profile 只决定拓扑、不决定键名"。
5. **文档漂移（低，未改，按"不改 docs"留给文档笔）**：`scripts/README.md:192/228` 与 `docs/research/...` 里的键形仍是旧写法；`SessionKeyRegistry`/`RunStore` 的 Javadoc 已同步。
6. **并发施工**：`RedisFrameStore`/`FakeFrameRedis` 正被另一 agent 改（XRANGE 5.0.14 面）。我的实现**刻意不碰**这三个键，与其"不加 tag"的现状一致；若对方那笔误加了 tag，会与我这边形成写/删分裂 —— 建议提交时 check 一次 `grep "{run:" backend/src/main/java/com/example/configmgr/ai/run/RedisFrameStore.java` 应为空。
