## 实现口径

- 默认 dry-run；`--apply` 才写；`--rollback` 反向（tagged → 旧裸键）；`--run-id` 支持单值/逗号/重复参数。
- 节点只读 `AI_REDIS_CLUSTER_NODES`（`nodesFromEnv` 在 `scripts/redis-run-migration.mjs:94`），缺失、空白、无端口、端口越界全部直接失败，没有默认节点。
- 发现用 `SCAN` 逐 master（`discoverRunIds`，`:183`），不调用 `KEYS`；`--run-id` 时完全不扫描。
- seq/xevents 必须同时存在；缺一或全缺则整 run `skipped`，报告 `reason`，不写任何键。
- 目标不存在才写：STRING 用 `SET NX`；HASH/LIST/STREAM 先写同槽临时键（`<target>:__migrate_tmp__`）再 `RENAMENX`，避免并发写入被合并且绝不覆盖。目标已存在则逐值对账：一致 `identical`（0 写），不一致 `conflict`（整次 apply 拒绝写入）。
- 保留 STRING 值、HASH 全字段、LIST 顺序、STREAM 显式 entry ID/字段顺序、PTTL（临时键上 `PEXPIRE`，`RENAMENX` 保留 TTL）。
- 源默认保留；`--delete-source` 在所有 run 写完并逐项二次对账后才删除，任一轮失败不会提前删源。
- 冲突/Redis 错误即停，CLI 输出 `MIGRATION FAILED` 并以 1 退出，不打印成功结论。
- apply 输出逐项 `verify=value-equal`、`writes/deleted`，并给 rollback 命令提示。
- 针对 Redis 5.0.14：显式 `protocol: 2`（ioredis@6 默认 RESP3）并 `disableClientInfo: true`（避免 `CLIENT SETINFO`）。
