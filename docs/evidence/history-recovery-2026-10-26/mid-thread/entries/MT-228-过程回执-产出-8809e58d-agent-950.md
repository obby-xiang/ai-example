## 三个最关键的实现发现

**1. 三个 HITL API 在 1.79.1 里已收敛为一条链。** `packages/react-core/src/v1-deprecated/hooks/use-copilot-action.ts:198-213` 把 `renderAndWaitForResponse` 直接判成 `hitl` 类型，`:272-279` 分派给 `useHumanInTheLoop`；v1 的 `useHumanInTheLoop`（`use-human-in-the-loop.ts:189-197`）只是把 v1 参数形状规整后转发给 v2。真正独立的是**两条**：前端工具悬挂链、AG-UI 标准 interrupt 链。

**2. `useHumanInTheLoop` 的「暂停」物理实现是 handler 返回一个永不 resolve 的 Promise。** `use-human-in-the-loop.tsx:32-60` 返回 `new Promise(...)` 并把 `resolve` 存进 ref，`respond`（:23-30）才调它；返回值经 `run-handler.ts:1186-1193` → `toToolResultContent` 变成 `{role:"tool",toolCallId}` 消息（:1310-1316）并触发续跑。而 `useInterrupt` 走 `RUN_FINISHED{outcome:{type:"interrupt",interrupts}}`（`runtime/src/agent/index.ts:2127-2137`、`:2500-2512`，暂停靠 `InterruptSignal` 异常抛出）→ 前端 `ɵInterruptState` 累积响应、**全员齐备才**发一次 `runAgent({agent, resume})`（`core/src/interrupt-state.ts:123-158`）→ 同一 thread 新一轮 run。**`interrupt.id === toolCallId` 是贯穿全链的恒等式**（`runtime/src/agent/index.ts:1991-1998`）。

**3. 刷新恢复不靠任何前端持久化。** `CopilotChat.tsx:567` 调 `connectAgent` → runtime runner 重放该 thread 的全部历史事件（`runner/in-memory.ts:886-933`，`compactEvents` 压实 + `emittedMessageIds` 去重 + 在飞流桥接）→ 前端以 `toolExecutionMode: "restore"` 处理，而 restore 模式**只重跑 HITL handler**（`run-handler.ts:935-946`，`reconnectBehavior` 默认 `passive`，绝不重放其他副作用）。

**额外（有决策价值）**：按 CopilotKit 自己的二分法（`docs.copilotkit.ai/human-in-the-loop.md`：LLM 决定暂停=`useHumanInTheLoop`；代码路径决定=useInterrupt），**本仓确认门属链 B，而现有 `SpToolCallingManager` 实现形似链 A** —— 这条已作为 P0 挂账（需显式选定并落档理由，不要求立即改代码）。
