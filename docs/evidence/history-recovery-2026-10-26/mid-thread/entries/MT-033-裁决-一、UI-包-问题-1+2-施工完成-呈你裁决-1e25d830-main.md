## 二、问题 3：业界调研结论 + 我的设计终案

**调研核心发现**（子智能体检索，来源含 Element Plus / Ant Design / MUI / Vuetify / PatternFly / USWDS / GOV.UK 官方文档，GitHub Actions / GitLab / Argo / Airflow / Jenkins 官方手册）：

1. **没有任何主流组件库把「只能跳到已完成步骤」写进组件契约**——AntD 维护者原话：能否点击因业务而异，由业务自行实现。点击规则是我们的自由裁量。
2. **两种主流模型**：表单向导弹（PatternFly：已访问步可回点、未到达步禁用、**提交后步骤条禁编辑**）与工作流产品弹（GitHub/Argo/Airflow：**点节点一律=查看**，运行中给实时日志、已结束给归档只读，变更动作是显式按钮）。
3. **只读查看的硬教训**：业界**不推荐整页 disabled**——disabled 控件不可聚焦、不可复制、读屏读不到值、灰字对比度差（WCAG 豁免仅限"无信息价值"的控件）；应优先 readonly 语义或快照面板。
4. 失败步标红+自动定位（GitHub 自动展开失败步骤）；红色只用于错误，取消用中性色（GOV.UK）；可点击节点必须是真按钮、不可点击节点不要"看起来可点"。

**你的参考思路与业界高度吻合**，我采纳为主干，补三个业界校准点。终案：

| 状态 | 步骤条节点 | 上一步/下一步 | 交互性质 |
|---|---|---|---|
| **进行中**（ACTIVE/FAILED 未终态） | 不可点（视觉也不呈现可点） | 可用（现状行为+守卫） | 可编辑 |
| **已结束**（COMPLETED/CANCELLED） | **全部可点 = 本地切换查看**（★不发 `PUT /step`、零服务端写入） | 也可用（纯翻页查看） | **查看模式**：动作按钮全隐藏、表单只读、顶部「任务已结束，仅供查看」横幅 |

校准点说明：

- **进行中节点不可点**——采纳你的口径（与 USWDS「步骤条不是导航」一致）；进行中想回看前步，现有「上一步」本就可达，不为快捷性引入节点语义二义（查看 vs 编辑）。
- **已结束的查看模式不做独立页面**——采纳你的口径，复用向导页 + 查看模式开关（判定=`task.status ∈ {COMPLETED,CANCELLED}`，进入时 `loadTask` 已拿到）；★**关键防护：查看模式切步绝不发 `PUT /step`**（否则会把已完成任务的 `currentStep` 改写，这是本设计最大的坑）；`flushEditors` 等写侧守卫在查看模式整体旁路。
- **只读实现分两档**：v1 务实=表单 `disabled`+动作按钮隐藏（表格/结果/问题表非表单控件，不受影响、保持可读）；登记观察项=后续按业界规范把有信息价值的输入改 `readonly` 语义。
- **顺手修**（与查看模式强绑定）：导出向导补 `resumeJobs`（施工报告 O-3）——否则已结束导出任务进查看模式无作业数据可看；导入 `latest()` 取最早作业的 bug（O-2）一并修，否则查看模式展示错误轮次。
- 失败步 per-step 标红（EP `el-step` 支持单步 status，现状是容器级粗染色）+ 取消任务中性色。
