### I1. 阶段 A 的“立即”证据其实可能是 10s 后采的（`S:839-869`）

修法（3 行重排）：kill 后立刻先做 A3（CLUSTER INFO）→ A2（PONG）→ 最后才做 A1（慢探针），并给 A3 单独打时间戳写进 `failover-stages.tsv`（现在 A3 完全没有时间戳）。

### I2. “死节点不可达”是弱断言，任何非 PONG 输出都算 PASS（`S:844-850`）

`grep -q "PONG"` 取反即 PASS——`docker run` 起不来、镜像缺失、`timeout` 杀掉（`RCLI_RC=124`）、空输出，全都算“不可达”。`RCLI_RC` 在 `S:167/193` 赋值后**从未被读取**。

修法：改成显式失败证据，否则这条在最该红的时候也会绿：

```bash
if printf '%s' "$dead_out" | grep -qiE 'refused|timed out|Could not connect'; then
    pass "kill 后立即 PING 死节点：连接失败（不是 PONG）" "rc=$RCLI_RC"
else
    fail "死节点探针既非 PONG 也非预期连接失败（探测本身可能没执行）" "rc=$RCLI_RC $dead_out"
fi
```

### I3. `redis-cli --cluster create` 无超时，理论可无限等（`S:461-469`）

5.0.14 的 `clusterManagerWaitForClusterJoin()` 是 `while(!clusterManagerIsConfigConsistent()){ printf("."); sleep(1); }`，**没有总超时**。真发生总线不通时，只能等 job 的 `timeout-minutes: 25` 兜底（`W:34`），白烧 25 分钟且证据是半套。

修法：改一行 `create_out="$(timeout 240 docker exec "${NODES[0]}" redis-cli --cluster create ... 2>&1)"`（`with_timeout` 写死 10s，不要复用）。

### I4. 报告说 `docker logs` 也“白名单外即 FAIL”，实际那段没有门禁（`S:1010-1019`）

`check_logs` 只在 `commands.log` 上做 FAIL 判定（`982-1008`）；节点 `docker logs` 只被 `grep` 进 `log-scan.txt` 备查，**没有任何断言**。报告第 25 行“`:973` 扫描 `commands.log` 与各节点 `docker logs`，白名单外错误即 FAIL”是 overclaim。

## Important（1 条，建议同批修，不阻塞首跑）

### I2 残留：rc=124 且输出为空时必判红，与函数注释自述矛盾（`S:187-195` + `S:920-932`）

注释写“timeout 杀掉 rc=124 …… 空输出、PONG、docker 启动失败都不算”，但实现是 `case 1|124` **且** 必须命中关键字——而 124 的典型形态恰恰是**空输出**，于是 124 分支永远走不到 `pass`。触发面：`docker run` 探测一个“已停止容器释放掉的 IP”时，若包被静默丢弃（无 RST、无 ARP 拒绝），10s 后只剩 rc=124+空输出 → 现在会 FAIL 并打印“探测可能未执行”（**误导性诊断**：探测其实执行了）。反过来，Docker IPAM 很可能把刚释放的 IP 直接分给探针容器本身，此时拿到的是 `Connection refused`——**能过，但不是“节点死了”的证据**。

修法（4 行，推荐 B：把决定性事实从 TCP 语义里摘出来）：

```bash
	# S:894 之后
	running="$(docker inspect -f '{{.State.Running}}' "$master_container" 2>/dev/null)"
	# S:925 分支改为：
	if [ "$running" = "false" ] && is_expected_connect_failure "$RCLI_RC" "$dead_out"; then
		pass "kill 后死节点：容器已停止 + 探针明确连接失败" "rc=$RCLI_RC +${row_rel}ms"
	elif [ "$running" = "false" ]; then
		pass "kill 后死节点：容器已停止（探针 10s 无响应 / 或端口已释放，弱证据）" "rc=$RCLI_RC +${row_rel}ms"
	else
		fail "docker kill 未生效：容器仍在运行" "$master_container"
	fi
```

这样最坏情况不再误红，且**真正要防的失败（kill 没生效）**变成确定性判定——比原来的 TCP 探测强。

> 若不想加 `docker inspect`，最小改法是把 `124)` 单列：`case "$rc" in 1) ...;; 124) return 2;; *) return 1;; esac`，调用处把 2 记为“10s 内无任何响应（弱证据）”。
