## 三、语义变更清单（逐条单列）

1. **G6 提示口径（用户直裁覆盖原派工单）**：在途轮里回车/发送 **零提示**。旧行为 = store `noticeBusySend()` 写「本轮进行中：本条消息未发送…」。仓内既有规格本来就是这个口径：`AiPanel.vue` 的 `onComposerKeydown` 注释「流式中 preventDefault 后静默返回（**不发送 / 不停止 / 不提示 / 不换行**）」、`composerHardDisabled` 注释「`ai.loading` 不硬禁用 —— 生成中仍可继续编辑」；唯一与之一致性冲突的是 store 的程序化守卫及其用例 `ai-panel-parts-render.spec.ts:5273`（`expect(notice).toContain('本轮进行中')`）→ 改为 `expect(notice).toBeNull()`。4 处 `vi.spyOn(store,'noticeBusySend')` 的"未调用"断言改为更强的 `expect(store.notice).toBeNull()`（方法已删除）。
2. **停止不再给顶部提示**：删「已请求取消本轮对话」/「本轮已取消」，改由消息尾「已停止」chip 承载（S3）。
3. **`stop()` 语义**：从"只清挂起标志"改为"本地就地收敛 + 立即 `loading=false`"（输入框立刻解禁）。`b1-suspend-disconnect.spec.ts:592` 由 `status:'running'` 改为 `status:'cancelled', requiresAction:false`（旧断言锁的是脏态）。
4. **`awaitingExternal=false` 的恢复**：从"整体早退、不挂流"改为"在途轮静默全量续收"（`restore-request-emitted.spec.ts` 第三例改写并改名）。
5. **409 不再出现**：`busyConflict` 状态、横幅、「一键重挂」按钮、`（本轮未开始：…）` 占位、带 runId 的文案全部移除；409 时撤回乐观用户气泡 + 空气泡，草稿只留在输入框。
6. **后端取消会写半截正文进记忆**（带 `stopped` 元数据）。旧注释「半条消息会污染下一轮记忆」不删，改为记录新口径的代价与标记语义。
7. **后端取消会补裁决帧**（`confirm_decision(cancel)` / `frontend_tool_result(CANCELLED)`），此前只改 Redis 条目不发帧。
8. **`RunStore.save` 对 RUNNING 也写 session→current 索引**：`/runs/current` 对在途轮 `found:true`；每笔快照写多一次带 TTL 的 SET（量级 = 快照写本身）。
9. **会话门可被"死轮"释放一次**（`RunLiveness`：终态 / 无租约 / 本进程无写出器 / 活动超 `app.ai.resume.zombie-age`）。反向红线：任一"活着"的证据都仍 409。
10. **`reattachActive` 不再是 UI 入口**：保留为刷新恢复的内部静默路径（无占位文案、无 notice、复用宿主消息），供 G2 与两处既有 epoch 语义用例使用。

### 停止面
11. 纯文本流式中停止：正文保留 + 「已停止」；**刷新后半截正文仍在**（镜像 + 后端记忆双份）。
12. 工具执行中停止：该卡立刻「已取消」，输入框立刻可用，卡不再随刷新变「调用中」。
13. HITL 挂起中停止：输入框**立刻**解禁、卡只读「已取消」；再点卡不会 409。
14. GF 表单挂起中停止：表单收起、卡只读；输入框可用。
15. 连点两次停止：网络面板只有 1 次 `POST /api/ai/cancel/{runId}`；首点后按钮变「停止中…」disabled。
16. 停止后立刻发新消息：200、无 409、无幻影。
17. 停止后 60ms 内观察工具卡：不再新建/改写（迟到帧闸门）。
18. 另一页签停止同一轮：本页签在该轮 `done{cancelled}` 到达时出「已停止」。
19. 僵尸轮放行：构造"快照 RUNNING + 无租约 + 60s 无活动 + 无活连接"（或杀掉跑轮的进程后不重启）→ 新发送不被 409；活轮（挂起等人工、长流式）仍应 409。
