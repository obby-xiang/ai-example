# A09 产品缺陷补丁（frontend/src —— 本批受约束未落盘，供指挥/前端施工方应用）

## 目标文件

`frontend/src/stores/ai.ts` · `uploadHandoffAvailability()`（约 3317–3333 行）

## 缺陷

刷新恢复时 `rebuildUploadHandoffFromFrame` / 快照恢复路径存
`ref: target?.entry ?? validated.value.ref ?? null`：
模型发 `ui_request_upload` 时未显式给 `ref`（产品取区域声明的 `uploadEntry`），
args 里就没有 ref ⇒ 若历史回放早于路由页挂载（懒加载区块未到、区域还没注册），
重建出的 `activeUploadHandoff.ref` 落成 `null`，且**再也回不来**：
`uploadHandoffAvailability()` 开头 `if (!handoff.ref) return 'missing'` 直接一票判死，
区域后来注册了也不会复原 ⇒ 卡面永久「请先打开导入向导第 1 步」+ 主按钮禁用。

## 补丁（删 3 行 + 加 3 行注释）

```diff
       if (handoff.status === 'degraded') {
         return 'degraded'
       }
-      if (!handoff.ref) {
-        return 'missing'
-      }
+      // ref 只是"显式指定"；缺省（模型没给 ref）时落点由区域声明的 uploadEntry 决定，
+      // 而刷新重建那一刻区域可能尚未注册 ⇒ ref 落 null。此时不能一票判死：
+      // 区域一旦重新注册，判据必须跟着复原（resolveUploadRegion(null) 取区域声明的入口）。
       const target = resolveUploadRegion(handoff.ref)
       if (!target || target.region.root.isConnected !== true) {
         return 'missing'
       }
       return target.region.readOnly?.() === true ? 'missing' : 'waiting'
```

`resolveUploadRegion(null)` 本来就会回落到"任一注册区域声明的 uploadEntry"（目前只有
`import.upload` 声明），故删掉这一票否决不会放宽其它判据：区域仍不在 ⇒ `target === null` ⇒ 仍 `missing`。

## 已验证（模拟补丁效果，未改 src）

在 `@stub` 诊断用例里人为把 `ImportWizardView.vue` 模块加载延迟 5s（确定性制造
"历史回放早于路由页挂载"），刷新后：

| 阶段 | handoff.ref | availability | 按钮 |
| --- | --- | --- | --- |
| 刷新前 | `import.upload.choose` | `waiting` | 可点 |
| 刷新后（路由页未挂载） | `null` | `missing` | 禁用 |
| 区域已重新注册（`[data-ai-ref="import.upload.choose"]` 在） | `null` | `missing` | 仍禁用 ← 缺陷 |
| 把 `handoff.ref` 回填成区域声明的入口（= 补丁后的判据） | `import.upload.choose` | `waiting` | 启用 |

即：补丁足以复原，且 reactivity 足够（回填后 500ms 内按钮即变可用，无需额外触发器）。
