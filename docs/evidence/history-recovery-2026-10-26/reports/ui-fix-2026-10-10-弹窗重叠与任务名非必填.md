### 修 3a（P2）导入向导第 4 步 collapse 长标题行高异常

锚点：`ImportWizardView.vue:143-146`（`el-collapse-item` 的 `#title` 插槽）

| | 修复前 | 修复后 |
| --- | --- | --- |
| 写法 | `:title="\`${defName(...)}（${code}）— ${rowCount} 行\`"`（字符串 prop） | `<template #title><span class="block whitespace-normal leading-snug">…</span></template>` |
| 2 行标题的 header 高 | **97px**（= 2 × 48px 行高 + 1px 边框） | **48px**（= `min-height:var(--el-collapse-header-height)`，内容 35.8px 垂直居中） |
| 1 行标题的 header 高 | 49px | 48px |

机制要点（也是本轮唯一「按报告直做会失败」的点，已实测纠正）：`.el-collapse-item__header` 是 `display:flex` + `line-height:48px`，其子 `.el-collapse-item__title` 被 flex 块化（block 容器），**行盒高度由该块自身的 strut 决定**。因此：

- 若把 `leading-snug` 加在 title 内的 **inline `<span>`** 上 → 实测 header 仍 97px（父块 48px strut 把行盒撑回去），**无效**；
- 必须让承载文字的元素**自己成为块容器**：`<span class="block …">`（实测 48px）或 `<div class="…">`（实测 48px）→ 有效。

垂直居中不是新增能力：`.el-collapse-item__header{align-items:center}` 本就居中（实测 `headerAlignItems=center`），修好行高即同时得到「行高自适应 + 垂直居中」。EP 结构（`el-collapse` → `el-collapse-item` → `__header` → `__title` 插槽 → `__arrow`）未改，仅把标题从 `title` prop 换成 EP 原生 `#title` 插槽。

断言级别：**【实测】**（真实 app 第 4 步：`/import?taskId=99`，桩上游喂 67 字超长配置名强制折行；另有一次**机制探针**在应用 CSS 上下文内对 `before / inline-span / block-div / block-span` 四变体同屏测量，见 `shots/probe/01-mechanism-probe.png`）。

### 修 3b（P2）`ElMessageBox.alert` 的 `join('\n')` 多条目挤成一行

锚点：`ImportWizardView.vue:537-543`（`handleUpload` 内），新增 import：`:214` 的 `h`

```ts
await ElMessageBox.alert(
  h('span', { class: 'whitespace-pre-line' }, result.unmatchedFiles.join('\n')),
  '以下文件未匹配到配置项',
  { type: 'warning' }
)
```

选型说明：`ElMessageBox` 的 `message` 在本仓版本（EP 2.14.7）支持 `string | VNode | () => VNode`（`messageBox.mjs:26` 对 `isVNode(props.message)` 走 default 插槽）。两条候选里：
- `dangerouslyUseHTMLString: true`：需要自己拼 HTML 并对**用户上传的文件名**做转义，XSS 面被主动引入——**弃**；
- **VNode + Tailwind `whitespace-pre-line`（采纳）**：零转义、零 XSS 面，且与仓内既有 `whitespace-pre-wrap` 口径一致（`components/AiPanel/AiPanel.vue:145/148/164`）；仓内无 `dangerouslyUseHTMLString`/`h()` 先例，故选「最简且 EP 原生支持」的 VNode 方案。

实测（机制探针，真实应用的 EP CSS + 本仓 Tailwind 上下文内同屏对照 4 个未匹配文件）：

| | 修复前（纯字符串 `join('\n')`） | 修复后（VNode + `whitespace-pre-line`） |
| --- | --- | --- |
| `white-space` | `normal`（`\n` 被折叠） | `pre-line` |
| `innerText` | `a.xlsx b_报价单.xlsx c_很长的配置编码文件名称.xlsx d.xlsx`（**空格相连**） | `a.xlsx\nb_报价单.xlsx\nc_很长的配置编码文件名称.xlsx\nd.xlsx`（**逐条换行**） |
| 文本行盒数 | 2（在 420px 盒里任意位置折行） | 7（4 条目各起一行，长文件名自身折行的部分算在内） |

断言级别：**【实测】（机制级）**——弹窗DOM 由探针按 EP 的 `.el-message-box__message > p` 结构复刻；真实触发路径需要后端上传接口返回 `unmatchedFiles`，本次**未跑真实上传**（见 §5 遗留）。逻辑等价性由 `typecheck` 通过 + `ElMessageBox` 入参类型（VNode）可接受共同保证。
