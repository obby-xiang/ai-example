| GF 表单卡（填写+提交） | **复现**。提交后回执卡面 = `✓ 已确认  生成式表单 · form={"scenario":"CLARIFY","t…`（**纯 schema JSON**），展开「查看详情」也**只有 schema JSON，已填值完全不在** |

## 3. 根因

### RC-1（渲染面，R-165 回归，工作区在途未入库）

`AiPanel.vue:2381 hitlReceiptSummary(part)` **没有 GF 分支**：

```ts
const label = toolLabel(part.name)              // →「生成式表单」
const parsed = JSON.parse(part.args)            // ← GF 的 args 是整份表单 schema
const pairs = Object.entries(parsed).slice(0,3).map(([k,v]) => `${k}=${...}`)
return `${label} · ${pairs.join('，')}`          // → 生成式表单 · form={"scenario":"CLARIFY",…}
```

GF 的工具入参是 `{"form":{scenario,title,fields:[…]}}`，于是**回执卡面的「一行自然语言」被整份 schema JSON 顶替**。

而 R-165 **S5a 项 2 又删掉了唯一的可读值面**：5a382b0 版回执卡（`AiPanel.vue:199-201` + `:1168-1172`）有一条

```
<div v-if="part.submittedValues" data-testid="receipt-values">已提交：{{ submittedValuesSummary(part.submittedValues) }}</div>
```

现状该函数已退役（退役注释在 `AiPanel.vue:2396-2400`），值被折进折叠的 mono JSON 盒（`AiPanel.vue:251-277` + `receiptDetailText()` `:2041-2052`）。施工报告自陈：`<LOCAL_WORK>/r163-chat-ui/施工报告-R165-S5a.md` §项 2「小节标签｜『已提交值』键值行 + 『原始参数』标签 + `kvRows()` 整块退役」、§7.2「回执『已提交值』折进 mono 盒」，且 §8.1 明写「**真机未覆盖 GF 表单卡**…走注入取证」——这正是漏网口。

**切刀归属**：R-165 **S2**（`施工报告-R165-S2.md:69`）只是结构重排（当时仍保留 `rc-kv 已提交值` 行）；真正删除可读值面的是 **S5a 项 2**。两批均在工作区未暂存（`git status` → ` M frontend/src/components/AiPanel/AiPanel.vue`）。

### RC-2（数据面，GF-B 起的老账，非 R-165）

`stores/ai.ts:1968-2001 submitGenerativeForm()` 的写回被守卫短路：

```ts
const outcome = await this.submitFrontendToolResult(...)   // :1980
if (this.activeForm?.toolCallId !== form.toolCallId) return // :1981 ← 这里就 return 了
…
this.upsertToolPart(host, { … submittedValues: values … })  // :1993-1999 永不执行
```

结局帧比 POST 先到，把 `activeForm` 置 null（`ai.ts:2409-2417` 的 `case 'frontend_tool_result'`），于是 `activeForm` 已为 `null` → 守卫命中 → 写回整块跳过。

**时序硬证据**（`rootcause/cardreg-gf-order.mjs`，5ms/20ms 采样，2/2 一致）：
```
{"t":70,  "ev":"POST sent"}
{"t":82,  "ev":"FRAME frontend_tool_result"}   ← 帧先到
{"t":107, "ev":"POST resolved {\"ok\":true}", "activeForm":null}
FINAL [{"status":"succeeded","req":false,"sv":null}]   ← submittedValues 始终为 null
```
连带 `G06`（in-session 展开）里连 `values` 键都没有；刷新后走历史重建 `ai.ts:956-963` 才从后端 `toolCallStates.submittedValues` 回读到 `{task_type:"EXPORT",task_title:"卡片回归巡检",want_schedule:false}`（`receipt-values` 命中）——但**卡面依旧是 schema JSON**。

该守卫可追溯到 GF-B 提交 `8f5c2a3`，5a382b0 与现状**逐字相同**，故 **RC-2 早于 R-165**；R-160 已在 `docs/demo/hitl/r160-issue14-验证报告.md:9` 登记过「提交后…无『已提交』行：submittedValues 未持久化」，当时只修了刷新路径。R-165 把值挪进折叠 JSON 盒后，这条老账的可见后果被放大成「整张卡只剩 JSON」。
