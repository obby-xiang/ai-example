# 小结：若引入渲染，最小依赖增量与主要技术约束

**依赖增量（取决于渲染路线，非裁决）**
- 最小面：`markdown-it`（或 `marked`）单运行时包；若要出 HTML 走 `v-html`，须再 + `dompurify`。
- 加代码高亮：+ `highlight.js` 或 `prismjs`（含语言子集注册的体积）。
- 加 Mermaid：+ `mermaid`（本组中体量最大，带 dagre/d3 系传递依赖），是**单独一级**的增量，与 markdown 渲染可分离决策。
- 若走 KaTeX：+ `katex` 且需构建期拷贝字体资产。
- 零依赖路线（自建 VNode 渲染器、不落 `v-html`）在技术上可行，但那部分成本转为自写代码与自测责任。
- 全部候选**必须存在于华为云镜像**（npmjs 直连实测不通）；yarn 1.22 + CI `--frozen-lockfile` 要求 `yarn.lock` 同步更新并提交；`manualChunks` 是手工枚举（`vite.config.ts:48-55`），较重的包需显式规划 chunk。

**主要技术约束**
1. **逐 token 重解析**：正文是每 token 拼接（`stores/ai.ts:1253`），且 watch 已在每 token 触发滚动（`AiPanel.vue:704-710`）；未闭合的表格/代码围栏在流中会反复重排 —— 业界把「Markdown 流式重排」直接列为反模式（`业界调研-raw.md:46`）。
2. **一个渲染点两种输入**：流式逐 token、历史整段（`stores/ai.ts:459-479`）、sessionStorage 镜像三条路径共用 `m.content` 渲染位，渲染必须对「半截 Markdown」幂等且不炸。
3. **安全面从 0 变 1**：仓库现有纪律是「永不 v-html」（`FormRenderer.vue:12/111`、`form-schema.ts:9`）；引入 HTML 渲染必须配套 sanitize 或自建白名单。
4. **复制口径分裂**：`copyMessage` 复制 `m.content` 原文（`AiPanel.vue:629-653`），渲染成富文本后「看到 ≠ 复制到」需要重新定义。正文、`reasoning`、`run.result`、`run.args` 四个位置现在都是纯文本，渲染范围要显式划定。
5. **样式基座缺失**：无 `prose`（Tailwind 无 typography 插件）、`preflight: false`，需自带 Markdown 元素样式；气泡仅 `max-w-[82%]`、13px/1.6 的窄栏版式，表格与代码块必须显式处理横向溢出。
6. **零自动化兜底**：前端无测试框架、CI 只跑 typecheck+build（`ci.yml:53-79`），端口渲染行为只能靠人工/仓库外脚本留证；且「新增测试框架」本身需另做裁决（`施工卡.md:184` 先例）。
