## 八、施工裁决与留痕（权限内自决，供复审）

1. **RunStore↔LeaseService 耦合点**：注入可空 `LeaseService`（4 参 `@Autowired` 构造，保留 3 参构造给单测/`InMemoryRunStore`），`save` 终态**直接** best-effort 调 `releaseRunLease`，不用回调钩子 —— 依赖方向本就单一（RunStore→LeaseService），少一层间接；批②b 只需在 ResumeService 里 `tryAcquireRunLease(runId)`，fence 写自动生效。对外四个薄口：`tryAcquireRunLease` / `releaseRunLease` / `heldRunEpoch` / `runLeaseKey`。
2. **instanceId 同源**：新增 `InstanceId`（进程内单值，口径与原 `RunStore` 现算一致），LeaseService 与 RunStore 共用；否则认领值、租约 owner、台账 `executedBy` 的"自己"判据会分裂。
3. **req 位合并规则**：只授予不清除（条目 JSON 自带的旧 `req` 保留），且 `markRequestEmitted` 读时已决即不写位（R3）；R1 形态（读时 PENDING、写前被决）下 req 位仍置位、决策不被覆盖 —— 对应"那一帧确实要发"的语义。`cancelPendings` 后条目保持 CANCELLED（R6）。
4. **`touchSuspendedRun` 续期面** = 心跳五键（`renewSuspensionTtl` 本体不动）+ session→current + `ai:req:` + `ai:decided:`。理由：req 位若先于待决条目过期，L0 修掉的洞会以"刷新拿不到卡"的形式复发。
5. **fence 拒写不抛**：只 WARN（含 `STALE_EPOCH` 字样），不推进 fence、不做 session 索引联动 —— 陈旧写方已不是续跑主人，抛异常只会打断它正在做的收尾。
6. **`deleteRun` 先 `releaseRunLease` 再删键**：否则进程内视图会变成"幽灵所有权"。
7. **降级**：`tryAcquire` 返 empty + `healthy=false`，`leaseOk()` 每次真打 PING（Redis 恢复自动回绿），降级期间 `heldEpoch=0` ⇒ 快照走 plain SET（E3）。
8. **性能口径**：`pending()` 多一次 HGET（req 位）、`pendings()` 多一次 HGETALL；`markRequestEmitted` 变成 2 读 + 1 HSETNX + 1 EXPIRE（每张卡一次，可接受）。
