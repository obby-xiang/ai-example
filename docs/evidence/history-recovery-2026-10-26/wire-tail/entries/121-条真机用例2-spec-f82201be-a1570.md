## 3 缺陷与发现

1. **已小修（语义变更：UI_* 机器码恢复透传）** —— `frontend/src/utils/frontend-tools.ts:1236` `normalizeExecutorReturn` 只透传 `outcome/availability/result/reason/sheetMeta`，**把 `code` 丢了** ⇒ 围栏给出的 `UI_REF_NOT_SNAPSHOTTED` / `UI_TARGET_DISABLED` / `UI_PRECONDITION_CHANGED` 到不了 store 与 `/api/ai/frontend-tool-result`，台账只剩结局文本（与蓝本 V-08「机器码上送并落档」直接冲突）。修法 4 行（`code: value.code` + 注释）。验证：`vue-tsc --noEmit` exit 0；`tests/ai-tool-receipt.spec.ts` + `tests/ai-snapshot.spec.ts` 24/24 绿；全量 vitest 见下。
2. **发现项（未修）`ui_select` 无可用目标**：全仓无 `[data-ai-option]`、无 `region.setters`、也没有任何控件在 `data-ai-verbs` 里声明 `select` ⇒ 语义选择在当前产品面上只能走到拒执分支（V-04 按真实行为断言，非降级断言）。要覆盖成功路径得先有一个声明 select 的控件。
3. **发现项 `ui_scroll` 可观测面窄**：表格行/标签只声明 `highlight`，页面里唯一放行 `scroll` 的是搜索框（表头、无滚动余量）⇒「位置变化」只能靠真人滚轮 + 元素回视口间接观测（V-05 已如此断言）。
4. **发现项 `ui_request_upload` 双造口**：`executeFrontendTool('ui_request_upload')` 恒回 degraded（“不走通用执行器”），参数校验只在 store 的 `openUploadHandoff` 与导出的 `validateUploadArgs` 上；V-07 参数面用真模块 `validateUploadArgs` 断言（同一造口）。另：蓝本写「文件名 >64 字被拒」，实现是**截断到 64 并保留扩展名**，按实现断言。
5. **发现项 下载可能长时间无结局**：`download_export_files` 在编辑器/引擎未就绪时 `buildXlsx` 的 promise 长时间不落地（实测无 toast、无 download、无错误），第一次调用可挂 >90s；先打开编辑器预热后 2.5s 内落盘。建议 `startDownloadInBackground` 加显式超时并把失败结局如实回灌。
6. **基建缺口**：`support/harness.ts` 的 `RUN_DIR` 写死（`test-results/.e2e-run`：`state.json` + `data/`），多路子智能体并行会互相 `taskkill` / 删对方 H2 目录。我未改 harness，改用自己的 `helpers-vl.ts`（独立目录 + 端口基 18930/18999/19001 + Redis DB 12）。**建议 harness 加 `E2E_RUN_DIR` 参数**，其余助手即可直接复用。
7. V-14 承载层下调：蓝本标「真模型」，实际用 `/api/ai/chat` 的 `context.extra.uiRegionCount` 走真后端披露 + 桩请求记录（`.tools.txt`）取证，比“采样 10 次 ≥9 次不调用”更确定，无需真 key。
