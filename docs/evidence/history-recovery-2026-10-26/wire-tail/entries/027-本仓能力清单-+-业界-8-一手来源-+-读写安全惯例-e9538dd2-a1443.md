## 4. 设计合理性结论

**总判断：方向正确、落地有 3 个契约级 bug 和 5 处"设计-实现"偏离；能力面在"聚合/确认/回滚"上对齐甚至超出业界，在"定位/排序/检索/历史/治理"上明显落后。**

### 已对齐或超出（应当保留）

1. **执行在前端、值不出服务端**：比 Airtable"在库内按权限处理"更彻底（本仓连服务端都不发）。
2. **写前预览 + 人确认 + 无时限等待**：与 Copilot Plan、Gemini preview card、Claude"给选项由人决定"同构。
3. **计数级预览（0 行进模型）+ 全量 diff 只在浏览器**：强于多数产品，是正确处理 3 万行的路径。
4. **行指纹整批拒绝**：业界一般靠 undo/版本兜底，本仓前置拒绝更保守（"宁可多拒一次"）。
5. **结构化条件回读**（predicate → "条件「region = XN」"）：对齐业界"NL→可见过滤条件"。
6. **单点尺寸闸 + 恒"共 N"**：可断言，优于黑箱摘要。
7. **只改内存、不落库、不触发作业**：权限边界清楚。

### 不合理 / 过度设计

1. `preview` 三档做成模型参数（应为 UI 控制）。
2. 读工具复用写工具的"选区优先"默认（读的默认应是整表/投影）。
3. `undo` 挂"人工等待"（语义上它不需要等人）。
4. 三阈值 + 数组 match + 2000 字符/8000 字符双闸，参数与代码面偏重。
5. 8 个工具名对单一表格面略多，但"细粒度胜出"有依据（SheetCopilot 消融），可保留。

### 不足（真正该补的）

1. 读侧缺 **Top-N/排序、全文检索、类型画像/异常**——回答"谁最多/哪几行有问题"的能力不足。
2. 缺 **单元格级地址**（A1），可核对性弱于 Claude/Excel。
3. 缺 **历史/变更集**（现在只有"上一次"）。
4. 数据最小化默认值反了：**默认全列、无白名单**，且 D2 记录/开关缺位。
5. 缺 **提示词策略**（默认聚合、采样非全量、写前先 count）。
6. "业务行不出浏览器"这一口径失实，属治理红线，应先订正再扩能力。
