## 预算扣除的实现方式

**计量源放在 `ToolActivityBeacon`**（它本来就是这个 run 的"进程内活动账本"，看门狗与兜底判据都已经持有它）：

- `gateWaitFinishedMs`（已结束窗口之和）+ `gateWaitSinceMs`（当前窗口起点）；`gateWaitMs(runId)` 返回「已结束 + 进行中」——**含正在进行**是关键：等待没结束时预算也必须暂停，否则一次十几分钟的表单填写期间每一拍都会判"预算已耗尽"。
- `ConfirmGate.await` 在循环前后 `beginGateWait/endGateWait`（`finally` 保证配对），同一 run 的工具是串行结算，不需要嵌套计数（已在注释写明）。
- `StreamWatchdog` 构造时抓 `gateWaitBaseMs` 基线，tick 判定用 `(now − turnStartedAt) − (gateWaitMs − base)`：**只扣本尝试窗口新增的等待**，重试后新看门狗从新基线起算，不会把上一段的等待重复扣。
- `ResilientChatService.awaitSettled` 原本是"一次 `get(remain)`"，会把无上限的等待在 300s 一刀切死；改成 **1s 切片循环**，每片重算「预算 − 已用（扣等待）」；`catch` 里的 `overBudget`（重试三条件之一）同样扣除。重试语义本身（`startedCount` / 副作用判定）**未改**。
