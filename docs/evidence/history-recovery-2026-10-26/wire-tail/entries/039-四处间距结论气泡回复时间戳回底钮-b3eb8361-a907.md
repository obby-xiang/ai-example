## 题 1：用户消息气泡内部下方间距过大

**根因（确证，非猜测）**：用户消息走的是**与 AI 完全同一条 markdown 渲染链路**，因此吃到了 `.md-body p { margin: 0 0 12px }`。

- 渲染路径：`stores/ai.ts:1738 recordUserMessage()` 造 `parts:[{kind:'text', text: content}]` → `AiPanel.vue:190` 的 `block.kind === 'text'` 分支 → `<div class="md-body" v-html="markdownHtml(m, block)">` → `utils/markdown.ts:208 renderMarkdown()`（markdown-it，`p` 在 `ALLOWED_TAGS` 第 41 行）。**用户消息同样产出 `<p>`，不是纯文本插值**。
- 气泡本体 `AiPanel.vue:173-179`：`px-2.5 py-2`（=8px 上下 / 10px 左右）+ `border 1px`。**padding 上下对称（8/8）**，与 v7 的 `py-[8px]` 一致。
- `ai-chat.css:113 .ai-chat .md-body p { margin: 0 0 12px; }`，而全文**只有 `:first-child {margin-top:0}`（:99），没有任何 `:last-child {margin-bottom:0}`**（我 grep 过 `last-child|:last` → 0 命中）。
- 气泡带 `overflow-hidden`（BFC，`AiPanel.vue:174`）→ 末段 `p` 的 12px 下外边距**不会塌陷出去，被算进气泡高度**。

| 位置 | 当前值 | v7 同位置 | 差值 |
|---|---|---|---|
| 文字上沿→气泡上边框 | 0（first-child mt 归零）+ 8 padding = **8px** | 8px（裸文本 `py-[8px]`） | 0 |
| 文字下沿→气泡下边框 | **12（p margin-bottom）+ 8 padding = 20px** | 8px | **+12px** |

**whitespace-pre-wrap 不是元凶**：当前 `AiPanel.vue` 全文无 `whitespace-pre-*`（仅 `ai-chat.css:135/164/222/289` 命中，均属 code/th/td/mermaid）；`renderMarkdown` 会吃掉消息尾部换行，不产生空 `<p>` 或尾 `<br>`。**它是历史形态**——`git show 59ccdc4^:…AiPanel.vue:193` 是 `<div class="whitespace-pre-wrap">{{ chSplit… }}</div>`，R-163 T1 把用户消息一并换成 markdown 链路后，`p` 的 12px 才进到气泡里（本次回归的上游来源）。

**建议修正值**（二选一，因 R-165 铁律「禁动 ai-chat.css」需指挥官裁）：
- (A) 根治：`ai-chat.css` 在 :99 那条旁边补 `.ai-chat .md-body > :last-child { margin-bottom: 0; }`（1 行，同时解掉题 3 的一半）。
- (B) 零 CSS：`AiPanel.vue:190` 的 `class="md-body"` 加 `[&>*:last-child]:!mb-0`（`!important` 才能压过 `.ai-chat .md-body p` 的 (0,2,1) 特异度）。
- 修后气泡内下沿 = 8px，与 v7 齐。

**附带两点（同区域，建议一并裁）**：
1. `w-full` 让短消息气泡恒为 86% 宽：`:174` 是 `min-w-0 overflow-hidden w-full px-2.5 py-2` + `:176` 用户侧 `max-w-[86%]` → `width:100%` 覆盖了 flex `items-end` 的收缩适配，v7 用户气泡只有 `max-w-[86%]`（块级 + `items-end` = 贴身收窄）。→ 建议 `w-full` 也按 role 分派（助手保留，用户去掉）。
2. **S2 的用户气泡字号修正实际未生效**：S2 把字号改成 role 分派（`:175-177` 用户 `text-[13.5px]`），但真正承字的是内层 `.md-body`，而 `ai-chat.css:95` 在 `.md-body` 元素**自身声明**了 `font-size: 13.8px; line-height: 1.7` —— 后代自身声明恒胜过从祖先继承的值（与特异度无关），故用户正文字形仍是 **13.8px/23.46px**，不是 13.5px。S2 报告 §4-R3 测到的「13.5px/22.95px」是**气泡外壳**的 computed，不是文本 run。若要 13.5px 真落地，需 `[&_p]:text-[13.5px]` 这类作用到 md-body 内部的选择器（或 commander 批 1 行 ai-chat.css）。

## 题 3：AI 正文 → 时间戳/操作行 间距

同样口径（当前工作区 = `md`12 + 容器 `py-2` 下 8 + 元信息行 `mt-[6px]`）：

| | 值 | 构成 |
|---|---|---|
| **当前工作区** | **26px** | `md-body p` 12 + 容器 `py-2` 下 8（`:174`）+ `mt-[6px]`（`:438`） |
| HEAD(916e83a) | **24px** | 12 + 8 + `mt-1` 4 |
| v7 | **20px** | 正文包裹层 `mb-[14px]`（`v7.html:67-69` 的 `<div class="mb-[14px]"><p class="m-0">`）+ `.afoot mt-[6px]` |
| **差值** | **+6px**（HEAD +4px） | 12+8=20 ↔ v7 的 14 |

**根因**：v7 在消息正文段落上是 `<p class="m-0">`（段落外边距**显式清零**）+ 包裹层 `mb-[14px]` 承担节奏；本仓把 `.md-body p` 的 12px 留着、外层包裹层没有 margin、又加了 8px 容器内边距，等于「20px 顶掉 14px」。`:first-child{mt:0}` 只处理了上沿——**下沿缺口正是不对称的源头，与题 1 同一根因**。

**建议修正值**：`mb:0` 落地后为 8+6 = **14px**，比 v7 的 20px 偏紧 6px；把它补回到元信息行 `mt-[6px]`→ 助手侧 `mt-[12px]`（配合题 2 的 role 分派），即得 8+12 = **20px = v7**。（边界情形：若末块是回执/思考卡（`mb-[14px]`，`:203/:258`）或工具卡（只有 `mt-1.5`、无 `mb`），间距由卡片自身 margin 决定，与正文块不同，本次不属用户所报四点。）
