## 2. L-105 停止按钮尾部竞态

**结论**：前端停止按钮 → `ai.stop()` → `POST /api/ai/cancel/{runId}`；后端端点在 `AiController#cancel`，权威态写 Redis `ai:cancel:<runId>`，同进程监听器/看门狗（1s 一拍）发现后走 `cancelTerminal`。服务端比界面多几个字符，代码上有两条明确来源：

1. **输出守卫尾窗**：`ResilientChatService#consume` 里 `guard.feed(raw)` 会扣住末尾可能的敏感模式前缀（≤128 字符），这部分**没有作为 delta 发出、也不在累加器里**；取消时 `drain(guard, out, accumulator)` 先 `accumulator.append(tail)` 再 `out.delta(tail)`（`:1504-1515`），而前端早已 `abort()`，这条 delta 收不到 ⇒ 服务端持久化正文比 UI 多出这几个字符（280→283 的 +3 与此吻合）。

## 4. L-121 e2e 手写迷你 Redis 客户端

**结论**：客户端在 `frontend/e2e/support/harness.ts`（`flushRedisDb` + `redisCommand`）。手写原因写在注释里：**不引第三方依赖**。仓库**没有根 `package.json`**，`frontend/package.json` 的 dependencies/devDependencies 中**没有** `ioredis` / `redis` / `@redis/client`，`yarn.lock` 也无对应条目，因此 harness 没有现成客户端可用。读响应确实是「见到第一个 `\r\n` 就收工」：数据事件里只要 buffer 含 `\r\n`（或 `$-1`）就 `finish()`，大值跨多个 TCP chunk 时只拿到前半截。

证据：
- `frontend/e2e/support/harness.ts:153-195`：`flushRedisDb`（注释「极简 RESP 客户端：仅用于 SELECT + FLUSHDB（不引第三方依赖）」），SELECT 回包也只等首个 `\r\n`（`:232-234` 的同类判据在 `redisCommand`）
- `frontend/e2e/support/harness.ts:201-246`：通用 `redisCommand`；收包判据在 `:240`
  ```ts
  if (buffer.length > 0 && (buffer.includes('\r\n') || buffer.startsWith('$-1'))) finish()
  ```
  `finish()` 返回 `buffer + sink.end()`（`:216-222`），所以同 chunk 内的小值完整，跨 chunk 的大值被截断。
- 跨块 UTF-8 已修（`utf8Sink`，`:145-151`），但**收包长度**仍是启发式
- 现调用面（小值）：`harness.ts:442/444`（FLUSHDB）、`frontend/e2e/support/helpers-mdxy.ts:176`（`LRANGE ai:safety:<sid>`）、`frontend/e2e/support/helpers-nfezui.ts:193-201`（TTL/整数回包）

- 依赖面：`frontend/package.json:15`（dependencies）、`:33-34`（devDependencies 仅 `@playwright/test` 等）；仓库根无 `package.json`；`frontend/yarn.lock` 无 redis 客户端条目
