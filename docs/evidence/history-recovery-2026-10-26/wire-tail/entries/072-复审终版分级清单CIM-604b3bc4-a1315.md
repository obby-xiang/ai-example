### I-1（Important，本批必修）`updateProvider` 不翻转 `source`，击穿"用户改过的不动"

- **位置**：`ai-example-code/wt-model-config-b2/backend/src/main/java/com/example/configmgr/ai/config/AiConfigWriter.java:249-311`（`updateProvider`）；对照 `:236`（`createProvider` 里唯一一处 `setSource(SOURCE_DB)`）。
- **事实**：全文件仅 `:236` 一处 `setSource`；`updateProvider` 事务内改了 8 个字段，**没有一处**动 `source`。
- **后果三条**（均可在代码里闭环）：
  1. **标签说谎**：设置页 `AiSettingsView.vue:148` 的 `sourceLabel()` 用 `provider.source === 'ENV_SEED'` 判"环境种子/设置页创建"。用户在 UI 改过 env 种子行后，仍显示"环境种子"。
  2. **seed-force 覆盖用户改动**：`AiConfigSeeder.java:116-117` 的保护条件是 `if (!SOURCE_ENV_SEED.equals(provider.getSource())) return;`，注释写的就是"用户在 UI 改过这一行 ⇒ 不碰"。该不变量**从未被写入路径建立**，于是 `seed-force=true` 时会把 `displayName/baseUrl/completionsPath` **改回 env 值**。
  3. **`keyLast4` 与实际密文错配**（最脏）：seeder 在 `AiConfigSeeder.java:124-127` 会 `setKeyLast4(last4(envApiKey()))`，但**不动** `keyCipher`。用户在 UI 换过 key（`keyRef=DB`、密文=用户 key）后跑 seed-force ⇒ 密文还是用户的，`last4` 却变成 env key 的末 4 位，UI 显示的掩码对应一把**不是**当前生效的 key。
- **修法**（3 行 + 1 个回归测试）：

```java
// updateProvider 事务内，saveAndFlush 之前
if (!AiProvider.SOURCE_DB.equals(existing.getSource())) {
    existing.setSource(AiProvider.SOURCE_DB);   // 用户一改就"脱离种子"：seed-force 不再覆盖
}
```

### I-2（Important，门禁前置；基线既有 flake）

### M-1（Minor）探活把 `KEY_UNREADABLE` 报成 `AUTH_FAILED`

```java
KeyResolution key = this.configService.resolveKey(provider);
```
