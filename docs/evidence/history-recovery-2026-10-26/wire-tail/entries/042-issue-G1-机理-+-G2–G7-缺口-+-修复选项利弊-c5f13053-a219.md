## A.5 严重度评估与披露矩阵结论

**结论摘要【实测（代码级）】**：`send()` 的静默 `return` 代码成立（`stores/ai.ts:575-579`），**但 UI 层不可达**；真正需要修的是 `loading` 的三处复位竞态。

**根因复核结论一句话（§1.4 原文）**：

> **issue 的代码级事实成立（`stores/ai.ts:577-578` 的 `!this.loading` 静默 return），但"静默丢弃连发消息"的因果链在现 UI 下不成立 —— `canSend = !loading` 使输入框与发送按钮同时 `disabled`，Enter 连事件都到不了 `send()`；可复现的真缺陷是相反方向的 `loading/状态失步`：终帧提前清（`:1255-1257`）、`finally` 无条件覆盖（`:625-627`）、`stop()` 提前清（`:953`）三处都会把"正在跑的轮次"标记成空闲，从而放开输入、覆盖 `currentAbort`、丢掉对新流的取消能力。**

**复位路径逐条核对（§1.1）【实测】**：正常（收到 `done`）→ `handleFrame` 终帧分支 `:1255-1257` **且** `send` 的 `finally:625`（是，**两次**，终帧早于 `finally`）；异常 → `catch:622-623` → `handleChatError` → `finally:625`（`handleChatError` 自身**不动** `loading`）；abort → `stop():948` abort → reject → `catch` → `finally:625`，`stop()` 自身也在 `:953` 清 `loading`（是，两次，`stop()` 早于 `finally`）；断流 → `finally:625` + `onClose:596-608`；**守卫命中 → 无复位（`:578` 直接 return），静默、无 UI 反馈**。

## B.5 q1-q8 探针矩阵概要与 fetch/EventSource 桩需求（§4）

**桩需求（关键差异）**：

> issue#2/#3 的探针（`<SCRATCH>/issue2-reports/evidence/probe-src.ts`）**只把 axios 适配器换成假后端**（`probe-src.ts:198` `http.defaults.adapter = …`），而 `POST /api/ai/chat` 走的是 **`fetch` + `ReadableStream`**（`api/sse.ts:325-347`）与 **`EventSource`**（reattach 通道），**均不经过 axios** ⇒ 本 issue 必须**扩展桩层**。

1. **`window.fetch` 桩**（覆盖 `SSE_PATHS.chat = '/api/ai/chat'`）：模式 A（正常）返回 `Response`（`status 200`，`body` 为受控 `ReadableStream`），可**逐帧定时投喂** `start`/`message_start`/`delta`/`done`（帧格式照 `types/sse.ts`），并支持"**保持流不关闭**"（用于把 `loading` 钉在 true，观测守卫/禁用态）；模式 B（409）返回 `status 409` + JSON `{code:'SESSION_BUSY', message, sessionId, runId, degraded, reattach}`（照 `AiController:163-176`）；模式 C（503）`{code:'SUSPEND_POOL_SATURATED', …}`（回归用，非必需）；需**记录调用次数与请求体**（证明"第二次请求到底有没有发出"）。
2. **`window.EventSource` 桩**（覆盖 `/api/ai/events/<runId>`）：可控回放帧 + 记录**实例数**（用于 G4 双连接取证）。
3. **真实 `AiPanel` + 真实 pinia `ai` store**（当前 issue2/3 探针只挂视图，不含面板）⇒ 需 `app.use(ElementPlus)` 并挂载 `AiPanel`（或其宿主 `App.vue`），以便观测 `disabled` 属性、按钮可用性、`el-alert`（`notice`）文本。
4. **观测面**：`ai.loading / suspended / notice / busyConflict / stopped / streamInterrupted / activeRunId / messages（含 assistant.done）`、DOM（textarea/发送按钮的 `disabled`、提示 Alert 文案）、`window.__fetchCalls`、`window.__esInstances`。
5. 不含后端（纯前端桩）⇒ **不需要起 Java 服务**；若要"409 真值"可用 §4.3 的 503/409 桩等价替代，后端链路的权威性由现有 `SessionGate`/`AiController` 用例覆盖。
