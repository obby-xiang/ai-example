## 2. 重点标注

### 2.1 上下文管理 / 压缩 / 记忆族（现状：基本整体空白）

已有的是**被动窗口**：`chat:mem:<sessionId>` LIST + 40 条上限 + 6h 滑动 TTL + 整窗口覆盖写 + `trimKeepingToolPairs`；用户侧**零可见性、零可控性**。业界工具向产品的"用量指示器 + 自动/手动压缩 + 换任务请新开对话"三件套在本仓 **M2 去向表零命中**——即该族**既未施工也未立项**，只有业界调研给出 P1 建议。相关但分散的登记：单条消息体上限（B11，待裁决）、会话 TTL 绝对上限（B12）、多实例写互斥（B10）、模型侧工具结果截断（R10-1 已判必修但未入 R 表）、usage 入库（R7-1/B3）。

### 2.2 「主流聊天产品标配」但本项目未处置

按 `业界调研-结论.md` 采用面为**普遍/常见**、而本仓未处置者：

- 消息级操作条（业界共识 4–5 个）：**复制已做**；**重新生成、点赞/点踩、编辑重发或从此分支**全部未做（赞踩暂缓、其余未处置）——这是"标配落差最大"的一组。
- 重新生成同时被业界用作**错误恢复**主路径（OpenAI 官方排查文档、M365 埋点 `RegenerateClicked`）——本项目错误态只给"一键重挂该轮"，无"重新生成"。
- 上下文三件套（用量指示器 / 压缩 / 重置指引）——见 2.1。
- 生成中排队下一条 + 停止后「继续/重新生成」。
- 会话级快捷键体系与空态快捷键提示。
- 可访问性（aria-live 策略）——业界也无厂商官方文档，属需自定规范项。

### 2.3 已明确"不做/规格内"、不应再计入缺口

- 无历史会话列表 / 切换 / 重命名 / 删除 / 归档 / 会话绑定任务（DC-06③ 订正注记）；会话 = 页签。

- 渲染面（Markdown/代码高亮/数学/Mermaid）——**用户裁决暂缓**，覆盖面见 §4。
