## 三、装配偏差（与指派口径不同，均已实测验证）

1. **Redis DB 18 在本机不存在**：Memurai 只有 0..15，`SELECT 18` 返回 `-ERR DB index is out of range`，首棒 harness 卡在 Redis 探活 120s 后失败。改用 **DB 12**（A/B 同库；当时 0/7/8/10 有键，12 为空）——见 spec 头注释。
2. **`--output=test-results/.artifacts-mdo`**：`playwright.config.ts` 把 `outputDir` 硬编码为 `test-results/artifacts`，与三路并行同族 + 提交官共用同一目录，实测出现过一次 `browserContext.close: ENOENT …-recording5.trace` 的假失败（M-08 断言本身是通过的）。用独立 `--output` 后消失。**这是 harness 并行债（建议登记）**：`outputDir` 应随 `E2E_RUN_DIR` 参数化。
3. **`--app.ai.hitl.frontend-tool-timeout=15s`**：产品默认 120s ≥ 单例超时，D-11 无法在默认值下观测；改为 15s 并断言 `/health.frontendToolTimeoutSeconds` 同源。
4. **两实例拓扑**：harness 没有"第二个有 key 的主后端"位，但降级面 B 的 `/events`、`/runs/{id}`、`/confirm`、`/frontend-tool-result`、`/cancel` 都不查可用性 —— 令 `E2E_REDIS_DB == E2E_REDIS_DB_DEGRADED` 即得到"两个不同 JVM 看同一份台账"的真跨实例面（M-01/M-02/M-09/O-03 的真值来源）。

## 五、发现的缺陷 / 值得注意的行为

1. **P2 缺陷（已挂账 `E2E-O02b`，`test.fail()`）**：停止与回车落在同一 tick 时，输入框里**新打的草稿被上一轮提示词覆盖**。同 tick 下 `stop()` 同步把 `loading` 置 false，紧随的 Enter 二次进入 `AiPanel.send()`（清空 inputText 后失败），两次"原稿回流"顺序让旧稿最后落地。实测两条分支都会把旧稿写回。**未改 src**：批③c 有他人在途改 `AiPanel.vue`，改它必冲突 —— 建议提交官决定是否随批修（修法方向：`send()` 回流前比对"当前轮次身份/roundEpoch"，或 stop 后在同一 tick 内锁住 composer）。
2. **消息级「已停止」标识在同 tick 竞态下也会丢**（`msg-stopped-*` 计数为 0），与上一条同源；O-02 已把该断言让给后端终态判据，避免假绿。
3. **蓝图 M-06 的路径与产品实现不一致**：目标任务是"不存在"时，`ToolPreflightService` 在**出卡前**就拦下（不出确认卡、无 `confirm_request` 帧），所以"批准后拦截"只能由"上下文任务 ≠ 入参任务"这条执行前对账触发。用例按真实路径断言，建议蓝本补一句（预检先拦 / 对账后拦两条路都不执行）。
4. **蓝图 M-02 的 `LEASE_HELD_ELSEWHERE` 在本装配下取不到**：B 无续跑服务，决策落 B 后 `resumeOutcome=NO_RESUME_SERVICE`；该精确断言需要两个都有模型的实例（同 M-03 的前置）。用例断言的是"决策落 B（`storedBy`）+ 台账收敛 + A 真执行"这一组更本质的事实。
5. **桩夹具坑（影响后续所有"断流"用例配方）**：`kill-stream=<ms>` 单用**不会**造成失败——桩在一个 tick 里同步写完所有帧，socket 销毁时 `[DONE]` 已到手；必须配 `slow-first-byte`（或 `stall-frames`）让 kill 计时器先跑。D-09 注释里已写明。
6. **D-06 的"发送闸关闭"档（`composerOverLimit`）在真输入下不可达**：textarea 带 `maxlength=8192`，真实键入/粘贴都到不了 8193；能验的是"到顶文案 + 仍可发 + API 侧 400"。属覆盖限制，非缺陷。
7. **`playwright.config.ts` 的 `outputDir` 未参数化**（见装配偏差 2）：并行多域时是真实的假红源，建议登记为 harness 债。
8. 正面证据：`/health` 的 `instanceId`、`storedBy`、`executedBy`、`pending[].req` 四个面在跨实例用例里三方同值，可作后续 M 域取证的稳定锚点。
