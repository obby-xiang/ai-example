# 5. `data/` 目录现状（两层）

**现状一句话**：仓根 `data/` **未被 git 跟踪也未被 .gitignore 覆盖**（`git status` 显示 `?? data/`），里面是"运行时状态三件套"：H2 库、上传/导出文件、KB 语料 + Lucene 索引；另外 `backend/data/` 是**同一套的相对另一份**（因为后端常以 `backend/` 为 cwd 启动，`.gitignore` 只忽略 `backend/data/`）。

```
data/
├── config_mgr_db.mv.db                # H2 文件库（含 ai_provider/ai_model/ai_setting/ai_config_audit 等）
├── files/                             # 上传/导出件（app.file.storage-path）
│   └── 6c03e7f8-…-81a73839d69e.xlsx
├── kb/                                # 本地知识语料（app.ai.kb.dir）
│   ├── 01-region-tariff.md … 20-kb-maintenance-faq.md   （20 篇）
│   └── manifest.json
└── kb-index/                          # Lucene FSDirectory（app.ai.kb.index-dir）
    └── build-76249952920000/          # 每次重建一个 build-<nanoTime>，成功后原子切换

backend/data/                          # 第二份（cwd=backend 时产生；.gitignore 已忽略）
├── config_mgr_db.mv.db
├── files/  （40+ 个 uuid.xlsx）
└── kb/     （20 篇 md + manifest.json，无 kb-index）
```

证据：`find data -maxdepth 2`（根目录 4 个子项，`kb` 21 文件，`kb-index` 1 个 build 目录）；`git status --porcelain data` → `?? data/`；`.gitignore` 含 `backend/data/`、`*.mv.db`、`frontend/.env.local`、`backend/config/*`（+ 白名单示例），**不含根 `data/`**。这也解释了为什么既有文档反复强调 `./data/kb` 是 cwd 相对路径——同一份仓在两处各播了一份样例。

### 会被波及的面
`.gitignore`（若要显式忽略根 `data/`）；部署脚本/文档里所有 `./data/...` 口径（`docs/知识库维护手册.md:10,20,81-86,103`、`application.yml:38,270-271,413`）；若改成"从文件读 AI 配置"，新配置文件放哪（`data/` 还是 `backend/config/`）会直接决定**生产升级时文件会不会被覆盖**。

# 你认为的修改点候选清单

1. **新增文件配置模型 + 解析器**：定义 `ai-config.yml`（或 json）schema，逐字段镜像 `ai_provider` / `ai_model` / `ai_setting` 三表（含 `key_ref=ENV` 语义），放在 `app.ai.config.file` 指向的路径，启动期 fail-fast 校验（复用 `AiEndpointGuard` + `AiProperties` 同姿态）。
2. **把 `AiConfigService` 的读源抽成 `AiConfigSource` 接口**（`DbAiConfigSource` / `FileAiConfigSource`，按 `app.ai.config.source=db|file` 装配），保留 `ConfigSnapshot` 与方法签名不变，这样 25 个 config 单测与 `AiProviderRegistry`/`ContextConfig` 的消费面零改动。
3. **version 号语义收敛**：文件源用文件 mtime+sha 代替 `ai_setting['config.version']`（`AiConfigService:197-208` 的比对分支要加一支），并决定 Redis `ai:cfg:ver` 是否保留（多实例改文件后不重启不会自动生效，需登记为知悉风险）。
4. **条件化 DB 侧资产**：`@ConditionalOnProperty(app.ai.config.source=db)` 包住 4 个实体/4 个仓储/`AiConfigSeeder`/`AiConfigWriter`，并把 V4 从 `db/migration` 移到可选位置（注意既有库的 Flyway history 校验，需要 `ignore-migration-patterns` 或保留空迁移占位）。
5. **设置页写端点降级**：`AiConfigController` 的 7 个写端点（`:104/:113/:125/:181/:187/:193/:206`）在文件源下改为只读或"写文件 + 校验 + 提示重启"；前端 `AiSettingsView.vue` + `api/aiConfig.ts` 的保存按钮语义要跟着改。
6. **新增"远程文件"服务端点**：如 `GET /api/ai/kb/files/{*path}`（或 `GET /api/ai/files?path=`），落在 `AiKbController` 旁，必须复用 `LocalDirKbSource:109-115` 的越界闸 + 支持 `If-None-Match`/304，使其满足手册 §8.2 的四条契约（这样 KB 用 `source=http` 指回自己即可模拟远程）。
7. **KB 默认切到 `source=http` 指向本机自服务端点**（`app.ai.kb.http.base-url`），`local` 源保留给开发；同时确认 `CachedKbSource` 的 Redis 缓存不会掩盖文件变更（sha 判据已在，但第一次冷启动仍走 `prepare()`，`KbSampleSeeder` 在 http 源下无操作）。
8. **样例播种路径改为可配 + 显式只执行一次**：`KbSampleSeeder` 的 classpath 源（`pom.xml:126-148`）在"生产不带样例"时要么不打包、要么由 `app.ai.kb.seed-samples=false` 关掉，避免生产 `data/kb` 被自动写入。
9. **文档与运维口径同步**：`docs/知识库维护手册.md` §1/§3/§8/§8C、README、`backend/config/application.yml.example`；新增"AI 配置文件格式与热更说明"一节（当前所有相关文档都写"DB 为真源"）。

## 需要上游拍板的两个歧义（影响清单形态）

- **"远程文件服务"由谁提供**：① 后端自己新增一个端点、本地文件当远程（最小改动，复用 §2 契约与 `LocalDirKbSource` 路径闸）；② 仍由外部服务提供，只把"服务端契约"落成文档/桩。两种做法在 §2 与 §6 改造点上完全不同。
- **AI 配置文件是否允许热更**：现有 DB 读路径有"1s 节流 + 版本号 + 跨实例 Redis 失效"三件套；文件源若不实现 watch/轮询，"改文件必须重启"会与设置页现有交互（保存即生效）冲突，需明确取舍。

**未验证项**：没有起服务，因此 §1"缺表 ⇒ 启动失败"、§4 的 Flyway history 冲突结论均为**基于配置与代码的推断**，建议落地前用一次性 H2 副本实测（`mvn -q -Dspring.flyway.enabled=false` 对照跑一遍即可证伪/证实）。
