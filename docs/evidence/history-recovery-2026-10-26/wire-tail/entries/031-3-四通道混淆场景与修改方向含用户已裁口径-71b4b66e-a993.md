1. **频道信号缺位**：四类卡在 400px 面板里都落成“白底描边卡 + 36.4px 单行头 + 右侧 chevron”，用户只能靠读字判断。调研明确说：区分靠**左色条 + 卡头图标 + 文案**三重冗余，颜色不能是唯一手段（WCAG 1.4.1）。

## 四、修改方向与取舍

### 方向 A：调研直译——补“三重冗余”频道皮肤（推荐作为基线）

在现有骨架上加三个信号，不动 36.4px 头几何：

- **左边缘 4px 色条**：A 无/2px 中性；B 琥珀（不可逆可加红/斜纹）；C 品牌蓝；D 2px 状态色（绿/灰/红）。
- **卡头首图标形状**：A 状态字形；B ⚠ 三角（与错误卡圆形 `!` 区分）；C 编辑/清单图标；D 结果字形 ✓/✗/!。
- **标题动词化**：B “待你批准：…” + 风险等级；C “请填写…（N 项必填）”；D 过去式（已有）。

**来源**：前三项是调研第 6 轮原文；`cardChannel(part)` 纯函数、Tailwind 类映射、`data-channel` 是工程推断。
**取舍**：改动最小、扫视识别最强；但引入“左色条”这一新视觉原语，会与 r12-r14 “卡头对齐工具卡”的观感产生张力；必须先让用户确认“条在卡边、不在卡头”是否可接受。若只加颜色不加图标/文案，违反 WCAG 1.4.1，不能做。

### 方向 B：结构去重——一卡一头（推荐与 A 并行做）

不新增颜色，先解决“卡中卡/双卡头”：

- **B 门卡**：把外层工具卡头改成门卡自己的头（⚠ + “待你批准：…” + 风险/等待态），删掉体内重复的“需要你确认后才能继续”行；或者反过来，隐藏外层头，让门卡内框成为唯一头。
- **C 表单卡**：把 `FormRenderer` 的 `.gf-hd` 合并进外层卡头（一个头 = 表单图标 + 标题 + “N 项必填”），或在外层有 live form 时隐藏外层头。**不能两层都留**。
- **D 回执**：可先把“头前加结果图标 + 摘要动词”做实，壳是否去边框留给用户裁。

**来源**：调研只给“一张卡一个卡头/已决退场”的原则；具体合并方式、DOM 改动、测试影响是工程推断。
**取舍**：不引入新颜色，和 r12-r14 冲突最小；但单靠结构，远看仍是一排白卡，识别强度不如 A。GF 双头是当前最明显的“低级观感问题”，建议无论选哪个方向都修。

### 方向 C：布局分层——interrupt / activity / receipt 三种容器（候选，较大）

- A 工具卡保持中性白卡；
- B/C 作为“打断卡”用独立容器（抬升/内嵌/强调条），与普通活动卡分开；
- D 作为“回执行”扁平化（去边框/浅底/2px 状态边），真正退场。

**来源**：NNG“需要决策→打断”、调研“已决退场”是原则；具体布局分层是工程推断。
**取舍**：区分最强、最符合“决策不是日志”的语义；但改动最大，会重开 r12-r15 的卡头/壳观感，且可能打断“正文→工具→正文”的时序连续感。建议**只作为 demo 的第二变体**，不直接进第一版实现。

### 推荐

**A + B 作为一个 demo 的两个必选层，C 作为同 demo 的第二变体供用户二选一。**

理由：

- 只做 A：GF 仍然是双卡头，用户第一眼看到的还是“工具卡里长了一张表单”，左色条救不了结构问题。
- 只做 B：结构干净了，但四类卡仍共享白壳，历史流里还是靠读字。
- A+B 既补了调研的视觉频道，又修了最明显的卡中卡；且 36.4px 头、chevron 靠右、折叠语义全部不动，对 r10-r15 的回归面最小。
- C 留给用户看完 A+B 后决定“要不要更强分离”，避免一上来就推翻 r12-r15。

## 七、需要用户裁的具体选择

1. **区分轴**：按**功能四通道**（工具 / 门 / 表单 / 回执），还是按**类型四族**（H1 / H2 / H3 / GF 各一套视觉）？两者不是一回事。建议前者为主轴，类型差异用徽标/文案做二级区分。
2. **左色条**：是否允许在卡根加 4px 左条？这是调研首推、也是与 r12-r14“卡头对齐工具卡”张力最大的一个新原语。若不允许，只能走“图标 + 动词 + 结构”区分，强度会弱一档。
