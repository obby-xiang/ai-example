## 一、根因结论

### 1. 适配器失效机理（已在真机 stack 直证并复现）

预修复基线（11b 整文件串跑）第一次就红在 T02，栈顶是：

```
TypeError: Cannot read properties of null (reading 'getRowCount')
  at Y.getRowCount (spread-sheets chunk)
  at Object.rowCount (SpreadGrid.vue:252)
  at findRows (sheet-tools.ts)
```

而同一时刻的截图里表格**正常显示 5 行** —— 说明活着的 worksheet 没问题，是适配器闭包里的那个 worksheet 已经死了。

机理链：

1. `SpreadGrid#loadFromXlsx / loadFromJson` 走 `workbook.fromJSON(...)`；SpreadJS 的 `fromJSON` 会**重建工作表集**并丢弃旧实例（内部引用置空）。
2. 旧实现 `getSheetAdapter()` 用 **worksheet 对象身份**做 WeakMap 键（L-74），`buildSheetAdapter(sheet)` 把建对象那一刻的实例**闭包捕获**进 `rowCount/getCell/getArray/...`。
3. 调用方在重建**前一瞬**解析到上下文、重建后读取时（或首屏 xlsx 还在载入时就解析），拿到的适配器指向已废弃实例：`getRowCount()` 抛上面的 TypeError，`getValue/getArray` 读回 `null`（聚合把 null 归成一组 ⇒ "共 1 组" 的退化读数）。
4. e2e 侧之所以能稳定命中：`openExportedSheet` 只等 canvas 可见，不等内容载入；`page.evaluate` 里的 `await` 边界（微任务）足够让 `loadFromXlsx` 的续体先执行 `fromJSON`，随后探针才去读。

预修复实测：**2/2 次完成的整文件串跑都红**（第一次 T02+T03，第二次 T03，18/20、19/20）。

修法（产品侧，行为不变）：
- 适配器改为 **live 绑定**：每次操作先 `isLiveSheet()` 判定；仍被工作簿持有就用自己（多 sheet 切换不跨表），已被 `fromJSON` 丢弃就改绑到当前活着的表；整本工作簿没了才抛可读错误。适配器缓存键仍是"当前活动 worksheet"，重建后自然是新适配器（撤销栈仍按表隔离）。
- 新增 `whenLoaded()`（在途载入计数，`loadFromXlsx → loadFromJson` 可嵌套），`sheet.current` 交出适配器前等它归零 —— 关掉"表格位置已挂载、内容还没载入"的窗口（这就是 T05「0 行」/ T13「0 组」的形态）。

### 2. T05 / T13 的"串扰"源（结论：不是用例之间，是测试与并发编辑之间）

先排除用例间串扰：Playwright 每个用例都是**全新 browser context**，`stores/workspace.ts` 的 `pageHandlers`、AiPanel 状态、sessionStorage 镜像都不可能跨用例；后端数据也按用例各自建任务。

仓外归档证据 `<LOCAL_WORK>/_ci-real/out-stub11b/` 里两条红的真实形态是：

- **T13**：工具卡本身**成功且数据正确**（"decimalPlaces 2：4 行 / 0：1 行 / 共 2 组"），红在用例自己的 `resolveSheetContext` 返回 `ok:false` → `null`；
- **T05**：工具回灌文本正是 `当前页面没有可操作的表格`（= `getPageHandler('sheet.current')` 为 null），预览卡没出；
- 两条的页面快照里都出现了 SpreadJS 的兜底 DOM「**你需要一个完全支持HTML5 Canvas的浏览器来运行SpreadJS**」；
- 两条 trace 的模块 URL 带 Vite HMR 的 `?t=` 时间戳，且**在用例执行期间还在变**（例：`router/index.ts?t=…413848` → 两秒后 `?t=…415875`）。

结论：红的时候 e2e dev server 正跑在**被并发编辑的活动工作树**上。HMR 的 `?t=` 会重新取模块 ⇒ 同一页面里可能同时活着两份 `stores/workspace.ts`（`pageHandlers` 是**模块级 Map**）：视图注册在旧实例、工具/用例读到新实例 ⇒ "当前页面没有可操作的表格"；SFC 热替换还会让 `SpreadGrid` 中途重挂 ⇒ 画布退回"需要 Canvas"兜底 DOM。所以不是"用例 A 脏了用例 B"，而是"运行期有人在改这份源码"。

修法（隔离，不改开发体验）：`e2e/support/harness.ts` 起 dev server 时设 `VITE_HMR=0`，`vite.config.ts` 据此把 `server.hmr` 置 `false`（Vite 的 `createHMROptions` 直接返回 false，不再推送失效）⇒ 一次页面生命期内模块图不可变；每个用例仍是新 page，新代码照常生效；5202 开发默认仍开 HMR。
