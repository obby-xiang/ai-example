# 历史遗漏补档 · 只以 wire 末条长文形式存在的稿（wire-tail）

> **定位**：2026-10-26「历史遗漏补档」批的**分支三**。前两批分别是 `wire-only/`（末条首行为 Markdown 标题的 138 件）与 `mid-thread/`（中间稿 388 件）；本批处理**上一轮报告留下的另一面**——末条 assistant 文本 ≥8KB 但**首行不是标题**的项目域长文（逐件复核后入库 188 件）。
> **性质**：全部为**历史分析 / 过程证据**，是**当时时点**的结论，**非现行基线、非验收结论、不是当前缺陷清单，也不是当前有效裁决**。正文逐字保留（仅路径 / 会话标识 / 身份 / 密钥 / 命名纪律脱敏 + 占位符归一 + 行尾空白规整），**不改写旧结论、不补写、不删段**。
> **纪律**：本批**零 git 写操作**（无 add / commit / push / stash）、未改产品代码、未改本目录以外任何文件（含父级 `history-recovery-2026-10-26/README.md`、`wire-only/`、`mid-thread/`、`reports/`、`audits/`、双看板、`docs/research/` 同日并行件）、未起停服务、未再委派。**原始 wire 永不入库**；本目录只入"从 wire 抽出的文本副本"。
> **与既有目录的关系**：父级 `history-recovery-2026-10-26/README.md` 的最后统一更新、以及各批的索引登记，均由**其它 agent / 后续批**负责；本批只交本目录 + 本 README + `selection.json`。

## 0. 本批做了什么（一句话）

按「项目域子 agent / 主会话 wire 的**末条 assistant 文本** ≥8KB **且首行不是 `#` 标题**」复现候选面（215 件），逐件核覆盖率与去重后把 **188 件**归档进 `entries/`，每件带身份、消息序号、历史时点、原基线、分类、与既有件关系、来源哈希与覆盖率；其中 **5 件**是本批对边界件做**实际 diff** 后改判入库的（1 件覆盖率卡线 + 2 件同题并行复跑 + 2 件不同仓的变体勘察）。

同时必须并排说清的三件事：

1. 这 188 件**不是** 188 个当前缺陷；
2. 其中 **51 件过程核验**（占 27%）**不是** 51 条有效裁决，只是"当时那一次取数/复核/回收"的回执；
3. 「覆盖率 <60%」只说明**仓内与落盘语料里没有逐行等价内容**，**不等于**"这项结论现在仍成立"，更不等于"这是个缺口"。

## 1. 提取口径（可复现）

### 1.1 取什么、不取什么

| 项 | 口径 |
|---|---|
| 扫描面 | 会话根的 `agents/*/wire.jsonl`（含 `agents/main/wire.jsonl`），沿用既有索引 `index.jsonl` 的 2,253 个 wire 快照 |

### 1.2 候选面怎么来的（沿用上一轮报告）

上一轮（`agent-241`）的口径：全部 wire 中，**子 agent 末条 ≥8,192 B** 的 600 件里，**首行非 `#` 标题**的 267 件，减去**本会话**（施工当日会话）46 件与 **30 个非项目会话**的 21 件，得 **200 件子 agent 候选**；再加**主会话同口径 15 件**，共 **215 件**（= 200 子 + 15 主）。本批不重跑该筛选，只复现其**逐件判定**与**入库**。

### 1.3 覆盖率算法与语料快照（本批独立复算）

- **行指纹**：每行 `NFKC` → 空白折叠 → `trim`，丢长度 <6 的行，取 `md5[:16]`。
- **覆盖率** = 候选去重行指纹中"在语料里出现过"的比例；**最高单件** = 与单个语料文件的重合行数 / 候选去重行数（用于判断"是否已被某一件覆盖"）。
- **语料快照（写入 `entries/` 之前冻结）**：`1395` 个 md/txt、`172,198` 条行指纹 = 仓内全量 md/txt（含 `history-recovery-2026-10-26/` 既有 138 + 388 + 51 + 5 件）。**不含本批将写入的任何文件**，因此不存在"把自己产物判成重复"或"自己抬高覆盖率"的循环。
- 与报告口径的差别：报告的语料含仓外落盘件（≈2,000+ 文件），本批只用**仓内**语料，故本批复算值系统性偏低（例：`83b890a8/agent-124` 报告 0.60、本批 0.597；另有多件报告 0.05–0.13、本批 0.02–0.09）。**两列数字不同不是矛盾，是语料面不同**；逐件报告口径值写在每件的页首块里。

## 3. 这 188 件是什么、不是什么

| 常见误读 | 事实 |
|---|---|
| "188 件 = 188 个待修缺陷" | **不是**。其中 87 件是复核、51 件是过程回执；同一问题常被多件重复核验，反向也有"一份复核报 10 条问题"的情况。**件数不等于缺陷数** |
| "51 件过程核验 = 51 条有效裁决" | **不是**。过程核验是"派发回收 / 字节校验 / 结论速览 / 逐字提取"，价值在于**过程可追溯**（谁在什么时点取了什么数），不在于结论权威性 |
| "覆盖率 0% = 全新发现" | **不是**。覆盖率只说明"仓内与落盘语料无逐行等价内容"；被改写成摘要并入某件、或落在 `.log/.json` 运行产物里的内容，本批语料都看不到 |
| "文中写'已修复/已实测' = 现在是好的" | **不是**。全部为 2026-10-04～10-25 的只读快照；本批**未对当前 HEAD 复验任何一条**，行号、哈希、测试数字都是当时值 |
| "多件互相印证 = 双人复核" | **不是**。多数同题多稿是**同一模型、同一提示**的并行复跑（§6.2 是实例），一致性可能只反映模型稳定性 |
