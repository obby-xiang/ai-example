## 5. 偏差与遗留

| # | 偏差/取舍 | 理由 | 影响 |
| --- | --- | --- | --- |
| D-1 | `FrameStore` 用 `nextSeq` + `append` 两个方法，而非设计稿写的单方法 `append(runId, frame) → seq` | A19 的单帧上限判定是"整帧含 `seq` 的字节数"，截断必须发生在落档之前；单方法形态会把落档提前到截断之前，导致事件日志里躺着未截断帧、回放与实时流分叉 | 语义与设计意图一致；接口多一个方法 |
| D-2 | `RunStoreFrameStore`（LIST 兼容实现）保留在 main（包内可见） | 非 Spring/单测/conformance 替身（`InMemoryRunStore`）按 LIST 语义重写，若强制它们改用 Stream 口径，等于改写 7 个 conformance 类的断言基础；设计稿 §2.1 的"单实现"针对**生产装配**，而生产装配恒为 `RedisFrameStore`（`RunRegistry` 六参构造），兼容类不可达 | 生产只有一条实现；兼容类由 Javadoc 标注 `生产装配不可达` |
| D-3（**收口轮已被 D-3′ 取代，见 §6.1/§6.6**） | Stream 读取用 `XREVRANGE ... COUNT = min(窗口, 末号 − afterSeq)` 取尾部，而非无条件 `XRANGE` 全窗 | 唤醒是"每帧一次"的高频路径，全窗 6000 条逐帧读会 O(window) 爆炸；seq 单调 ⇒ 差量必在尾部，条数上界即末号差 | 语义不变（仍按 seq 排序/去重）；代价是"物理顺序 ≠ seq 顺序"的极端场景（同一 run 双实例并发出帧，批② fencing 后不该出现）可能少读 → 由下一次唤醒/`?lastSeq` 重连兜底 |
| D-4 | 发布唤醒早于本地扇出，但"本地水位登记"在发布之前 | 同步总线（测试替身/未来替换实现）会把唤醒同步回调到本实例；先登记水位才能让自唤醒看到"无差量"而不重复投递 | 与设计稿"append→PUBLISH→本地扇出"的顺序一致，只多一步水位登记 |
