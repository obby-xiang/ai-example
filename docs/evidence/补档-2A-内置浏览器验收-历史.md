## 3. 关键缺陷（现场复现）

### 3.1 超时在现场被渲染成「已拒绝」（FAIL）

复现：

1. 对活跃任务 #323 发起 `start_export`，出现确认卡；
2. 不点任何按钮，等待 240s；
3. 到期后卡头显示 **✗ 已拒绝**，卡体 reason 为 **CONFIRM_TIMEOUT**（截图 `13-timeout-actual-rejected-badge.png`）；
4. 刷新页面后，同一张卡显示 **! 已超时**（截图 `14-timeout-after-reload-expired.png`）。

结论：持久化/历史映射是对的（`TIMEOUT → expired`），**实时帧路径错了**。实时路径把 `confirm_decision(approved=false)` 一律落成 `status='rejected'`，`readOnlyStateOf` 又优先读 `decision='rejected'`，于是「已超时」永远进不了实时只读态。

- 源码佐证：`frontend/src/utils/parts.ts:405-420`（confirm_decision 非批准 → `status:'rejected'`）；`frontend/src/utils/blocks.ts:334-359`（decision=rejected 优先 → `'rejected'`）；`historyToolCallStatus` 对 TIMEOUT → `expired`（历史正确）。
- 影响：A 的第三态现场 FAIL；刷新后才正确。

### 3.2 GF 已提交的只读值现场为空（FAIL）

复现：

1. 生成「备注」单字段表单，填「只读验收测试备注」，点提交；
2. 现场卡头 ✓ 已提交，摘要「已提交 · 备注 只读验收测试备注」，零按钮，输入框原生 disabled——**但输入框是空的**（截图 `10-gf-submitted-expanded-empty-input.png`）；
3. 刷新页面后同一张卡展开，输入框显示「只读验收测试备注」（截图 `15-gf-submitted-after-reload-filled.png`）。

结论：摘要取 `part.submittedValues` 是对的，但 `FormRenderer` 在只读卡首次挂载时拿到的是 null，之后 `writeSubmittedValues` 写入新值也不会更新已初始化的 model。

- 源码佐证：`frontend/src/components/AiPanel/FormRenderer.vue` 的 `initialModel()` 只在 setup 调用一次，未 watch `props.initialValues`；`frontend/src/stores/ai.ts:2235-2245` 先 `await submitFrontendToolResult(...)` 再 `writeSubmittedValues(...)`，结局帧先到即先挂只读卡。
- 影响：B 的已提交态现场 FAIL；刷新后 PASS。

### 3.3 「已批准 · 执行失败」第四态不可达（FAIL）

复现：

1. 对已完成任务 #322 发起 `start_export`，点「确认执行」；
2. 后端返回 `TASK_FINALIZED`（任务已 COMPLETED，禁止新建作业），模型文字也说「系统拒绝了这次调用，导出作业没有启动」；
3. 卡面仍是 **✓ 已批准**，折叠为成功态，没有「已批准 · 执行失败」徽标，也没有失败原因行（截图 `02-approved-export-expanded.png` / `03-approved-collapsed.png`）。

结论：现场没有渲染出第四态。若后端把业务拒绝作为 `ok=true` 的工具结果回传，前端就没有 `status='failed'` 可读；需要在后端/帧层明确失败语义，或在前端按结果语义落 failed。该路径本轮未改码。
