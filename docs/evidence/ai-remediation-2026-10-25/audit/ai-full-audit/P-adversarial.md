## 2. Highest confirmed issues (worth carrying into the final audit)

1. **Stale memory/history after takeover (P1-N1 + P1-N2).** Fencing protects `save` only. A frozen-then-resumed driver still writes `ai_chat_message` first-write-wins and the memory window last-write-wins, and still takes seq numbers, appends frames (including a second `done`) and ledger rows for up to one renew interval. `/history`, memory and snapshot can disagree permanently; the archive can hold two terminals, which the L-143 reattach logic explicitly assumes cannot happen. Only reachable with 2+ JVMs and a freeze/takeover.
2. **Park without externalised state (P1-N3).** `saveSuspended` silently drops the snapshot on a read-only authority while pending entries are already written. The card exists, the snapshot says RUNNING, `ResumeService` refuses (`PENDING_UNRESOLVED`), and the state has no self-healing path before TTL. This is the one park-path defect that can strand a run with no terminal frame at all.
3. **Card that can never be published (P2-G2).** One failed HGET inside `markRequestEmitted` aborts publication before the latch/await section; the entry stays PENDING with no `req` bit, so refresh builds no card and resume refuses. Unrecoverable from the UI.
4. **Purge claims completeness it cannot know (P2-G1).** A best-effort session-index SADD plus a permanent completeness sentinel means `DELETE /session` can answer `complete=true` while that run's keys — including `ai:pending` with tool args/results — survive for 24 h.
5. **Parked card loses its only pointer (P1-N4).** `RUNNING` writes `session:current`, and the terminal clear only removes its own value, so a second turn in the same session erases the parked run's discoverability. Refresh cannot rebuild the card.
6. **Frontend dead ends on the suspend seams (P3-01/02/03/06/07).** All five are real, all are in seams with zero test coverage; all are recoverable by `stop` or one refresh, so none should be graded S2. The genuinely uncorrected one is P3-06 (a failed `/history` skips `/runs/current` too, so even the run pointer is never consulted).
7. **DOM tools: hidden controls are writable and snapshots go stale (P4 F-D1/F-D2).** The step gate exists and is dead (zero `allowSteps` registrations); the snapshot cache is not invalidated by any write verb and survives across turns, so the model re-verifies against a pre-action picture and can undo its own click. Both are Important and both are masked by tests that either assert the hidden-step visibility as expected (`ai-region-batch-b.spec.ts:172-189`) or call `bumpAiEpoch()` themselves (`:363-364, 378`).
8. **Guard-internal failures become 500s and permanent form deadlock (P5-01/P5-02).** A cascaded enum skips member validation when the parent is absent (contradicting its own javadoc), and a `step` overflow escapes the result guard as `NumberFormatException` → 500, with the pending entry still open ⇒ the form can never be submitted, only cancelled.
9. **Two "version + retry" disciplines that disagree (P5-03, P5-04).** KB records a version as seen before the rebuild succeeds (stale index for the refresh interval), and one NULL `ai_setting.value_json` makes every config load fail forever — cold start misreports it as "AI 未启用".

## 3. Test-truthfulness corrections that change acceptance

- **`InMemoryRunStore` duplicates `create()`** (already canonical, T-1) — still the single largest evidence gap.
- **P4's own admissions are confirmed**: `ai-region-batch-b.spec.ts` pins cross-step visibility as *expected*; both closure tests need `bumpAiEpoch()` to observe their own action; `sheet-preview-highlight.spec.ts:152` asserts a property the fake adapter cannot express.
- **`parts-residue-cleanup.spec.ts:126-145`** asserts the error-frame segment outcome but not `store.suspended`, so P3-01 is invisible.
- **`restoredPendingQueue` / `revealNextRestoredPendingCard` / `toggleExpand`** have **zero** references in `frontend/tests` (grep) — P3-02 and P3-04 are entirely untested.
- **P2-G3 correction**: `ResumeDispatchRetryTest` only stubs the inner `ResumeService` outcome; the outer `RejectedExecutionException` branch has no case, which is why the A-inventory "15 backoffs" claim survived.
