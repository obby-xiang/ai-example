## 2. Highest confirmed issues

1. **Cross-task data write via stale editors (FA3-N1).** A task switch does not reset `uploadedFiles`/`savedDefs`/`editorLoaded`, and `loadEditorsNow` refuses to reload for any task whose `currentStep≠0`; the next advance writes every mounted grid into the **new** task's file. Same-defCode pairs are the norm (all tasks draw from the same definitions), so this is reachable by ordinary navigation + AI `navigate_to`. Impact S1-grade, prerequisite-gated ⇒ S2.
2. **Empty-workbook overwrite of server-side results (FA4-01, FA3-N5).** Both the export "保存修改" and the import "advance" path can replace a real server file with a header-only workbook and still report success (`validateLocal` on `fields=[]` returns no issues; `GET /files` failure is swallowed). Both feed the existing zero-row chain (BZ-01), and the original bytes are unrecoverable.
3. **Silent numeric rewriting on the write-back path (FA3-N12).** `String(Number(text))` normalizes NUMBER cells on every read-back/flush: zero-padded codes and >2^53 identifiers are permanently changed in the file that PRECHECK/IMPORT/export consume. No warning anywhere.
4. **Global memory-index destruction through a crafted session id (FA2-N1).** `__ids__` collides with `chat:mem:__ids__`: reads throw `WRONGTYPE`, and one `DELETE /session/__ids__` deletes the whole conversation index. Downgraded to S3 (self-healing, no user data lost, no consumer lists sessions) but it is unauthenticated shared-state destruction and belongs next to the canonical `{x}` aliasing (ID-04).
5. **Filter loss turning a scoped export into a full export (FA1-N2 + FA4-02).** The guard accepts empty-string values and duplicate fieldCodes; the draft round trip drops/collapses them; `startExport` persists the rebuilt condition and ignores the failure. The user approved "filter by X"; the job exports everything, and both the receipt and the card say it succeeded.
6. **Session gate can silently stop being a cross-instance gate (FA2-N5, FA2-N6).** A lost/foreign lock only WARNs (`degraded` stays false) and a diagnostic GET failure makes `Busy.runId()` equal the caller's own runId, which `ResumeService` reads as "acquired". Both leave two drivers on one session while every response surface says the gate is fine.
7. **Destroy completeness (FA2-N8, FA2-N9).** The memory write-back can land after the purge deletes it (the DONE snapshot precedes `convergeMemory`), and `chat:mem:staging:*` is outside the destroy surface — full-window plaintext survives "complete=true" destroys for up to a session TTL.
8. **History falsification and stale model-visible state (FA1-N4, FA5-N1).** `/history` re-runs `list_tasks` against the live DB for every historical call, so a refresh shows a different table than the turn produced; and the frontend's second-layer same-arg dedupe returns pre-action snapshots with a "not executed again" note — pinned as expected behaviour by `ai-snapshot-dedupe-epoch.spec.ts:58-70`.

## 3. Duplicates, boundaries, narrow prerequisites

- **Duplicates / extensions:** FA2-N1 → ID-04; FA2-N5/N6 → MD-18/F-03 family (new state, same subsystem); FA2-N8 → F-04 (memory face, not covered there); FA2-N9 → RT-28; FA3-N1 → FE-16; FA3-N5/N6 → BZ-01 entry points; FA4-01 → BZ-01; FA4-02/03 → W-06 residual; FA4-11 → BZ-25; FA5-N1 → FE-33 (second layer, separate fix point); FA6-03/01 → new.
- **Demo boundary:** FA2-N1's "unauthenticated" framing is in-boundary (sessionId is client-declared by design in a no-auth demo); the defect is the *shape validation* and the key-collision, not the absence of auth. FA2-N7's pool-size items are configuration hygiene; the two timing keys are the only ones with cross-instance consequences.
- **Narrow runtime prerequisites:** FA2-N2/N3 (frame-store tail probe / cross-instance window — plausible, not re-derived), FA3-N8 (write-side partition), FA4-05/06/07/09/10/13–20 (interleave or display), FA3-N16/N17, FA5-N2/N3/N5–N7, FA6-02/04–11 (S4).
- **Refuted:** FA3-N2 (no producer of `goto_step` while the wizard is mounted; `import.nextStep` does flush). FA5's own C1–C7 refutations match my earlier reads (notably C6 and C7).
- **Test-integrity that changes acceptance:** (i) `ai-snapshot-dedupe-epoch.spec.ts:58-70` locks the stale snapshot as required behaviour; (ii) `export-wizard-batch-download.spec.ts:84-89` excludes the "grid exists but unloaded" branch by construction and asserts a false "two paths same-source" premise; (iii) `gate-matrix.spec.ts` / `goto-step-readonly-guard.spec.ts` mock `useTaskStore`, so `resolveWizardRoute`'s real fallback is untested; (iv) `watch-publish-outcome.spec.ts` stubs `totalElements == content.length`, so the 50-cap is structurally invisible; (v) `ResumeDispatchRetryTest` never exercises the outer `RejectedExecutionException`; (vi) the import-wizard write-back path has no view-mounted test at all.
