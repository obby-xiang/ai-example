## 3 `resetDegradation` 根因确认（既有缺陷，非本批引入）

| 步骤 | 事实 |
| --- | --- |
| ① 现象 | 前端全量在并行 worker / 本机负载抖动下会出现**同一批 12 条** mermaid / 代码块用例连带变红；单跑该文件或降负载即绿 |
| ② 既有性 | **父提交 `d8056d5` 独立复现**：同样 CPU 压力下 `12 failed / 500 passed`（512 例）——本批改动之前就有 |
| ③ 根因 | `markdown.ts` 的 `degraded` 是**模块全局**单例，判据是**墙钟** 24ms 预算（`RENDER_BUDGET_MS`）：某次渲染因 CPU 抖动越预算 ⇒ 置位 ⇒ **其后同进程所有渲染**都关高亮/mermaid（产品语义 = 页签级粘滞，见 N-b） |
| ④ 为什么是"连带 12 条" | 并行 worker 下首个用例的一次慢渲染把开关置位，后续 12 条用例共享同一模块实例 ⇒ 全部走降级路径 ⇒ 断言与预期不符 |
| ⑤ 修法 | `markdown.ts` 导出 `resetDegradation()`；`tests/setup.ts` 全局 `beforeEach` **每例归零** ⇒ 用例之间不再继承时序判定 |
| ⑥ 验证 | 修后：常规 521 全绿；**加压实测**（`fe-global-load`）同样 **521/521** 绿 —— 这是"根因修掉"而非"降低负载躲过去"的判据 |
| ⑦ 未修的残余 | **24ms 预算路径本身仍无实测覆盖**（没有用例稳定地跑出"超预算 ⇒ 置位 ⇒ 下一次渲染降级"）⇒ 看板 `:79` 的 degraded 行**仍挂**，只销记"测试面跨例污染"这一半 |

## 4 本轮三条微修（M-a / N-a / N-b，合流后落地）

| # | 位置 | 改动 | 理由 |
| --- | --- | --- | --- |
| **M-a** | `scripts/verify-e2e.ps1:35` | 「每个 sessionId ≤ 2 次」→「每 sessionId ≤ 22 次（TC18 取消后重试循环），全程最坏 ~40 次；故限流在 E2E 显式抬高」 | 原文与用例实况不符：TC18 是"2 次尝试 + 1 次并发探针 + 最多 20 次取消后重试"，同一 sessionId 的真实上界是 22（绝对上界 23，见 §7 注①）。注释写小了，会让后来者以为默认额度够用 |
| **N-a** | `frontend/tests/setup.ts` | `resetDegradation()` 调用加 `typeof === 'function'` 防御 | 未来若某个 spec `vi.mock('@/utils/markdown')`，具名导出变 `undefined`，全局 `beforeEach` 会每例抛 TypeError，把失败原因指向错误方向 |
| **N-b** | `frontend/src/utils/markdown.ts:145` | 「会话级粘滞」→「页签级（模块全局）粘滞」 | 产品语义按**页签**收敛（刷新页签归零），实现是模块级单例；原措辞与"新会话也不同"的直觉冲突。`tests/setup.ts` 注释同步 |

三条均**只动注释与一处防御**，零产品行为变更；前端 522/522、typecheck 0、build ✓ 均在修补后实测（见 `-提交报告-` §1）。

## 7 遗留清单（本确认轮）

1. **`context` 与另两个入口未受控**（M3 / M4）：本批只封闭 `message` 这一条；`/confirm.reason`、`/frontend-tool-result` 无长度闸。→ 批②③。
2. **前后端 8192 交叉校验缺失**（M2）：两处字面量同值但无自动校验。→ 批②或配置下发。
3. **24ms 预算路径无实测覆盖**：跨例污染已根治（§3），但"越预算 ⇒ 置位 ⇒ 降级"这条路径本身仍无用例。→ 看板 `:79` 仍挂。
4. **E2E 不覆盖限流**（裁决 I3）：由单测覆盖；E2E 参数抬高到不可达量级。
5. **注①（M-a 的算术）**：TC18 同一 sessionId 的绝对上界是 **23**（2 次确认尝试 + 1 次并发探针 + 20 次取消后重试），注释按 22 记（不含并发探针那条 409 —— 它同样计数）。两者都远超默认 20/分，**结论不变**（例程必须显式抬高），故按"≤22 + 全程 ~40"的口径留痕，不为此再改注释。
6. **前端 5 例的 flaky 邻域**：新 spec 已自足；`ai-panel-parts-render.spec.ts`（187 例）仍是时敏大文件，本轮未拆（超出本批范围）。
