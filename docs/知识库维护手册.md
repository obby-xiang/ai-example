# 业务知识库维护手册

> 适用版本：业务知识问答 v1（Lucene 内嵌 BM25 + agentic 检索）。
> 读者：知识库维护人、配置管理员、运维。

## 1 知识放在哪里

| 形态 | 位置 | 用途 |
| --- | --- | --- |
| 本地目录（默认） | `./data/kb/`（`app.ai.kb.dir`） | 单机/内网部署；`*.md` + `manifest.json` |
| HTTP 知识服务（生产） | `app.ai.kb.http.base-url` | 多实例共享同一份语料，应用只拉不写 |
| 仓内样例 | `docs/kb-samples/` | 功能验证与测试用；**不是**生产语料 |

本地试跑 / 首次部署**不需要手工搬文件**：应用启动时会自动把随包样例播种到 `./data/kb`（规则见 §8C）。仅在运行中替换语料后才需要手动重载：

```bash
curl -X POST http://localhost:8080/api/ai/kb/reload
```

> `backend/data/` 在 `.gitignore` 中（业务数据不入库）。样例仓 `docs/kb-samples/` 随仓提交，是**唯一事实源**；构建期原样拷入 `classes/kb-samples/`，仓内不存第二份。

## 2 manifest.json 写法

```json
{
  "version": "kb-2026-10-21",
  "generated_at": "2026-10-21",
  "docs": [
    {
      "id": "region-tariff",
      "title": "区域费率管理口径（样例）",
      "summary": "一句话摘要（提示词目录用）",
      "tags": ["费率", "GLM"],
      "aliases": ["费率表", "区域价格"],
      "aliases_en": ["regional tariff", "rate table"],
      "sha": "文件的 sha256（小写十六进制）",
      "updated_at": "2026-09-01",
      "file": "01-region-tariff.md",
      "terms": [
        {
          "name": "标准费率",
          "aliases": ["基准费率", "基础价"],
          "section": "区域费率管理口径（样例） > 1 定义",
          "answer": "预制答案：区域内默认档位的费率，字段 base_rate。"
        }
      ]
    }
  ]
}
```

> 上面的 `region-tariff` 就是仓内随包样例本身（`docs/kb-samples/01-region-tariff.md`）：它的正文二级标题是 `## 1 定义`，所以 `terms[].section` 写 `区域费率管理口径（样例） > 1 定义`；`title` 带「（样例）」是因为样例文档标题本身带这个后缀 —— 换成生产语料时**不要照抄该后缀**。

字段口径：

- `id`：可读 slug，**改名等于换一篇文档**（引用/台账会断），不要随意改；
- `title`：章节路径的根（`title > 二级 > 三级`），也是标题域检索的权重源；
- `summary`：提示词目录里的摘要；省略时用 `title`；
- `tags`：参与召回（低权重）；
- `aliases`：中文口头叫法/同义词（**高权重**，`kb_lookup_term` 也认）；
- `aliases_en`：英文术语/英文叫法（可空；索引进 `aliases_en` 字段，权重同 aliases；用于英文提问命中中文语料）；
- `sha`：增量判据。local 源每次按文件实算并覆盖过期值（WARN），HTTP 源以 manifest 声明为准；
- `updated_at`：冲突裁决"以新者为准"的依据，也是回答引用里的字段；
- `file`：相对路径，缺省 `<id>.md`；越界路径（`../`）会被拒绝；
- `terms`：`kb_lookup_term` 的预制答案（可选）。`section` 写完整章节路径更利于定位。

## 3 新增 / 修改 / 删除文档

### 3.1 新增

1. 在知识目录新增 `md` 文件（建议"编号-英文 slug.md"）；
2. 在 `manifest.json` 的 `docs` 追加条目，写入 `file`；
3. 计算 sha：`sha256sum 文件名`（Windows：`certutil -hashfile 文件名 SHA256`）；
4. `updated_at` 写当天日期；
5. 调 `POST /api/ai/kb/reload`，再查 `GET /api/ai/kb/status` 确认 `doc_count` 增加。

### 3.2 修改（原子写入 + sha 校验）

知识文件可能被热重载读到"写了一半"的版本，**务必原子替换**：

```bash
# 1) 写临时文件
cp new-content.md data/kb/.tmp-01-region-tariff.md
# 2) 原子替换（同一文件系统内 rename 是原子的）
mv data/kb/.tmp-01-region-tariff.md data/kb/01-region-tariff.md
# 3) 重算 sha 并更新 manifest（同样 tmp + rename）
sha256sum data/kb/01-region-tariff.md
mv data/kb/.tmp-manifest.json data/kb/manifest.json
```

`manifest.json` 也要 tmp + rename。改完调 reload。若只改文件不改 manifest：local 源会实算 sha 并告警，仍会重建；HTTP 源不会（以 manifest 为准）——生产环境必须同时更新 manifest。

### 3.3 删除

从 `manifest.json` 移除该条目即可（文件可保留）。reload 后该文档立即退出检索面；本地文件残留不会让助手"记得"它。

## 4 热重载与状态

| 端点 | 作用 |
| --- | --- |
| `GET /api/ai/kb/status` | `ready/doc_count/chunk_count/built_at/last_error` |
| `POST /api/ai/kb/reload` | 同步重建；`rebuilt=true/false` + 状态 |
| `GET /api/ai/kb/docs` | 当前加载的文档清单（id/title/tags/updated_at/sha 前缀） |

热重载是**原子**的：新索引在 `data/kb-index/build-*` 建好后才切换 reader；进行中的检索要么用旧索引、要么用新索引，不会读到半成品。重建失败（manifest 坏、单篇缺失、HTTP 5xx/超时）时**保留旧索引**，`last_error` 给出可行动原因。

## 5 aliases 维护

- 只登记**真实在用的口头叫法**（工单、群聊、培训里出现过的），不要堆砌近义词；
- 一个别名只指向一篇文档/一个术语，冲突时按 manifest 顺序先登记者优先；
- 别名命中是**高权重召回**，但 `kb_lookup_term` 仍是精确匹配：别名写错就等于没写；
- 词表类文档（如术语表）适合集中登记别名，避免每篇文档重复。

## 6 terms（预制答案）维护

- 只放**口径稳定、逐字可引用**的短答案（一两句话），长答案写进正文让模型用 `kb_read_doc` 读；
- `section` 写完整路径（`文档标题 > 二级 > 三级`），便于回答里给出 `[doc_id §章节]`；
- 未命中时助手会明确说"未找到"并转 `kb_search`，**不会**用近似词兜底——因此不必为每个近义词都建 term，交给检索；
- 修改 answer 后记得更新 manifest 的 sha 与 updated_at。

## 7 切块与检索口径（写文档时要知道）

- 按 `##` 切章节；`###` 及更深标题会另起一块；块目标 300–800 字（`app.ai.kb.chunk-min/max-chars`）；
- 章节路径（`标题 > 二级 > 三级`）会作为前缀进入索引，同一段正文在不同章节下不会互相冒充；
- 代码块、mermaid 图、表格**整块保留**，不会被内部空行切开；单个超长块会按字符硬切（尽量在换行/标点处）；
- 标题域加权 3、章节 2、别名 4、标签 1、正文 1；原始 BM25 分**不返回给模型**，只返回 high/medium/low；
- 0 命中（`no_match`）只返回检索词与 2–3 个**近似标题**（纯标题文本、不带 `doc_id`）：近似标题不是命中，仅供助手换词重查，不会被当成引用依据；
- 单次工具结果 ≤ 8000 字符（含定界与截断标记），超出会截断并标注。

写作建议：一个 `##` 讲一件事；表格列多时不必拆；mermaid 用 ```mermaid 包裹；长文用多级标题分节，便于 `kb_read_doc` 按 section 读。

## 8 生产 HTTP 源接入

### 8.1 配置

```yaml
app:
  ai:
    kb:
      enabled: true
      source: http
      index-dir: /var/lib/config-mgr/kb-index
      refresh-interval: 10m
      http:
        base-url: https://kb.internal.example/api/kb
        connect-timeout: 5s
        read-timeout: 10s
        auth-env: KB_HTTP_AUTH
```

`source=http` 时 `base-url` 必填（**空则启动失败**，不会静默回落 local）。

### 8.2 服务端契约

1. `GET {base-url}/manifest.json` 返回第 2 节的 JSON，建议带 `ETag`；
2. `GET {base-url}/{file}` 返回 UTF-8 Markdown；
3. 支持 `If-None-Match`：未变化返回 `304`（不带 body）；应用据此跳过整轮重建；
4. 鉴权头：应用把环境变量 `KB_HTTP_AUTH` 的值整段作为 `Authorization` 头发送（如 `Bearer xxx`）。

### 8.3 鉴权与安全

- 变量值**只从进程环境读取**：不写配置文件、不落库、不进日志/错误响应；
- 轮换 token 只需重启进程（或重新部署环境变量），无需改配置；
- 错误面只暴露 HTTP 状态码与目标名（`manifest.json` / `文档 <id>`），不含响应体、URL 查询串或请求头；
- 拉取到的正文与本地源一样过 `<knowledge>` 定界、"数据非指令"声明、定界符剥离与 8000 字符闸。

### 8.4 失败语义（fail-open）

| 场景 | 行为 |
| --- | --- |
| manifest 5xx / 超时 / 坏 JSON | 保留旧索引 + WARN + `last_error`；检索面不变 |
| 单篇 404/5xx | 整轮刷新失败（不静默少一篇），保留旧索引 |
| ETag 304 | 不重建，`rebuilt=false` |
| 某篇 sha 变 | 只重拉该篇，其它篇复用切块 |
| 定时刷新 | 默认 10m（`refresh-interval`），启动后先异步建一次 |

排障：先看 `GET /api/ai/kb/status` 的 `last_error`，再核对 `base-url` 可达性、鉴权变量、manifest 的 sha 是否与服务端文件一致。

## 8A 生产缓存层（Redis，追加 3）

多实例部署时，知识源与索引之间有一层手写 cache-aside（**不是 Spring Cache**）：

- **键族**（会话无关的全局知识域，前缀 `kb:`）：
  - `kb:cache:doc:<id>`（HASH：content/etag/sha/updatedAt）
  - `kb:cache:manifest`（HASH：etag/version/json）
  - `kb:cache:manifest:version`（INCR，跨实例传播"知识已更新"）
  - `kb:cache:refresh:lock`（`SET NX PX 30000`，刷新权，单飞）
- **读取链**：索引永远从缓存重建。local 源也过缓存（读盘 → 写缓存 → 建索引），因此多实例看到同一份字节；缓存为空的冷启动才回源（local 读盘、http 拉远端）。
- **刷新**：定时 10m（有效阈值带 ±10% jitter）+ 版本号轮询（默认 30s）；抢刷新权的实例用 `If-None-Match` 拉 manifest，变更文档写缓存后 `INCR` 版本；其它实例发现版本变化即从缓存增量重建并原子切 reader。
- **TTL**：`kb:cache:doc:*` 与 manifest 键**不设 TTL**；只有锁键 30s（不续租，崩溃即让位）。
- **stale-if-error**：远端 5xx/超时 → 继续供旧料 + WARN，**不清空缓存**；可容忍的陈旧上限 ≤ 刷新间隔（10m）+ 索引重建耗时（当前语料为秒级）。超过该窗口仍失败时，应视为知识源故障并介入。
- **降级**：Redis 不可用时自动直连知识源（WARN），单实例知识问答不受影响；多实例共享能力暂时缺失。
- 键内只存业务知识原文（非对话数据）；鉴权头不经本层、不落缓存、不进日志。

## 8B 国际化口径（追加 4，单语料原则）

- **不建翻译副本**：知识正文只有中文一份，英文通过 `aliases_en` 桥接召回；避免中英两套正文漂移（以哪套为准会成为新的口径问题）。
- **维护 `aliases_en`**：只登记用户真实使用过的英文术语/产品名，大小写不敏感（standard analyzer 统一小写）；一个英文别名只指向一篇文档。
- **回答语言**（语言口径 4B）：**默认中文**；用户改用其它语言提问时，**从其语言**作答（不只英文——用户说什么语言就用什么语言回答）。检索侧仍按用户自己的术语走词表桥接去命中中文正文，语义不做翻译。
- **内部标识不翻译**：`doc_id`、章节路径（`标题 > 二级 > 三级`，以及回答里的 `[doc_id §章节]` 引用）、工具名（`kb_search` / `kb_read_doc` / `kb_lookup_term`）与错误码（如 `AI_UNAVAILABLE` / `AI_KEY_MISSING`）**一律保持原文**，不随用户语言本地化——它们是对外契约面标识，翻译后维护人无从定位，日志与调用也无法对齐。
- **LLM 查询翻译**归 v2：当前不做"英文问题自动翻译成中文再检索"的模型调用（成本与不可控性），先用词表桥接；词表覆盖不足时由维护人补充 `aliases_en`。
- 英文别名与中文别名分字段存放：`aliases` 只放中文叫法，`aliases_en` 只放英文，避免检索权重互相稀释。

## 8C 样例随包带入与首启自播种

样例不再需要"从 `docs/kb-samples/` 手工拷到 `backend/data/kb/`"：它们随构建产物一起发布，首次启动自动落到 `app.ai.kb.dir`。

**打包链路（仓内只有一份样例）**

1. `docs/kb-samples/`（20 篇 + `manifest.json`）= 唯一事实源；
2. `backend/pom.xml` 的 `maven-resources-plugin` 在 `process-resources` 阶段把它**原样**（`filtering=false`，字节不动）拷到 `target/classes/kb-samples/`；
3. Spring Boot 重新打包后位于 `config-mgr.jar` 的 `BOOT-INF/classes/kb-samples/`。

**首启播种规则（local 源）**

| 启动时 `app.ai.kb.dir` 的状态 | 行为 |
| --- | --- |
| 目录不存在 / 存在但为空 | 从 classpath 播 20 篇 + `manifest.json`，随后正常建索引 |
| 目录已有 `manifest.json`（含上次播种的结果） | 跳过，不重播、不覆盖 |
| 目录非空但缺 `manifest.json` | 跳过并 WARN（视为既有语料，避免混料）；按原状加载，缺 manifest 时知识库保持"加载中" |
| `app.ai.kb.source=http` | 不播种（无本地目录，生产路径不变） |

**字节口径（零 sha WARN）**：manifest 的 `sha` 按 **LF** 计算，而 Windows 工作区检出通常是 CRLF。播种器写入前统一做换行规范化（CRLF → LF），因此落盘文件的实算 sha 与 manifest 声明一致；`LocalDirKbSource`（按文件实算）与 `KbService`（按规范化正文比对）都不会再告警。构建期拷贝不做 filtering，保证"源码样例 → classes → jar"字节一致，转换只发生在播种这一刻。

**失败姿态**：播种任何异常只 WARN，不阻断启动（知识库按目录现状加载，fail-open）。写入先落到同目录的临时 staging，成功后整体换入，失败不会留下"半份语料 + manifest"。

**维护要点**

- 改样例：只改 `docs/kb-samples/`（同步更新 manifest 的 `sha`），重新构建即生效；不要直接改 `data/kb/` 里的播种副本（它不会被下次启动覆盖，会被当成普通语料）。
- 生产替换：另建目录并改 `app.ai.kb.dir`，或切 `source=http`；本机制只在"空目录"时介入，不会覆盖生产语料。
- 验证：`unzip -l backend/target/config-mgr.jar | grep kb-samples`（应见 20 篇 + `manifest.json`）；启动后 `GET /api/ai/kb/status` 应为 `ready=true, doc_count=20`，日志无"sha 与文件不一致"告警。

## 9 样例文档标注

`docs/kb-samples/` 的 20 篇文档均为**样例**：每篇文末有"本文为样例文档"声明，manifest 的 `version` 含 `kb-samples`。样例中不得写入真实客户名、真实项目编码、真实费率或个人数据；替换为生产语料时不要直接改样例文件，另建目录并在配置中指向它。

## 10 常见问题

**Q：reload 返回 rebuilt=false，是失败了吗？**
A：不是。false 表示"没有变化或刷新失败"；看 `last_error` 是否为空。空 = 已是最新。

**Q：助手说"知识库中未找到"，但文档里明明有？**
A：先确认该文档在 `GET /api/ai/kb/docs` 里；再让助手换同义词（别名是否登记）；最后检查该词是否只出现在代码块/图片替代文本里。

**Q：改了文档但检索结果没变？**
A：HTTP 源需同时更新 manifest 的 sha；local 源会自动发现。确认 reload 后 `built_at` 是否变化。

**Q：索引目录可以删吗？**
A：可以。删除后下次刷新会重建（启动时也会异步重建），不影响知识源本身。

**Q：一个文档多长合适？**
A：单篇建议 ≤ 1 万字；更长请拆分或多用二级标题分节，`kb_read_doc` 支持按章节与 offset 连续翻页。
