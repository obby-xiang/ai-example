## T3-1 R1 慢订阅者隔离（S1-1/S1-2 重构版）

**现状**（实测）：`SseChatEmitter.emit()` 在 `emitLock` 内「取号→落档→遍历订阅者同步 send」（:424-446）；`replayAndAttach`→`replayLocked` 同样持锁同步 sendTo（:122-133, :351-375）；慢订阅者 TCP 背压可阻塞整轮（含心跳）。

**线程模型（S1-1 修订）**：
1. `emitLock` 内只保留：取号、落归档、`touchActivity`（S3-9：必须留锁内同步，否则僵尸判定输入随投递延迟漂移）、**帧入各订阅者队列**。
2. 投递走**共享有界投递池**（容量初值 4，压测定值；拒绝策略=CallerRuns 不允许，溢出即摘除该订阅者）；**每订阅者"drain 进行中"CAS 独占标志**：入队后 CAS 抢占 drain 权，抢不到则由在跑 drain 者带走新帧——保证单订阅者 FIFO 且一条慢连接只占一个工作线程。
3. **replay 路径并轨（S1-2 修订）**：`replayAndAttach` 在 `emitLock` 内完成「收集回放帧（LRANGE 只读）+ 创建订阅者 + 回放帧入队首 + 挂订阅」原子交接；网络写出统一走异步队列。回放收集在锁内只读归档，不做 IO 写。
4. **溢出摘除=主动断连（S2-1 修订）**：摘除时必须显式 `emitter.complete()`（或 completeWithError），触发前端 onerror/onclose → lastSeq 重挂补帧；补"摘除后断点续收 seq 无洞"用例。
5. **不变量（S2-2）**：队列容量 < 归档窗口 3000，单测锚定；容量 256 为初值，T3-5 压测定值。
6. **容量联动（S2-8）**：公式改为「专用池 ×2 + 投递池 ≤ boundedElastic 容量」，纳入 §13.2#2 压测与 AiProperties 注释。

**R1 裁决（回放帧量 vs 队列容量，GLM 复核阻塞项，指挥官 2026-10-09 裁）**：回放初始批**豁免有界容量**——replayAndAttach 锁内收集的回放帧入队不受实时容量 256 约束，上界 = EVENT_WINDOW（3000）；不变量「队列容量 < 归档窗口」**只约束实时段**。理由：实现最简（入队分回放/实时两口径）、无续灌游标复杂度；内存可控（T3-2 后 delta 不入档，归档帧为小型状态帧）；验收项「回放 3000 帧不阻塞 emit」可达。备选方案（drain 进度驱动分批续灌）登记备选不实施。单测锚定双不变量：实时段 256 溢出摘除 + 回放段 3000 全量可入队。

> **施工注记（修复批第 2 轮，红队 S1 击破后定口径）**：**实时闸按实时段计数而非队列绝对长度** —— 回放批与实时帧共用同一条订阅者队列（单队列 FIFO 混合序），容量闸判据为「队列中的**实时**帧条数」（入队元素带实时/回放标记，回放批不计入），而非 `queue.size()`。理由：按绝对长度判定时，慢重挂者回放 3000 帧入队后，排空期间的任一实时帧（挂起期每 2s 心跳）会把回放 backlog 误判成实时溢出而摘除健康订阅者，重挂后剩余回放 ≥256 再被摘除 = 确定性饥饿（红队探针实测复现）。实时段自身超限仍摘除（S2-1 语义不变）。证据：`docs/evidence/M2-T3a-施工与验证-K2.8.md` 第八节 8.1。

**验收**：单慢订阅者不阻塞同轮其他订阅者（投递节奏偏差 < 1s，测量边界=摘除前）；慢重挂者回放 3000 帧不阻塞 emit；溢出摘除后前端重挂补帧 seq 无洞；8 路并发 0 丢消息回归不破。

## T3-2 R2 seq 持久化 + delta 跳过归档（强耦合同批，禁拆）

**设计**：
1. 新增键 `ai:seq:<runId>`（String，已发放最大业务 seq）。**TTL 与归档同寿（S3-6）**：值随每帧 emit 刷新 TTL=session-ttl，与 `ai:events:<runId>` 同刻过期。
2. `nextSeq`（emitLock 内）：候选 = max(归档末帧, ai:seq) + 1，发放即 SET。
3. **SET 失败口径（S2-4）**：WARN 级日志 + 继续出帧（韧性优先）；承诺收窄为「归档部分失败场景」——整体 Redis 宕机下重号风险仍在，登记观察项。补 SET 失败分支用例。
4. **delta 跳过归档**：`appendEvent` 对 delta 帧跳过（与心跳同待遇）。**强耦合声明（S2-3）**：本项与 ai:seq 键同批上线，禁止拆批——delta 不入档后归档末帧更不可靠，续号必须已由 ai:seq 接管。
5. **includeDelta 路径处置（S2-3+盘点补强）**：`replayTo(..., includeDelta=true)` 全仓零调用（连测试都一律传 false）——施工时删除该参数与死分支，并登记 `persistedFrameCount` 语义变化（不再含 delta）。施工前必查：既有帧协议测试（ChatTurnFrameSequenceConformanceTest、ReattachLastSeqConformanceTest、SseFrameSequenceConformanceTest、SseChatEmitterFramesTest）有无依赖 delta 入档的断言。
6. events 端点全量读（RunStore.events :618-634）本就是回放唯一读者路径，随 replay 并轨自然一致。

**验收**：发放 3 帧后落档第 2、3 帧失败→重启→续跑，新帧 seq=4 无重号；delta 不进归档（LLEN 只计状态帧）；SET 失败分支用例绿；既有 263 全绿。

> **后果注记（验收发现登记，S3-4）**：delta 不入档后，**断流期间的正文尾部不可由回放复原**——断点续收仅保证状态帧 `seq` 无洞，正文尾部能否补齐取决于前端兜底路径（待 T3b 确认）。本项不改设计口径，仅登记后果。

## T3-4 预检查文件指纹锚定（仅 IMPORT 生效）

**设计（S2-5/S2-6/S2-7 修订）**：
1. **写路径（S2-5）**：`resultJson` 目前是死列（setResultJson 全仓零调用）。由 `PrecheckJobRunner` 在数据面事务内 `setResultJson`+`save`，明确与 afterCommit 终态写（JobTerminalWriter）的先后：指纹摘要先于终态提交，避免 IMPORT 建作业时摘要未提交的竞态。
2. **摘要结构（S2-6）**：`{defCode:{fileType:{sha256,size}}}` 键控——PRECHECK 读盘可能回落 EXPORT 类型文件（:101-106），IMPORT 只读 UPLOAD，比对按各自 fileType 取对应指纹，杜绝"记 EXPORT 比对 UPLOAD"恒 409。
3. **仅 IMPORT 生效（S2-7）**：PUBLISH 读 staging 不读文件，维持既有 PRECHECK_NOT_PASSED 状态守卫，不加指纹。
4. **历史兼容（S2-6）**：无指纹的历史 PRECHECK 一律从严 409 PRECHECK_STALE（视同未预检查），同步改既有受影响用例。
5. **指纹计算成本（S3-5）**：`FileStorageService.read` 是 readAllBytes 全量读，"成本≈0"表述撤回——改用流式 digest（DigestInputStream）计算 sha256，避免二次全量内存加载；百 MB 级件的一次顺序读成本在验收中实测记录。
6. TOCTOU 窗口（guard→落库→afterCommit）维持不闭合，登记观察项。

**验收**：替换上传件→IMPORT 409 PRECHECK_STALE；未替换→放行；EXPORT 回落与 UPLOAD 交叉 fileType 用例；历史无指纹兼容用例；PrecheckGateGuardTest 五分支不破。

## 施工注记（GLM 复核 R2~R6，随施工落实）

- **R2（T3a，drain 收尾竞态）**：drain 者收尾必须「先清 CAS 独占标志、再复查队列非空则重新 CAS 抢回」，固定该顺序，否则存在「判空→入队 CAS 失败→清标志退出→新帧无人投递」丢 drain 窗口。配并发单测（入队与 drain 收尾交叠）。
- **R3（T3a，池语义）**：投递池「容量 4」= 工作线程数；池任务提交被拒（队列满）时摘除触发本次提交的订阅者；慢连接占满 4 线程后其余订阅者 drain 排队等待——纳入 T3-5 场景 E 实测。
- **R4（T3b，第 4 方案三缺口）**：① ConfirmGate→ResumeService 构造器循环依赖，沿用 AiController 的 ObjectProvider 惰性注入解环；② resume 触发点移出 submitLock 且异步化（resume 同步段含快照重建与工具执行，HTTP 线程直调拖长 confirm 响应）；③ saveSuspended→latch 注册毫秒窗内同进程 confirm 也满足 woke=false+SUSPENDED——触发前校验本进程无该 runId 活跃等待，防双驱动（claimExecution 原子认领兜底恰好一次）。
- **R5（T3b，T3-10 截断层级）**：单帧上限截断必须为**字段级**（result/text 值截断 + truncated 标记），严禁帧字节级截断——JSON 破坏后反序列化失败帧被静默忽略（RunStore.java:629），回放丢帧=seq 洞。
- **R6（全局，编号歧义）**：技术方案 §13.2 注记的「T3-8」指排期 T3 批次条目 8（SSE 扇出），与本设计卡 T3-8（TTL 裁定）同名异义；引用一律加「排期条目/设计卡条目」前缀。
