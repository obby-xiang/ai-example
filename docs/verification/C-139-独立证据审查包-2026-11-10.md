## 3. 独立重算口径

1. **正文与 parts**：由 `dom-*.json` 的白名单（kind/name/toolCallId/status/requiresAction/text 长度+散列）
   重算每个 ASSISTANT 的正文长度/散列、parts 数量与顺序；不得只看 `summary`。
2. **同 run 单时间线**：同一 `runId` 下 assistant 数量与 entryId 不得重复；toolCallId 全局唯一。
3. **卡片**：按 `testId`/`bodyTestId`/`state` 重算数量与顺序；`hitl-receipt` 的 `ro-body-*` 必须与 toolCallId 配对。
4. **seq 口径**：C-131/C-138 保持强 `seq`；C-161 GF standard 的稳定性指纹排除 `seq`，
   但 `pending-segments-shape.json` 中 `shape=present` 时必须核对 `entryId + segments[].seq` 前后一致；
   `shape=absent` 只记录形态，不判 PASS。
5. **C-138 增量**：`timing-proxy-incremental.json` 的 `lastSeq` 必须来自后缀在途时的公开 `runSeq`；
   回放帧 `seq` 必须严格递增且全部 `> lastSeq`，且包含 `done`/`error` 终帧。
6. **代理时序**：`timing-proxy-log.json` 中首条 history `delayMs=800` 且 `status=200`，其后 history 均为 `0`。
7. **副作用**：以 `network-faults.json`/`publicApiRequestCounts` 重算 chat/confirm/feedback/events/resume，
   刷新前后不得新增；业务计数以 `summary` 引用的任务/作业证据重算。
8. **清理**：`cleanup.json` 必须 `status=COMPLETE`；会话、任务与临时资源不得残留。
