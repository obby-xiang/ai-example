### 7.2 实际证据和清理门槛

- 每轮保存 `summary.json`、分阶段 `dom-*.json/.png`、`history-*.json`、`history-network-*.json`、`business-*.json`、`copy-*.json`、`network-faults.json`、`page-close.json` 和 `cleanup.json`，目录为 `<OUT_DIR>/ai-tool-card-recovery/<SCENARIO>/<LOCALE>/<UTC-UUID>/`。
- running 必须由 5ms 只读采样/MutationObserver 同时抓得 store running 和 DOM `state=running`，不能用 succeeded 截图补写。C-140～C-144 与 C-153 的实时、history 重建、刷新 1、刷新 2 四阶段复制均必须真实点击并读取实际剪贴板写入参数及成功反馈，逐段核对正文和完整可见摘要；C-153 另须保存真实表单输入、单次提交和成功卡证据。观察器/剪贴板 hook 异常不得吞。
- history 每阶段重新经公开 API 读取并比较消息、entryId/runId、正文哈希、工具 ID/状态；故障只记 UNAVAILABLE、HTTP status、安全错误名/业务码，不得写成 `messages:[]`。业务证据仅落 fixture/本场景任务的 ID、步骤、状态、条件哈希和作业白名单字段，其他任务只留总数与指纹。`historyRequests/cdpErrors/networkRequests` 分别硬限 512/64/4096，超限 FAIL 并停止追加；`network-faults.json` 和错误证据只存有界摘要、去重状态及最多 16 条尾部样本，不保存完整数组。
- C-145 的 503 次数、后续真实 200/完成事件和自动恢复完成缺一不可；C-146 每次持久重试必须实际发出请求并再次以 503 终态完成，不能固定等待冒充预算耗尽。所有异常只保留安全错误名、HTTP status 和业务码，不写 `error.message`。
- CDP new、WebSocket open/close、命令和 target close 均有界超时；`page-close.json` 必须有 close HTTP 200、WebSocket closed 和 target 消失回读。cancel 记录 HTTP/业务码并轮询真实 run 终态，随后两次 DELETE 会话并回读空 history；任务按当前完整作业 ID 集合做公开条件删除，空集合显式传参，409 不强删，最终 GET 404。任何清理缺证据均判 FAIL/INCOMPLETE。

直接 Redis、直接数据库、真实供应商（使用桩时）、后端内部永久故障、多实例和 Redis Cluster 未另行执行时均为 NOT_RUN。静态审查、脚本 `node --check` 和既有 C-130 证据均不得把本节任一场景改写为 PASS。
