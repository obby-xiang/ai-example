## 3. 关键语义

### 3.1 三个创建入口页与类型分型

- 页面：`tasks`、`export`、`import`（`ContextBuilder.CREATE_ENTRY_PAGE_IDS`）。
- 类型提示：显式 `taskType` 优先；缺失时由页面推断（`export`→EXPORT，`import`→IMPORT）；`tasks` 页未知，reason 分别描述 EXPORT/IMPORT 两种调用。
- EXPORT 指引包含 `conditions={}`；IMPORT 指引明确“不要传 conditions”；实际 `create_task` 参数在确认帧中核对（EXPORT 带空 `conditions`，IMPORT 完全不出现该键）。

### 3.2 IMPORT 的创建后收集能力（如实）

- EXPORT 有宿主一次性选择表单（`DefinitionSelectionForm.parkIfDue`，仅 `export/SELECT_DEFS`）。
- IMPORT **没有**该宿主表单；`ImportWizardView` 的 UPLOAD 页有配置选择控件（`DefSelector`），提交点在「下一步」。拒绝理由、提示词与文档均按此表述，不承诺 IMPORT 有同样的宿主表单。

### 3.3 拒绝后的纠正与收尾

- 触发事实：本 run 存在 `generative_form` + `FORM_CREATE_ENTRY_REQUIRED` 的已结算 pending，且仍无 `taskId`、`create_task` 已披露、本 run 尚无 `create_task` 记录。
- 只触发**既有一次性** create_task 纠正（`CREATE_TASK_CORRECTION_MARKER`）；模型仍不创建时如实结束，不自动创建。
- 非拒绝路径仍保留既有 `TaskIntent` 判据（兼容原行为）；拒绝路径不依赖它。
- **步数已到顶时不再纠正**：快照 `toolSteps >= max-tool-steps`（本轮已追加 `STEP_LIMIT_WRAP_UP`）直接返回 false，避免“停止工具”与“调用 create_task”矛盾，也避免产生被步数跳过的可见创建卡（`ResilientChatService:1752` 前后的结构化检查）。

### 3.4 重复拒绝的有界收敛

- 每次专用码拒绝占用一个既有工具步（`stepsUsed`，跨挂起持久化）。
- 达到 `max-tool-steps` 后，`settleBatch` 追加既有 `STEP_LIMIT_WRAP_UP`；模型据指令结束（GREEN 场景实测 `done`）。
- 仍不遵守收尾指令的模型由既有总预算/看门狗兜底（与其它工具刷调用同一机制，本批未新增状态机）。

### 3.5 终态 transcript

- 静默拒绝没有工具帧，时间线也没有对应工具段；若原样保留会触发 `AI_TRANSCRIPT_INCOMPLETE`。
- 终态写入前只过滤**专用码**的 toolCall 与 TOOL 响应（assistant 正文保留），其它码/正常工具不动；这与前端历史幻影卡过滤同口径。
