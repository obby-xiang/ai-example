r7 两件事：①**单层滚动**——同一视觉列只留内容区那一层内滚，卡片与外层包裹不再叠加第二条相邻滚动条（多步只读卡此前把步骤内的选项滚动区一起克隆进了外层滚动区，属嵌套双条）；②**限高上调**——字段类 280px、表单 / 组合类 320px，仍按历史裁决族取值、纯限高内滚无展开钮。

K1 已决统一原样 UI 只读渲染：任何结束场景（已批准 / 已拒绝 / 已超时 / 已取消 / 已提交 / 执行失败）都保留原卡——选项按当时勾选态保留、输入按当时所填保留、参数区字段表原样；操作按钮在已决分支里整块不渲染；状态徽标 + 决策时间（decidedAt）+ 只读标记固定在卡头；卡永久留在消息流，锁定不降对比度。
K2 H1 审批卡独立存在：绝不进多步流；终态恰四态——已批准 / 已拒绝 / 已超时 / 已批准·执行失败，没有已取消。
K3 「执行失败」= 已批准后工具执行失败：卡头徽标「已批准 · 执行失败」，参数区原样（记录批了什么），失败原因单独一行常驻卡面。
K4 已取消只属于非审批类：H2 单选 / H2 多选 / H3 输入 / 多步组合流 / GF 生成式表单可以取消；审批卡（H1）没有这个出口。
K5 待决侧操作按钮一律常驻：当前不可用的按钮用 disabled 禁用态（不隐藏、不整块消失）；按钮一律底部靠右，flex-1 占位右排、主钮最右，禁止居中；按钮行统一为「取消（如有）在最左、主操作在最右」；步进首步的「上一步」按 G2 单独例外 —— 不入 DOM（不用 disabled 占位）。
K6 选项一律一行一个：多选 = 复选框逐行，单选 = 单选框逐行；「其他」也是一行，其文字输入框常驻显示（不需要先选中才出现）；选了「其他」但输入框为空 ⇒ 提交钮 disabled。
K7 拒绝后「修正走会话」：拒绝不改写旧卡——AI 在消息流按反馈重新提案，出现一张新的待决审批卡，旧卡原样留证（见 B2）。
K8 全 Tailwind：只用 hitl-interrupts.css 预编译产物内的类（或任意值类），禁手写 CSS、禁 style 标签、禁行内样式；界面禁 emoji（✓ / ✗ / ! 字形可用）；单文件制。
K9 未提交不记录：凡不是点「提交」收尾的结束场景（取消 / 超时等，含超时后视为提交的情形），卡上的表单与输入一律回到初始空态再锁定——不留半成品值。
K10 只读态用原生 disabled：已决卡内所有表单控件（复选 / 单选 / 文本 / 数字 / 日期 / 开关）一律设原生 disabled 属性；卡面底色、边框、内边距与待决态完全一致（无只读专用底色 / 无下划线化改写），仅靠原生禁用观感 + 卡头「只读」标记 + 徽标区分；已决卡内按钮数仍为 0。
K11 内容区限高内滚按历史裁决族：字段类（审批卡参数 / 选项列表 / 输入字段）280px、表单 / 组合类（GF 字段区 / 多步只读卡）320px，一律 max-h + overflow-y-auto、无展开钮；同一视觉列**只允许一层滚动**（内滚区之外，卡片与外层包裹不得再出滚动条）。
