超时门卡纠偏（用户真机实报重点）

超时 = 已决态：按钮整块消失，chip 不再显示「等待确认」核心实装偏差纠偏

现象（用户真机实报）：门卡倒计时归零后，卡头 chip 仍写「等待确认」、正文写「确认已超时（按钮已置灰）」，而拒绝 / 确认执行双钮依然挂在卡面上（只是置灰）—— 文案承认已超时，卡面却还在等用户点，自相矛盾；置灰钮仍占位、仍可聚焦，用户会以为「再等等还能点」。

裁定：超时 = 已决态，走与 已批准 / 已拒绝 / 执行失败 同一条只读渲染分支 —— 卡头徽标改「! 已超时（已置灰作废）」、chip 不再显示「等待确认」、按钮整块消失（不是置灰保留）、参数区只读保留、说明行「本轮将按拒绝 / 超时收尾」保留。

定性：本现象属实装偏差，非口径分歧 —— v7.9 裁决（第 19/20 点区域）已定「已决态一律不渲染按钮」，超时分支没有跟上。

按钮文字防折行（用户截图实报）

文字一律单行完整；空间不足改排布，不牺牲文字核心实装缺陷

现象：400px 窄栏下门卡操作行的两个按钮被长文案挤到内容宽度以下 —— 「拒绝」折成两行、「确认执行」折行，按钮看起来像被压扁的两个竖条（用户截图实报）。

规则：按钮文字一律单行完整，任何宽度下不折字；窄栏空间不足时改变按钮排布（整行下移），不牺牲文字。

根因：按钮缺 whitespace-nowrap（文字可折行）+ flex 挤压（flex-shrink 默认 1、无 flex-none、无最小宽度），长文案行把两个钮压到内容宽度以下 ⇒ 文字折行。

① 现状 · 折行丑态行宽 348px
确认已超时（按钮已置灰），本轮将按拒绝 / 超时收尾
按钮缺 nowrap + flex-none：被长文案挤到内容宽度以下，「拒绝」折成两行、「确认执行」折行。
② 新规 · 400px 侧栏（同行右对齐）行宽 348px
确认已超时（按钮已置灰），本轮将按拒绝 / 超时收尾
按钮 flex-none + whitespace-nowrap + min-w-[64px]/[88px]；操作行 flex-wrap —— 空间够时两钮同行右对齐，文字完整单行。
③ 新规 · 300px 侧栏（按钮组整行下移）行宽 248px
确认已超时（按钮已置灰），本轮将按拒绝 / 超时收尾
空间不足：按钮组整行下移并右对齐（flex-wrap + ml-auto）—— 改变排布、不牺牲文字，两钮仍各自单行完整。

规则与落点

面内容
