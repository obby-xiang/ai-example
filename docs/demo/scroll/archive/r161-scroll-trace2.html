自动钉底 + 回到底部按钮 · 方案 demo

左侧窗格是真实可滚动的消息流。点「▶ 播放回复」模拟一条含确认门 + 生成式表单的流式回复。对照两模式：①工具卡插入时是否自动钉底；②向上滚一点（20px）是否就出「回到底部」。
模式：
离底 0px ｜ 跟随=true ｜ 浮钮=隐
↓ 回到底部
修复口径（本 demo 提案，锚点 = AiPanel.vue）： ①ResizeObserver 内容重钉底：消息容器挂 RO，内容任何增高（工具卡/确认门/表单/折叠展开）只要处于跟随态即重钉到底——覆盖现状「指纹 watch 只盯末段文本」盲区（:1041-1047）与「nextTick 单次快照」缺口（:741-752），取代 :1052 的 setTimeout hack； ②阈值拆分（:489 一值双用是「上滚一点就出钮」的根因）：跟随解除闸保留 32px；浮钮显示阈值 = max(200px, 50% 视口高)，回落 <32px 隐藏（滞回防闪）——本 demo 修复模式按此实现； ③回归保护（用户要求「后续调整不受影响」）：施工必带 spec 断言钉死新阈值与 RO 重钉行为（钉点清单见排查报告 §4）； ④程序化钉底保护：所有程序化钉底统一走 pinBottom()，其 scroll 事件回声按落点识别并跳过跟随闸——否则「已在底部时点播放」会被开场新增空行把 scrollHeight 顶高造成的中间态离底（实测 42px）误判成用户上滚，跟随闸被锁死、整条回复不再钉底。
待裁可选项（demo 右上角开关）：Ⓐ上滚期间来新内容，浮钮变「↓ N 条新消息」计数 pill（Vercel/OmniGrid 主流形态）；Ⓑ点击回底改平滑滚动（behavior:smooth，可被用户滚动打断）。另：滚动容器补 role="log"（无障碍，无视觉影响）。
现状模式复现的逻辑缺陷：文本 delta 走指纹 watch 会滚；确认门/表单插入与确认后卡体展开只增高度、不进指纹 ⇒ 视口原地不动、底部内容被顶出视野；且任一离底 ≥32px 的 scroll 事件即把跟随闸锁死（:496），本轮后续全部不滚。
