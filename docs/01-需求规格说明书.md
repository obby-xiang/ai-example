## 1. 项目背景与目标

企业系统中存在多种配置项，每种配置项结构不同（字段集合、类型、必填、下拉选项均不同），且配置项本身会随业务演进动态增减。同时配置项分层级管理（全局 / 地区 / 项目）。日常运维中，最频繁的“快速实施任务”是**配置导出**与**配置导入**两类长流程任务。

本系统目标：

1. **动态配置建模**：配置项的结构（字段定义、类型、必填、下拉选项、依赖）完全由数据驱动，可在界面上动态定义、动态渲染表单与表格，新增配置项类型无需改代码。
2. **导出配置任务**：选择配置 → 按各配置项结构设置查询条件 → 异步导出 Excel（进度可见）→ SpreadJS 在线编辑 → 选择打包/全部下载。
3. **导入配置任务**：下载模板 / 上传 Excel（或 zip）→ 在线编辑 → 异步预检查（进度+明细，含配置先后依赖）→ 导入（未发布，进度+明细）→ 发布（进度+明细）。
4. **AI 助手**：左右双栏布局，右侧 AI 对话栏常驻；后端 AI Runtime 通过工具调用直接驱动左侧业务工作区（渐进式披露：不同页面暴露不同工具），解决“用户操作与 AI 对话状态同步”问题。
5. **交付**：需求规格、技术方案、实现方案、测试用例、验证结果等全部文档入 docs/ 目录，git 全程提交过程记录。

## 2. 术语定义

| 术语 | 说明 |
|---|---|
| 配置定义（ConfigDef） | 一种配置项类型，含编码、名称、层级、字段集合、依赖。例如“服务器参数配置” |
| 字段定义（FieldDef） | 配置定义下的一个字段：编码、名称、类型、必填、下拉选项、引用等 |
| 配置数据行（ConfigRow） | 某配置定义下的一行业务数据（表头=字段，行=数据） |
| 层级（Level） | 全局 GLOBAL / 地区 REGION / 项目 PROJECT，一个配置定义只属于其中一个层级 |
| 范围（Scope） | REGION/PROJECT 层级下，数据行所属的具体地区/项目名 |
| 生效数据（Published） | 已发布、对外生效的配置数据；未发布数据为草稿 |
| 批次（Batch） | 一次导入任务的工作单元，包含若干文件，经历 检查→导入→发布 |
| 导出任务（ExportTask） | 一次导出任务，包含若干配置定义及各自的查询条件 |
| UI 事件（ui_event） | 后端 AI 工具执行后发给前端、用于驱动工作区状态变化的指令 |

## 3. 功能需求

### 3.1 配置定义管理（基础能力，支撑动态渲染）

**FR-DEF-1 配置定义 CRUD**
- 定义字段：编码（唯一，用于文件匹配）、名称、层级（GLOBAL/REGION/PROJECT）、说明、依赖配置（可多选）、排序、启用状态。
- 支持新增、编辑、停用、删除（删除需无数据行）。

**FR-DEF-2 字段定义（表头）动态管理**
- 每个字段：编码（英文/下划线，唯一）、名称（中文表头）、类型、是否必填、下拉选项、数值范围、默认值、引用（类型为引用时指定引用配置+引用字段）。
- 字段类型：文本 TEXT、长文本 TEXTAREA、数字 NUMBER、布尔 BOOLEAN、日期 DATE、下拉 SELECT、引用 REFERENCE。

**FR-DEF-3 动态渲染**
- 配置数据表格/表单、导出查询条件表单、导入检查规则，全部依据字段定义在运行时渲染，配置定义变更后无需改代码即可生效。

### 3.2 配置数据管理（基础能力）

- 配置数据行 CRUD；REGION/PROJECT 层级数据行必须携带“范围”。
- 生效数据（published）与草稿数据（batch 内未发布）分开展示；草稿可预览。
- 数据行校验与导入检查共用同一套规则引擎（类型/必填/选项/范围/引用存在性）。

### 3.3 导出配置任务

**FR-EXP-1 选择配置**：列出启用的配置定义（可按层级、关键字过滤），多选。

**FR-EXP-2 查询条件**：对每个已选配置，按其字段结构动态渲染查询条件表单：
- TEXT/TEXTAREA：等于 / 包含；NUMBER/DATE：等于/大于/小于/介于；BOOLEAN：等于；SELECT：多选（in）。
- 条件可留空（导出全部）；REGION/PROJECT 层级可填“范围”过滤。

**FR-EXP-3 导出执行与进度**
- 异步执行，任务级+文件级双进度，通过 SSE 实时推送；刷新页面后可恢复查看进度（任务持久化）。
- 每个配置导出为一个 xlsx 文件（含表头、数据、说明 sheet）。
- 数据量大时可见进度（按行处理百分比）。

**FR-EXP-4 在线编辑与下载**
- 导出结果可用 GrapeCity SpreadJS 在线编辑（每个配置一个编辑页签）。
- 单文件下载；勾选部分配置打包下载（zip）；全部下载（zip）。zip 由后端打包。

### 3.4 导入配置任务

**FR-IMP-1 模板下载**
- 选择配置后，可下载单个配置模板（xlsx）或多个配置模板（zip）。
- 模板 = 说明 sheet（表头含义、类型、必填、选项、依赖说明）+ 数据 sheet（表头行+示例行+下拉数据验证）。

**FR-IMP-2 上传与在线编辑**
- 上传单个 xlsx 或多个文件的 zip；**按文件名匹配配置编码**（`{编码}.xlsx`，允许 `{编码}(1).xlsx` 等序号后缀），不匹配的文件在报告中提示。
- 上传后覆盖同配置的旧文件；可下载已上传文件在 SpreadJS 中编辑后重新上传；也可不下载直接“基于模板在线编辑”再上传。
- 即使未上传，也可打开在线编辑器编辑并保存为待上传文件。

**FR-IMP-3 检查（预检查）**
- 异步执行，进度可见（按文件、按行推进），结果明细：每个文件 状态/总行数/错误数/警告数。
- 检查规则：字段类型、必填、选项合法性、数值范围、引用字段存在性（对已发布数据+本批次前序文件）、依赖配置存在且非空（**配置先后依赖**）。
- 依赖顺序：按依赖关系拓扑排序依次检查，被依赖者先检查/导入。
- 错误（阻断）与警告（不阻断）分级；错误明细可查看、可下载为 xlsx。

**FR-IMP-4 导入**
- 异步执行、进度可见；导入时**再次检查**，全部通过的文件才落库。
- 落库数据为**未发布状态**（草稿，带批次号），不影响线上生效数据。

**FR-IMP-5 发布**
- 用户核查无误后发布；发布前**再次检查**，通过后该批次数据转为生效数据，同配置定义下旧生效数据被替换（保持只有一份生效版本）。
- 异步执行、进度与结果可见；发布成功后可在数据浏览页查看生效数据。

### 3.5 AI 对话助手（右侧常驻）

**FR-AI-1 布局与生命周期**
- 右侧 AI 对话栏常驻；对话会话以浏览器页签为单位唯一（前端 sessionStorage 生成 UUID），**不持久化、不看历史**；新页签=新会话，关闭页签即销毁。
- 页面切换时对话继续（上下文快照随页面更新）。

**FR-AI-2 后端 AI Runtime**
- 全部 AI 逻辑（提示词、工具注册与执行、Agent 循环）在后端；前端只负责发送消息、渲染流式输出、执行后端下发的 UI 事件。API 密钥不出后端。

**FR-AI-3 渐进式披露（不同页面不同工具）**
- 工具按页面注册：导出页/导入页/配置定义页/数据浏览页 + 全局通用工具；AI 只能调用当前页面允许的工具，系统提示词中仅披露当前页工具清单。

**FR-AI-4 状态同步**
- 业务→AI：每次发消息携带“上下文快照”（当前页面、向导步骤、已选配置、查询条件、任务/批次 id 等），后端存入会话。
- AI→业务：工具执行结果附带 ui_event 指令（跳步、勾选配置、填条件、打开表格、触发下载、刷新列表、打开页面、提示等），前端统一分发到与用户点击完全相同的 store action，保证两侧状态一致。
- 工具执行过程（工具名/参数/结果摘要）在对话流中可见（透明可审计）。

**FR-AI-5 交互能力**
- 流式输出（含推理过程折叠展示）；可停止生成；可清空会话。
- 典型指令：询问有哪些配置、帮我导出 XX 配置、设置查询条件、帮我检查上传的文件、发布批次、解释错误明细等。
- 提供快捷指令（按当前页面动态推荐）。

### 3.6 快速实施任务管理（任务中心）

**FR-TASK-1 统一任务列表**：查看全部历史任务（导出任务 + 导入任务合并展示），含任务唯一键、类型、名称、涉及配置、状态、进度、消息、创建时间。

**FR-TASK-2 持久化**：任务在创建时即持久化入库（导出任务在向导“开始导出”时创建并立即落库，导入任务在“创建/复用导入批次”时创建并立即落库），运行中与历史任务刷新页面/重启服务后均可查；状态与进度随执行实时写库。

**FR-TASK-3 实时状态**：运行中任务自动轮询刷新（状态/进度来自持久化快照，SSE 订阅与轮询互为补充）。

**FR-TASK-4 任务恢复**：从任务列表一键跳转对应向导并恢复该任务视图（运行中任务自动重新订阅进度）。

**FR-TASK-5 过滤与分页**：按任务类型（导出/导入）过滤；服务端分页（可调每页 10/20/50/100）；任务列表按创建时间倒序。

**FR-AI-6 刷新恢复**：同一页签内刷新页面后，按会话自动恢复对话历史（用户/助手消息与工具卡片）；后端会话为内存态，后端重启后历史自然失效，前端自动降级为新会话（不报错）。

### 3.7 非功能需求

| 项 | 要求 |
|---|---|
| 界面语言 | 全中文 |
| 数据库 | 嵌入式 H2 文件库（backend/data），无需外部服务 |
| 端口 | 启动前检测占用，被占用则修改配置换空闲端口 |
| 任务可靠性 | 长任务异步执行；进度 SSE 推送 + 持久化快照（刷新可恢复） |
| AI 安全 | 密钥仅后端持有；工具执行结果回灌模型前截断；工具权限按页面隔离 |
| 兼容 | 上传 zip 防路径穿越（zip-slip）；文件名严格匹配编码 |
| 文档 | 需求/技术/实现/测试用例/验证结果等全部落 docs/ |

## 4. 界面需求（左右双栏）

```
┌──────────────────────────────────────────────────────────┐
│ 顶部导航：导出配置 | 导入配置 | 配置定义 | 数据浏览          │
├────────────────────────────────┬─────────────────────────┤
│ 左侧：业务工作区（多步骤任务向导）  │ 右侧：AI 对话栏（常驻）    │
│  - 步骤条 / 动态表单 / 表格       │  - 消息流（含工具执行卡片）  │
│  - SpreadJS 在线编辑            │  - 快捷指令 / 输入框        │
│  - 进度条 / 结果明细             │  - 思考过程折叠             │
└────────────────────────────────┴─────────────────────────┘
```

- 导出向导 3 步：①选择配置 ②查询条件 ③导出与在线编辑下载。
- 导入向导 4 步：①上传/模板/在线编辑 ②检查 ③导入 ④发布。
- 进度区统一组件：任务状态、百分比、阶段消息、每文件状态。

## 5. 验收标准（摘要，详见 docs/04-测试用例.md）

1. 配置定义动态增改后，表单/表格/导出条件/导入检查即时按新结构工作。
2. 导出全流程：多选、条件过滤正确、进度实时、xlsx 可下载可编辑、打包/全部下载 zip 内容正确。
3. 导入全流程：模板（单个/zip）可下载且含下拉验证；上传 xlsx/zip 文件名匹配正确；检查/导入/发布三步均异步+进度+明细；依赖顺序与引用校验正确；未发布不影响生效数据；发布后替换生效数据。
4. AI：流式输出、工具可见、按页面渐进披露、ui_event 正确驱动工作区（与手工操作等价）、页签会话隔离、可停止/清空。
5. 全部测试用例通过，验证结果记录在 docs/05-验证结果.md。
