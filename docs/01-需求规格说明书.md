## 1. 项目概述

### 1.1 背景

系统中存在大量**结构各异的配置项**（配置定义），其字段、类型、校验规则均由系统动态定义。实施人员需要频繁地完成配置的**导出**（交付/备份/线下加工）与**导入**（环境初始化/批量变更）。

为降低实施门槛，平台提供：

1. **多步骤任务向导**（业务工作区）：覆盖导出/导入全流程；
2. **常驻 AI 对话栏**：用户用自然语言即可完成同样的操作。

### 1.2 目标

- 用户既可以只用工位区向导完成全部操作，也可以只用 AI 对话完成全部操作，两条通路**功能等价**；
- 两条通路**状态实时联动**但**架构解耦**（未来去掉任意一方，另一方不受影响）；
- 导出/检查/导入/发布等耗时操作**可见进度、可取消**；
- 所有任务**持久化**，可查看历史任务状态与进度，可恢复继续处理。

### 1.3 范围

包含：配置项动态建模与渲染、导出任务、导入任务、任务管理、AI 对话（后端 AI Runtime）、状态联动。
不包含：多用户/权限体系、审批流引擎、配置项定义的新增/修改界面（定义由种子数据提供，字段结构动态读取）、跨浏览器页签的实时同步。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 配置项（配置定义） | 一种配置数据类型，含编码、名称、层级、字段结构（字段编码/名称/类型/必填/枚举选项/是否业务键） |
| 配置数据行 | 某配置项下的一行业务数据，以「字段编码 → 值」的 JSON 形式存储 |
| 层级 | 配置项归属：全局（GLOBAL）、地区（REGION）、项目（PROJECT），一个配置项只属于一个层级 |
| 适用范围 | 地区/项目级配置数据行上的范围值（如华北地区、PRJ-1001），全局配置无此列 |
| 业务键 | 配置项内唯一标识一行的字段组合（如参数名），用于比对新增/修改/删除 |
| 快速实施任务 | 一次导出或导入的完整执行过程，多步骤、有状态、可恢复 |
| 暂存（STAGED） | 导入但未发布的数据状态；发布（PUBLISHED）前的隔离区 |
| 会话（Session） | 浏览器页签级的 AI 对话上下文，刷新保持、关页签即销毁、不持久化 |

## 3. 功能需求

### 3.1 配置项动态建模

**FR-C01 配置项目录**
- 系统按种子数据提供 ≥6 个配置项，覆盖三个层级；
- 每个配置项含：编码（唯一）、名称、层级、描述、依赖项（可为空）、字段列表；
- 字段含：编码、名称、数据类型（文本/整数/小数/日期/布尔/枚举/适用范围）、是否必填、枚举选项、是否业务键、排序号。

**FR-C02 动态渲染**
- 前端所有表格/表单/查询条件均由字段定义**动态渲染**，不硬编码任何具体配置项结构；
- 枚举字段渲染为下拉；布尔渲染为复选；适用范围字段按范围字典渲染为下拉。

**FR-C03 配置数据**
- 每个配置项预置业务数据行（其中至少一个配置项数据量较大，用于验证导出进度）；
- 查询条件按数据类型支持不同操作符：文本（=、≠、包含、IN）、数值/日期（=、≠、>、<、区间）、布尔/枚举/范围（=、≠）。

### 3.2 导出配置任务（EXPORT_CONFIG）

步骤：`选择配置 → 查询配置 → 导出配置`。

**FR-E01 选择配置**
- 以配置项卡片（按层级分组）多选；必须至少选择 1 个才能进入下一步。

**FR-E02 查询配置**
- 每个已选配置项独立设置查询条件（0..n 条），字段与操作符由该配置项结构动态生成；
- 不设条件 = 导出该配置项全部已发布数据。

**FR-E03 导出配置**
- 后端逐配置项执行查询，**显示总进度与各配置项状态**；耗时操作异步执行；
- 结果按配置项分页签用 SpreadJS 在线展示，**可编辑**；
- 可勾选若干配置项**打包下载（zip）**，也可**全部下载**；单个配置项直接下载 xlsx；
- 下载文件由当前 SpreadJS 内容生成（保留用户在线编辑结果与数据校验下拉）；
- 导出完成（非下载完成）即任务成功。

### 3.3 导入配置任务（IMPORT_CONFIG）

步骤：`选择配置 → 上传配置 → 检查配置 → 导入配置 → 发布配置`。

**FR-I01 选择配置**
- 同 FR-E01。

**FR-I02 上传配置**
- 每个已选配置项可：**下载模板**（单个 xlsx；多个由前端打包 zip）、**上传文件**、**在线编辑**（未上传也可直接按模板在线编辑）；
- 上传支持：单个/多个 xlsx，或一个 zip（前端解包）；**按文件名匹配配置项编码**，未匹配的文件明确报错；
- 上传或在线编辑保存后覆盖该配置项在任务中的暂存数据；上传后仍可再次在线编辑。

**FR-I03 检查配置（预检查）**
- 后端异步执行，显示进度与逐项检查结果；
- 检查规则：表头/必填/类型/枚举/业务键重复/适用范围合法性/**跨配置项依赖**（被依赖配置项需先满足：如“告警阈值.指标编码”必须存在于“指标字典”的上传数据或已发布数据中）；
- 存在错误则不能进入导入；警告不影响；
- 检查结果按配置项分组展示错误明细（行号、字段、原因）与依赖说明。

**FR-I04 导入配置**
- 后端异步执行，显示进度与结果；导入前再次校验，有问题则中止；
- 导入采用**暂存区方案**：数据落库为 `STAGED` 状态，不覆盖 `PUBLISHED` 数据；
- 存在依赖的配置项按依赖顺序导入；
- 导入完成后展示与当前已发布数据的差异摘要（新增/修改/未变化/将替换范围）。

**FR-I05 发布配置**
- 用户确认后执行；后端异步执行，显示进度与结果；发布前再次校验（含依赖）；
- 发布 = 用暂存数据**替换**对应配置项、对应适用范围内的已发布数据（范围外数据不动），`STAGED → PUBLISHED`；
- 发布成功后任务成功；失败给出明细，可修复后重试（重新上传→检查→导入→发布）。

### 3.4 任务管理

**FR-T01 持久化**：选择任务类型并创建任务的那一刻即持久化（H2 文件库），含全部步骤状态与参数；刷新/重启后可继续。

**FR-T02 任务列表**：任务中心查看全部历史任务：类型、状态、当前步骤、进度、创建/更新时间；支持按类型/状态筛选。

**FR-T03 状态与进度**：任务状态机：`执行中（含等待用户输入/后台执行）→ 成功 / 失败 / 已取消`；后台操作执行中实时显示进度（百分比 + 当前处理项 + 分项状态）。

**FR-T04 恢复**：非终态任务可「继续处理」，将任务绑定到当前会话并打开向导（定位到当前步骤）。

**FR-T05 取消**：后台操作执行中或等待用户时，可取消任务；取消在当前配置项处理完的边界生效。

### 3.5 AI 对话（后端 AI Runtime）

**FR-A01 通路等价**
- AI 通过后端工具（Function Calling）调用与 REST 完全相同的服务层完成业务操作；
- 不存在前端 AI Runtime；AI 无法完成的浏览器本地动作（如文件上传、下载文件）由 AI 明确引导用户在工作区完成；
- AI 可代替用户在线提交配置数据（在线编辑通路），实现纯对话完成导入全流程。

**FR-A02 工具渐进式披露**
- 无任务时：仅任务/目录类工具；导出任务进行中：目录 + 导出工具；导入任务进行中：目录 + 导入工具；
- 当前步骤不适用某工具时，工具执行层返回约束提示（三层防御：动态注册 / 提示词约束 / 执行层守卫）。

**FR-A03 会话规则**
- 会话 ID 存 `sessionStorage`：同一页签刷新不丢（对话历史与任务上下文均可恢复），新页签即新会话，关页签即销毁；
- 对话历史存后端内存（ChatMemory，按会话隔离），**不持久化**，服务重启即清空；
- 页面刷新后对话历史从后端内存恢复展示；提供「清空对话」。

**FR-A04 上下文与准确性**
- 每轮请求注入当前会话状态摘要（当前任务类型/步骤/已选配置/各配置数据就绪情况），AI 决策始终基于**请求时刻**的最新状态；
- AI 需要明细数据时通过工具现查（pull），不做工作区状态的全量推送。

**FR-A05 流式与活动可见**
- AI 回复流式输出（SSE token 流）；AI 执行工具时，对话栏实时出现「操作卡片」（如：已选择 3 个配置项）。

### 3.6 状态联动（解耦要求）

**FR-S01 单一事实源**：任务/步骤/进度等共享状态只存在于后端；REST、AI 工具都是同一服务层的适配器。

**FR-S02 视图联动**：任一通路发生状态变化，后端通过 SSE 向会话广播（任务快照/进度/活动）；工作区与对话栏各自订阅渲染；用户在工作区手工操作后，AI 下一轮对话基于最新状态。

**FR-S03 非耦合**：移除 AI 对话栏（不出示、不调用），工作区全功能可用；反之仅用 AI 对话（不打开向导）也能完成导出/导入全流程（下载类动作除外，AI 引导用户操作）。

**FR-S04 导航主权**：AI 创建/推进任务不直接操纵前端路由；前端收到事件后自行决策（工作区处于首页时自动进入向导，否则通知并提供跳转入口）。

## 5. 验收标准（汇总）

1. 工位区向导独立完成：导出全流程（选择→条件→导出→在线编辑→打包下载）、导入全流程（选择→上传/在线编辑→检查→导入→发布），数据正确落库为 PUBLISHED；
2. AI 对话独立完成：创建任务、选配置、设条件、启动导出并查询结果；创建导入任务、提交数据、检查、导入、发布；
3. 联动：AI 操作后工作区实时更新；工作区操作后 AI 基于新状态应答；刷新页面对话与任务状态均恢复；新页签为全新会话；
4. 检查规则全部生效（含依赖检查与依赖顺序导入）；发布前数据隔离（STAGED）；
5. 任务中心可见全部任务、状态、进度；可恢复/取消；
6. 后端 JUnit 测试全部通过；E2E 场景在真实浏览器中验证通过并留证。
