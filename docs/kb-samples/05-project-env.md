# 项目环境管理口径（样例）

> 本文为**样例文档**，仅用于知识库功能验证，不含真实业务数据。

## 1 定义

项目环境（PROJECT_ENV）描述一个项目可用的运行环境集合，包括环境编码、环境类型、所属区域、默认币种与状态。它决定项目导出数据的范围与默认参数。

## 2 环境类型

| 类型编码 | 名称 | 用途 | 是否允许生产数据 |
| --- | --- | --- | --- |
| DEV | 开发 | 联调与自测 | 否 |
| TEST | 测试 | 功能验证 | 否 |
| UAT | 验收 | 用户验收 | 否 |
| PROD | 生产 | 正式运行 | 是 |

## 3 维护规则

1. 一个项目至少有一个 PROD 环境；
2. 环境编码在项目内唯一，跨项目可重复；
3. 环境所属区域决定默认费率，变更区域需要重新核对费率；
4. 环境停用前必须确认没有在途作业；
5. 环境清单（口头叫法）就是 PROJECT_ENV 的列表。

## 4 常见问题

**问：项目环境与区域是什么关系？**
答：环境属于区域，区域决定默认费率与告警阈值；一个区域可以有多个项目环境。

**问：可以把 DEV 环境改成 PROD 吗？**
答：不建议。类型变更会影响导出范围与权限校验，应新建 PROD 环境并迁移项目。

**问：环境清单在哪里看？**
答：配置管理平台「配置定义 → PROJECT_ENV → 数据浏览」，或让 AI 助手检索"项目环境"。
