# 查询条件写法（样例）

> 本文为**样例文档**，仅用于知识库功能验证，不含真实业务数据。

## 1 结构

查询条件由范围条件与字段条件两部分组成：

```json
{
  "scopeKeys": ["R-NORTH", "R-EAST"],
  "fields": [
    {"fieldCode": "level", "operator": "EQ", "value": "A"},
    {"fieldCode": "base_rate", "operator": "GTE", "value": 2.0}
  ]
}
```

字段条件之间是 AND；范围条件之间是 OR（命中任一范围即可）。

## 2 操作符

| 操作符 | 含义 | 值形态 |
| --- | --- | --- |
| EQ | 等于 | 标量 |
| NE | 不等于 | 标量 |
| CONTAINS | 包含子串 | 文本 |
| LIKE | 模糊匹配 | 文本 |
| STARTS_WITH | 前缀匹配 | 文本 |
| IN | 在集合内 | 数组 |
| EMPTY | 为空 | 不带值 |
| NOT_EMPTY | 不为空 | 不带值 |
| GT/GTE/LT/LTE | 比较 | 数值/日期 |

## 3 注意

1. IN 的值必须是数组，传字符串会被拒绝；
2. EMPTY/NOT_EMPTY 不带 value，带了也会被忽略；
3. GLOBAL 级定义忽略 scopeKeys；
4. 日期比较使用 `yyyy-MM-dd` 格式，不接受时间戳；
5. 条件为空对象等价于"不过滤"，不要用空条件冒充"查不到"。

## 4 常见错误

**错误：** 把 `fields` 写成扁平对象 `{"fieldCode":"level","operator":"EQ","value":"A"}`。
**后果：** 前端只读 `fields` 数组，扁平形态会被静默丢弃，表现为"工具成功但条件为空"。

**错误：** 用 `EQ` 比较数值却传字符串 `"3.40"`。
**后果：** 类型不匹配，比较结果不可靠；数值列请传数值。

## 5 与预览的关系

条件设置后只影响当前浏览器里的预览；落库发生在向导推进步骤时。关闭页面不会自动保存条件。
