# 配置定义与字段口径（样例）

> 本文为**样例文档**，仅用于知识库功能验证，不含真实业务数据。

## 1 定义与数据的关系

配置定义（ConfigDefinition）描述"一类配置由哪些字段组成"，配置数据是按定义落库的具体记录。定义是结构，数据是内容；改定义影响所有引用它的数据。

## 2 层级

| 层级 | 含义 | 典型定义 | 范围键 |
| --- | --- | --- | --- |
| GLOBAL | 全局 | CURRENCY | 无 |
| REGION | 区域级 | REGION_TARIFF | 区域编码 |
| PROJECT | 项目级 | PROJECT_ENV、PROJECT_MEMBER | 项目编码 |

层级决定范围过滤的行为：GLOBAL 忽略范围条件，REGION 按区域过滤，PROJECT 按项目过滤。

## 3 字段类型

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| STRING | 文本 | "R-NORTH" |
| INTEGER | 整数 | 100 |
| DECIMAL | 小数 | 3.40 |
| DATE | 日期 | 2026-01-01 |
| BOOLEAN | 布尔 | true |

## 4 字段属性

### 4.1 必填（required）

必填字段为空时，预检查直接失败。不要用空字符串代替"未填写"，空字符串会被当作有效值。

### 4.2 主键（key）

主键字段组合唯一。多字段主键时，所有主键字段都必填。主键重复是导入失败最常见的原因。

#### 4.2.1 复合主键的排序

复合主键在索引与导出的排序按"字段在定义中的声明顺序"，不按字母序。调整声明顺序会改变导出行的排序，属于可见变更，需要通知使用方。

#### 4.2.2 主键缺失

主键字段为空时，预检查直接失败并指出行号；不要用占位值（如 `0`、`N/A`）填充主键，占位值会造成更难发现的重复。


### 4.3 引用（refDefCode）

引用字段的值必须存在于被引用的定义中。引用已停用的定义时，预检查会提示"引用已停用"。

### 4.4 枚举（enum）

枚举值来自定义，不接受自定义值。枚举值大小写敏感，`A` 与 `a` 是两个值。

## 5 变更定义的影响

1. 新增字段：旧数据该字段为空，读取时按空值处理；
2. 删除字段：历史数据保留但不再展示，属于高风险操作；
3. 修改类型：需要数据迁移，不能直接改；
4. 修改必填：已有空值数据会导致后续导入失败。

定义变更必须评估存量数据，不能只看新数据能否导入。

## 6 常见问题

**问：定义可以改名吗？**
答：名称可以改，编码不行。编码是数据引用的键，改名不会破坏引用。

**问：一个字段可以既是主键又是引用吗？**
答：可以，但引用目标必须存在且唯一。

**问：为什么导入提示"字段不存在"？**
答：导入文件的列名与定义字段编码不一致，或定义尚未发布。

## 7 附录：字段校验伪代码

```java
for (FieldDef field : definition.getFields()) {
    if (field.isRequired() && isBlank(row.get(field.getCode()))) {
        errors.add("必填字段为空：" + field.getCode());
    }
    if (field.isKey()) {
        String key = row.get(field.getCode());
        if (!seenKeys.add(key)) {
            errors.add("主键重复：" + key);
        }
    }
}
```

伪代码仅表达校验顺序，不代表真实实现；真实实现以服务端预检查为准。
