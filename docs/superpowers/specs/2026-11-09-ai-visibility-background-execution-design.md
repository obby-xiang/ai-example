# AI 可见性与后台执行治理设计

日期：2026-11-09

## 问题证据与分析

1. `api/sse.ts#getPageVisible` 在标签页隐藏时无限等待，SSE 建连、重连和 `probeReattach` 同步停止；`stores/ai.ts` 的 history、重挂和自动恢复也复用该门，造成隐藏页收帧、回灌、恢复全部中断。
2. `document.hidden/visibilityState` 只描述浏览器生命周期，不等于业务页面不可见。后台页签、独立窗口、分屏、多显示器和 DOM 可操作性是不同概念；`document.hasFocus()` 同样不能作为执行许可。
3. `ai-dom-tools.ts#isElementVisibleForAi` 只核对 DOM 连接、CSS、hidden/inert 等，不覆盖视窗与裁剪容器；点击、填写、选择前没有统一的滚动和复核，存在“用户看不清却被程序点击”的反向缺口。
4. `navigate_to/select_definitions/confirm_step/set_condition` 与文件选择、人工表单、通用 DOM 写操作被同一策略处理，未区分可后台完成的业务动作和必须由用户参与的步骤。
5. 前端默认执行预算 60s、后端默认 120s，不是两者同为 120s；真正缺陷是隐藏页计时器可能被节流，且主要按 timeoutSeconds 折算而非统一 expiresAt 绝对期限。
6. 后端已有 park 一次性到期任务和重挂收敛，但一次性任务异常不重试，实例退出后缺少共享周期兜底，可能永久 PENDING。
7. 隐藏期未消费请求帧恢复后重放，可能重复执行或回执 DUPLICATE；相同结果应幂等收口，真实冲突不得掩盖。

## 结论与目标

- 页面可见性只影响需要用户观看或参与的步骤，不得成为传输、恢复和后台业务执行总开关。
- 业务可见性按当前路由、任务绑定、页面挂载、UI 代次判断；元素可操作性再按 DOM 存在、CSS、禁用、视窗与裁剪判断。视窗外不当然不可执行，允许时先滚动再复核。
- 隐藏页仍收帧、恢复、执行允许的业务工具并回灌；人工确认、生成式表单、文件选择等继续由用户处理。
- 前后端以 expiresAt 为共同绝对期限，重复结果幂等收口，真实冲突保持失败。
- 后端到期任务具备有界重试、跨实例共享扫描和启动恢复，保留 guard/fence/单写者与 FRONTEND_TIMEOUT=结局未知。

## 非目标与约束

- 不新增依赖、线程池、每 run 线程、供应商/模型特判或无界扫描。
- 不改变 HITL/表单人工决策，不把 DUPLICATE 一律吞成成功，不掩盖真实副作用冲突。
- 不修改普通测试代码，不执行测试验证；生产编译/构建和脚本语法检查必须实际执行。
- 当前恢复提示批次正在修改 stores/ai.ts，本批该文件必须等其完成后接续，禁止并行覆盖。

## 方案比较与裁决

- 仅给 getPageVisible 加超时：把无限等待变成有界失败，不能恢复收帧，不采纳。
- 传输与业务执行解耦，按真实业务/元素可操作性分类，并补后端到期兜底：采纳。
- 全面取消所有可见性检查：会保留路由过期和不可见 DOM 误操作，不采纳。

## 施工与验收边界

- `api/sse.ts`：隐藏时仍建连/重连/探测。
- `stores/ai.ts`：待前一批完成后移除 history/恢复门，处理重复回执幂等语义。
- `ai-dom-tools.ts`：统一路由/代次/元素/视窗可操作性，必要时滚动后复核。
- `frontend-tools.ts`：按 expiresAt 计算剩余预算并区分不可操作结果。
- `ConfirmGate.java` 与共享运行器：有界重试、跨实例扫描、启动恢复。
- 独立场景覆盖后台四类工具、视窗元素、无客户端到期、实例切换、重放幂等；DeepSeek 不使用 CU，逐场景执行。
