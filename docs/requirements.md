## 1. 项目背景

本系统演示一种**通用的 AI 协作运行时（AI Copilot Runtime）**架构，以配置项的"快速实施"场景为业务载体，实现：
- 业务向导（左侧）与 AI 对话框（右侧）的实时状态同步
- 不同页面/步骤向 AI 暴露不同工具集（渐进式披露）
- 后端 AI Runtime（Spring AI 1.1.8），不在前端保存 API Key

## 2. 功能需求

### 2.1 配置项管理

#### 2.1.1 配置定义（动态结构）
- 每种配置定义有唯一编码（code）、名称、层级（GLOBAL/REGION/PROJECT）、字段列表
- 字段属性：编码、标签（中文）、类型（STRING/NUMBER/DATE/ENUM/BOOLEAN/REFERENCE）、是否必填、是否主键、下拉选项（ENUM）、引用目标（REFERENCE）
- 系统预置多个配置定义（含数据种子），管理员可通过 UI 增改
- 配置定义之间可建立依赖关系（引用另一个定义的主键字段）

#### 2.1.2 配置层级
| 层级 | 说明 | 系统字段 |
|------|------|------|
| GLOBAL | 全局，不区分地区/项目 | 无 |
| REGION | 地区级 | region_code（下拉）|
| PROJECT | 项目级 | project_code（下拉）|

#### 2.1.3 配置数据
- 发布后的数据存入主数据表（config_data_rows）
- 导入流程中的中间数据存入暂存表（config_staging_rows）
- 支持按层级、编码、主键值查询

### 2.2 快速实施任务

任务类型可扩展（当前实现导出和导入两种），每类任务有独立的步骤序列。

- **任务详情**：流程步骤进度、各配置项条目状态（检查通过/已导入/已发布/失败）、

- **状态流转**：作业完成后自动更新任务与条目状态

#### 2.2.1 导出配置（EXPORT）

步骤：**选择配置 → 查询条件 → 执行导出**

| 步骤 | 操作 | 说明 |
|------|------|------|
| 选择配置（SELECT_DEFS） | 勾选要导出的配置项 | 多选，显示层级/字段数/行数 |
| 查询条件（QUERY_COND） | 为每个配置项设置过滤条件 | 字段类型决定操作符；地区/项目多选 |
| 执行导出（EXPORT） | 启动异步导出作业 | SSE 推送进度；每个配置生成一个 xlsx |

导出结果：
- 列表显示每个配置文件的行数、状态
- 可在线用 SpreadJS 打开编辑（保存回后端）
- 可勾选单个下载或全部打包下载（zip）

#### 2.2.2 导入配置（IMPORT）

步骤：**上传配置 → 检查配置 → 导入配置 → 发布配置**

| 步骤 | 操作 | 说明 |
|------|------|------|
| 上传配置（UPLOAD） | 选择配置、上传 Excel/ZIP | 可下载单个/批量模板；ZIP 按文件名匹配配置编码；支持 SpreadJS 在线编辑 |
| 检查配置（PRECHECK） | 后端预检查 | 按依赖顺序检查；SSE 推送进度；显示错误/警告详情 |
| 导入配置（IMPORT） | 写入暂存区 | 预检通过后可操作；显示与当前发布数据的 diff |
| 发布配置（PUBLISH） | 原子性事务提交 | 需用户确认；再次做发布前校验；显示发布结果 |

### 2.3 AI 对话功能

#### 2.3.1 整体布局
- 左侧：业务工作区（占 65%），右侧：常驻 AI 对话栏（占 35%）
- AI 对话栏不随路由切换销毁

#### 2.3.2 会话生命周期
- 会话 ID（sid）存于浏览器 sessionStorage（页签唯一，复制页签时重建）
- 后端内存存储（Caffeine），TTL 30 分钟（无活动）
- 不需要持久化历史对话，刷新同一页签时从后端内存恢复当前会话

#### 2.3.3 渐进式工具披露
AI 在不同页面/步骤只能看到对应的工具集：

| 页面/步骤 | 可用工具 |
|----------|---------|
| 全局 | 导航、获取工作区状态、列出/查询配置定义 |
| 任务中心 | + 创建任务、列出任务 |
| 导出-选择配置 | + 选择/取消配置、获取配置详情 |
| 导出-查询条件 | + 设置/获取查询条件 |
| 导出-执行导出 | + 启动导出、等待导出完成、打开文件编辑器、下载 ｜**注记（2026-10-10 等待成本治理批 A）**：本行的"下载"即 AI 工具 `download_export_file`，其接线已按裁决改为**「即发即回」**——AI 侧只等**前置校验**（参数 / 任务绑定 / 结果存在性 / 切页），校验失败即如实回灌失败（卡片 failed），校验通过则回灌"已发起下载"并**立即返回**，不再等浏览器下载链路；同一配置在途时回执改为"已在进行中、本次未重复发起"。**覆盖口径**：本行的"下载"只覆盖到"已发起"，**不含**浏览器侧落盘结局（无二次回灌通道，属显式登记的残余面）。原实现同步等链路，被宿主浏览器拖住时回灌迟到 ⇒ 后端按超时收尾并回"本次调用未获得数据"（假失败，文件其实已落盘）；原表述按只追加纪律保留留痕。 |
| 导入-上传配置 | + 选择/取消配置、下载模板、绑定文件、请求文件上传 |
| 导入-检查配置 | + 启动预检、等待预检完成 |
| 导入-导入配置 | + 启动导入、等待导入完成、查看 diff |
| 导入-发布配置 | + 启动发布（需确认）、等待发布完成 |
| 配置定义管理 | + 草拟/保存配置定义（需确认）|

#### 2.3.4 状态同步
- 前端通过 PUT /api/ai/sessions/{sid}/context 上报当前页面、任务 ID、步骤
- AI 运行时每轮构建工作区快照（任务状态、当前步骤、选中的配置等）注入上下文
- AI 工具修改业务数据后，前端通过任务 SSE 流感知更新

#### 2.3.5 HITL（人在回路）
- 高风险操作（发布）须用户在 AI 面板的确认卡片上批准
- AI 的确认请求包含：操作摘要、影响说明、可修改的关键参数
- 用户可批准、拒绝（均作为工具结果回填）
- 拒绝后 AI 继续对话，不挂起

## 3. 非功能需求

| 类别 | 要求 |
|------|------|
| 语言 | 界面全中文 |
| 数据库 | H2 文件模式（`backend/data/`），ddl-auto:validate + Flyway 管理 |
| 文件存储 | 本地磁盘（`backend/data/files/`）|
| AI Runtime | 后端，API Key 不落前端 |
| 并发 | JDK 21 虚拟线程；每个 AI 会话同时只允许一个活跃 run |
| 进度 | 所有长任务（导出/预检/导入/发布）均通过 SSE 实时推送进度 |
| 取消 | 任务/AI run 均可取消 |
| 演示延迟 | 每批处理加可配置延迟（默认 500ms/批）模拟真实耗时 |
