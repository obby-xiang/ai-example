## 2. 核心流程实现

### 2.1 导出配置（3 步向导）

```
[前端] 步骤1 勾选配置（动态表格）
  → 步骤2 每个配置渲染动态条件表单（操作符按字段类型：等于/包含/大于/小于/介于/多选in；地区/项目带“范围”过滤）
  → POST /api/export/tasks {defCodes, conditions}
[后端] ExportService.create → 落库 PENDING → TaskRunner（异步线程池）执行：
  逐个配置：条件引擎查询 → POI 生成 xlsx（说明 sheet+数据 sheet，SELECT 列带隐藏 sheet 下拉验证）
  → 行级/任务级进度 publish 到 ProgressHub → SSE 推给前端
  → 完成后 filesJson 清单（{编码}.xlsx 可直接回传导入）
[前端] 步骤3 订阅 SSE：进度条 + 每文件状态 → SpreadJS(ExcelIO) 打开在线编辑
  → 单文件下载 / 勾选打包下载 / 全部下载（后端 zip，条目名={编码}.xlsx）
```

条件引擎（ConfigDataService.matchOne）：TEXT eq/contains；NUMBER/DATE eq/gt/lt/between（数值比较优先，失败按日期，再字符串）；BOOLEAN eq；SELECT eq/in。

### 2.2 导入配置（4 步向导）

```
[前端] 步骤1 勾选配置 → 模板下载（单 xlsx / 多 zip；GET /api/import/templates）
       上传（xlsx 或 zip 多文件；POST /batches/{id}/files，文件名匹配：{编码}.xlsx 或 {编码}(N).xlsx）
       SpreadJS 在线编辑（已上传文件或模板为起点）→ 保存并上传=覆盖
[后端] ensureBatch（同配置组未发布批次复用）→ 上传落盘 data/imports/{batchId}/{编码}.xlsx
[前端] 步骤2 检查 → POST /batches/{id}/check（异步）
[后端] 按依赖拓扑顺序逐个文件：
       解析（表头按中文名/编码匹配；未知列=警告；缺必填列=错误）
       → ValidationEngine 逐行校验（类型/必填/选项/数值范围/引用存在性/范围必填）
       → 引用值集合 = 已发布数据 + 本批次前序通过文件（依赖保证被引用者先检查）
       → 明细落盘 .issues.json + 每文件状态写回批次
[前端] 步骤3 导入 → POST /batches/{id}/import（导入前再次检查）
       通过文件 → 删旧草稿 → 插入 published=false + batchId；失败文件 SKIPPED
[前端] 步骤4 发布 → POST /batches/{id}/publish（发布前最终检查）
       全部通过 → 删除同定义旧生效数据 → 批次草稿转 published=true（替换生效）
```

### 2.3 AI 对话（Spring AI 官方能力组合：ChatClient + @Tool + ToolCallingManager 扩展点）

端点：`POST /api/ai/chat`（SSE 流式）、`POST /api/ai/confirm`（普通 JSON：释放 HITL 确认门，事件继续走原 chat 流）、`POST /api/ai/stop`、`POST /api/ai/clear`、`GET /api/ai/history`（刷新恢复：按页签会话返回 用户消息+助手文本+工具卡片摘要，会话持久化于 H2）、`GET /api/ai/tools?page=`。

架构（框架合规：协议/循环/Schema 全部交给 Spring AI）：

```
ChatClient(chatModel).prompt()
  .system(渐进式披露提示词).user(消息)
  .toolCallbacks(当前页 @Tool 回调)          ← Spring AI 自动生成 JSON Schema
  .toolContext({session, sink, services})     ← 官方 ToolContext 注入通道
  .advisors(MessageChatMemoryAdvisor(ChatMemory→H2 会话))  ← 官方历史记忆
  .stream().chatResponse()                    ← 官方 Agent 循环在 ChatModel 内部完成
OpenAiChatModel ← toolCallingManager(HooksToolCallingManager)  ← 官方扩展点：
  ① 工具执行前后 → SSE tool_start/tool_result（可见性）
  ② confirm=true 的工具 → 注册确认门并挂起（boundedElastic），前端确认/取消/超时/断连 → 放行或
     以“用户取消”结果回填，由模型如实解释；客户端断开（SSE completeWithError）自动释放确认门
流式增量：ChatResponse.getResult().getOutput().getText()（delta）+ getMetadata().get("reasoningContent")（思考折叠）
```

SSE 事件协议（前端 ai store 逐类消费）：

| 事件 | 负载 | 前端行为 |
|---|---|---|
| reasoning | {content} | 思考过程折叠区追加 |
| delta | {content} | 正文流式追加 |
| tool_start | {name, args} | 工具卡片（执行中） |
| tool_result | {name, ok, summary} | 工具卡片着色 + 结果摘要 |
| ui_event | {type, ...} | 统一分发器 → 各 store action |
| done | {content} | 收尾 |
| error | {message} | 错误提示 |
| usage | {usage} | token 统计（可选展示） |

ui_event 类型与目标 action：

| type | 目标 | 效果 |
|---|---|---|
| open_page {page} | router | 切换页面 |
| goto_step {step} | 当前向导 store | 跳步骤 |
| select_defs {task, defCodes} | export/import store | 勾选配置（同用户点击） |
| set_conditions {defCode, conditions} | export store | 填充条件表单 |
| export_started {taskId, snapshot} | export store | 记录任务+订阅 SSE+跳步骤3 |
| import_batch {batchId} | import store | 记录批次+跳步骤1 |
| import_action {batchId, action} | import store | 跳对应步骤+订阅 SSE（任务已由后端启动） |
| download {url, filename} | 浏览器 | 触发下载 |
| refresh_defs / refresh_data | defs store / 数据页 | 刷新列表 |
| confirm_tool {toolName, toolCallId, summary} | AI 面板 | 渲染确认卡片（HITL）；确认/取消 → POST /api/ai/confirm，原 chat 流继续推进 |

### 2.4 任务中心（快速实施任务管理）

```
[后端] GET /api/tasks?type=EXPORT|IMPORT&page=1&size=20
       → 合并 export_task 与 import_batch 两表（均 H2 持久化，创建即入库）：
         {key: EXPORT-{id}|IMPORT-{id}, id, taskType, taskTypeName, title, status, progress,
          message, defCodes, filesCount, createdAt, updatedAt}
       → 按创建时间倒序，服务端分页返回 {total, page, size, rows}
[前端] /tasks 页面：
       - 统一表格：类型/名称/涉及配置/状态(中文+着色)/进度条/消息/创建时间
       - el-pagination 分页（10/20/50/100 每页，翻页/跳页）
       - 每 4s 轮询刷新当前页（状态与进度在执行过程中已实时写库，刷新页面不丢失）
       - 点击行/查看 → 按类型跳转向导并恢复任务视图（运行中任务自动订阅 SSE 进度）
       - 新建导出任务/新建导入任务 → 跳转对应向导（创建即持久化）
```

持久化时机：导出任务在“开始导出”点击时 `POST /api/export/tasks` 立即落库（PENDING→RUNNING→SUCCESS/FAILED）；导入任务在“创建/复用导入批次”时 `POST /api/import/batches` 立即落库（CREATED→…→PUBLISHED/FAILED）；两表状态/进度随异步执行持续写回。

## 3. 关键实现细节

- **Spring AI 1.1.8 官方能力组合（不自行实现）**：工具=`@Tool` 注解方法（`ToolParam` 描述参数，Schema 自动生成）；Agent 循环=ChatClient 流式 + 模型内部 ToolCallingManager；历史=MessageChatMemoryAdvisor + 自定义 ChatMemory（H2 持久化，conversationId=页签 sessionId）；HITL=组合包装官方 DefaultToolCallingManager（仅确认门与 SSE 可见性两个钩子）。注意：1.1.8 无 `FunctionCallingOptions`（用 `ToolCallingChatOptions`）、`ToolCallbacks` 在 `org.springframework.ai.support`、流式 reasoning 从 `getMetadata().get("reasoningContent")` 取、`AssistantMessage` 无 reasoningContent 字段。
- **HITL 线程安全**：确认门挂起在 boundedElastic（整条流 subscribeOn），阻塞不占用 Netty 事件循环；SSE 客户端断开 → completeWithError → 自动释放确认门并终止流，避免线程泄漏。
- **SpreadJS/ExcelIO 17.x API**：`excelIO.open(file, success, error)` 返回 JSON → `spread.fromJSON(json)`；`excelIO.save(json, success, error)`；file 必须为 File 类型（fetch 的 Blob 需包装），验证期发现直接传 spread+blob 的旧式重载会触发 FileReader 类型错误。
- **依赖拓扑排序**：Kahn 算法，被依赖者在前；环依赖报错。
- **发布替换语义**：发布 = 删除同定义旧生效数据 + 批次草稿转生效（单一生效版本）。
- **幂等守卫**：check/import/publish 在执行中重复触发直接返回（用户点击与 AI ui_event 双入口不会双跑）。
- **xlsx 校验往返**：模板内嵌下拉验证经 ExcelIO 编辑导出后仍为 Excel 原生 DV（参考项目已验证同机制）。
- **大文件处理**：POI 流式事件模型不适用场景（行级校验需全量读），当前为 DOM 模式；>10MB 建议后续切 SXSSF/流式解析（扩展点）。
- **模拟延迟**：`app.task.simulate-delay-ms=5` 按行推进可见进度（演示大导出场景），生产可设 0。

## 4. 扩展性设计（已预留）

1. **条件引擎换存储**：ConfigDataService 查询接口不变，内部可从内存过滤替换为“动态列表/JSONB+索引/ES”，仅改实现类。
2. **对话历史**：AiSessionStore 增加 H2 落盘即可（会话对象已收敛读写点）。
3. **工具扩展**：新增 @Component 实现 AiTool 接口即可自动注册；pages 白名单控制披露。
4. **新任务类型**：复制 ExportController/Service 模式 + 注册页面与工具，向导前端加一路由。
5. **多用户/权限**：batchId/defCode 已具备租户隔离落点；AI 会话 key 可升级为 userId+sessionId。

## 5. 已知限制与说明

- SpreadJS 为商业组件：未配置 LicenseKey 时为评估模式（水印提示），功能完整；正式使用需购买授权并配置 `VITE_SPREADJS_KEY`（.env.local，不入库）。
- 条件过滤在内存进行，适用于中小规模（万级行内流畅）；更大规模见 §4。
- 模型服务为 DeepSeek deepseek-flash（V4.1-Flash，推理模型）：回复前有思考过程（界面折叠展示），工具调用实测可用。
