## 1. 发布模块重写（ADR-7 + Q14 定案）

**语义**：行级 upsert + 范围差集删除（保留 combined 乐观锁全部机制）。

| 要素 | 规格 | 出处 |
|---|---|---|
| 匹配键 | 配置项 × 业务键（含范围维度 __scope，FR-1.3） | FR-1.3 / V2 |
| 已存在行 | 更新字段值，**保留行 id**，version 递增（OPTIMISTIC_FORCE_INCREMENT 原语义） | V5 |
| 新业务键行 | 插入，version 从 1 起 | — |
| 范围差集删除 | 本次导入覆盖范围内、未出现在导入数据中的旧 PUBLISHED 行删除（事务内）——"范围内替换"业务语义的实现 | V2（glm 语义等价） |
| 冲突检测 | baseVersion 快照比对原样保留：导入时记快照，发布前比对当前 version，不一致 → 作业 FAILED + issues 文案（"发布冲突：行 X 在导入后被其他操作修改…"）；并发发布同范围时 upsert 路径下快照比对照常触发 | V5 / Q14 |
| 发布前终检 | 保留基座既有终检（FR-3.5） | 基座 |
| 事务边界 | 整个发布（upsert+差集删除+状态推进）单事务；作业全程状态机照 ADR-8 | ADR-8 |

**行为对照（红线 3）**：
- 重放 baseline-combined.md B2 导入发布场景：发布前后行数变化须与基线一致
  （APPROVE_ROLE 4→5、CURRENCY 5→7、DOC_TYPE 5→6、PROJ_APPROVE 0→3）；
- 重放 V2 双范围场景（glm 种子 REGION_NETWORK）：发布 R1 不影响 R2（逐字段含 __id 比对——
  注意：upsert 路径下同业务键行 __id 保留，这是与 glm 删建语义的**有意差异**，记决策点：
  __id 保留是 Q14 定案的直接后果，业务等价）；
- 重放 V5 并发冲突场景：T_A/T_B 同改一行并发发布，后者 FAILED + 原文案；
- 新增"并发发布同范围"场景（Q14）：两任务同范围不同行并发发布，快照比对触发冲突。

## 2. 作业治理修正（ADR-8 修正①②③ + W1 边界）

| # | 修正项 | 规格 | 出处 |
|---|---|---|---|
| ① | StaleJobRecoveryRunner 扫描范围 | 含 PENDING + RUNNING（基座实测残留为 PENDING） | Q6/V6 |
| ② | 僵尸恢复动作 | 标记作业 FAILED **并联动回写任务状态**（任务→失败/可恢复态），不自动重排队；重跑经任务中心一键恢复（FR-4.2） | Q5 定案 |
| ③ | 取消标志 | **Redis 共享标志为准**（键 `job:cancel:{jobId}`，持有实例在分片/事件边界轮询，延迟 ≤1 分片）；进程内直通知仅可选加速、失败不视为错误 | CH-P9/W1 |
| ④ | 取消已终态作业 | 返回 409 JOB_ALREADY_FINAL（不再静默 200） | W1 边界 |
| ⑤ | 进度快照 | 作业推进时同步回写任务/作业表的 processed/total（消除"事件领先于库"、运行中列表进度恒 0） | Q16⑤/W2 附带 |
| ⑥ | 任务态机断头路 | 补齐 CANCELLED/FAILED 任务态写入路径（取消联动、作业失败联动、僵尸恢复联动三处） | Q16④ |
