# S4.2 AI Runtime 合流执行规格书

> 日期：2026-10-07　主笔：指挥官（Kimi K3）
> 地位：S4.2 施工的唯一依据。执行者只执行、不重新裁决（决策卡流转纪律）。
> 依据：ADR-1~6、DC-01/02/05/12、Q2/Q10/Q11/Q13、SP-01ab/c/d、SP-02、W2。
> 范围：main-v2 后端 `ai/` 包整包替换 + 配套配置/控制器。不含前端（S4.4）、不含发布语义（S4.3）。

## 1. 目标与边界

把 combined 基座的手工协议 AI 层（AiService 巨型类）**整包替换**为官方循环运行时，
同时落地四个已在独立 spike 验证的机制——本规格的核心是**四机制的集成形态**（Q13：
此前四机制各自验证，从未共存，本规格定义它们在同一运行时的组装关系）：

| 机制 | 出处 | 集成落点 |
|---|---|---|
| M1 官方循环 + Hooks 确认门 | SP-01ab / deepseek HooksToolCallingManager | `SpToolCallingManager`（组合官方 DefaultToolCallingManager） |
| M2 Redis 会话记忆 | SP-01c / `RedisChatMemoryRepository`（SPI 实现） | `MessageChatMemoryAdvisor` 挂载，CONVERSATION_ID = sessionId |
| M3 挂起态外置 + 跨进程续跑 | SP-02 / RunStore + 重建完整历史 | `RunStore`（Redis）+ 续跑服务；硬规范①外置先于阻塞 ②续跑必须重建完整历史 |
| M4 韧性（断流重试/完成帧校验/取消） | SP-01d / ResilientChatService | 每轮重建请求 + 双超时 + 重试三条件 + start/done/error 终帧 |

横切：会话串行化（ADR-5 单值门 409 + Redis 锁 + reattach）、reasoning 补丁（ADR-4）、
渐进披露三重防线（FR-5.2）、OpenAI 兼容全配置化（DC-01）、禁用虚拟线程（DC-12）。

## 2. 包结构（backend/src/main/java/com/example/quickstart/ai/）

| 类 | 职责 | 主要移植来源 | 关键约束 |
|---|---|---|---|
| `config/AiModelConfig` | ChatModel/ChatClient 组装 | deepseek AiModelConfig + sp02 SpikeConfig | 官方扩展点接入；RetryTemplate 仅非流式（ADR-6） |
| `config/ReasoningAwareOpenAiChatModel` | reasoning_content 回填补丁 | **kimi-k3 同名类** | 同名包 Override 单方法；Javadoc 注明"升级后评审移除"（ADR-4） |
| `memory/RedisChatMemoryRepository` | 官方 SPI：Redis LIST+滑动 TTL 6h | **sp01c 同名类 + MessageJsonCodec** | saveAll=整窗口覆盖写；含 toolCalls/toolResponses 往返（SP-01c 实测） |
| `memory/MessageJsonCodec` | Message↔JSON 编解码 | sp01c | 类型字段+内容+toolCalls+toolResponses+timestamp |
| `gate/SpToolCallingManager` | 确认门 + 前端工具挂起 + 可见性钩子 | deepseek HooksToolCallingManager + sp01ab SpikeToolCallingManager | 组合官方 DefaultToolCallingManager；挂起前先写 RunStore（硬规范①） |
| `gate/ConfirmGate` | 确认门状态机（放行/拒绝/超时取消） | sp01ab Gate | 超时自动取消；决策写 Redis（APPROVED/executed 标记，SP-02 E2 语义） |
| `run/RunStore` | 挂起态/台账 Redis 外置 | **sp02 RunStore + RunSnapshot** | 含 assistant(tool_calls) 完整快照；跨进程台账 executedBy（防重放） |
| `run/ResumeService` | 续跑：重建完整历史→官方循环 | sp02 ExplicitLoopRunner（重建部分） | 硬规范②：续跑必须重建完整历史（system/user 不丢）；runId 互斥锁（N4③） |
| `run/ResilientChatService` | 流式编排：每轮重建+双超时+三条件重试+完成帧 | sp01d ResilientChatService | 两条硬规范（阈值>最长工具耗时；缺终帧=断流）；副作用信标 |
| `run/CancellationRegistry` | 取消标志（Redis 共享，轮询≤1分片） | sp01d CancellationRegistry + combined JobCancellationRegistry 语义 | ADR-8 修正③：Redis 为准，直通知仅加速 |
| `session/SessionGate` | 同 sessionId 单值门 409 + reattach | ADR-5 补记 | 409 携带进行中 runId；Redis 锁 watchdog 续期+轮终态主动释放；锁降级=进程内单值门（§13.1） |
| `session/AiSessionService` | 会话生命周期（页签 sessionId） | deepseek AiSessionStore（改 Redis 存储） | TTL 6h 滑动；无长期留存（DC-02/D1） |
| `tools/AiTools` | @Tool 业务工具集（渐进披露分组） | deepseek AiTools + 基座业务服务 | 与 REST 同服务层（单一事实源，FR-5.4/D2） |
| `tools/ToolScopeFilter` | 按页面/步骤/任务类型披露子集 | deepseek ToolMeta + kimi frontend-tools 可用性表 | 三重防线：过滤+提示词声明+执行兜底（FR-5.2） |
| `web/AiController` | /api/ai/chat（SSE）、/confirm、/frontend-tool-result、/history、/events/{runId}（reattach） | sp01ab/sp02 控制器形态 | 全 SSE 首包 start 事件；确认/回灌幂等（SP-01d V-d2B：重复 toolCallId 拒绝） |
| `exec/AiExecutorConfig` | 线程模型 | DC-12 + 重审 N1 | 专用有界平台线程池（挂起承载，饱和 503 SUSPEND_POOL_SATURATED）；承认 boundedElastic 各占 1 条；禁用虚拟线程 |

## 3. 集成关键时序（四机制如何咬合——Q13 的核心答案）

1. 请求进入 → SessionGate 取 Redis 锁（409/reattach 分流）→ AiSessionService 校验 TTL 会话
2. ResilientChatService 开流：先发 start 帧 → 构建本轮请求（ChatClient + MessageChatMemoryAdvisor(Redis 记忆) + ToolScopeFilter 披露子集）
3. 官方循环执行 → 遇确认门/前端工具 → SpToolCallingManager **先把快照写 RunStore（含 assistant(tool_calls)）**，再阻塞挂起（专用池线程；ConfirmGate 等待决策，心跳保活）
4. 决策到达（confirm/回灌）→ 幂等校验（重复 toolCallId 拒绝）→ 回填循环继续
5. 断流 → 副作用信标判定（未产出且无副作用才重试）→ 每轮完整重建请求（含完整历史）
6. 进程死亡恢复 → ResumeService 扫 RunStore pending → 重建完整历史 → 官方循环续跑（台账防重放，APPROVED/executed 幂等键）
7. 终了 → done/error 终帧 → SessionGate 释放锁 → 记忆窗口 saveAll 落 Redis（覆盖写）

**一致性风险点（Q13 首要用例）**：步骤 7 的 saveAll 窗口覆盖写与步骤 3/6 的 RunStore 快照
是两套存储——续跑重建历史必须以 **RunStore 快照为准**（它含未入窗口的挂起轮），
不能让记忆窗口裁剪吃掉挂起轮的 tool 配对。ResumeService 重建后完成时，
以完整历史一次性 saveAll 刷新记忆，保证两者收敛。

| `app.ai.resilience.first-byte-timeout` / `inter-event-timeout` / `max-attempts` / `total-budget` | 待 §13.2 #2 压测 | 双超时+预算 |

## 5. 集成冒烟用例（S4.2 出口，Q13——四机制同开，不得以分项叠加替代）

| # | 用例 | 通过标准 |
|---|---|---|
| SM-01 | 续跑×记忆窗口一致性（Q13 首要） | 挂起轮的工具配对不被窗口裁剪吃掉；续跑后历史完整（system/user/assistant(tool_calls)/tool 全序列） |
| SM-02 | 断流重试 × 挂起交织 | 挂起等待期间上游静默 → 不误判断流（阈值>最长工具）；恢复后循环正确 |
| SM-03 | 会话串行化 × reattach | 运行中同 sessionId 第二轮 409 携 runId；reattach 重挂收流；锁过期早于轮结束无丢消息 |
| SM-04 | 重启续跑全链路 | 挂起中 kill → 重启 → 补执行恰好一次 → done 终帧 → 记忆收敛 |
| SM-05 | HITL 三结局 × Redis 记忆 | 放行/拒绝/超时后历史均正确落窗口，后续轮次记忆正常 |
| SM-06 | TC-AI-03b（SP-02 未闭合项） | 续跑后再发起外部工具调用在新进程内再次挂起 |
| SM-07 | 空 Key 启动 | 无 AI_API_KEY 时后端正常启动，业务 API 全通，AI 端点 503 |
| SM-08 | 双向导 AI 联动 E2E | AI 驱动导出+导入全链路（渐进披露子集正确、HITL 确认、终态快照正确） |

## 6. 不做清单（防范围蔓延）

- 不做 pub/sub 跨实例扇出（M2 激活包，DC-11）；不做事件缓冲/回放（W2 结论：新建项，M1 快照轮询为权威）；
- 不改发布语义/作业治理（S4.3）；不动前端（S4.4）；
- 不做权限/认证（DC-10）；不引入虚拟线程（DC-12）。
